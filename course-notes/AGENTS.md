# 网站课程笔记整理项目

本目录管理当前网站仓库的课程笔记整理工作。开始工作先读 README.md、prompts/rewrite.md 和 prompts/review.md。用户只要求搭建项目时，仅建立流程，不批量改写笔记。用户请求整理课次后，按以下完整流程执行。

## 目标与范围

- 模型由用户在 Codex 中选择 6-luna；脚本负责本地盘点、草稿、校验和发布，不调用模型 API，也不修改聊天的模型设置。
- 当前仅处理 src/data/notebook-config.mjs 配置的 2026 秋季四门课：概统、计算理论基础、操作系统、计算机视觉。
- 每次课一篇，篇内按知识主题组织。课堂知识保持完整，正文只包含知识陈述、必要动机、直觉、定义、性质、定理、证明、算法、例题、反例、代码和易错点。
- 原始 OnlineCourses 及 main-notes 的文件只读；其还原规则服务于课堂代餐。网站版采用本目录的整理规则，课程事务、师生闲聊、预告、转写过程和来源时间不进入网站正文。
- 不删除有知识内容的问答、比喻或“补充说明”；先提取有效知识，再改写。不设压缩比例，不以字数判断完成度。

## 执行流程

1. 运行 `npm run notes:inventory`，再用 `npm run notes:status` 选取待整理或需要更新的课次。来源删除时标记缺失，不能自动删除已发布页面。
2. 运行 `npm run notes:prepare -- --note <course-id/YYYY-MM-DD>`。读取返回目录的 task.md，以及 source.md、source-reports/、原始转写、材料索引。工作目录按来源指纹分版本；恢复任务时继续同版本草稿。
3. 建立完整知识清单。review.json 中 source_units 是自动定位的原文章节范围，不能当作自动识别出的知识清单。逐段阅读 source.md，在 reason 中列出该段实际知识、命题/例题和保留/排除理由；必要时另建本地 outline.md 细化，不漏掉无标题段落。
4. 依 prompts/rewrite.md 写 note.md；长篇按完整知识主题分段处理，保持命题与证明、题目与解答的连续性。分段完成后重新通读全文，统一符号、术语和标题，消除重复。
5. 结合原复查报告回查 SRT/DOCX。纯 ASR 错字直接使用正确术语；公式、结论、例题参数和逻辑冲突必须实际核对。必要时读取已定位的课件页或录屏画面；资料不能自动成为课堂事实。DOCX/PDF/PPT 等采用当前可用的对应文档技能读取。没有实际查阅的材料不得声称已核对。
6. 允许补齐推导/解答和纠正明确错误，正文分别标记“补充推导”“补充解答”“勘误”。每项在 additions 中登记对应标题、依据及 verified。不得编造缺失参数。未解决的知识冲突先留在草稿；若排除无法恢复的内容，必须说明原因，并确认不影响所保留知识的自足性。
7. 按 prompts/review.md 由人工或另一独立复核会话检查。复核身份不得伪造；撰写者的自检不能充当独立复核。至少 5 个可验证断言实际回查依据；问题修正后重新核实。记录真实阅读范围和复核范围，不声称未做过的全文 SRT 审计。
8. 所有覆盖项有去处、补充明确、疑点解决或明确排除、独立复核完成后，才把 checks 填为 true、status 改为 ready。运行 `npm run notes:validate -- --note <id>`，修复全部错误。
9. 运行 `npm run notes:publish -- --note <id>`，仅更新该篇网站 Markdown、对应核查记录和 catalog.json。`notes:sync` 是同一操作的别名。不得使用旧的“传入原笔记目录并整批复制”操作。
10. 批次完成后执行 `npm run check`、`npm run build`、`npm run verify`。检查公式、代码、标题以及对应阅读页；机检不证明知识正确。来源盘点后的 stale 成果必须完成更新才能通过网站构建门禁。
11. 将本批次实际变更的 `notebook/2026-autumn/<course>/<date>.md`、`course-notes/reviews/<course>/<date>.json`、`course-notes/catalog.json` 提交到当前网站 Git 仓库。使用精确路径 `git add`，查看 staged diff 后再 commit；不要用 `git add -A` 混入用户的其他修改。提交说明描述课程、日期或批次。推送在用户要求推送时执行。原材料、临时草稿和本地配置不提交。

## 发布纪律

- 正文从二级标题开始，仅使用二、三级标题。公式用 $ 或独占一行的 $$；不使用图片、脚本、来源时间戳、还原版元信息和“老师强调”等标签。
- 检查新增内容是否超出当次课知识主题；补充不能扩成课外教材章节。每条新增内容及勘误都登记，不能只登记类型总数。
- 每条原文章节记录有 include / merge / exclude 决定、具体理由及正文标题映射。隐藏在章节中的事务和知识必须分别判断。章节映射完整不等于知识完整，要人工逐项确认知识清单。
- 对原文声称“已复核”“全部覆盖”等表述，不直接继承为本轮结论；真实执行后才能记录。
- reviews/ 及 catalog.json 是公开仓库内容，只记录知识覆盖、补充依据和核查结果，不复制师生个人对话、事务通知全文、完整字幕或机器上的绝对路径。原始来源路径以源目录的相对路径表示。
- 外部来源改变后先重新 inventory，再 prepare 新版本。不能修改 input_hash 或 publication 哈希来绕过校验；不能手改发布文件后再“补一个哈希”。
- 20 篇现有网站快照在初始清单中都是待整理；不得将它们标为审核通过，不得把零篇整理成果的启动校验描述成课程内容验收。
