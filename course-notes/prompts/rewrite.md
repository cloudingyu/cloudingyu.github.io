# 网站知识笔记撰写任务

读取 task.md 指定的课次与输入，按下列要求整理；成果写到同目录 note.md，核查记录写到 review.json。

## 阅读与规划

1. 完整顺序读取 source.md；分段时记录实际行范围。先列出所有定义、性质、结论及条件、证明、算法、例题、反例、动机、知识问答和易错点。
2. 读取 source-reports/ 的既有疑点与材料归属说明。这些记录是核查线索，不是已经验证的正确答案。
3. 每个 source_units 的 source_heading 和行范围保持原样；在 reason 列出实际知识与处理理由。知识保留为 include，多个来源归入同一主题时为 merge；纯事务、无关闲聊或明确不能恢复的内容为 exclude。include/merge 的 output_heading 必须逐字对应 note.md 中的标题文本（不含 ## / ###）。
4. 给需要核对的结论建立 issues；从原始转写查找对应时间或段落，必要时实际读取对应课件页/画面。SRT 是含有 ASR 错误的课堂定位载体，不能据此证明数学结论正确。DOCX 原文按段落定位。

## 写作

- 每次课一篇，按知识依赖重排，不按课堂事件叙述。直接陈述“概念是什么、为什么需要、条件是什么、如何推导、如何使用”。
- 删除日期/节次/内容元信息、时间戳、来源说明、点名、个人故事、闲聊、课程评分、作业安排、预告和转写过程。个人故事中的知识或工程权衡提取后保留。
- 保留有助于理解的动机和直观解释；合并重复表达；学术问答融入知识主题。“老师强调”改为准确的知识限制或易错点。
- 定义保留量词与适用范围；证明保留关键步骤和每步依据；算法保留输入、操作、输出和限制；例题保留题目条件、解题思路、步骤和答案。不要仅留结论，不擅自将普通解释升级为定理。
- 格式采用普通段落、二/三级主题标题、必要的列表与表格。内容标签按需使用 **定义**、**命题**、**证明**、**题目**、**解答** 等；不强制每个主题具有全部栏目。
- LaTeX 使用 $...$ 和独占一行的 $$。代码使用有语言的闭合代码围栏。正文使用文字、表格、公式和代码，自足地解释原图含义。
- 允许补齐当次主题内的证明或解答，标记 **补充推导** / **补充解答**；明确错误纠正为 **勘误**。每一项在 additions 中分别记录 {type, output_heading, reason, verified: true}，reason 写具体逻辑/计算依据及实际查阅的位置。
- 参数缺失不得猜测。可恢复的题目先核对；无法恢复的题目排除不可信解答，记录理由，保留其中已确定的知识。有意义但条件不完整的题面可注明“条件不全”，不要在正文复制 ASR 错误原句。
- 标记未解决的问题，不能为通过校验而随意写 resolved/omitted。omitted 必须说明排除了什么，以及对知识完整性的影响。

## 交付

通读合并后的全文，对照知识清单逐项查漏，重算例题，检查条件、证明和符号。填写真实 author 和 reading 范围；未审阅材料写“未读取：原因”，没有独立材料写“无独立材料”。撰写者完成自检后交给独立复核者；独立复核完成前 status 保持 draft，不填造 reviewer。

工作目录中的 outline.md、分段草稿、截帧和原始摘录仅用于本地处理，不进入发布正文或公开核查记录。
