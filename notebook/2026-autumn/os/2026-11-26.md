## 一、持久性与 I/O 设备 [00:01:44–00:07:04]

### 1.1 课程的第三部分：持久性

今天开始讲操作系统课程的第三部分，叫做**持久性**（persistence）。前面两部分分别是**虚拟化**（virtualization）和**并发**（concurrency），第三部分要回答的问题是：数据怎么样才能被持久地保存下来。

计算机系统里承担这件事的部件，就是各种各样的 I/O 设备，也就是我们经常用的 I/O 设备、硬盘。所以硬盘是实现持久性最关键的一个部件——这一讲先把 I/O 设备讲清楚，再讲硬盘，最后讲架在硬盘之上的调度。

### 1.2 为什么计算机必须有 I/O 设备

老师的讲法是从"没有 I/O 会怎样"开始的。CPU 负责执行，RAM 负责存储，这两个部件如果单独工作，就只能执行固定的任务：既没有外界输入，也没有对执行过程的控制，它只能在内部自己跟自己打交道——执行事先写死的程序和数据，对外界没有任何反馈。所以必须通过 I/O 与外界打交道。

从结构上看，冯·诺依曼结构把计算机系统分成五块，其中两块就是输入和输出，也就是说 I/O 一个人就占了五块里的两块。I/O 设备还承担着与人的交互（鼠标、键盘）、与其他设备的交互（网络设备）、与其他系统的交互，以及数据存储（硬盘），因此它是计算机系统里非常重要的一块。像硬盘、鼠标、显示器这些负责与外界打交道的部件，都可以认为是**外设**（peripheral），或者就叫 I/O 设备。

### 1.3 持久性：断电以后数据还在不在

**定义**：持久性是指关机、断电以后，数据以及与之相关的信息是否还会丢失。

RAM 是断电以后数据就没有了的部件，所以持久性必须由别的部件来实现：断电以后数据仍然被保存下来。这一部分的讨论因此与持久性存储设备紧密相关，而硬盘正是其中最典型的一个。

### 1.4 用几个典型部件估算一台计算机的能力

老师顺手给了一个看机器的方法：一台计算机的能力大致可以用几个典型部件来刻画。平时看配置最关心三块——CPU 有多大（算力）、内存有多大、硬盘有多大；现在可能还会关注显卡。也就是说，一个系统的典型能力，大致就是"CPU 的算力 + 存储的容量 + I/O 设备"这几项，其中"存储"特别指断电以后还在的那一部分，也就是硬盘有多大。

这也说明 I/O 设备并不是外挂的附属品：不同 I/O 设备之间的差异非常大，而正是这些设备的组合决定了整个系统的外部交互能力。

## 二、I/O 设备的抽象：三个寄存器 [00:07:05–00:11:34]

### 2.1 设备形态与接口的差异

硬盘是 I/O 设备，鼠标是 I/O 设备，显示器也可以认为是 I/O 设备，但它们千差万别。按方向分：有的只做输入，最典型的是键盘；有的只做输出；有的输入输出都做，最典型的是硬盘——硬盘既可以写也可以读。

除了功能方向不同，它们的读取速率也差异很大，连接方式也不一样：不同的外部设备用不同的接口与计算机系统互联。操作系统的任务就是把这些接口差异屏蔽掉，提供一个统一的访问模式。

### 2.2 总线层次与 I/O 地址空间

按典型的计算机结构看，主板上的连接是分层的：北桥（north bridge）一侧接 CPU、内存、显卡这类高速部件，南桥（south bridge）一侧接各种较慢的外设。层与层之间通过不同的总线连接，典型接口有 USB、PCI/PCIe、SATA 等等。

接口规定了两件事：交互的速率是多少，控制指令长什么样。这就是不同接口的真正区别。USB 是目前用得最广的一种，很多外部设备都可以用 USB 互联，能实现高速互联；而像硬盘这样追求高性能的设备，则会用专用接口。

这些接口最终都能连到整个计算机系统上，CPU 和内存都可以与它们交互。实现的方式是做 I/O 地址编制：为各个 I/O 设备分配地址，从而让不同的外部设备可以被统一寻址、统一访问。

### 2.3 用三个寄存器描述一个设备

**定义**：操作系统把设备的读写操作抽象成三个**设备寄存器**（device register）上的操作，分别是状态（status）、命令（command）和数据（data）。

三个寄存器各自的分工是：

1. 状态寄存器记录当前这个设备处于什么状态，最典型的就是"忙不忙"；
2. 命令寄存器放要对设备执行的具体操作，比如对硬盘执行一次写；
3. 数据寄存器放真正要传输的内容。

于是"跟一个设备打交道"就被压缩成"读写这三个寄存器"。典型的操作过程是：把命令写到对应的寄存器，设备随后按命令去做后续的操作。

之所以要这样做，是因为每个设备的内部实现都不一样：硬盘的实现跟键盘完全不一样；即使都是硬盘，不同厂商的实现也可能不同。抽象的目的就是把底层细节藏起来，只保留一层大家都公认的、最基本的接口，而最典型的就是这三个寄存器：记录设备状态、记录要处理的数据、记录要执行的操作。

### 2.4 设备内部被隐藏的实现

三个寄存器背后是设备自己的实现。典型的设备内部有它自己的 CPU、自己的内存，还有一些其他专用芯片，每个设备都不一样。

键盘就是一个好例子：键盘上其实有一块单片机，也就是一个非常简单的处理器，负责处理按键、生成相应信息——所以键盘本身也是一台计算机。硬盘控制器同样如此，它里面也有一个处理器，负责处理对应的指令。

## 三、状态检查：轮询与中断 [00:11:35–00:17:16]

### 3.1 轮询写协议与 CPU 的时间线

对一个设备（比如硬盘）做一次写操作，协议是四步：

1. 读状态寄存器，如果设备处于忙的状态，就原地循环等待；
2. 把要写的数据写入数据寄存器；
3. 把命令写入命令寄存器，设备随后把状态重新置成忙，表示它已经开始处理这次操作；
4. 再读状态寄存器，继续等设备不忙。

老师把 CPU 和磁盘两边的时间线对齐讲了一遍。A 进程想发起一次 I/O，CPU 读状态发现设备忙，就在这个 while 循环里等；磁盘这时开始执行 A 进程的这次操作；随后 CPU 把数据写进数据寄存器、把命令写进命令寄存器；磁盘接着处理 A 的数据；等这次操作结束，CPU 才继续执行 A，A 结束后再切换到 B 进程。

问题出在 A 占用 CPU 的那段时间里：这段时间几乎全部花在反复查询"忙不忙"上。磁盘比 CPU 慢得多，如果让 CPU 不断地查询，就意味着 CPU 的大部分时间都在跑那个 while 循环。

> **老师强调**：忙等的模式去设计磁盘的读写，不是一个合理的模式——CPU 很快、磁盘很慢，让 CPU 一直查询，效率就比较低。

### 3.2 中断：把 CPU 从同步等待里解放出来

为了改变这个过程，引入**中断**（interrupt）。它的逻辑是：A 设备（进程）不用在那里等，把任务交给设备，等设备做好以后它自然会告诉你"做好了"，你再返回来、恢复前面被打断的执行点继续做就可以了。

这就是中断要做的事：让 CPU 不要一直跟慢速设备做同步等待，把这段时间解放出来。所以中断方式通常比查询方式快得多——CPU 不用等磁盘的读写状态，直接就可以去做其他事情。

> **老师总结**：中断本质上就是把 CPU 从与慢速设备的同步等待中解放出来。

### 3.3 中断一定更好吗

老师在这里停下来问了一句：有没有可能中断比轮询还慢？随后自己给出了例外。如果要做 I/O 的那个设备非常快，用中断反而不划算：中断有一套固定的处理流程要走，而设备快到只需要循环几次就完成时，直接轮询、循环几下就好了，这时轮询完全可能比中断更快。

所以两种方式要看适应的场景，一般来讲中断效果更好，但"设备很快"是一个明确的反向条件。

### 3.4 中断风暴与中断合并

还有一种情况：大量的中断同时到达（floods of interrupts）。这意味着系统要频繁地处理中断，处理中断本身就把时间占满了，做不了其他事情——不断在处理中断，实际工作推进不了。

减少这种开销的办法是把中断推迟、用批处理的方式交付，而不是来一个处理一个。

**补充说明**：根据本节补充材料《36. I_O Devices.pptx》第 19 张幻灯片，这种"一直在处理中断、始终没能推进实际工作"的状态在课件里叫 **livelock**（活锁）；相应的改进叫 **interrupt coalescing**（中断合并），即把若干个中断攒成一批再交付；课件还给出一种混合做法——设备完成时间不确定时，先自旋一小段，再转入中断等待。

### 3.5 小结：状态检查的两种方式

状态寄存器这一维只有两种实现：轮询（polling）和中断（interrupt）。它们适应不同场景，通常中断效果更好；设备极快时轮询更划算；中断过密时则要用推迟、批处理来压制开销。

## 四、数据传输与控制方式 [00:17:16–00:23:20]

### 4.1 PIO 与 DMA

状态讲完，接着是数据寄存器。它负责存真正要操作的内容：要往硬盘写东西，就得把要写的数据放到对应的区域去传输。传输有两种办法。

**编程式 I/O**（Programmed I/O, PIO）：由 CPU 亲自把数据交给设备——CPU 把要写的数据放进数据寄存器，每一次搬运都要 CPU 参与，所以效率相对较低。

**直接内存访问**（Direct Memory Access, DMA）：CPU 只把数据放在内存里的对应位置，I/O 设备直接对内存进行操作，CPU 不参与中途的搬运。

把两种方式放回时间线就看得更清楚。用中断以后，A 发起 I/O 就可以切换到 B，CPU 利用率已经提升；但"把数据搬给设备"这一段仍然要 CPU 做。改用 DMA，这一段也交给设备，于是数据传输期间 CPU 同样可以去干别的事情——这就是在数据传输环节上的进一步优化。

### 4.2 控制：特殊指令与内存映射

第三个寄存器是命令，它对应"用什么方式向设备发指令"，实现方法也有两种。

**特殊指令**：每个设备通常有自己独立的端口（port），CPU 用专门的指令（x86 上是 in/out）通过端口与设备通信，从而操作这个设备。

**内存映射 I/O**（memory-mapped I/O）：把硬件相关的寄存器映射到内存地址空间里，于是对这些地址做普通的访存操作就等于操作设备寄存器——用操作内存的方式来完成对设备的控制。

老师对这两种方式的态度很直接：差别不大，两种都在实际使用。

### 4.3 三个维度的组合

到这里，一个典型的外部设备或 I/O 设备的接口就被拆成了三个正交的维度，每个维度各有两种典型实现。

| 维度 | 对应寄存器 | 实现一 | 实现二 |
|---|---|---|---|
| 状态检查 | 状态 | 轮询（polling） | 中断（interrupt） |
| 数据传输 | 数据 | 编程式 I/O（PIO） | 直接内存访问（DMA） |
| 控制方式 | 命令 | 特殊指令（端口 + in/out） | 内存映射 I/O |

老师强调，这三条就是理解一个 I/O 设备的全部抓手：把这三个寄存器理解清楚，这个 I/O 设备就理解了；至于具体用哪种实现，不同设备可以自由组合。

## 五、设备驱动与存储栈 [00:23:28–00:25:58]

### 5.1 多样性带来的适配问题

外部设备的种类太多：速度不一样，操作类型也不一样。要让所有这些设备都能被系统使用，就需要一层适配机制，把各种硬件 I/O 操作都用统一的方式描述出来。

这一层就是**设备驱动**（device driver）。Linux 内核里有大量代码都在做这件事：Linux 源代码中约 70% 是驱动代码。比例之所以这么高，是因为每个设备的具体实现都不一样，驱动只能一个设备写一份。

### 5.2 存储栈的分层

对典型的存储设备，从硬件往上是一条清晰的分层链：硬盘 → 驱动 → 调度 → 文件系统 → 应用。

这条链里驱动这一层比较关键：它负责把上层的需求转化成底层的具体实现。再往上，调度层决定请求以什么顺序下发到硬盘——这正是本讲后半部分的主题。

### 5.3 I/O 设备部分的收束

把这一部分收一下：I/O 设备千差万别，但理解它们只需要抓住三个寄存器——状态、命令、数据；每个维度各有两种典型实现，状态是轮询或中断，数据是 PIO 或 DMA，控制是特殊指令或内存映射。把这三组选择说清楚，一个设备的行为就说清楚了。

> **老师总结**：I/O 设备这一块相对来说比较简单——三个寄存器，加上每个寄存器背后的两种实现机制。

## 六、机械硬盘的结构 [00:26:21–00:36:10]

### 6.1 硬盘的基本接口：一个扇区数组

硬盘是一个大容量的存储设备，而且是非易失的：断电以后数据还在。这里先讲比较早期的机械式硬盘，后面再讲现在更主流的固态硬盘。

从接口上看，机械硬盘把盘上的存储区域当作若干个**扇区**（sector）的集合，也就是一个可以用扇区号寻址的地址空间；基本操作只有两个——读和写。

硬盘比内存慢得多，这个"慢"恰恰意味着优化空间大：正因为每次访问都要花时间，才有必要去研究这些时间花在哪里、能不能少花一点。

### 6.2 盘片、盘面、磁道、柱面、扇区

硬盘的典型结构是一组盘片。每个盘片的表面都涂有存储介质，正反两面都可以写数据。为了提供更大的容量，通常把很多个盘片装在同一根轴上叠在一起：一片盘面能存很多东西，很多片盘面一起就能存更多；所有磁头装在同一套机械臂上，一起移动、一起读写。

盘面很大，所以要继续细分。

**定义**：盘面上被划分成的一圈一圈的同心圆环叫做**磁道**（track）。磁道记录的是移动臂能够访问的那一圈位置。

**定义**：不同盘面上相同位置的磁道合起来叫做一个**柱面**（cylinder）。

每条磁道再被划分成若干个**扇区**（sector），不同扇区存放不同的内容。

这三个术语是后面所有讨论的基础：寻道是在磁道之间移动，旋转是在磁道内等扇区转过来，而柱面则决定了"不用移动磁头就能连续访问"的范围。

### 6.3 读一个 12 号扇区：定位的全过程

老师用"读 12 号扇区"这个具体例子把整个过程走了一遍。

**例子**：要读盘面上的 12 号扇区。

12 号扇区位于偏外圈的某条磁道上。磁头的移动方式很受限：它固定在一根转轴上，只能沿着这根轴做径向移动，不能直接跳到任意一个扇区上去。所以读一个扇区要分两步走。

第一步是把磁头从它当前所在的磁道移动到 12 号所在的那条磁道，这个过程叫做**定位**（positioning），其中移动磁头到目标磁道所花的时间叫**寻道时间**（seek time）。

第二步是等。磁头到了目标磁道以后，12 号扇区未必正好在磁头下方，还要等盘片旋转，把 12 号转到磁头底下才能读。这一段等待叫**旋转延迟**（rotational delay）。

第三步才是真正把数据读出来、送到目的地址，这段时间叫**传输时间**（transfer time）。

所以一次读操作至少要经历三段时间：寻道、旋转、传输。老师特别提示了这个结构的不对称之处：磁头只能沿轴移动，盘片必须旋转，两个装置配合起来才能覆盖盘面上的任意位置——这也是机械硬盘所有性能问题的根源。

### 6.4 三段时间的第一次分解

把上面的过程抽象一下，访问一个扇区的时间就是

$$\text{访问时间} = \text{寻道时间} + \text{旋转延迟} + \text{传输时间}$$

这三项的性质完全不同：寻道取决于磁头要走多远，旋转取决于盘转多快，传输取决于盘的数据带宽。后面三节分别处理这三项，最后再讨论哪一项才是真正的变数。

## 七、访问时间的三部分 [00:36:18–01:01:47]

### 7.1 寻道：机械约束与非线性

寻道的目的就是把磁头移到目标磁道。磁头装在一个固定转轴上，只能沿着这个轴做径向的旋转移动，所以"移动到某条磁道"这件事本身是一次机械动作。

寻道时间和什么有关？直接相关的因素是两条磁道相距多远：一般来讲相距越远，花的时间越长。但这个关系不是线性的——磁头刚开始是静止的，为了移动到目标位置，它要先加速、再匀速、然后减速、最后稳定下来（settle），所以近距离寻道和远距离寻道的差距并不按比例增长。

课件给出的典型量级是：一次完整寻道通常几毫秒，课件上的典型区间是 4–10 ms。

统计上还有一个常用的结论：**平均寻道距离约为最大寻道距离的 1/3**。这个 1/3 不是随口给的，老师花了不少时间讲它是怎么来的。

### 7.2 平均寻道距离为什么是最大距离的 1/3

**推导**：设盘上共有 $N$ 条磁道，编号从 $1$ 到 $N$（最内圈为 $1$，最外圈为 $N$，反过来编号结论一样）。

第一步，设定随机模型。一次寻道的起点磁道号记为 $X$，终点磁道号记为 $Y$，并假设 $X$ 与 $Y$ 都均匀分布在这 $N$ 条磁道上。一次寻道要跨过的磁道数就是两点之差的绝对值

$$d(X,Y)=|X-Y|.$$

第二步，写出平均值的定义。$(X,Y)$ 一共有 $N^2$ 种取值组合，因此平均寻道距离是

$$\bar d=\frac{1}{N^{2}}\sum_{X=1}^{N}\sum_{Y=1}^{N}|X-Y|.$$

第三步，算内层求和。固定起点 $X$ 时，终点取遍 $1,\dots,N$，距离序列是 $X-1,X-2,\dots,1,0,1,\dots,N-X$，这是一个等差数列（先递减到 0 再递增），于是

$$\sum_{Y=1}^{N}|X-Y|=\frac{X(X-1)}{2}+\frac{(N-X)(N-X+1)}{2}.$$

第四步，对 $X$ 求和并除以 $N^2$。上式对 $X$ 求和后总量级是 $N^{3}/3$，再除以 $N^{2}$ 就得到 $\bar d \approx N/3$。也就是说平均寻道距离约为最大寻道距离（$N$ 条磁道的跨度）的 $1/3$。老师说自己没有去逐项验证到底是 $\frac{1}{3}N$ 还是 $\frac{1}{3}(N-1)$，但量级上就是 $1/3$，这点差别无关紧要。

第五步，换一个几何视角看同一件事。把 $(X,Y)$ 铺成一个 $N\times N$ 的正方形，正方形上每个格点 $(X,Y)$ 的"高度"取成距离 $|X-Y|$。对角线上 $X=Y$，高度处处为 $0$；离开对角线往两侧走，高度线性升高，最角上达到 $N$。这样得到的图形是两个对称的四面体（金字塔）。每个四面体的体积是

$$V=\frac{1}{3}\times \text{底面积}\times \text{高}=\frac{1}{3}\times\frac{N^{2}}{2}\times N=\frac{N^{3}}{6},$$

两个合计 $N^{3}/3$；再用总体积除以底面积 $N^{2}$，得到平均高度 $N/3$——和逐项求和的结果一致。老师用的正是"用体积除以底面积求平均高度"这个算法。

第六步，解释为什么不是直觉上的 $1/2$。很多人第一反应是平均距离应当是最大距离的一半。但只要起点不是固定的，$1/2$ 就不对：只有当起点永远固定在某一端（最内圈或最外圈）时，终点在 $1$ 到 $N$ 上均匀取值的平均距离才是 $N/2$。而实际寻道时起点和终点都是动态的，两端都靠中间的格子多、靠边的格子少，平均值就被拉低到 $1/3$。

第七步，说明这个结论的适用边界。$1/3$ 依赖"起点、终点在磁道上均匀分布"这一假设。真实负载往往不是均匀的：有些数据是热点，会被反复访问；有些数据几乎不被访问。在这种偏斜的访问分布下，$1/3$ 这个结论在很多负载下并不成立。

> **老师强调**：这个三分之一是做了一个假设的——它假设访问在磁道上均匀分布。

### 7.3 旋转延迟与转速

旋转延迟是"等目标扇区转到磁头下面"的时间。磁头已经停在目标磁道上，但它只能固定在磁道的某一个角度位置上，扇区只能靠盘片旋转送过来。

具体等多久取决于目标扇区当前离磁头多远，而这个位置是无法预测的。所以取统计值：最差情况是目标扇区刚好错过磁头、要等整整一圈；平均而言要等半圈。

一圈要转多久由转速决定。机械硬盘的这个参数叫 **RPM**（revolutions per minute，每分钟转数）。

**定义**：RPM 表示磁盘每分钟转多少圈，直接刻画盘片转得多快。

以常见的 7200 RPM 为例：一分钟转 7200 圈，所以一圈的时间是

$$\frac{1\ \text{min}}{7200}=\frac{60\ \text{s}}{7200}=8.3\ \text{ms}.$$

平均旋转延迟取半圈，即 $8.3/2 \approx 4.15$ ms。高端盘可以到 15000 RPM，此时一圈是 $60/15000=4$ ms，平均半圈约 $2$ ms。

转得越快，等的时间越短，性能越好；对一个确定的型号，旋转延迟基本是一个固定值。

### 7.4 传输时间

传输时间是把数据真正搬出来、送到目的地址的时间，取决于硬盘本身的带宽。一个扇区通常是 512 字节，如果有效带宽是 100 MB/s，那么读一个扇区的时间是

$$\frac{512\ \text{B}}{100\ \text{MB/s}} \approx \frac{512}{100\times 10^{6}}\ \text{s} \approx 5\ \mu\text{s}.$$

这个数比前两项小三个数量级——传输本身非常快。

### 7.5 哪一项才是变数

三段时间放在一起看，性质差别很明显：

| 分量 | 量级 | 是否可预测 |
|---|---|---|
| 寻道 | 毫秒级（4–10 ms） | 不可预测，取决于当前磁道与目标磁道的距离 |
| 旋转 | 毫秒级（半圈，7200 RPM 时约 4.15 ms） | 基本固定，由 RPM 决定 |
| 传输 | 微秒级（512 B 约 5 µs） | 基本固定，由带宽和块大小决定 |

变数最大的是寻道时间：你不知道目标磁道和当前磁道相距多远，所以它是唯一一个会大幅波动的量，也自然是优化的重点。旋转和传输则都相对固定，可以按参数估出来。

## 八、顺序与随机：两种负载的性能差 [01:01:48–01:11:10]

### 8.1 最好的情形：顺序负载

如果一次访问要读的所有内容都在同一条磁道上、并且连续存放，那么磁头根本不需要移动，寻道时间为 0；剩下的瓶颈只有传输时间。这是硬盘性能最好的情形，能接近标称的最大传输速率。老师把这种情形叫做顺序负载：所有要读的块正好落在同一条磁道或者相邻磁道上，磁头几乎不用移动，真正主导时间的就只剩传输。

这正好解释了磁盘碎片整理为什么有用：碎片整理做的事情，本质上就是把同一个文件的数据块搬到相邻的位置上。这样读这个文件时磁头不需要来回移动，可以连续读下去，读取速度显著提升。

> **老师提示**：碎片整理的逻辑就是设法让同一个文件的内容在盘上连续存放，从而把随机访问变成顺序访问。

反过来，如果数据随机散布在不同磁道上，每读一块都要移动磁头、再等旋转，寻道和旋转延迟全部叠加进来，性能就会被显著拉低。

### 8.2 随机负载：两块硬盘的算例

课件给了两块真实硬盘的规格，老师用它做了两道当堂计算的题。

| 规格 | Cheetah | Barracuda |
|---|---|---|
| 容量 | 300 GB | 1 TB |
| RPM | 15000 | 7200 |
| 平均寻道 | 4 ms | 9 ms |
| 最大传输速率 | 125 MB/s | 105 MB/s |
| 盘片数 | 4 | 4 |
| 缓存 | 16 MB | 32 MB |

先看顺序访问。顺序访问不需要寻道，所以吞吐率就等于最大传输速率：Cheetah 是 125 MB/s，Barracuda 是 105 MB/s。这也是厂商标称的那个数字。

**例题**：Cheetah 上随机读 16 KB 块的平均访问时间与吞吐率。

**题目**：已知 Cheetah 的平均寻道时间 4 ms、转速 15000 RPM、最大传输速率 125 MB/s，每次随机读 16 KB，求单次读的平均时间与吞吐率。

**解答**：
第一步，寻道时间直接取平均值 $4$ ms。
第二步，旋转延迟取半圈。15000 RPM 下一圈是 $60/15000=4$ ms，半圈即 $2$ ms。
第三步，传输时间 $=16\ \text{KB}/125\ \text{MB/s}\approx 0.128\ \text{ms}$，老师取约 $125\ \mu\text{s}=0.125$ ms。
第四步，三项相加：$4+2+0.125=6.125$ ms，即约 $6.1$ ms。
第五步，吞吐率 $=$ 数据量 $/$ 总时间 $=16\ \text{KB}/6.1\ \text{ms}\approx 2.5$ MB/s。

**结果与点评**：一次随机 16 KB 读要 6.1 ms，吞吐只有 2.5 MB/s，比标称的 125 MB/s 低了将近 50 倍。可见标称速率是一个极端理想值——只有在完全顺序、不需要寻道和旋转等待时才可能达到。

**例题**：Barracuda 上随机读 16 KB 块的平均访问时间与吞吐率。

**题目**：已知 Barracuda 的平均寻道 9 ms、转速 7200 RPM、最大传输 105 MB/s，每次随机读 16 KB，求单次读的平均时间与吞吐率。老师把这一问留给全班当堂算。

**解答**：
第一步，寻道时间 $9$ ms。
第二步，旋转延迟：7200 RPM 下一圈 $60/7200=8.3$ ms，半圈约 $4.1$ ms。
第三步，传输时间 $=16\ \text{KB}/105\ \text{MB/s}\approx 0.149\ \text{ms}=149\ \mu\text{s}$。
第四步，三项相加：$9+4.1+0.149\approx 13.2$ ms。
第五步，吞吐率 $=16\ \text{KB}/13.2\ \text{ms}\approx 1.2$ MB/s。

**结果与点评**：13.2 ms、1.2 MB/s。Barracuda 容量更大，但随机访问比 Cheetah 还慢一倍——它的 RPM 更低、平均寻道更长、传输速率也更低，三项全面落后，慢是正常的。

### 8.3 不能只看纸面参数

老师接着做了一个改动：假设 Barracuda 的最大传输速率不是 105 MB/s 而是 500 MB/s，随机读 16 KB 谁更快？

答案仍然是 Cheetah。原因是随机访问的总时间里，寻道和旋转占绝对主导：Barracuda 的传输时间即使从 149 µs 降到 33 µs，总时间也只是从 13.2 ms 降到 13.1 ms，几乎没变；而 Cheetah 的寻道加旋转只有 6 ms。前两项参数决定了胜负，第三项怎么改都翻不了盘。

> **老师强调**：买硬盘不能直接看纸面参数，还要考虑这些因素里哪一个占主导。

由此也能看出机械硬盘为什么被淘汰：寻道要移动机械臂、旋转要等盘片转过来，这两段时间太长。现在主流用的是**固态硬盘**（Solid State Drive, SSD），它没有机械结构，不存在寻道时间和旋转延迟，直接按地址去读，性能要好得多。它的读取逻辑跟读内存有点类似，所以快。

顺便对比一下顺序与随机的差距：Cheetah 顺序 125 MB/s、随机 2.5 MB/s，相差约 50 倍；Barracuda 顺序 105 MB/s、随机 1.2 MB/s，相差接近 100 倍。这个差距正是机械硬盘必须尽量避免随机访问的原因。

## 九、磁盘缓存与页缓存 [01:11:15–01:16:53]

### 9.1 磁盘缓存与轨道缓冲

硬盘自己带一小块内存，叫**磁盘缓存**（drive cache），也叫**轨道缓冲**（track buffer）。它的容量通常不大，早期是 8 MB、16 MB，新的盘可以到 128 MB。

它的用法是：读的时候，把整条磁道的数据一次性读进缓存——反正在等旋转的这段时间里盘本来也在转，不如把整条磁道都拿下来。这样后续对同一条磁道的任何请求都能直接从缓存里快速响应，这就是它叫"轨道缓冲"的原因。读缓存的加速是无损的：缓存里放的是盘上真实内容的副本，命中就省一次机械访问。

### 9.2 回写与直写

写的时候，硬盘有两个选择，这是本节最需要分清的一对概念。

**回写**（write back）：数据写进缓存就向 CPU 报告"写成功"，此时数据其实还没有落到盘片上。好处是快——从上层看，一次写只用等缓存的时间。

**直写**（write through）：必须等数据真正写到盘片上了才报告成功。慢，但语义正确。

回写的风险很明确：报告成功之后如果掉电，缓存里的数据就丢了，而调用方以为已经写成功了，于是产生数据不一致。所以从语义正确性上说，直写才是可靠的做法。不过回写能让硬盘显得更快，因此多数硬盘默认开启写缓存；这个行为可以在操作系统里配置，指定某个盘要不要启用回写。

> **老师强调**：回写是"感觉快"，直写才是"语义正确"——两者的差别就在于掉电时数据还在不在。

### 9.3 页缓存

操作系统内核里也有类似的机制，叫**页缓存**（page cache）：它把文件的内容缓存在内存里。文件本来存在硬盘上，读一次之后把内容留在内存，下次再读同一个文件就直接命中内存，速度就快了。

缓存的原理其实非常简单：用快的介质去替代慢的介质。但快介质容量有限，只能放一部分数据，于是就产生了命中与不命中：命中就读快介质，不命中还得回到慢介质去读。所以缓存是否有效，取决于命中率——命中率高，平均访问时间才接近快介质。

页缓存需要动态维护：内核要不断调整它的大小和里面放哪些页，这部分机制课件只作了介绍，老师提示有兴趣可以去读延伸材料。

**补充说明**：根据本节补充材料《37. Hard Disk Drives.pptx》第 50 张幻灯片，页缓存的两个配套动作分别是 **readahead**（预读，`readahead()` 系统调用会把后续文件块提前取进页缓存，顺序 I/O 受益最大）和 **write behind**（回写脏页：修改页时只标记为脏，等该页被淘汰或内核周期性回扫时才异步写回磁盘）。课件还提醒不要把页缓存（在主存里）与磁盘缓存（在盘上）混为一谈。

## 十、I/O 调度：从请求流到服务顺序 [01:16:56–01:23:58]

### 10.1 为什么 I/O 需要调度

对硬盘的访问从来不是单个请求，而是一串请求：一个进程要读文件 A 的某个位置，另一个进程要读文件 B 的某个位置，请求 A、请求 B、请求 C 依次到达。它们本来是连续到达的。

问题是，机械硬盘上一次随机访问要付出寻道加旋转的代价，而这个代价与"先服务谁"关系极大。于是就有了一个可以利用的空间：既然请求都已经在队列里，服务顺序未必要按到达顺序来，可以重排。这就是**重排**（reorder），也叫**调度**（scheduling）。

这种重排对外部是透明的：上层只是提交请求，究竟谁先被服务由内部决定。

**I/O 调度**（I/O scheduling）要解决的问题，与 CPU 调度在形式上是同一个：手上有一堆待办，什么时间选哪一个。老师顺带回顾了 CPU 调度的典型做法——先来先服务，或者多级反馈队列（先按一种策略把进程降到下一级，下一级再用另一种策略）。区别只在对象：CPU 调度是在时间片用完或进程结束时选下一个进程，I/O 调度是在一批到达的请求里选下一个下发的请求。核心逻辑一致，都要选一个合适的顺序，目标也一样：缩短等待，并且避免**饥饿**（starvation）。

> **老师强调**：I/O 调度和 CPU 调度解决的问题是类似的，都是"什么时间选哪个"；但 I/O 调度里，磁头当前位置与请求位置的相对关系，比请求本身的长短重要得多。

### 10.2 FCFS：先来先服务

讲调度一般从最简单的开始，就是 **FCFS**（First-Come-First-Serve，先来先服务）。它的规则就是按到达的先后顺序服务，先到的先做。

FCFS 的优点很实在：不需要额外的数据结构，来一个排队、按顺序取就行，实现复杂度最低。这也是它至今仍被使用的原因。

**例题**：同一组磁盘请求在 FCFS 与重排两种服务顺序下的总时间。

**题目**：六个请求的扇区号如上，磁头初始位置在 300001 附近；每次跨区定位（寻道加旋转）约 10 ms，同一区域内连续访问可以忽略定位时间。分别按到达顺序和重排后计算总时间。

**解答**：
第一步，按 FCFS 原序服务。请求在 30 万区和 70 万区之间来回跳：300001 → 700001 → 300002 → 700002 → 300003 → 700003，一共跨区 5 次，每一次都要重新定位，因此总时间约为 $6\times 10=60$ ms。
第二步，把同区的请求归到一起：300001、300002、300003 连续读，700001、700002、700003 连续读。此时只需要两次远距离定位——一次从 30 万区到 70 万区，一次在 30 万区内起始定位——之后区内是顺序的，几乎不再花定位时间。
第三步，总时间约为 $2\times 10=20$ ms。

**结果与点评**：同样六个请求，60 ms 与 20 ms，差了三倍。FCFS 的毛病在这里暴露得很清楚：它只看到达时间，完全不看请求落在盘上的什么位置，因此遇到这种交替访问就无法利用"同一区域可以连续读"这个事实。老师由此指出 FCFS 不是一个好的调度策略——它没有考虑后续访问的位置特征，一旦负载里存在这种特征，性能就会明显变差。

## 十一、SSTF、SCAN 与 C-SCAN [01:34:43–01:49:41]

### 11.1 调度器放在操作系统还是磁盘里

在讲具体算法之前，老师先问了一个架构问题：调度器应该放在哪里？有两个候选位置。

一是放在操作系统里。操作系统在把请求下发给磁盘之前，先在自己的队列里重排顺序，然后按新顺序逐个下发。

二是放在磁盘里。操作系统把所有请求都发给磁盘，磁盘自己维护一个调度器，在内部决定先执行哪一个。

两种都能实现，但代价不同。操作系统的困难在于信息不足：有些算法需要知道磁头当前在哪个磁道、当前转到什么角度，操作系统拿不到这些信息，除非硬件专门提供查询接口去问。而磁盘内部天然知道自己的当前磁道、当前状态和全部细节，所以在盘内实现更自然。现在的磁盘能够同时容纳多个未完成的请求，本身就带有比较复杂的内部调度器。

### 11.2 SPTF 与 SSTF

FCFS 之后，老师接着讲一个更典型的算法。**SPTF**（Shortest Positioning Time First，最短定位时间优先）的规则是：每次总是选择定位时间最短的那个请求来服务。这里的定位时间包含两部分——寻道时间和旋转延迟。

它是一个贪心算法：每一步只看眼前最优，选完再重新评估。

SPTF 只能在磁盘内部实现。因为要比较"定位时间"，必须同时知道寻道距离和旋转角度，而旋转角度只有在盘内才能预测；把这两部分时间加起来估一个总定位时间，也只有磁盘自己能做到。

操作系统只能实现它的退化版本——**SSTF**（Shortest Seek Time First，最短寻道时间优先）：只考虑寻道时间，选离当前磁头位置最近的那条磁道上的请求，不考虑旋转。

> **老师总结**：操作系统实现调度时能获得的信息少，磁盘实现时获得的信息多——这就是同一个算法在两层上会有不同形态的原因。

### 11.3 SSTF 的队列演算与三个性质

**例子**：设当前磁头位于第 53 号磁道，等待队列里有若干请求，其中能清楚辨认的包括 65、67、37、14、98、122、124 等。按 SSTF 服务，顺序是这样推出来的。

1. 从 53 出发，看谁最近：65 距离 12，37 距离 16，所以先服务 65；
2. 到 65 之后，67 距离 2，37 距离 28，选 67；
3. 到 67 之后，37 距离 30，14 距离 53，选 37；
4. 到 37 之后，14 距离 23，选 14；
5. 到 14 之后，剩下的都在高处：98 距离 84，122 距离 108，124 距离 110，选 98；
6. 到 98 之后，122 距离 24，124 距离 26，选 122；
7. 最后服务 124，距离 2。

所以服务序列是 53 → 65 → 67 → 37 → 14 → 98 → 122 → 124。每一步都只做一件事：在剩余请求里挑离当前位置最近的那个。

这个规则带来三个需要说清楚的性质。

第一，饥饿。如果总选离当前位置最近的请求，那么远离当前磁头位置的请求就可能永远排不上：只要不断有新的、落在磁头附近的新请求到来，那些远处的请求就会被一次次跳过。SPTF 和 SSTF 都有这个问题。设想盘的两端各有一个请求，而磁头一直在中间区域服务不断到来的近处请求，那么两端的那两个请求就可能长时间得不到服务。

解决思路是给等待设一个上限。一个简单办法是成批服务：把请求分成固定长度的一批，每一批内部按 SSTF 选，一批服务完就重新开始下一批。这样任何请求最差的等待时间也就是一批的长度，饥饿就被一个有界的量挡住了。

第二，偏好中间磁道。SSTF 会系统性地偏向中间的磁道，而不是两端的磁道。原因不复杂：SSTF 用距离衡量优先级，而中间位置到其他各条磁道的平均距离更短，两端位置到其他磁道的平均距离更长。

估算一下就清楚了：设磁道编号 $1$ 到 $N$，对位置 $i$ 计算它到其余 $N-1$ 条磁道的平均距离

$$\bar d(i)=\frac{1}{N-1}\sum_{j\ne i}|i-j|.$$

$i$ 取在中间时，两侧的项都只延伸到一半，和最小；$i$ 取在端点（$1$ 或 $N$）时，距离从 $0$ 一直加到 $N-1$，和最大。平均距离短的位置，在"选最近"的规则下被选中的概率自然更大，所以中间磁道会被优先服务，两端磁道更容易被冷落。这也解释了为什么 SSTF 的公平性不好。

第三，贪心不等于全局最优。

**课堂问答**：老师问 SSTF 是否保证总移动量最小，有同学指出这是一个贪心算法。老师认可了这个说法，并补充说：贪心算法只能保证每一步局部最优，不能保证全局最优，因此 SSTF 并不保证总移动次数最小。字幕未记录学生作答的原话。

### 11.4 SCAN：电梯算法

SSTF 最大的问题是饥饿。针对这一点，后来的做法是先排序再扫描，代表就是 **SCAN**，也叫**电梯算法**（elevator algorithm）。

> **老师比喻**：SCAN 的工作原理就跟电梯一样——电梯往上走的时候不会突然往下，而是一直上到最高层；下去的时候也不会在中途反复折返。

具体规则：把请求按磁道号排序，磁头沿一个方向一直扫到端点，扫的过程中遇到请求就服务；到端点后折返，反方向再扫一遍，路上遇到的请求同样服务。

这个规则同时解决了两件事。一是不会饥饿：一个来回总能把你的请求扫到，最差也就是等一趟。二是移动距离仍然可控：顺着方向走，不会像 FCFS 那样来回乱跳。所以 SCAN 既考虑了公平性，也在相当程度上减少了移动距离，是一个很经典的算法。

**例子**：以当前磁道 53 为例，若磁头朝磁道号减小的方向移动，途中遇到的第一个请求是 37，就先服务 37；继续减小到最远端后折返，返程依次遇到 67、98 等服务。

SCAN 的缺点在公平性上：它对中间磁道更友好。因为磁头来回都要扫，中间位置在一个来回里会被经过两次，等待时间短；而两端位置刚被扫过就要等磁头走到另一端再回来，等待时间明显更长。

### 11.5 C-SCAN：只在一个方向服务

为了修掉 SCAN 的这个偏向，有了 **C-SCAN**（Circular SCAN，循环扫描）。它和 SCAN 的唯一区别是：只在一个方向上服务，返程不服务。

具体做法：磁头沿一个方向扫到端点，沿途服务所有请求；到达端点后直接返回另一端，返回途中不服务任何请求；回到起点后再重新开始单向扫描。

**例子**：当前在 53，朝磁道号增大的方向服务，沿途把比 53 大的请求依次服务完；到端点后空跑回最小端，返程不服务；再从最小端开始向大号方向扫，依次服务 67、98 等。

这样改的效果是等待时间变得均衡：不再有"端点刚被扫过就要等一整个来回"的情况，所有位置的最大等待都接近一个完整的扫描周期。代价是返程那一趟完全浪费掉了。

老师还提示，这个算法和实际代码里的读循环是对应的：一个进程反复调用读、每次读一小块，在 C-SCAN 下这些请求会被按位置成批服务。

### 11.6 工作保留、预期式调度与公平调度

讲完三个基本算法，老师补了两个更细的概念。

**工作保留**（work conservation）：只要还有活可干，调度器就不让磁盘闲着，立刻取下一条。大部分调度器都是工作保留的。

但有时候等一等反而更好：如果系统预期马上会来一个位置相邻的请求，此刻先发一个远处的请求就会浪费一次寻道；等一小会儿，把两个请求合并成一次寻道，总代价更低。这种"故意让盘空闲一小段"的调度器叫**预期式调度器**（anticipatory scheduler），它是非工作保留的。

再进一步是**公平调度**。前面的算法都只看位置，不看"是谁发的请求"。公平调度要解决的是：有的进程读得多、有的读得少，怎样保证所有进程都能以合理的顺序访问硬盘、等待时间都比较短。Linux 里的实现叫 **CFQ**（Completely Fair Queueing，完全公平队列）：为每个进程维护一个队列，按权重分配每单位时间能发出的 I/O 次数；队列之间做加权轮转，时间片长度与优先级成比例；只有当某个队列空闲了一段时间，才把它的时间片让出去（这一步也是一种预期）；队列内部再对请求顺序做优化。

老师说明这一部分只要了解前面几种比较简单的调度算法就可以了，CFQ 这类实现属于了解层面。

## 十二、本节回顾 [01:49:45–01:51:12]

### 12.1 I/O 设备与磁盘的两条主线

第一条主线是 I/O 设备的抽象。设备千差万别，但它们的逻辑是一样的：都有一个状态、一个命令、一个数据，也就是三个寄存器；区别只在于每个维度选了哪种实现——状态用轮询还是中断，数据用 PIO 还是 DMA，控制用特殊指令还是内存映射。

第二条主线是机械硬盘与它的调度。传统磁盘的访问时间受机械性能支配：寻道要移动机械臂，旋转要等盘片转过来，这两项都是毫秒级，而真正的数据传输只有微秒级。所以顺序访问与随机访问的性能可以差到几十倍甚至上百倍，这也正是需要对请求排序、需要碎片整理、需要在"公平"与"移动距离"之间做取舍的原因。

这也是机械硬盘被固态硬盘取代的根本原因：SSD 没有机械结构，不存在寻道时间和旋转延迟，直接按地址读，读起来更像读内存，所以快得多，如今已经是主流的存储介质。

> **老师总结**：慢的设备才值得花时间去调度——磁盘这类又慢又有状态的设备，调度带来的收益最大。
