## 一、分割的任务定位与定义 [00:03:09–00:09:45]

### 1.1 从检测到分割

上节课看完了目标检测（object detection）这一块，也让大家上机实践了一次。老师先从这次实践的体感说起：写代码的时候应该能直接感受到，目标检测的难度比之前做的分类（classification）要高一截，无论从算法上还是从工程实现上，复杂度都增加了很多。

这节课转到计算机视觉里另一个非常重要的分支——**分割**（segmentation）。分割顾名思义，就是把一张图分成不同的区域（region），分成不同的、带有语义的区域。老师补充说，其实分到多细都可以算分割：切成一个个小像素块也算，只是看你怎么定义"根据什么去做这个划分"。这节课先看图像的分割（image segmentation）。

分割这条线的发展是跟着深度学习一路走的：从 AlexNet、ResNet 那一批网络起来之后，分割也跟着起来，从 2012 年到现在，它反过来给 backbone 贡献了很多算子。老师提醒，之前学过的 dilation（空洞）、group（分组）这些操作，最初就是从分割的工作里出来的。

### 1.2 分割的任务定义

分割对大家来说其实是非常容易理解的一件事。老师用检测作对比：目标检测是用一个框把目标框出来，但框只能给出大概的位置，框里面到底哪个像素是猫，其实不知道；分割则是逐个像素地回答——你告诉我哪个像素属于这只猫，哪个像素属于那只狗，需要逐像素地把目标分割出来。

在分割的结果里，被标上类别的那张图叫 **mask**（掩码）。mask 一般用不同的颜色代表不同的类别或不同的实例，反正就是代表不同的分割片段。课上的例子里，蓝色表示猫，黄色表示狗。

### 1.3 语义分割：逐像素分类，且不区分个体

分割里面其实有一系列不同的任务定义，老师带着逐个看。先看**语义分割**（semantic segmentation），因为后面还有实例分割和全景分割。

课上用的例子是 **Cityscapes** 数据集。这个数据集是当年奔驰和欧洲的一个研究所合作做的，他们在欧洲 28 个城市采样了行车记录仪的数据。这个数据集把类别分成了大概 18 个类别，比如道路、人、车，还有一些人行道、建筑等等。图里红色的是人，蓝色的是车。

"semantic"这个词来自 NLP，意思就是"带有语义的"。所以语义分割里不同颜色分割出来的东西都是有语义的：person、road、car、tree、building，甚至 driver 这类驾驶员身份也做了区分。

换一个角度看，语义分割其实就是逐像素点的分类。如果把一个 person 当成一个整体看，它是分割；但如果换个角度，它就是一个分类问题——我要知道这个像素是哪一个类别、另一个像素是哪一个类别。只要能做到逐像素的分类，把每个像素的类别都定好，它们自然而然就连成一片，成为一张分割的 mask。

语义分割还有一个很重要的特点：它不区分个体。观察课上那张图会发现，当路边有几辆车、几个人重叠的时候，它是不做区分的——两辆车叠在一起，它会整个给你画成"车"；两个人站在一块，它也是把两个人画成同一块，不会区分 person one 和 person two。而在目标检测里恰恰要区分：到底是 person one 还是 person two。语义分割里不需要，它只需要知道这个像素是 person、那个像素是 car 就够了。车辆连在一块、树连在一块、人连在一块，都不做区分。

所以语义分割的本质是：不去区分个体，更关心的是逐个像素的分类。

## 二、把分类网络改造成分割网络：从朴素方案到 FCN [00:09:47–00:19:51]

### 2.1 分类网络的结构性障碍

在分析分割模型之前，老师先带大家回头看 CV 里之前流行的分类模型：AlexNet（课上写作"Ex net"，有典型的上下两个分支），以及它夺冠这个节点。为什么要回头看分类？因为这两个任务有共性：大家做的都是一种分类，无非一个是 image-level 的分类，一个是 pixel-level 的分类。

但直接拿分类网络来做分割是不行的。分类 CNN 的流程是：给一张图，一路做下采样（downsample），2 倍、4 倍、8 倍、16 倍、32 倍，最后到 $1\times 1$。到 $1\times1$ 的时候，整张图的 $H\times W$ 已经被彻底扔掉了，只剩 Z 轴上很长的一维（1024 或 2048），最后分类出一个 label，比如"这是一只猫"。

问题就出在这里：如果你想知道"这个像素是什么"，这个信息在下采样的过程中已经逐渐被丢掉了；尤其下采样到 $1\times1$ 的时候，一整张图就变成了一个像素，已经没有办法表示位置。而分割想要的恰恰是：这个猫爪子这一块的像素是 cat，它下面那块是 background。

老师在这里点出 CNN 的本质：它做的事情是把一个 region 映射成一个类别。而分割需要的是每个像素的类别，这两件事对不上。为了让大家真正体会到后面那些模型的厉害，老师抛出了一个问题：现在给你一张有**两头牛**的图，你要怎么做才能实现逐像素的分割？他特意让大家先自己想几分钟，"因为你要先想一下，才能感受到后面这些算法、这些模型挺厉害的"。

### 2.2 朴素方案一：逐块抠图

站在 2012 年刚拿到 AlexNet 代码的位置上，最直接的想法是：抠小块。我只抠这么一小块出来做一个分类，是不是就可以给这个方块打上一个标签？每个小块都抠出来送进去。

不能把一整张图直接送进去，因为整张图送进去它只会告诉你"最显著的是牛"，不会告诉你有几头、在哪。而 CNN 有一个特点：无论你抠出来的块多大，它都会 resize 到合适的输入范围，最终只给你出一个 label。那么一小块一小块地抠、一块一块地分类，是不是就能知道这一块是牛、那一块是牛？

这个方法确实能得到结果，但缺点很明显，老师让大家类比 R-CNN 系列要解决的问题去想。答案很快就出来了：太慢。一张大图要抠多少个方块、要把 CNN 跑多少遍？而且得到的标签还是"这个块的主体是什么"——蓝色方框里放着牛，我只能告诉你整个这个蓝色方框里的主体是牛，至于框里更小的像素到底是不是，我并不确定。

### 2.3 朴素方案二：整图多标签

另一个思路是把整张图 resize 到网络能接受的 $H\times W\times C$ 之后送进去。这样它能做分类，甚至能做多分类：分类时通常取 top-1，如果不取 top-1 而是取一个阈值（比如置信度超过 0.5 就判定存在该类别），它就可以挑出任意多个类别，比如一张图里同时挑出 grass、cow、tree 三类。

但这个方案的问题依旧：你还是不知道这些类别在哪里。老师连着问了两遍"是不是你还是不知道他到底在哪里"，让台下感受这个瓶颈。所以 2013、2014 年大家在做的，基本就是这两类办法；直到 2014 年，有人提出了一个非常 elegant 的做法，到现在都有影响，引用量已经很高。

### 2.4 FCN 的核心想法：停止下采样，再上采样回去

这个 elegant 的做法，就是在 CNN 的基础上改。老师先引导大家注意一件事：分割最终输出的结果，跟原图是同一个分辨率——因为要逐像素对应，不像素地对应，所以最终的输出也应该跟原像素一样大。要达到这么大的输出，你就需要有一个同样大的 feature map。

既然如此，做法就很自然：把前面正常的 CNN 下采样到一定程度之后，不再继续下采样，而是直接上采样（upsample）回去。代价无非是多耗一点 GPU 显存——而时间已经到了 2014 年，已经有好卡了。

上采样是什么？就是把一个像素变成一个 $2\times2$，或者变成一个 $4\times4$，可以理解为 pooling 的反操作；当然也有更复杂的做法，比如线性插值。老师打了个比方：现在有一张一寸的照片，要变成两寸，你们平时做的就是上采样。

## 三、FCN 的结构、维度与输出 [00:19:54–00:29:27]

### 3.1 梯形结构与维度链

把前面的部分遮住，前面那一段大家其实很熟悉：一路下采样 2 倍、4 倍、8 倍，都是学过的东西。FCN 不同的是后面——它整体是一个梯形：输入图像有这么大（假设是正方形，边长记作 $H=W=512$），一路下采样下去，然后从某个位置开始再升回去。

按标准 VGG 网络的口径，每次下采样 2 倍，维度是这样一条链：

| 阶段 | 特征图空间尺寸 | 相对原图 |
|---|---|---|
| 输入 | $512\times512$ | $1\times$ |
| 第 1 次下采样 | $256\times256$ | $1/2$ |
| 第 2 次下采样 | $128\times128$ | $1/4$ |
| 第 3 次下采样 | $64\times64$ | $1/8$ |
| 第 4 次下采样 | $32\times32$ | $1/16$ |
| 第 5 次下采样 | $16\times16$ | $1/32$ |
| 常规分类网络继续 | 一路到 $1\times1$ | 空间维度消失 |

常规分类网络到这里之后会继续降，比如降到 $8\times8$ 甚至直接到 $1\times1$，变得很小。而 FCN 在这里**停住**：认为 $16\times16$ 这个大小已经足够保留信息了，不再继续下采样，而是反过来逐步上采样——$16\times16$ 升到 $32\times32$，再升到 $64\times64$，一路回到 $512\times512$。

上采样的粒度是可以调的。如果显存不够、不需要那么精细，也可以一步从 $16\times16$ 直接放大到 $512\times512$；逐步升和一步升都能work，区别只在于精度和显存的取舍。

需要注意，这一路升上去的仍然是 feature，只不过是把这个 feature 放大（upsample）了。最终我们得到的是一个 $512\times512$ 的 feature map——而在分类网络里，最后的 feature map 是 $1\times1$、Z 轴 1024 或 2048。

### 3.2 逐像素分类头与 argmax

有了 $512\times512$ 的 feature map 之后，分类方式就变了。假设类别数是 $K=21$（以 Cityscapes 口径），我们让每个像素单独做一次分类——每个像素拿出来的那一维特征，就相当于分类网络里那个 $1\times1$ 的输入。把每个像素都这样处理一遍，最终得到的是一个 $H\times W\times K$ 的 map，也就是 $512\times512\times21$。

这 21 个通道上，每个位置输出的就是该像素属于 21 个类别的概率（用 softmax + cross entropy 那一套，概率加起来为 1）。在每个像素位置上取概率最大的那个类别（top-1），就能得到每个像素的类别：这个位置 top-1 是 background，那个位置 top-1 是 dog，另一个位置 top-1 是 cat。由于这个 feature map 跟原图一样大，每个像素取一个类别之后，就直接得到了一张跟原图同尺寸的分割 mask。

老师在这里顺便把 **argmax** 讲清楚：argmax 就是挑出概率最大那一项的下标。比如只有三个类别，预测概率分别是 $0.1$、$0.7$、$0.2$，那么

$$\operatorname*{arg\,max}_{k\in\{0,1,2\}}\; p_k = 1$$

label 就等于 1。因为 dog、cat 这些类别到底对应 0、1、2……哪一个 ID 是事先规定好的，顺序不能乱。

所以 FCN 与分类 CNN 的差别，其实只在最后一步：分类是把 $1\times1\times1024$ 拿去做分类、取概率最大的类别；分割因为要每个像素都分类，最终的 feature map 是 $H\times W$ 再带一个 Z 轴（512 或 128 个通道），再映射成 $H\times W\times K$，逐像素取 top-1。

### 3.3 "全卷积"的含义：全连接层的输入尺寸约束

这个方法叫 **全卷积网络**（Fully Convolutional Network, FCN）。为什么叫"全卷积"？因为在这之前，最后那一步——比如从 $16\times16$ 一步降到 $1\times1$——通常是用一个全连接层（fully connected layer）实现的。全连接层的特点是：所有的神经元都要互相关联，最终把 $H\times W$ 压成 $1\times1$。

全连接层有个硬约束：输入尺寸必须固定。如果这一层是全连接层、输入是 $7\times7$，那你给我的输入就必须是 $7\times7$；不是 $7\times7$，就违反了这一层的定义，网络不接受。

而卷积不一样：卷积是拿着核在图上滑过来、滑过去，你的输入有多大跟它没关系，它按滑窗规则算就行。老师用一句话概括这个对比——全连接是"站在那儿不动"的，卷积是"扫过来扫过去"的。

FCN 的做法是把全连接层那一层直接换掉：把全连接层的**权重继承过来**，改成一个卷积核（比如 $7\times7$ 的卷积核），于是这一层就变成了卷积层。这样一来网络里所有的全连接层都被去掉了，"全卷积"的名字由此而来。

> **老师强调**：全卷积网络的一个特点，是你无论输多大的图它都能接受，它不去限制你输入图的大小。

## 四、跳跃连接与 FCN-32s/16s/8s [00:29:30–00:39:47]

### 4.1 上采样为什么补不回细节

接下来老师让大家注意一个容易被忽略的事实：在逐步上采样的过程中，比如把 $16\times16$ 升到 $32\times32$ 的时候，前面网络里其实存在一个同样大小的 $32\times32$ 的特征（以及 $64\times64$、$128\times128$ 的），是镜像对称的。那么问题来了：既然这里有，为什么不把前面那份特征也利用一下？这是很宝贵的特征资源。

在讲怎么利用之前，先要讲清为什么需要利用。老师的质疑是：你前面已经下采样过一遍了，信息已经丢了，然后你又上采样回去，你凭什么保证能把细节还原出来？

他给了两个很具体的例子。一只猫的尾巴非常长，你下采样下去的时候把猫尾巴丢了，那为什么上采样还能把猫尾巴复原？一根头发丝飘得很长，原图是 1024，你下采样到 $128\times128$，可以想象这根头发丝在 $128\times128$ 的分辨率下必然会丢失——这时候如果没有 1024 的原图了，只有 $128\times128$，你再上采样回 1024，这根头发丝还能复原吗？不能了，因为这个信息已经丢了。

老师给了一个可以自己动手验证的实验：随便找一张高清图，把它下采样到一个很小的尺寸（比如 $64\times64$）保存下来，不要按 Ctrl+Z 撤销，另存一份，然后再把它打开、resize 回 $1024\times1024$，看看细节丢了多少。

### 4.2 跳跃连接

结论就很自然了：既然浅层还保留着那根头发丝所在分辨率的特征，那就把它利用上。最简单的做法是把它拿过来加一下——因为两者的 $H\times W$ 是一样的；或者 concat 起来，逐元素相加也行，$H$、$W$ 一样，两种方式都可以。这样就等于把浅层的高分辨率细节直接送给了深层的输出。

FCN 当年就是这么做的，这个连接叫 **skip connection**（跳跃连接）：上采样到一定维度之后，去前面找一个跟自己分辨率一样的 feature，skip 过来相加。

> **老师比喻**：skip 就像是深层的网络已经记不清细节了，那就把浅层还记得的那份细节直接抄一份给它。

后面很多工作都是这个思路的变种。比如非常著名的 **特征金字塔网络**（Feature Pyramid Network, FPN），虽然它主要用在检测里，但基本逻辑是一样的：从不同层级各提一个特征，把分辨率小的统一上采样到最大的那个，让它们都一样大，然后 concat 起来做后续的统一处理。这跟 FCN 里的 skip 本质上是同一件事——都是去利用前一层的、更高分辨率的特征，因为高分辨率特征里包含更多图像的细节（image detail）。再往后 ResNet 的 skip 也是类似的思想。

> **老师提示**：以后自己做一个网络，如果发现效果不好或者哪里不对，都应该最朴素地想一下——我能不能从前面 skip 一个特征过来放到这一层，它可能都会有用。不必一上来就上更复杂的 skip、各种各样的"连连看"（老师顺带提到讲 CNN 时讲过的 DenseNet，那是全部都连上）。

### 4.3 FCN-32s / 16s / 8s 的命名与效果

FCN 的几个版本是按"一次要升多少倍"命名的，非常直白：

| 版本 | 从哪里开始恢复 | 需要一次上采样的倍数 | 是否用 skip |
|---|---|---|---|
| FCN-32s | 下采样 32 倍后的特征（$16\times16$） | $32\times$ | 否 |
| FCN-16s | 下采样 16 倍后的特征（$32\times32$） | $16\times$ | 是，从 $1/16$ 层 skip |
| FCN-8s | 下采样 8 倍后的特征（$64\times64$） | $8\times$ | 是，从 $1/8$ 层 skip |

FCN-32s 是下采样 32 倍之后直接升 32 倍回原图；FCN-16s 是先升到 16 倍、把前面 $1/16$ 分辨率的特征 skip 过来相加或 concat，再继续升；FCN-8s 同理，只要升 8 倍就够了。

效果对比很直观。看车轮：FCN-32s 出来的车轮基本分辨不出来，因为分辨率损失太大，空间细节基本都丢了，只能大概猜一个"车轮长这个样子"；到 FCN-16s，车轮已经开始变圆了；到 FCN-8s，车轮更圆、更准。人的细节也一样：FCN-8s 能看出手，FCN-16s 手就没了，FCN-32s 更没有了。

### 4.4 为什么 FCN-4s / 2s 反而更差

按这个逻辑推下去，是不是再来一个 FCN-4s（只升 4 倍）、FCN-2s（只升 2 倍），细节就会更好？这篇论文把这些实验都做了，结果反而是 FCN-8s 效果最好，FCN-4s 和 FCN-2s 并没有取得更好的效果。

原因老师讲得很清楚：虽然离原分辨率越近的地方，特征保存得越详细，但我们最终做的是一个**语义**的分类任务。你把特征抠得太细，低层特征到一定程度之后全是转角（corner）这类东西，它跟"这是一个 person"毫无意义，甚至反而会降低分类性能。

> **老师总结**：所以这是一个折中，最终折中在 FCN-8s。

## 五、DeepLab 与空洞卷积 [00:39:48–00:47:13]、[00:57:27–01:13:19]

### 5.1 DeepLab 系列与"à trous"的命名

FCN 之后有一个非常著名的系列叫 **DeepLab**。老师坦言这是"我当年的一个噩梦"，因为它一直在迭代版本，就像现在大模型一直在迭代版本一样，从 v1 到 v2、v3 一直出。

DeepLab 最核心的东西是**空洞卷积**（dilated convolution）。有意思的是命名之争：这篇论文里把它叫做 convolution à trous，这是个法语词，也是"洞"的意思；而另一篇与它有争议的论文用了 dilation 这个词，最终大家通行叫 dilation。

DeepLab 用了空洞卷积，另外还用了**条件随机场**（Conditional Random Field, CRF）做后处理。CRF 这节课不细讲，老师只说它本质上是个概率模型问题，感兴趣可以自己去看。

### 5.2 诉求：既要用预训练 CNN，又不想下采样

讲空洞卷积之前，先讲它为什么被发明出来。老师把思路拉回到最朴素的层面：我们之前看到，所有制约因素都来自 CNN 必须一路下采样——一直下采样到一个很小的尺寸，直到 $1\times1$，整个 $H\times W$ 维度就失去了。那最朴素的想法就是：**我能不能不要下采样了？**

如果不下采样，一路保持 $512\times512$，那么后面就不需要任何上采样，直接在这个 $512\times512$ 上做分类就得到结果了，为什么还要接后面那一堆上采样？

但这个想法有两个当时迈不过去的坎：

1. **显存撑不起来。** 你可以自己手算一下 feature map 要占多少显存：单张 feature map 是 $512\times512\times C$，而网络里每一层都要存这么大的 feature，还要存反向传播的中间结果，加起来存不下。
2. **必须用预训练的 CNN。** 分类网络之所以好用，是因为它在 ImageNet 上预训练过，有上百万的数据。而分割的标注难度是肉眼可见的：让你们现在标一张图、不借助任何工具，一个像素一个像素地抠，估计一个早上也标不完；就算用 Photoshop 拿着线去连，也要连很久。所以当年分割数据集规模很小，几千张，撑死了上万张。拿这一万张从零训一个网络，根本收敛不了。因此只能基于在 ImageNet 上预训练过的模型去改。

老师顺带吐槽了一句行业黑话——这种做法"放到现在这个叫做 SFT"，并回忆起在公司时天天听人说"对齐颗粒度"，说字节还好，一般听 talk 没那么多黑话。

于是矛盾就很清楚了：**既想用 CNN 的预训练能力，又不想让它下采样那么多**，这是一个天然的冲突。要同时满足这两个条件，只能做一个适度的折中。老师让台下想：回想 CNN 那一节讲过的网络结构，CNN 是靠什么下采样的？

### 5.3 去掉 pooling 之后：感受野缩小

答案就是 pooling。CNN 是通过 pooling 来下采样的，那把 pooling 去掉，是不是就不下采样了？如果把所有的 pooling 都去掉，网络的形状就变成了前面说的那种"从 $512$ 一路保持 $512$ 的形态"，因为不再有下采样。

但去掉 pooling 会带来一个新问题，这个问题要回到讲卷积时的一个概念：**感受野**（receptive field），也就是这个卷积核能覆盖的区域有多大。本来加上 pooling 的时候，深层的卷积已经能够覆盖你全图了；而把 pooling 去掉之后，感受野能覆盖的范围会大幅减小。

老师用一个小例子把它算清楚：

- 假设一个 $4\times4$ 的区域，做一次 2 倍下采样，变成 $2\times2$；
- 此时一个 $2\times2$ 的卷积核，四个点分别对应回原图的四个 $2\times2$ 小块，合起来正好覆盖整个 $4\times4$——也就是说，这个卷积"看得到全图"；
- 现在不做下采样，仍然是 $4\times4$，同一个 $2\times2$ 卷积核只能罩住四个点，只覆盖全图的一小块，它"看不到全图了"。

换句话说，原本下采样之后，图像上相隔很远的两个位置被压到了相邻位置，它们在同一个卷积窗口里发生了计算交互；现在不下采样、保持高分辨率，这两个位置隔得太远，一个 $2\times2$ 的卷积再也无法让它们发生交互。可是语义分割恰恰需要这种远距离的交互来判断"这一块整体是什么"。

我们要的正是：用不下采样的高分辨率结构，同时保持原本卷积的作用范围。怎么办？

### 5.4 空洞卷积

**课堂问答**：老师问，之前在讲卷积的那节课里讲过，哪种卷积能做到"不改变卷积核参数、却能扩大作用范围"这件事？台下有学生答出了空洞卷积，老师确认：对，就是刚才说的 dilated convolution。

**定义**：空洞卷积（dilated convolution）。在不增加卷积核参数量的前提下，把卷积核的元素按一定的**膨胀率**（dilation rate）在空间上拉开，中间填入零，使得同样大小的核在输入上覆盖更大的区域。

放到刚才的例子来算：本来一个 $2\times2$ 的核只覆盖相邻四个点；把膨胀率调大，让核的元素之间隔开（中间差零），它采样到的就是原来 $4\times4$ 区域里四个分散的点——这四个点恰好对应下采样之前的四个 $2\times2$ 小块。于是：

- 卷积核的参数没有变（还是那 4 个权重、还是 $2\times2$ 的核）；
- 但一次计算就让原本相隔很远的区域发生了直接的交互；
- 等效地恢复了 pooling 曾经提供的感受野。

> **老师强调**：空洞卷积的价值就在于它同时满足了两个互相冲突的要求——既维持了高分辨率（不下采样），又维持了原本的感受野。这正是 DeepLab 能用预训练 CNN 又不丢分辨率的关键。

### 5.5 DeepLab 的实际结构与"桶形"

不过 DeepLab 实际的做法并不是纯粹地"完全不下采样"，而是有修正的。它先正常下采样到 8 倍，然后从那里开始把后面的 pooling 全部去掉，之后一路保持同一个分辨率不变，直到输出。

按 $512\times512$ 的输入算：

| 阶段 | 空间尺寸 | 说明 |
|---|---|---|
| 输入 | $512\times512$ | 原图 |
| 正常下采样 8 倍 | $64\times64$ | 保留预训练网络的浅层，省显存 |
| 之后所有层（去掉 pooling） | 一直是 $64\times64$ | 不再降分辨率，用空洞卷积维持感受野 |
| 输出 mask | $64\times64$ | 直接在这个分辨率上出结果 |
| 最终上采样 | $512\times512$ | 8 倍，用传统图像处理即可 |

为什么要先降 8 倍而不是完全不降？老师给了两条理由：一是显存，完全不降撑不住；二是靠近 RGB 那一侧的浅层特征太杂乱，也没有必要维持那么高的分辨率。而 8 倍的上采样，在有深度学习之前的传统图像处理技术就能做得很轻松，所以这 8 倍的细节损失是可以接受的。

网络形状的对比很能说明三个模型的关系：

- **FCN**：编码-解码像一个沙漏，两个梯形对撞（有人把它叫 hourglass，沙漏状）；
- **U-Net**：把这个梯形反转一下，每次上采样都用一根线把对应的浅层连过来（skip），因为整体形状像字母 U 而得名；
- **DeepLab**：变成一种桶状——先降 8 倍，然后直直地保持到最后，再一次性升回去。

> **老师比喻**：这几个模型的结构差异，说白了就是把同一个梯形换个方向摆、换个位置加 skip 而已，本质都是"降下去、再升回来、中间把浅层接过来"。

### 5.6 CRF 后处理

DeepLab 里另一个部件是 CRF。老师用最直白的话解释它在做什么：我根据预测出来的结果，以及你周围像素的一些条件，综合判定我到底是不是某一类。比如你现在把某个像素判成飞机了，我不太相信，我要看一下 RGB 的图、看一下周围像素的分数分布，再综合评定一下这到底是飞机还是天空。

但老师明确说这节课不细讲 CRF，因为"CRF 也是一个概率数学问题"，感兴趣的自己去看，它叫条件随机场。他重点讲了 CRF 后来的命运，也就是为什么现在用得很少：

1. **它是一个后处理方式**，跟 CNN 网络完全没关系。必须先把 prediction mask 预测出来，然后再去处理它。
2. **它很慢，而且只能在 CPU 上算。**
3. **它的数学公式确实复杂一点**——老师调侃说"这是数学家们非常喜欢干的"。

这里老师讲了一段亲身经历：前段时间有一位香港大学的老师来上海开会，专门给他发 email 约时间，见面给他解释了一堆数学公式，说自己用一种更好的后处理方式替代掉了 CRF。但老师作为搞计算机的人对此不太感兴趣，理由很直接：你弄了这么多东西，最终效果一看只提升了 0.001，"我这个还不如多收集几组数据"。

他进一步点出这类方法的适用边界：CRF 最擅长解决的是"补洞"——比如预测出来的 mask 里，飞机中间有一个洞被判成了 background，CRF 会根据周围都是飞机、以及 RGB 值相近，把这个洞补全。但这样一个小洞，对于搞工程的人来说，加 100 组数据可能就解决了。

> **老师总结**：这属于计算机的人跟数学的人不同的思维方式——我们喜欢"大力出奇迹"，搞个 100 万张图，这个问题自然而然就解决了。

CRF 在流行了一段时间之后逐步就不用了。老师说，如果以后做项目，想在自己的 mask 上再挤零点几个点，仍然可以拿 CRF 去处理一下，包括现在的大模型输出也能扔进去处理，只是处理范围和效果对工科思维的人来说性价比不高。

### 5.7 ASPP 与 v2/v3

除了空洞卷积和 CRF，DeepLab 还在上面加了一个叫 **ASPP** 的模块，全称是空洞空间金字塔池化（Atrous Spatial Pyramid Pooling）。它要解决的是**上下文**（context）问题：我这个像素跟我周围的这些像素的信息我都要获取，但到底需要多大范围的上下文，我不知道。

所以 ASPP 用了一个并行的结构：几条并行的分支，每条分支的空洞卷积的 dilation rate 不一样，覆盖的范围就不一样——有管这么大范围的、有管那么大范围的、还有更大的。这样最终达成的采样效果，就是对全图各种范围都做了一次采样：旁边的采样了，更大范围的也采样了。这是这篇论文主要的贡献点之一。

DeepLab 后面还出了 v2、v3。老师说 v3 这个版本大概到 ECCV 2018 了，离我们很近，这个系列一直在出；后面用了膨胀规划等一些策略，改进就比较小了。值得注意的是，CRF 到 DeepLab v3 自己就已经不用了——这个方法本身开始被放弃。

关于"多尺度"，老师顺带把概念串了一遍：上节课刚讲过，不确定的时候就从前面 skip 一个特征过来；skip 一个叫单尺度，skip 多个就叫多尺度。这跟 FPN 是一个道理——从前面的不同位置多 skip 几个，因为不同 level、不同 scale 的特征各有自己的特点。

> **老师比喻**：多尺度就像你要做一个决定，把小学的你、初中的你、高中的你都问一遍，看看他们有什么意见。虽然他们还没到你这一步、没你这么成熟，但他们也许保留了你性格里最原始、最该被尊重的那部分东西。

## 六、PSPNet 与跨卡 BatchNorm [01:13:20–01:25:36]

### 6.1 金字塔池化

DeepLab 之后还有一系列工作，其中比较著名的是 **PSPNet**（Pyramid Scene Parsing Network）。老师先解释了一下名词乱象：当时这些词用得很多，有的叫 scene parsing，有的叫 semantic segmentation，有的叫 semantic parsing，其实本质都一样，翻译成中文都应该翻成"图像分割"。

PSPNet 做的事情跟 DeepLab 是类似的：前面的 CNN 也采用"下采样 8 倍、后面不再降"的架构，这种架构发明出来之后大家一直沿用。所以论文里干脆不画了，只画一个 CNN 表示"它也是下采样 8 倍"：输入 $512\times512$，出来的特征图是 $64\times64$。

它在后面做的是**金字塔池化**：对 $64\times64$ 的特征图做不同尺度的池化，输出分别取 $1\times1$、$2\times2$、$3\times3$、$5\times5$。

| 池化输出 | 含义 | 提供的信息 |
|---|---|---|
| $1\times1$ | 整张图压成一个向量 | 全局视野、大局观（global view） |
| $2\times2$ | 分成 4 个区域 | 较粗的区域级上下文 |
| $3\times3$ | 分成 9 个区域 | 中等尺度上下文 |
| $5\times5$ | 分成 25 个区域 | 更细的局部上下文 |

这些池化结果各自再上采样回同一个尺寸（$64\times64$），然后把原来的特征也 skip 过来，全部 concat 在一起，最后做一次卷积就出预测。论文里把这个叫做"强调全局上下文先验的多尺度"，也就是去聚合不同尺度的信息。

> **老师强调**：遇事不决 skip。

### 6.2 与 DeepLab 的差别

PSPNet 与 DeepLab 的区别在于"尺度"是在哪一步做的：DeepLab 是在卷积核上操作——改 dilation rate 让卷积核的尺度变化；而 PSPNet 是在特征图上直接做池化来得到不同尺度。

这个差别带来成本上的好处：论参数量和计算量，PSPNet 这种在特征图上池化的方式肯定更省一点。

### 6.3 显存困境与"等效 batch size"

讲完方法，老师讲了这篇工作论文里没写的一段"额外的事情"。PSPNet 是当年有人去商汤实习时做的工作——那时商汤如日中天，公司刚成立没多久，想打出名气去参加比赛，所以有了这篇工作。但老师强调：实际起大作用、能让他拿下冠军的，并不是 PSPNet 这个网络结构本身，而是几项当年被称为"黑科技"的东西。

第一项黑科技是**算力**。前面讲过，用 CNN 都要先在 ImageNet 上预训练，再在分割数据上微调。他们当时动用了整个公司的算力和资源，自己重新训练了一个 CNN。自己重训出来的 backbone 比别人强，整个 baseline 就水涨船高。

第二项黑科技跟 BatchNorm 有关。老师先回顾：BatchNorm 能很大程度加速收敛、提升效果，之前讲的是**单卡**上的 BatchNorm。但分割这种由于结构导致的"不下采样"设计非常耗显存，耗个几倍以上很正常，十倍以上也不稀奇。结果是：按当时通用的卡，一张卡是 12GB，12GB 的卡用这个网络结构一般只能塞下一张图，撑死了两张。

于是一个很自然的问题就出来了：假设用一台八卡的机器，每张卡只能塞一张图，那么 batch size 是多少？

台下的直觉答案是 8。老师说：你们以为的 batch size 是 8，但实际送进 BatchNorm 里算的 batch size 只有 **1**。

为什么？因为 BatchNorm 跟卷积不一样。卷积是一个通道一个通道地算就行了，不需要知道什么统计量；但 BatchNorm 需要知道**整个 batch 的均值和方差**。要算均值，你就得知道其他图的值——而其他图分散在另外七张卡上。当时还没有卡间通信这回事，一张卡内部通信就行了（老师用班级打比方：我们这个班是一张卡，另一个班是另一张卡，本来在自己班里算就行，不需要班级之间的交互）。所以每张卡只能拿自己那一张图算均值和方差，等效 batch size 就是 1——这跟没有 BatchNorm 几乎是一样的。

### 6.4 跨卡 BatchNorm

这件事当年让团队非常头疼。2017 年他们做了一件事：实现**跨 GPU 的 BatchNorm**——算的时候把其他几张卡上的值收集过来，算出整个 layer 特征值的均值和方差，算完再分发回去。

听起来很简单，但老师强调实际难度：牵扯到底层，因为这是卡间通信；如果正常用 Python 去写会非常慢，慢到你根本不想采用这个策略——本来两天就能训完的实验，你会发现要一年。

这里还有一个纯数学的问题：假设有两张卡，要算完 BatchNorm，卡间要通信几次？

- 第一步，算均值：比如在 0 号卡上算，那得让 1 号卡把它的值告诉你，把值拿过来，算一下均值——这是一次卡间通信；
- 第二步，算方差：得把均值还回去、告诉对方均值是多少——这是第二次通信；然后再把值收回来算方差；
- 第三步，算完方差还得通知对方方差是多少。

所以朴素做法要交互好几次，至少要两次。但这个公式其实比较简单，自己推一推就能把它化简，最后只用很少的卡间通信次数（两次）就能把均值和方差全部交换完成。写完之后速度很快，至少不会让人感受到影响。

效果上，这就真正实现了 BatchNorm 在 batch size 为 8 时的效果：原本你以为自己开了 batch size 等于 8，实际单卡编程时人家只收到一张图，实际起作用的 batch 只有 1；做了跨卡通信之后，实际起作用的 batch 就是 8，可以很大程度加速训练过程。

这段故事还有后续：商汤当年不愿意承认这件事，也不愿意公开，没有放出代码，只写在论文里。但一年后有人自己把它实现出来并开源了。PyTorch 那边一直有人留言要求支持 cross-GPU 的 BatchNorm，官方行动很缓慢（实现起来可能也确实不好弄），直到 2019 年才真正加入。老师说，这也算分割对 PyTorch 的一个贡献。回过头看，里面遇到的都是很实在的问题：分割要的显存很大，当时的 GPU 撑不住，那就得去解决、去折中、去解决跨卡通信。

最后老师感慨了一句商汤：当年发论文很猛，一开发通告就是"中了几十篇"，现在看来几十篇是很容易的事，但当年真的很猛；可一个公司没有自己的护城河、没有像 TikTok 那种粘性极高的现象级产品，现在运营就很不好。

## 七、实例分割与 Mask R-CNN [01:25:37–01:38:03]

### 7.1 回到两头牛：实例分割的定义

讲完语义分割，老师回到开头那个悬念：那张只有两头牛的图。语义分割出来、不加框的时候，它只告诉你"这是牛"，有几头不知道，你自己看；它只说这个像素是牛、那个像素也是牛。但现实生活里确实有诉求要区分这两头牛，那怎么区分？

这就进入下一个分割任务——**实例分割**（instance segmentation）。它的任务定义里最明显的一点是：如果一张图放到语义分割里，图里有几个颜色？两个颜色——车一个颜色、人一个颜色，至于哪个人是哪个人它不管，"I don't care"。但放到实例分割里就不一样了，每个 instance 你都要去区分：这四辆车都要区分出来，这两个人不是同一个人，你要用不同的表示，还要告诉我这是 person 这个类的第几个 instance，把 instance ID 区分出来。

实例分割跟检测有点像：检测里面每个 object 都要框出来，而实例分割把"框出来"变成了"给出一个 mask"，一个 object 一个 mask，更具体。

### 7.2 从检测框到 mask 分支

有了这个认识，再加上上节课学过的那么多目标检测方法，老师让台下想：有没有什么想法？他提示说，你也许将会提出整个 AI 历史上引用最高的一篇论文（应该没有之一）；有人提到 ResNet 那篇应该比这个高，老师同意，说这篇大概排第二。

顺着 Faster R-CNN 的思路想就很自然：既然已经能出框了，从框到 mask 好像就那么一步的事。于是就有了 **Mask R-CNN**。

Mask R-CNN 跟 Faster R-CNN 非常像，代码简直就只改了一小部分——基本上是基于 Faster R-CNN 整体 95% 的代码去做的，下节课跑的时候应该有感受。改的地方在哪里？在 Faster R-CNN 里，每次 RoI 池化出来的那个 feature，本来是直接送到另一个小的 CNN 里，去出 box 和 classification。何恺明想的是：我在这一步直接出一个 mask 行不行？于是他在这一步直接把 mask 预测出来——用原本出目标检测结果的那个 feature，因为那个 feature 就对应着框出来那个 object 的区域，那么"这个区域里哪个像素属于这个 object、哪个不属于"，就可以做一个 mask 的逐像素二分类。

这样一来，原本输出 box 和 class 的那一步，就多加了一个输出 mask。就加了这么一件事，足以成为一篇引用二十多万的论文。老师说，大家一直说何恺明的工作都是"你能想到，但你就是做不出来"——他实现的是一种非常 simple、但能把效果做出来的东西。

所以实例分割的输出通常包含：mask、bounding box、类别、instance ID、以及概率，是捆在一起出的。

### 7.3 RoI pooling 的量化误差与 RoIAlign

Mask R-CNN 里有个必须解决的细节问题：对齐。前面 CNN 出特征之后，会有一些 region proposal（RPN 给出的候选区域），对应的 feature 要提取出来。原本这些 feature 是用来输出 box 和 class 的，现在还要输出 mask——而 mask 是逐像素的，对位置精度要求高得多。

问题在于：RPN 的 proposal 是从特征图上给出的，映射回原图、或者从原图映射到特征图，这个过程中会存在误差。老师回顾说，之前讲 Faster R-CNN 系列时讲过这一点：从这里到这里的映射会存在一个误差，而我们现在要解决的是像素级对齐的问题。

当时的处理方式有好几种，比如"强硬地给它挪一个位置"，让它对齐上去——也就是取整、量化。而 **RoIAlign** 的做法不一样：它按照真实的位置去采样。

具体做法是：根据框，每个地方都算出一个真实位置；拿到这个位置之后，在对应的地方用一种**采样**的方式取值——如果这个采样点落在四个特征点中间，就不强行选其中某一个，而是让周围这几个点各自把特征交出来，按距离加权算出我这个位置该有的特征。

> **老师比喻**：这就像我站在四个同学中间，我不说非要选其中某一位同学，而是说你们把各自的特征交给我，我去算一下我待的这个位置该有的特征是多少。

这样是一种更精准的对齐方式。老师强调这个上节课讲 Faster R-CNN 时讲过，这里就不赘述了。

### 7.4 实例分割不管背景

有了实例分割之后，确实可以把两头牛区分开了：这头牛叫牛一，那头叫牛二。但老师让大家对比一下语义分割那张图：有没有发现实例分割的结果没有那张图漂亮？语义分割的图更 colorful 一点。

为什么实例分割的图只剩两三个颜色？因为它**缺了背景**。实例分割有一个特点：它不管背景，跟 Faster R-CNN 的目标检测一样，它只管 object。这里 object 的定义一般可以理解为"前景中可以活动的物体"——比如黑板擦、鼠标都可以叫 object，而墙、地板这些挪动不了的东西就是 background。

## 八、全景分割 [01:38:07–01:42:26]、[01:52:46–02:04:30]

### 8.1 任务动机与最朴素的想法

实例分割不管背景，这在有些场景下就会出问题：因为有时候我们既想管前景、也想管背景。这时就有了**全景分割**（panoptic segmentation）。

这个任务离我们挺近，2019 年才被提出来。它当时的出发点就是：语义分割长这个样子，问题是 instance 之间不做区分（car 1、car 2、person one、person two 它都不分）；实例分割没有背景、不管背景。那么最朴素的想法就是把两者合在一起：前景用实例分割那套去处理，背景用语义分割那套去处理。

### 8.2 前景与背景的定义之争

**课堂问答**：老师随即把问题交给台下——如果你来定义这个任务，什么是前景、什么是背景？他特意强调这个问题的分量：你现在假设自己是这篇论文的作者，你在定义这个 task、在写这篇论文，你要让别人承认这是一个任务，那你就必须把前景和背景定义清楚；而且到很后面你会发现，分割、检测都会存在前后景的问题，所以这个问题值得想；如果定义得不好，就会天天有人给你发邮件问"到底什么是前景"。

老师先自己举了个反例式的思考：你总不能说"站在前面的是前景"吧——那跟我们正常人拍照就不一样了，我们拍照时主体、主人公是前景，后面那些游客都应该算作背景、应该全部给他 P 掉；可这张图里到底什么是前景、什么是背景？

他还提示了写论文的现实考量：如果定义得足够清楚、把什么算前景什么算背景说清楚，以后大家的分歧才会少一点。他甚至把这个 idea 直接送给台下："这个 idea 就给你们了，你们去定义这个 task。"

课堂安静了一段时间（这段时间里老师在等大家思考、也让人去查），之后重新收拢。

**课堂问答**：老师问有没有人想出来、有没有人搜出来，该怎么办。有学生提出"数量"。老师追问："数量怎么定义？"接着有人说"size"，老师判断"已经接近了"，并顺着复述了这个想法：小的算前景、大的算背景？随即他给出了反驳：那如果我直接一个人脸怼上来，这个是算背景还是前景？

老师解释为什么这个想法不成立：你这个想法引入了**现实空间**的问题；但我们做的是像素级的、图像空间的问题，这个"大小"你没法衡量——图像空间里的大小是一个**相对大小**，取决于你离摄像头多远。人脸怼上来那个脸那么大，我知道你想说的是在现实空间里面那个脸其实挺小的，但在图像里它很大。

### 8.3 可数 / 不可数

老师说"这个数量其实是很接近了"，然后给出他们后来的定义：**可数的（countable）是前景，不可数的（uncountable）是背景**。这一下就把问题收束住了，因为可数与不可数在中文和英文里本来就有定义——英文里什么时候用 much、什么时候用 many，都是规定好的。

用这个标准去检验，很多争议就变得可以讨论：

- 路：一条路你怎么数？图里这条路是连成一片的，你说哪条路是一条路？如果图像再扩展一点，哪个路是哪个 instance？按物理空间说，全世界的路可能都是一个 instance，那你在哪里把它切开？虽然有些路段叫邯郸路、叫国权路，但你从哪一个点切一下说"这是邯郸路、这是国权路"？只是我们大概到了这个区域就说这是国权路到了、这是邯郸路到了，但没有一个明确划分的话，是不能划分的，它按道理都是连着的。所以路是不可数的。
- 墙：你为什么认为这面墙跟那面墙不是一面墙？你要严格地从这儿划分说它是一个 instance，那你划分的道理到底在哪里？
- 树：老师说自己个人觉得树应该算可数，但论文里把树当成不可数的、当成一种背景。
- 楼：老师也觉得楼可数，但论文里 building 是当背景的、不可数的。

所以老师也承认，这个定义本身仍有一定程度的争议，但争议比"什么是前景"要小很多——因为可数/不可数是语言里已经定义好的东西。他顺势补了一句自己的理解：你也可以认为"可移动的、可数的物体"是前景。

### 8.4 数据集拼接与实际妥协

除了论文上写的定义，老师还讲了他们实际遇到的难题和妥协。前面讲过，分割的数据集很稀有、很少，所以他们是用已有数据集去合并的：用 COCO，这个数据集之前既能提供实例分割的标注、也能提供语义分割的标注。

合并的规则是：把实例分割数据集里出现的那些类别当作前景，剩下的用语义分割的标注去填背景。这其实就是刚才学生说的那个思路能"get 出来"的东西。

但这里有个现实问题：你没有办法重新标。一是重新标难度太大；二是实例数据集里，大部分标注的时候本来就基本只标了这种可数的物体（车、人），而路、建筑、树这些当时都被当作背景直接忽略了。所以只能用语义分割的标注把这部分背景填充上，合成出这样一个数据集。

合成出来的结果，老师坦言这张图都算好的——很多结果里 mask 跟背景之间是有**缝隙**的。原因很具体：实例标注的人和语义标注的人不是一批人，所以一定会出现微小的缝隙。你想想，原本在这里的这辆车和这里的这辆车，你能保证它是严丝合缝的吗？检查数据集会发现有不少缝隙存在。但老师认为这都是现实问题，到这个程度属于全体 researcher 都能理解的，什么 reviewer、AC 都能体谅：有这种问题就有，也不妨碍你定义这样一个任务，你只要把可数、不可数说清楚就可以了。

### 8.5 两个 head 与三任务对照

方法上，全景分割也是输出两个 head：一个 head 输出实例分割的结果，一个 head 输出语义分割的结果，最终把两个 head 的预测 merge 起来——能被 cover 住的就替换。但替换的时候总会出现缝，因为两个结果 merge 时必然会产生这样的问题。

为什么要分两个 head？因为这两条路线的方法本身不一样：实例这条路线跟 Faster R-CNN 类似，要能把 instance 区分开，就一定需要 RPN 那一套；而语义分割那边明显是更 elegant 的 dense 结构，我直接就要输出、逐像素给你分出来，但分出来之后 instance 区分不出来。所以只能出两个 head，一个预测语义分割、一个预测实例分割，最后 merge。

老师用一张表把三个任务的定义讲清楚了，并特意强调写论文时也要学会这种表达方式：

| 任务 | 每个像素给类别 | 区分个体（instance ID） | 管背景（不可数类别） |
|---|---|---|---|
| 语义分割 | 是 | 否 | 是 |
| 实例分割 | 是 | 是（仅前景） | 否 |
| 全景分割 | 是 | 是（前景） | 是 |

也就是说：语义分割什么类别都分，但不管 instance；实例分割给前景的 instance ID，但不管背景；全景分割两者都管。老师提醒，写论文时用这种表格，把"这个方法实现不了这个功能"用红色的叉标出来、能实现的打勾，"我三个功能都能实现"，读者一眼就清楚。

全景分割的结果里，两头牛和最后的背景都有了。但图上有一条黑色的绳没被分出来，老师解释这可能有两种情况：一是数据集里根本没有定义这个类别（不知道这是一条绳），二是它预测出来了但不知道该归到哪。因为语义分割和实例分割都存在一个限制：**只能预测预先定义好的类别**。比如预先定义了 80 个类别，我就只预测这 80 类；如果出现了第 81 类，有两种处理方式——第一种是把它分配成"我不知道"这一类，第二种是不管你是哪一类，我就从这 80 个类里挑一个跟你最近的。老师用"沃尔玛的塑料袋"的梗打比方：不知道它属于哪个类别，就从男女两个类别里给你选一个最近的。

## 九、Transformer 时代的分割 [02:04:35–02:22:04]

### 9.1 为什么不能逐像素 query

前面讲的任务基本都基于 CNN。进入 Transformer 时代之后，检测这边出现了 DETR，用 transformer 的 encoder-decoder 直接做；分割这边也出现了一系列基于 Transformer 的方法。

其中一个直接的问题是：Transformer 用 query 来做查询，那分割能不能让每个像素都出一个 query？不能。老师当场算了一笔账：如果输入是 $512\times512$，要让每个像素都出来，那差不多是

$$512\times512=262144\approx 25\text{ 万}$$

个 query，你根本就承受不起。这就是 transformer 用在分割上的核心矛盾。

在没有 Transformer 之前，分割可以理解成只有一个"片"：一个对称的 encoder-decoder，在解码端直接输出一个 $H\times W$ 的 mask 就得到结果了。这条路之所以可行，是因为它是稠密的、逐像素的。

### 9.2 MaskFormer：mask 与类别解耦

**MaskFormer** 换了一个思路。它仍然输出 mask，但这个 mask 的通道维 $C$ 是一个**跟类别没有关系**的数字——它自己定义的一个数字，跟 query 相关，你可以认为它是一个 feature。

具体流程是：

1. CNN 提出一个特征图，尺寸记作 $C\times H\times W$；
2. 用 transformer 的 decoder（这里只用 decoder，不用 encoder）对 $N$ 个 query 做处理，每个 query 出一个 $C$ 维的向量；
3. 把这 $N$ 个 $C$ 维向量与 $C\times H\times W$ 的特征图做内积，得到 $N\times H\times W$——也就是 $N$ 张 mask；

| 张量 | shape | 含义 |
|---|---|---|
| 图像特征 | $C\times H\times W$ | CNN backbone 输出 |
| query 嵌入 | $N\times C$ | $N$ 个可学习 query 的向量 |
| 内积结果 | $N\times H\times W$ | $N$ 张"无人认领"的 mask |
| query 分类 | $N\times K$ | 每个 query 的类别概率 |
| 相乘并聚合 | $K\times H\times W$ | 每个像素属于各类别的概率，argmax 得最终 mask |

老师用很形象的话解释这 $N$ 张 mask：你可以认为现在来了 $N$ 个分类器（$N$ 个 query），每个都要去分一个 mask；但我要分的这个 mask 是个什么，我也不知道，我先给你把 mask 分出来。于是你得到了 $N$ 个 $H\times W$ 的 mask，先放在这儿、"无人认领"——每个 mask 对应一个 query（比如对应那个红色的 query），但它到底是哪个类别，你还不知道。

另一方面，每个 query 出来的那一路是一个 $1\times C$ 的东西，可以做一次分类，这跟分类头很像：每个 query 出一个类别，比如这个对应 person、那个对应 dog、另一个对应 cat、再一个对应 car。而且下一张图里，同一个 query 可能对应的类别就变了——但每个固定的 query 一定会出一个类别。

于是这一步就分成两件事：一步用来做分类，一步用来产生 mask 区域。最后把分类结果与 mask 相乘/认领，就得到了带类别的分割结果。

老师特别强调这与 FCN 的本质差别：以前我们虽然是一整张图出一个 mask，但那个 mask 本质上是"你给每个像素分类"，所有像素的类别集合成了一张 mask，不存在"某一个 object 单独是一张 mask"这回事——分割功能是耦合在分类里完成的，你通过分类完成了分割。而 MaskFormer 是先把图里"长得像的整体"抠出来（mask），再给它认领类别——它是把分割与分类**解耦**了。

### 9.3 为什么用乘：重合冲突与概率竞争

老师接着回答了那个关键问题：为什么不直接"认领"，而要用内积、要用乘？

他先让大家回想全景分割里把实例分割和语义分割往一块合并时会有什么问题。缝隙间隔只是小问题，"最可怕的是重合"。

**课堂问答**：老师问合并时最可怕的是什么，台下有学生答出"对重合吧"，老师确认并展开。

重合的麻烦在于：如果分割得好当然没问题；如果没分割好呢？假设有一个人，他的胳膊本来没伸那么长，但因为分割性能不好，多出来的那一节胳膊被判给了旁边那个人。那么这一节胳膊到底属于谁？如果知道 ground truth，它属于红色小人；但蓝色小人分出来的结果里也有这一节。你把两个结果直接 overlap、直接合并，双方都去 claim "这是我的"，是不是就产生冲突了？

这里用乘的理由就出来了：

1. $K$ 本身是一个**概率**问题——每个 query 对每个像素给出的"这块归我"的概率；
2. 假设某一块像素，蓝色 query 给出的概率是 $0.1$、$0.7$、$0.2$ 这样的分布，而红色 query 对这块给出的概率是 $0.9$、$0.1$——红色能 claim 的概率本来就更大；
3. 把两者相乘之后，红色小人能 claim 的概率会更大，于是它就能把绿色/蓝色那个 claim 直接**压制**掉，那一节胳膊就被红色抢过来了。

所以在 $K$ 个类别的概率矩阵与 $H\times W$ 的概率矩阵相乘之后，得到的是一个 $K\times H\times W$ 的大矩阵，每一格都是概率；最后再用 argmax 去挑到底哪一个类别最大——红色在这块的概率更大，它就宣布"这块是我的"。这跟我们分割头那边的逐像素分类完全一样。

因此它不是通过"直接认领"，而是通过这样一种概率竞争的方式来做归属裁决。

### 9.4 Mask2Former：一套模型三种任务

MaskFormer 本身只做了语义分割——从标题就能看出来：《Per-pixel classification is not all you need for semantic segmentation》。但老师让大家想：这个结构是不是也适合做实例分割？因为这里说的只是一个"entity"、一个区域，我并没有说你这个区域到底是个什么。同样是把一块抠出来，它可能是把所有城市人都抠出来，也可能是把 person one 抠出来、把 person two 抠出来——那么下面这个 entity 对应的 mask 就有多种可能性。既然这样，实例分割是不是也能用这套结构？全景分割是不是也能？

作者手很快：这篇发完之后他立马想到了这个问题，马上做了第二篇 **Mask2Former**（masked attention mask transformer for segmentation），直接就能做三种分割。老师的评价很实在——这个作者跟我一样也是做语义分割出身，但他在大家都意识到这个问题的时候手更快一点，就把这个给做了。

Mask2Former 里 query 到底是什么？其实"也没有"——它只是一个可学习的 query（learnable query），完全靠 loss 来监督、自己去学：

- 如果 loss 监督的是语义分割，那它学到的就是"我一个 query 负责所有的车"，不管车在哪我都 query 你；
- 如果是实例分割，那它学到的是"我每个 query 只关注一个 instance 的 car"，按单个 instance 来看；
- 如果是全景分割，那它学到的是"我有一部分是这个 instance、是前景的，有一部分是背景的"。

所以这个 query 的可操作性很大，可以用一套模型去做三件事情。

### 9.5 通用模型的边界

这个思路大概在 2020 年很流行。因为在这之前，老师介绍的所有方法全都是"一个模型做一个任务"，全部是专用的；从这个时候开始出现了"通用"（universal）的模型——至少它能够把所有的分割任务都做了。

但老师也给了清醒的判断：由于 CV 本身的复杂性和难度，到现在也没有出现一个像 NLP 里那样、能一种架构解决所有 CV 任务的通用模型。大模型只能说"具备那个能力"，它的解决方式都是靠加一些特定的 head 去完成的——比如它要产生一个分割的 mask，它只能先出一个 token，然后一定要再加一个 segmentation head 才能把这件事解决掉。

Mask2Former 大概是 CVPR 2021/2022 的工作，离我们挺近，性能也很好。紧接着这个作者还做了 video 版本——他想到"video 好像也能做"：只要单帧出的效果够好，把单帧的结果连起来就行了。不过 video 那个版本因为他当时已经去公司了，只写了一个大概三到四页的 technical report 放在 arXiv 上。

> **老师强调**：从"一任务一模型"到"一套结构多任务"，真正的分水岭不是网络更深，而是把"分割"和"分类"这两件事在结构上解耦——mask 先出来，类别后认领。

## 十、开放词汇与指代分割 [02:22:09–02:34:27]

### 10.1 预定义类别的局限

讲到这里，老师停下来带大家反思一个问题：分割现在的问题是什么？为什么它到现在还值得做、还一直有新的工作出现？

他指出一个关键：目前这些任务的定义里，**都人为地降低了难度**。比如我就分割这 80 个类别，80 类以外的我不认识——你突然出现了一个什么新类别，它是不认识的、是不管的；你把"牛来了"的那个画面给它弄出来，它肯定不认识。

但实际生活中有没有这个需求？肯定有。我们总不能说，要处理一个新的东西就得重新训练一下——那肯定不愿意。早期一些公司做乙方时特别累、特别没有护城河，就是因为这个：甲方说这次要检测的类别有苹果，下次甲方说这次检测里有文字，再下一次甲方说我就检测那个蟑螂；你每次都要变、每次都要重新收集数据重新训练，没什么可扩展性。

所以现在的需求是：网络训练完之后，**即使你不认识，你也能够理解它**。就像人一样——我虽然没见过你这个物体，但我坐到电影院看到"牛来了"的那一刻，我愣三分钟、让自己忍一忍，我也能接受；下一次再出现的时候我也能接受。这是我们一种很强的能力。

### 10.2 zero-shot 与 open vocabulary

这种能力叫**零样本学习**（zero-shot learning），或者叫**开放词汇**（open vocabulary）的能力：我们能学习到一些零样本的、新的知识，能大概通过那个抽象的画面知道它是一头牛——虽然它的特征跟正常的牛相差很大，但我们能够通过已有的一些东西去接受它。

中间很长一段时间，这个方向很火。它的做法是：借助已经学过的视觉特征，加上各种类别之间的**语义关联度**，去推断没有见过的视觉 object。

- **飞机例**：我已经学到了车、学到了人、学到了地面上的那 80 个类别；你突然给我一张天上的飞机的照片，我没见过，但我希望你能够通过查一下维基百科、词典，根据你训练时见过的视觉数据特征，以及词典上这些语义的关联性，推断出它是一个飞机。
- **熊猫例**（老师用来解释原理）：一个小孩没去过动物园，但我们告诉他"动物园有个熊猫"，并且告诉他"熊猫就是黑白色的"；他还见过熊。于是我们给了他两样东西：一是灌输给他的 semantic knowledge（熊猫是黑白色的熊），二是他自己亲眼见过的黑白色、亲眼见过的熊的特征。把这样一个小孩放到动物园，他大概率是能找到那只熊猫的。这就是零样本学习。

### 10.3 指代分割与 VLT

比 zero-shot 更进一步的，是**指代分割**（referring expression segmentation）。老师先对比传统做法：传统的分割就是我认识哪个类别就给你打出来，不认识的我就乱处理或者不处理，而且类别是固定好的、它不接受指令——虽然我们刚才说那些类别都跟语义关联，但实际上它都是 ID 等于 1、ID 等于 2、ID 等于 3、ID 等于 4，这个类别只是我们人为把 1、2、3、4 跟 person、cat 去关联起来的。你现在突然直接给它一个命令，它就懵了，处理不了。

而现在要做的是：我给你一句话，比如 "small elephant on the left"，你身为一个人能不能找到左边那只小象？能找到。甚至我说 "small one on the left"、"左边那个小的"，我都没有说是哪个类别，你也能找到。老师感慨人与人之间的沟通有时候挺奇妙，非常喜欢用省略词语让对方猜——"表白的时候也不直接表白，也是让对方猜"。我们希望模型做的，就是直接输出这句话所描述的那个目标物体。

实现这个的模型叫 **VLT**（视觉-语言 Transformer，论文里是 vision-language transformer，用作 referring 的 query 生成）。它做的事情很巧妙：

1. Transformer 里的 query 本来就是一种"查询"的方式；
2. 那我现在都有这个句子去描述这个物体了，这个句子是不是可以直接作为 query？
3. 但它在最开始先让 language 去跟 vision 交互一下，得到一个初步的查询，然后生成一组 query；
4. 再拿这组 query 去 query transformer 的 decoder，让它产生出想要的结果。

这样做的好处是更天然地利用了 Transformer 的结构。老师对比说：之前 DETR 和 MaskFormer 里的那些 query，我根本不知道你这个 query 是什么——我学完了也不知道，就是让网络自己决定你这个 query 是什么；而在指代分割这个任务里，query 天然就是一种 language。

效果上，基本上都是人自然地表达的语言："左边那个人穿黑衣服"、"站在右边的那个个子高的那个胖的"——什么语言都可以。老师强调，这种情况下就再也不用像之前那样必须是 person，不能加"高的、矮的、胖的"任何前缀；现在人类自然语言交流的表达方式它就可以接受。

### 10.4 GRES：一句话指多个目标

但这里还有一个问题：早期是一句话只能指代一个 object。而我们日常交流中，一句话可能指好多个人——我说"左边这些"，那就是左边的十几位同学，不可能只是一个。那你的任务定义就要重新定义一下。

重新定义之后就有了 **GRES**（generalized referring expression segmentation）：一句话可能说的是"穿红衣服的那个男孩"（单数），也可能是"所有站着的人"、"左边的站着的两个人"、"左边的两个人"、"所有人除了穿黑衣服的那一个"——这时候指代的物体就是多个。

这就是逐渐走向现在的多模态大模型时代的分割。老师在这里很自豪地说：这个任务是他提出来的，包括前面那一片工作也是他的任务。他回顾当时的机缘：做这个的时候是 2019 年，根本就没有什么多模态大模型，视觉（CV）跟 NLP 都是分家的；当时做这个纯粹是因为 Adobe 的 Photoshop 需要这个功能——他们觉得 Photoshop 太复杂了，想弄出一种傻瓜式的 Photoshop：大家说句话、数个字，直接把这个东西分割出来，不要你用什么套索各种去选。他们发现了这个问题，于是重新定义了一下任务，也提出了一系列方法，恰好赶上了多模态大模型的时代脉搏。

在多模态时代，这种形式的分割非常合适：你现在给各种大模型调用，它就会去接受这种类型的任务，比之前那种纯粹预先定义好类别要方便多了。因为这是一种纯粹的跟人的交互，而且交互过程中语言不受限制，什么语言都行。

## 十一、SAM 与当前格局 [02:34:27–02:37:20]

最后老师讲了几个现在比较 famous 的模型，重点是 **SAM**（Segment Anything Model）。

SAM 是这个系列里现在最火爆的几个模型之一。这节课只看 SAM 的 image 版本，video 版本下节课再看——它后面也出了 SAM 2 和 SAM 3，都是 video 的。

SAM 的核心批评针对的是 query 的"死"：MaskFormer、DETR 里的那种 query 是一种**死 query**——你不能预先知道它是什么，训练完之后你不能跟它交互。而 SAM 想做的是"指哪打哪"：我给你一个 prompt，比如我点这儿，你就把这块分割出来；或者我说"剪刀"、说"黑色的那块铁"，都行——一种灵活的交互，你把它分割出来。

它能接受的 prompt 有 mask、point、box、text，都可以。你给一个框也行，给一个点也行，给一句话也行，它都能把目标做出来。

效果上，它零样本的能力非常强：没见过的它都可以分割得非常好。你可以假设自己任意拍一张图、认为它没有见过，扔给他，它都能把目标分割出来。

它的关键在于数据而不是结构。老师提醒：这种方法其实我们早期也都做过，它比较强的原因是它是一家 Meta 的公司做出来的——他们收集了大规模的一个**百万级的分割数据集**。你想，之前 ImageNet 也就是一个百万级的分类数据集，而它做了一个百万级的分割数据集，花了好多的卡、好多 GPU、好多钱，才把这个模型的泛化能力训出来。

所以老师说："这个叫做 segment anything，SAM，一定要记住这个模型——这个模型是现在通用的最强的分割模型。"它后面还有一系列版本，比如提高分辨率的版本（让 SAM 的分辨率更高一点），以及做刚才我们定义的那种任意交互任务的版本，也都是用 SAM 去做。

这些工作就构成了现在分割领域在顶会上的研究版图，也是当下研究的一些方向。
