## 二、期末大作业题一至题四：视频目标分割与分割质量检查 [00:03:09–00:16:04]

### 2.1 题一：复杂场景下的视频目标分割

第一个作业的主题是**复杂场景下的视频目标分割**。

**定义**：**视频目标分割**（Video Object Segmentation, VOS）是在一段视频中给定一个目标以及该目标在首帧上的掩码，让模型在这整段视频中持续地追踪并且分割这个目标。

这个任务的应用场景非常广阔，可以用于智能监控、自动驾驶、视频编辑等等。

**例子**：画面左上角的那段视频里，要在这段视频中持续跟踪一辆用黄色高亮标出来的车；右上角的那段视频画面中有三只狗，目标是在这三只狗中追踪某一只特定的狗。两段视频用的都是上面这个定义：给定一个目标和它在首帧上的掩码，然后让模型在整段视频里持续把它分割出来。

在这个领域，目前最先进的、也就是最 SOTA（state of the art）的模型是 Meta 发布的 SAM、SAM 2 和 SAM 3，它们是目前最好的视频目标分割模型。

这个任务其实已经完成了很多，在很多情况之下都已经取得了非常好的性能。但是在现实的部署中，它还面临着非常多挑战：因为训练场景更多是来自于真实拍摄的数据集，它跟真实场景之间可能还存在一些不稳定的因素，比如低光照、严重的遮挡、目标的长期消失和重现，以及相似物干扰等等。

所以即便是目前最强的 SAM 3，也难以解决这些全部的复杂场景。

**例子**：去年 8 月，实验室发布的一个数据集系统地覆盖了所有这些复杂场景。这些 case 其实很多，现在最强的模型也没有办法很好地解决。比如画面里有非常多的小鸡，而任务可能只是追踪其中的一只小鸡；又比如画面里有一辆车，这辆车可能先在这里被遮挡，然后重新出现，再被遮挡，再出现——这种消失重现的情况里往往还有相似物的干扰；还有的 case 要追踪的是影子，而不是某个具体的人本身；此外还会存在一些目标的行为等等。这些视频都是很难追踪的。

所以第一个作业，就是让大家去尝试针对其中的一种情况做改进：比如针对这种很严重的遮挡，或者这种消失重现，或者这种小目标，以及这种目标的变形等等，挑其中一种复杂场景去改进。改进可以基于 SAM 2，也可以基于 SAM 3。所以这个题目是一个开放性的题，需要大家自研算法，言之有理即可；大家可以把 SAM 2 或者 SAM 3 作为一个 baseline（基线模型）去进行开发。

这个作业的评价指标在那个文档中也给大家写过了。它基本的输入是：给一段视频序列，以及这个目标在首帧上的目标掩码；要求大家输出的是整段序列中这个目标逐帧的掩码。

评分细则如下：

1. 首先需要正确地实现这个模型，这是最基本的要求。
2. 要针对其中某一个特别的场景——比如消失重现、比如小目标追踪、比如相似物干扰等等——去设计你的算法，并且说明你为什么要这么设计、你设计出来的这个算法为什么能够解决这一特定的问题。
3. 可以做一些定性效果的展示。
4. 最后可能还会进行一些定量的评测，比如需要在这个数据集上做一个定量评测。
5. 还包括期末报告的撰写。

> **老师强调**：定量评测并不是核心的指标，核心的考察点还是在于你是如何设计这个模型本身的。

### 2.2 题二：把通用模型微调成特定领域的专家模型

第二个作业是特定领域的图像分割。这个 task 实际上是非常常用的一个任务：现在的分割模型，SAM 也好、SAM 2 也好，其实是一个通用的模型，不是一个具体的专家模型；现在的任务就是把这些通用的模型通过在特定领域的数据上进行**微调**（fine-tuning），使它变成一个专家模型。

**例子**：让 SAM 也好、SAM 2 也好，变成一个专门用于分割医学图像的模型，或者专门用于分割遥感图像的模型，或者用于分割工业缺陷的模型。

因为不同领域的任务有不同特点：医学图像可能光照就比较暗，也可能有专门的医学数据集里的 bias（偏置）在里面；遥感图像的特点可能在于它都是用非常远距离拍摄的，目标可能都非常小；工业缺陷可能也有它自己的特点。所以希望大家能够基于 SAM 也好、SAM 2 也好，在这些领域的数据上去做微调分割的工作。

第二个任务的评价指标也非常明确，是两个最重要的考察目标：

1. 在具体领域上的分割性能能够提升多少。比如在医学的肿瘤图像上做一个微调，那么这个 benchmark 大家可以自己选择。
2. 通用的指标。也就是在通用的图像分割数据集上，微调之后希望你的分割能力不要下降太多。

### 2.3 题三：分割结果的自动检查与纠错

第三个作业，看好像选的同学不太多，所以就快点过。它的 task 是分割的自动检查与纠错。

任务是这样的：比方说我有很强大的 SAM 或者 SAM 2 模型，那么对于真实的图像来说，我肯定是没有 ground truth（真值）的，也就是肯定没有真实的掩码。大家知道，如果要去标注一个掩码，其实是很耗时、耗力、耗人力的一个工作。所以就让模型去看：我没有 ground truth mask，但是我就看这个预测结果，让模型结合一张原图和一张它输出的预测的 mask，把这两个东西结合在一起，让模型自己去想它到底预测得对不对，也就是它预测的这个掩码有没有问题。

具体来说，可以输入一张图、输入一个预测掩码，然后自己去检测它有没有问题、有没有错误的检测；以及如果有错误的话，它是什么类型的错误——是少分割还是多分割，是分割到别的物体上去了，还是它自己的尾巴没有分割出来等等。在这个基础之上，还可以尝试一些自动纠错的改进，因为 SAM 和 SAM 2 是天然支持用点做一个 prompt（提示）去做这种纠错的。

这个作业的评价指标主要分成三点：

1. 有没有能力判断出它有没有错，也就是判断它是对还是错。
2. 它错的类型是什么，或者说它错的区域是什么，能不能给它定位出来。
3. 发现错误之后，你能不能去纠错。

这三个就是最根本的环节。

### 2.4 题四：指代视频目标分割

第四个 task 是**指代视频目标分割**（Referring Video Object Segmentation, R-VOS）。这个任务又回到视频了，做的是一个指代视频目标分割的任务。

它基本的任务是：给一段视频序列，再给一句语言表达作为 prompt，让模型把这句话所指的那个目标在整段视频里分割出来。

**例子**：给一个视频序列，给的语句是“请你分割出穿红色衣服的那个人”。这个在视频中是很简单的，就是左边这个人，因为他穿着红色的衣服；所以你看第一张图就知道要追这个人，然后再在整个视频中去追这个人。这是一个比较 basic 的 case。

**例子**：第二个 case 就上一点难度了。还是输入这个视频，但这个时候给的 prompt、给的这个 expression 是“哪只小鸟飞走了”。你看第一帧和第二帧，也就是看前面这些帧，其实都看不出是哪只鸟飞走了；你必须看到最后一帧，或者看到中间的某一帧，才知道是中间这只鸟、第二只鸟飞走了。在发现是这只鸟飞走之后，还需要把这只鸟对应的所有掩码都给它分割出来。

这就是非常经典的一个 R-VOS 任务，也就是 referring video object segmentation，指代视频目标分割。

这个任务的特点是：目标经常是在中间才出现的，或者说这句 expression 对应的一个核心动作可能是在中间才会发生的。

所以在传统的 R-VOS 任务中，往往采用的是 offline 的做法：首先把整个视频序列全部都给到模型，然后模型会先去完整地读取整个视频——比如整个视频可能 100 帧，他会先从第一帧看到第一百帧的所有信息——都看完之后，他再去统一地做一次处理。这是传统 R-VOS 的做法。

我们这个题目现在的做法是：假设是一个在线的场景，也就是我们看到这一帧的时候是看不到下一帧的，看到第二帧的时候是看不到第三帧的；它必须是一个顺序遍历的过程。视频帧是一帧一帧到达的，你在看到第 $t$ 帧的时候，是看不到第 $t+1$ 帧的。

这样其实才更像人类思考的模式。

**例子**：给我这个视频，然后我看到“哪只小鸟飞走了”这句话，那我可能的一个解决思路是：首先看到这几只小鸟，那我就有三个候选人，在这一帧中保持三个 target；然后到后面某一帧，我看到“飞走”这个动作终于出现了，那么我再把这三个 target 过滤到只剩一个 target。

这就是我们这个题目希望大家去完成的事情：把传统 R-VOS 的这种做法，转换成一种在线的模式。

> **老师提示**：这个事情其实做的人不太多，如果做得好的话，其实有机会发顶会。

下面几个点并不是硬性要求，只是给大家提供一些思路，当然不一定要按照这个做法来：

1. 建议大家去设计一个在线的 memory：这个 memory 对于所有视频的任务来说肯定都是需要的，但在我们这个题目里，它可以是一个在线更新的过程。
2. 也需要设置一些自动纠错：比如一开始你认为是这只鸟，然后你发现不对，好像是另一只鸟飞走了，那么你需要做一个纠错的过程。

这些也是大家可以去设计的，但不是必须的，只是给大家提供一些设计的思路。

模型方面，大家也可以基于 SAM 2 或者 SAM 3 进行修改，但是 SAM 2 和 SAM 3 都没有能够做成这件事，所以可以把它作为一个 baseline 的模型。

数据来源方面，老师说明会给大家提供三个数据集，最先点到的是 MeViS、Ref-YouTube-VOS，其余的名称紧接着继续往下报出。

### 3.2 题六：三维点云逐点部件分割

讲完第五题，换另一位助教上来，由他为大家讲解课程作业的第 6 到 10 题，他先介绍第六题。

第六题的任务是训练一个模型，对当前三维点云（3D point cloud）的每个点进行分类，也就是做逐点的部件分割。助教举了具体的分法：会把椅子的点云分为椅背、椅面、椅腿；把飞机的点云分为机身、机翼和尾翼。

**例子**：同一类物体的点云要按部件再细分——椅子的点分成椅背、椅面、椅腿，飞机的点分成机身、机翼、尾翼。

这里需要重点理解的是点云的无序性。

> **老师强调**：这里需要重点理解，点云它是有无序性的。

之所以要这样理解，是因为模型需要结合每个点的局部特征以及整个物体的全局特征，再加上物体类别的标签，才能完成这样一个分割。

在输入这一侧：输入是物体点云，从物体表面采样 $N$ 个三维点，维度是 $N\times 3$，每个点由 XYZ 坐标表示；助教建议每个物体采样 1024 或者 2048 个点。此外还有物体类别的标签，表示该物体所属的 ShapeNet Part 类别；这个数据集一共包含 16 个物体类别。

在输出这一侧：输出是把逐点的部件打上标签，维度是 $N$，也就是对每个点做一个部件类别的判断；另外还需要用不同的颜色把点云可视化出来。

作业用的数据集是 ShapeNet Part：它是一个包含 17000 个三维物体的数据集，覆盖 16 个物体类别和 50 种部件标签，助教在这里给出了数据集的链接。

测评指标是两个：instance mIoU 和 class mIoU（mean Intersection over Union，平均交并比）。instance mIoU 的计算方式是先计算每个物体的部件分割 IoU，然后再对每个物体取平均；class mIoU 则是分别对每个物体类别求平均，再对所有类别去平均。

评分细则主要分为下面几项：

1. 点云的数据处理：读取点云坐标、物体类别和逐点的部件标签，完成固定点数的采样，以及中心化和尺度归一化。
2. 模型实现：搭建或微调点云分割模型，模型要能够结合点云的物体类别信息，完成逐点的部件预测。
3. 损失函数：使用正确的损失函数，完成逐点部件的分类。
4. 指标计算：使用 instance mIoU 和 class mIoU 这两个指标进行计算。
5. 可视化：用不同的颜色展示点云部件分割的效果。
6. 模型新颖性：这一项主要体现自身关于本任务的思考就可以了。
7. 加分项：法向量的应用——把逐点的法向量作为一个额外的特征输入模型，进行相应的实验。这也算在设计的模型新颖性以及网络模型实现的效果里面。

参考论文方面，助教给出的是一篇经典的点云分割论文，并展示了这篇论文的分割结果作为示例。

### 3.3 题七：多人二维人体姿态估计

下面介绍第七题：多人的二维人体姿态估计（multi-person 2D human pose estimation）。这个作业的要求是：对一张包含多个人的 RGB 图像，定位每个人的主要身体关键点，比如肩膀、肘部、手腕、膝盖和脚踝，然后在原图上绘制出多人的骨架。助教推荐采用经典的 top-down 方法，也就是先检测图像中的人体，然后再分别预测每个人的关键点。

输入是原始 RGB 图像，即一张包含一个或多个人的彩色图像；输出是多人关键点，每个人输出 17 个关键点。

数据使用 COCO 2017，它包含自然场景中的多张图像，提供 17 类人体关键点及可见性标注。

测评指标用的是两个 OKS（object keypoint similarity，关键点相似度）的 AP（average precision，平均精度）：一个是从 0.5 到 0.95 的平均 AP（$\mathrm{AP}_{[0.5:0.95]}$），这是 COCO 人体姿态估计的主要指标，综合考虑了关键点的定位误差与人体尺度；另一个是比较放宽一点的指标，就是在 OKS 为 0.5 时的平均精度（$\mathrm{AP}_{0.5}$）。

第七题的评分细则：

1. 数据处理：正确读取图像、关键点坐标，并完成相应的坐标变换。
2. 网络构建：搭建或微调关键点模型，使它能够为单个人体预测 17 个关键点。
3. 多人推理流程：能够在图像中定位多个人体，完成每个人的关键点预测，并把结果映射回原始坐标处。
4. 指标计算：就是前面讲到的两个 OKS 指标。
5. 结果展示：在多人图像上绘制关键点以及人体骨架的可视化。
6. 模型新颖性：体现自身对本任务的思考。

参考论文给的是 Simple Baselines for Human Pose Estimation and Tracking，以及它对多人人体关键点估计的可视化结果。

### 3.4 题八：真实世界单幅超分辨率

第八个作业是真实世界单幅超分辨率（real-world single image super-resolution）。助教先讲了这个题目的背景：传统的超分，数据构建主要采用双三次下采样（bicubic downsampling），由人工生成低分辨率图像；但是我们的真实相机图像还会受到镜头模糊、传感器噪声等多种因素的影响。因此本项目要求用真实拍摄并配准的低分辨率、高分辨率图像对来训练一个超分模型，然后把低分辨率图像超分到高分辨率图像。

输入是低分辨率的 RGB 图像，要求做的是一个 $2\times$ 的超分，输出就是超分之后的高分辨率图像。

数据集采用的是 RealSR 这个真实世界的超分数据集，测评也在同一数据集的 $2\times$ 设定下进行；测评指标是经典的图像指标 PSNR（peak signal-to-noise ratio，峰值信噪比）和 SSIM（structural similarity，结构相似性）。

第八题的评分细则：

1. 数据处理：完成 RealSR(V3) 的数据读取与处理。
2. 网络模型实现：这里给出了几个比较经典的超分模型，但也可以不采用这些，采用现在比较更新一点的方法也可以。
3. 损失函数与训练：使用 $L_{\mathrm{MSE}}$ 等损失，在指定的数据集上完成模型的训练和微调，并展示损失的变化。
4. 基线指标：需要与双三次插值（bicubic）的方法作为 baseline 来进行比较。
5. 结果展示：展示低分辨率图像、模型输出的高分辨率图像，以及真实的高分辨率图像的整体与局部比对结果。
6. 模型新颖性：体现自身对本任务的思考与设计。

论文链接给的是 RealSR。

### 3.5 题九：三维点云补全

下面第九个作业是基于深度学习的三维点云补全。助教先说明实际情形：实际采集的点云会因为视角限制和物体遮挡而存在缺失。因此本项目要求利用深度学习模型，根据物体的残缺点云预测出完整的三维形状：模型需要恢复缺失的部分与结构，同时尽可能保留输入点云中已有的形状信息。

输入是一份残缺点云，从有效观测得到 $N$ 个三维点；这里的输入点云取 2048 个点。输出要求是 16384 个点。

使用的数据集是 PCN 数据集。指标有两个：一个是 Chamfer distance（倒角距离），它衡量的是预测点云和真实点云之间的双向最近距离；另一个是 F-score，在距离阈值为 0.01 时评估预测点云的准确率与覆盖率，数值也是越高越好。

第九题的评分细则：

1. 点云的数据处理：正确读取残缺点云，完成固定点数的采样、中心化和尺度归一化。
2. 模型实现：搭建或微调 PCN、FoldingNet、Point Transformer 等点云补全模型，从而实现从残缺点云到完整点云的预测。
3. 损失函数与训练：使用 Chamfer distance 等点云重建损失，完成模型的训练和微调。
4. 指标：展示训练损失的变化，指标的变化就是 Chamfer distance 以及 F-score。
5. 结果可视化：展示残缺的输入、模型的预测和真实的完整点云，并分析典型的成功与失败案例。
6. 模型新颖性：这里也同样需要有自身对本任务的思考。

讲到这里助教停下来问了一句"这有什么问题吗"，见没有人提问，就接着说：这里给出的经典论文也是 PCN 这篇论文。

### 3.6 题十：RGB 引导的稀疏深度补全

下面作业十是 RGB 引导的稀疏深度补全。助教先讲背景：深度传感器或视觉 SLAM（simultaneous localization and mapping，同步定位与建图）系统通常只能获取少量、离散的深度测量。这个深度补全任务要求结合 RGB 图像中的纹理和边缘信息，把稀疏深度恢复为完整的逐像素深度图，也就是实现一个融合 RGB 图像和稀疏深度的深度补全模型。具体设定是：从每张真实图像中随机采样 500 个有效深度像素作为稀疏深度输入；不需要去处理深度噪声或复杂的非均匀采样。

输入是 RGB 图像以及稀疏深度图，输出是稠密的深度图。数据是 NYU-Depth V2，它包含室内场景的 RGB 图像和对应的深度图；可以从真实深度图的有效像素中随机采样 500 个点来构造稀疏输入。

指标主要是 RMSE（root mean square error，均方根误差），以及预测深度的绝对相对误差。

第十题的评分细则：

1. 深度数据处理：正确读取 RGB 图和深度图，并生成包含 500 个有效点的稀疏深度。
2. 融合模型的设计、搭建与微调：联合使用 RGB 与稀疏深度，输出同分辨率的稠密深度图。
3. 损失函数的设计与训练：使用 $L_{\mathrm{MSE}}$ 等深度回归损失完成训练，并正确处理无效的深度像素，然后再做指标计算。
4. 指标计算：就是前面提出的两个指标，以及深度的可视化。
5. 结果展示：展示稀疏的输入、预测深度和真实深度，并分析物体边界或无纹理区域的结果。
6. 模型新颖性：体现自身对本任务的思考。

这个题给出的论文参考链接是 Sparse-to-Dense。

### 6.2 为什么需要深度学习框架

首先要明确，PyTorch 是一个深度学习的框架。那我们为什么需要这样一个框架？老师给了三点原因。

第一点，它能帮我们实现自动的求导，也就是说它能帮我们实现反向传播、梯度更新的这个过程。在框架出来之前，很多时候人不仅要去设计这个网络，还需要把反向传播这个过程也手搓出来。

**例子**：最经典的一个例子是 2012 年的 **AlexNet**。AlexNet 当年拿到了 **ImageNet** 上的分类冠军，而 Alex 这个人自己用了一年的时间，手搓了整个 AlexNet 的设计以及它的反向传播过程，当时是用 C/C++ 写出来的。这份代码现在在 GitHub 上还能找到。老师提到，这个例子丁老师上课时可能也讲过。

所以如果没有这种帮你自动实现的反向传播过程，你就需要花非常大的力气去做这个求导的过程。这就是第一点：深度学习框架能帮我们完成自动求导。

第二点是封装这些枯燥的操作。实际上 **CUDA** 在 2009 年就已经出来了，也就是说 CUDA 比深度学习框架要更早出现。但在这个框架之前，比方说我们要用 CUDA 的话，就需要用 C 语言去手动申请显存，然后还要把数据从 CPU 搬到 GPU，然后才能去计算——这可能是一个非常复杂的过程。

第三点是模块标准化。也就是说，有了像 PyTorch、**TensorFlow** 这样的框架之后，你去声明一个卷积、生成一个全连接、或者去定义一个多头注意力，都直接可以调用类或者包去实现，会更加标准化，比起自己手写要更加简洁。

> **老师总结**：深度学习框架的价值就落在这三点上——反向传播不用人自己手搓、底层繁琐的 CUDA 操作被封装起来、常用模块被标准化。

## 七、PyTorch 的训练流程：从数据到训练循环 [00:58:41–01:27:31]

### 7.1 PyTorch 与 TensorFlow 的代码风格对比

前面已经说明了为什么需要深度学习框架，接下来老师把 PyTorch 和 TensorFlow 这两套主流框架的代码左右对照：左边是 PyTorch 的风格，右边是 TensorFlow 的风格，按参数初始化、网络定义、优化器与训练这几个环节逐段对照，让大家看清楚两者的风格差别。

在参数初始化这一块，两套框架的写法基本上没有太大的区别。

差别首先出现在网络框架的定义方式上。PyTorch 的风格是：对一个网络定义一个类，就像写一个普通的 Python 类一样，用一个 `class` 把它包起来，比如示例里这个叫 `SimpleNet` 的类。这个类里包含两个主要部分。第一个部分是初始化函数 `__init__`，在这里面定义具体的一些网络模型结构，比如这个网络是什么类型、一共有多少层、每一层有多少参数等等。第二个部分是 `forward` 函数，它主要包含前向传播的过程。

TensorFlow 这边就不一样了。老师对比的是 TensorFlow 2.0 版本，它主要是用一行代码就可以直接声明整个模型，而且这一行代码不仅声明，还把这个模型给实例化了。这就是 TensorFlow 的风格。

第二个对比点是优化器和训练的写法，两者的差别也是类似的。对 PyTorch 来说，在定义好模型之后，需要首先实例化这个模型，然后把它转移到 CUDA 上，也就是把模型搬到显卡；接下来还需要人为地定义优化器，这个优化器里包含你选择什么优化器、选择什么样的学习率，以及你要根据自己的具体 task 去调你的损失函数。而 TensorFlow 那边同样是一行代码直接解决，这一行里面包含了损失函数，甚至把 metric 都给定义好了。

训练过程上的差别更明显。在训练过程中，常规的 PyTorch 风格主要也包含很多很多具体的步骤：首先你要有对应的输入 $x$ 和标签 $y$，比如这个 $x$ 可能是一张图，这个 $y$ 可能是这张图对应的分类标签（就比方说分类任务）；然后你做前向传播，前向传播有了预测结果之后，你去计算损失；计算损失之后，你可能需要去清空梯度、做反向传播，计算每一个位置传播过来的梯度；最后你去执行梯度的更新过程。而 TensorFlow 的风格还是一行，就是 `model.fit`。

到这儿为止，大家可能会觉得 TensorFlow 会更加简洁一点。老师的评价是：PyTorch 其实也不冗长，它只是把这整个过程弄得更加具体化了。

### 7.2 为什么 PyTorch 成为主流

那么为什么 PyTorch 成为了主流呢？老师从几个方面来讲。

第一个方面是它可调试。像刚才这些 PyTorch 的代码，可以直接用 PDB（Python Debugger）以打断点的方式来做调试。老师还提到，之后会讲到 PyTorch 可以让人做可控训练。这里有一个很自然的问题：看训练那一段代码，前向传播、计算损失之后，剩下的清空梯度、反向传播、更新参数这些步骤，完全可以让 PyTorch 自己去执行，为什么人还要把它们一行行写出来？老师解释说这里有一个现实层面的原因。

**例子**：假设你的显卡只支持把 batch size 开到 16，但是这个任务可能要看到 64 的 batch size 才会有最优的效果。这个时候你可以累积四次，也就是做四次的累积，然后再更新一次参数。这样你就用只能支持 16 batch size 的显卡，做到了能够支持 64 batch size 的这个任务。

老师把这个做法叫作 accumulation，也就是**梯度累积**（gradient accumulation）：把多个小 batch 的梯度先攒起来，再统一更新一次参数。老师还提醒，我们最后的实践中也会遇到这类困扰，所以要专门讲一下，这就叫可控训练。而 TensorFlow 那边就是一行 `model.fit`，非常封装化，这些中间步骤都收在封装内部。

另一个方面是版本迭代。PyTorch 历经很多代版本——老师说自己也不太清楚它现在到底是多少代——但总归来说，它整个 `nn.Module` 这一套结构其实是一直没有发生变化的。而 TensorFlow 的 1.0 和 2.0 版本差别非常大：它的 1.0 版本非常复杂，2.0 又非常简洁，所以它的版本迁移就很困难。

基于这些原因，目前我们绝大多数的工作、大家看到的这些主流工作，它开放的模型权重、开放的模型代码、训练代码、推理代码基本上都是基于 PyTorch 的。这也是我们今天为什么要用 PyTorch 来作为讲解的一个原因。

### 7.3 训练流程的四个步骤

框架选好之后，老师给出 PyTorch 的一个基本流程。这个基本流程主要分成四个步骤，而且这几步对不同的框架也都是类似的：

1. 数据预处理与数据加载：不管什么任务、不管什么模态的数据，都首先需要进行数据的预处理，把它转换成 PyTorch 能够接受的数据格式，也就是 tensor；
2. 搭建网络，也就是设计你自己的网络；
3. 选好优化器与超参：用什么优化器、什么学习率、什么**批大小**（batch size）、什么损失函数等等；
4. 开始执行模型的训练。

第一步的预处理是不挑任务的。不论你是什么任务，输入可以是图像，可以是视频，可以是音频，也可以是文本等等，你都需要首先把它处理成 PyTorch 能够接受的数据格式，这一步就叫数据加载。

数据加载之后，第二步可能会执行数据的增强。老师讲的动机是：数据的标注、数据的获取实际上是一个很累的过程，所以怎样用有限的数据去做到更大的效果、让它实现更强大的功能，很多时候我们会用**数据增强**（data augmentation）的方式。

**例子**：一张图可以给它加噪，给它旋转，给它翻转，给它裁剪等等，这样一张图就变成了好像变出了 4 到 5 张不同的图像。这就是数据增强的一个功能，同时也可以让模型训出来更加泛化。

在这之后，会有几个最基本的、也是最重要的一些数据格式转换。比如大家之后会用到 PyTorch 里面的 `ToTensor`，这一步其实就是把数据的类型——不论你原来是什么类型——都转换成 tensor，转换成 tensor 的格式。然后你可能还会做一些标准化的操作，比如减去一个均值、除以一个标准差，给它做一个 `Normalize`，做数据的标准化等等。这里说的标准化还包括除以 255 的这个归一化，实际上这个归一化的操作已经集成在 `ToTensor` 里面了，这都是一些细节。

数据预处理完之后，我们需要去做 `DataLoader` 的批次化打包。老师在这里停下来问了一个问题：为什么我们在深度学习的训练中需要 batch 这个东西？这个东西大家肯定都非常熟悉，但是有没有想过，为什么要开一个 batch？老师给了两个主要原因。

第一个原因是效率。GPU 最厉害的一个点在于它能够并行计算，所以如果你每次还是只喂进去一张图、喂进去一个 sample，然后出来一个 prediction 的话，那这个效率其实是跟 CPU 差不多的，效率很低。既然它可以并行运算，那我们肯定要充分利用它。这也是我们为什么喜欢显存更大的显卡——主要也是因为它的计算能力更强。所以第一个原因就是它能够算得更快。

第二个原因是稳定。如果你每次只是一个 sample，或者少了两个 sample、四个 sample，那不同样本之间的这个噪声可能很大，比方说其中可能有一些 bad case、一些 bad sample；如果你的 batch size 开得足够大，这些 bad case 就能够被平滑掉。

> **老师总结**：所以一个是稳定，一个是效率，这就是我们为什么要在 `DataLoader` 加载的时候去打这个 batch。

最后一步，我们会在训练过程中把我们的数据从 CPU 搬到 GPU 上。

第二步是搭建网络。网络刚才已经介绍过，PyTorch 的网络主要是你会定义一个类、定义一个网络，然后你会有一个 `forward` 函数，用这个 `forward` 函数去定义你的网络和它前向传播的基本流程。

常见的 PyTorch 模块，老师在这里举了几个例子：网络层里的线性层 `nn.Linear`、卷积 `nn.Conv2d`，还有多头注意力这一类结构，比如 `nn.MultiheadAttention`，以及注意力机制的其它形式。这些大家都可以直接通过 PyTorch 去做调用。

第三步是优化器。老师说常见的优化器这里就略过了，大家只要记住一点：

> **老师强调**：一般来说，现在都是用 Adam 这种带动量的梯度下降。

损失函数老师则展开讲了一下。这里列了三个不同的损失函数，不同的损失函数对应于、适应于不同的任务。

第一种，比如现在做的是回归任务，或者要做**目标检测**（object detection），那么这个时候一般会用**均方差损失**（mean squared error, MSE loss）。因为它的意思就是说，你的预测坐标跟真实坐标之间还差多少距离，比方说它可能是会用一个 $L_2$ distance 去计算它的一个损失。

第二种，如果是分类任务，一般来说会用**交叉熵损失**（cross-entropy loss）。它表示的是：比方说你要分为十类或者 100 类，那你就会有十个 logit 或者 100 个 logit，你哪个 logit 最大，对应的就是哪个类别。

第三种是从分类迁移过来的、用于分割任务的损失。老师在这里把这条迁移的推理讲了出来。

**推导**：

第一步，分割任务的定义是把一张图逐像素地分割成前景或者背景；

第二步，所以分割任务本身其实也是一种分类任务，只不过它这个分类的类别只有两类，就是前景和背景；

第三步，所以当我们把这个 cross entropy loss 的类别数从 10 或者 100 变成 2 的时候，它就会变成一种新的 loss，专门用于这个分割任务的监督。

当然，分割任务的细粒度也会更深。比方说图像分类任务，它是对于一张图判断出它是什么类别，所以它是 image level 的；而在分割任务里面它是 pixel level 的，这个老师之后也会讲到。

讲完流程，就进入今天的实验。老师说明：我们今天的这个实验主要会以 CIFAR-100 作为基本的数据集。这个数据集大家可能也都很熟悉，它有 6 万张图像，其中有 5 万张训练图像、一万张测试图像；它有 100 个类别，包含生活中所有常见的动植物、生活物品、交通工具等等。

第一步是 `ToTensor`。输入图像一般是 numpy 格式或者 PIL 格式，这两种格式都不能直接拿去做神经网络计算，所以要先把它转成**张量**（Tensor）的格式。

### 7.5 模型、损失函数与优化器

数据预处理到这里就完成了，接下来开始定义模型。因为这是一个分类任务，老师就简单地定义了一个 `SimpleCNN`——一个简单的**卷积神经网络**（Convolutional Neural Network, CNN）来做分类。

模型其实分成两个核心的模块，都在 `__init__` 函数里定义：

- `self.features`：**特征提取器**（feature extractor），也就是**骨干网络**（backbone）。图像输进去，通过卷积网络把图像的特征提取出来。老师说这个名字随便你取，叫 `self.backbone` 也可以。
- `self.classifier`：**分类头**（classification head）。特征提取出来之后怎么分类？这里一共有 100 类，所以最终一定要得到一个 100 维的输出，也就是 100 个类别的得分。做法是把特征展平到一维——展成一个一维的 tensor——再通过线性层把它变成 100 维。

老师强调这是一个很经典的操作：首先有一个特征提取器（一般以卷积网络为主），把图像特征提取出来；然后通过线性层去做分类。`self.classifier` 虽然名字叫 classifier，其实是由若干个线性层组成的。

`forward` 的过程因此非常简单：

```python
def forward(self, x):
    x = self.features(x)
    logits = self.classifier(x)
    return logits
```

输入图像进去，先经过 `features` 提取特征，再经过 `classifier` 得到分类结果。

**补充说明**：根据本节补充材料《实验1_1_PyTorch用法_CIFAR100.ipynb》的模型定义代码单元，`SimpleCNN` 的 `features` 由三组「`Conv2d`（3→64、64→128、128→256，`kernel_size=3`、`padding=1`）+ `BatchNorm2d` + `ReLU` + `MaxPool2d(2, 2)`」组成，特征图尺寸依次从 32×32 降到 16×16、8×8、4×4；`classifier` 依次是 `Flatten`、`Linear(256×4×4 = 4096 → 512)`、`ReLU`、`Dropout(0.5)`、`Linear(512 → 100)`。老师课堂上没有逐层念这些配置，只说明这是一个「简单的卷积网络」并指出两个核心模块的分工。

模型定义好之后，它还只是一个 Python 的 class，并没有实例化；所以要把它实例化，顺便把结构打印出来：

```python
model = SimpleCNN().to(device)
print(model)
```

到这里就是模型定义的部分。

接下来是损失函数和优化器，这一步比较简单。因为是一个分类任务，所以调用 `nn.CrossEntropyLoss()`，也就是**交叉熵损失**（Cross-Entropy Loss）。

```python
loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
```

优化器用 Adam，学习率设为 `1e-3`，也就是十的负三次方。

### 7.6 训练循环与第一个实验结果

然后定义一个训练函数，开始训练。老师指出，这里的过程跟 PPT 上讲的是完全一样的，一个 iteration 里依次是：

1. 前向传播：`pred = model(X)`；
2. 损失计算：`loss = loss_fn(pred, y)`；
3. 梯度清零：`optimizer.zero_grad()`；
4. 反向传播：`loss.backward()`；
5. 更新参数：`optimizer.step()`。

```python
for batch, (X, y) in enumerate(dataloader):
    X, y = X.to(device), y.to(device)
    pred = model(X)
    loss = loss_fn(pred, y)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

代码里每 100 个 batch 打印一次 loss（`if batch % 100 == 0`），这个打印是老师自己加的。老师说，你也可以把它打印出来，打印出来之后就能看到 loss 是如何慢慢收敛的过程。

**补充说明**：根据本节补充材料《实验1_1_PyTorch用法_CIFAR100.ipynb》的训练与测试代码单元，训练函数开头调用 `model.train()`，并把每个 batch 的 `X`、`y` 用 `.to(device)` 搬到 GPU；每 100 个 batch 把 `loss.item()` 记录进 `loss_history`，训练结束后用 `plt.plot(loss_history)` 画出 loss 曲线。测试函数里调用 `model.eval()`，在 `torch.no_grad()` 下前向，用 `(pred.argmax(1) == y)` 统计预测正确的个数，再除以样本总数得到准确率，同时累加测试损失。这些实现细节老师课堂上只说了「每 100 个 batch 打印 loss」「有个测试函数，直接执行就行」，没有逐行讲。

### 8.2 两个数据增强算子

这个实验的设计原则是控制变量：在第二个 section 里，我们的模型结构等等都没有发生变化，我们就看数据增强本身能不能够给模型的准确率带来一些提升。老师让大家一起跟着操作，先看代码能不能跑通。

代码的开头还是跟之前一样，导入这些基本的库，包括 Python 的库、画图的库（`matplotlib`），以及图像和画图相关的一些库等等。核心内容是预处理这一段：其中第三行、第四行（`ToTensor` 和 `Normalize`）是第一个文件里就有的，在这里我们另外加了两个数据增强的操作。第一个叫 `RandomHorizontalFlip`，从英文意思就可以知道，它表示的是一个随机的水平翻转，也就是把一张图左右转过来，这是第一个数据增强的操作；第二个写的是 `RandomRotation`，括号里写了一个 10。按讲义代码，这段预处理是这样写的（数值取自《实验1_2_数据增强》代码单元 1）：

```
train_transform = Compose([
    RandomHorizontalFlip(),
    RandomRotation(10),
    ToTensor(),
    Normalize((0.5071, 0.4867, 0.4408), (0.2675, 0.2565, 0.2761))
])
```

`RandomRotation(10)` 的意思是：一张图可以在负十度和正十度之间来回进行一个旋转。具体操作的时候，我的每一张图会任意地在 $[-10^\circ, +10^\circ]$ 之间选择任意一个角度——它可以是正三度，可以是负五度，可以是零度，当然也可以是负十度，它会任意选择一个角度。

`RandomHorizontalFlip` 则是默认以 50% 的概率翻转：也就是说 50% 的图像不翻转，50% 的图像翻转。老师点评说，这两个就是非常基础的数据增强操作。

这里有一条重要的使用规则：数据增强只需要对训练集做；对测试集，你不需要做数据增强，你只需要做推理就行了。因为测试集是要看效果的，所以这一步就正常去执行。

后面的设置里，除了预处理之外，这些超参我们都保持不变，batch size 也还是 64。老师接着处理了一个很实际的问题：这个数据集需要改一下路径，改成自己本地的路径才能读到数据。

> **老师强调**：这个路径问题也是一个非常经典的报错问题。大家如果用 Colab 的话，可能路径会有一些不一样的地方，大家也需要注意。

把正确路径调过来（老师现场用的是他自己本地的路径）之后，再把数据集下载、加载一遍。加载好了之后，可以随便取一个 batch，直观地通过图像来看一下数据增强的效果。老师当时把一个 batch（64 张）的图铺成网格展示出来，指着其中几张解释现象；老师也提醒，当然大家在本地的结果肯定也不一样，因为翻转和旋转都是随机的，每次取出来的 batch 都不一样。

**演示**：网格里能明显看到旋转之后的图。原本这些图是正的，现在它们被往逆时针方向旋转了一个比较小的角度，可能是三度或者五度等等；旋转完之后，它剩下的这些地方就用黑边给它补齐——这就是数据增强的一个效果。因此，凡是图里有黑边的，肯定就是刚才这个 `RandomRotation` 旋转完之后，空缺的地方需要用黑边补齐。另外还有一些图是经过翻转之后的；老师拿一张台灯图举例说，它本身可能就是翻转的，水平翻转之后它反而"正过来"了，所以单看一张图并不太容易判断它到底有没有被翻转。老师总结说，这就是数据增强的一些直观的操作。

老师也说明了这次为什么没有加噪：主要是 CIFAR-100 它本身的分辨率就太低了，它本身就是 32 的（$32\times 32$），如果再给它加噪，就真的看不清了，所以在这里就没有加噪。

> **老师提示**：加噪也是一个非常常用的数据增强的 trick，只是在这个数据集上不合适——32×32 的图本身已经够模糊了。

### 8.3 结果对比与数据增强的机制

- 完全一样的数据；
- 完全一样的模型；
- 完全一样的超参、一样的优化器设置；
- 完全一样的 epoch 数量（50）。

| 实验 | 训练集预处理 | 模型 | 训练轮数 | 测试准确率 |
|------|--------------|------|----------|------------|
| 第一个 section（基线） | `ToTensor` + `Normalize` | SimpleCNN（主干 + 线性分类层） | 50 epoch | 45.1% |
| 第二个 section（加数据增强） | 再加 `RandomHorizontalFlip` 与 `RandomRotation(10)` | 同上，未改动 | 50 epoch | 56.2% |

在上述条件下，加了数据增强的这次最终训到了 56.2% 的准确率，相比 45.1%——老师当场口述是"提升了 14 个点"，并强调这个提升是非常猛的。老师说，这就是数据增强带来的效果。

但老师同时提醒大家注意一个细节：它一开始、也就是第一个 epoch，准确率的提升还不是那么明显。原因是数据增强本质上是一种加噪——无论你是旋转也好、翻转也好，它本质上都是一种加噪。所以有噪声的数据，一开始可能学得还不如没有加噪的时候好；但是慢慢地，随着 epoch 的上升，这个模型会变得越来越鲁棒，因为它每次看到的样本都是不一样的。因此在相同的 epoch 之下，它最终会训练得更好。这就是加上数据增强之后的效果。

## 九、网络结构优化：残差连接与 ResNet-56 [01:53:16–02:11:29]

### 9.1 残差连接的动机与结构

第三个实验做的是**网络结构优化**，具体说就是**残差网络**（residual network）。老师说残差这个东西大家应该都听说过，但还是要从头讲一遍，因为"最开始残差为什么要加，这个目的其实非常简单、非常直接"。

动机这一句话就能说完：当网络不断加深，输入信号要一层一层往后传，中间经过的层数太多，就会"发生一些不太好的情况"——网络可能已经忘记这个输入本身是什么了。也就是说，后面那些层在拟合的，是一个已经被反复变换、原始信息被稀释掉的表示；越深，越容易丢掉最开始的输入长什么样。

所以残差的做法是：在主干之外再开一条**捷径连接**（shortcut connection），把进入网络之前的那个输入原样保留一份，最后和主干算出来的结果加在一起。这样哪怕主干把信息加工得面目全非，原始输入仍然有一条直接的通路能到达后面的层。

> **老师比喻**：加 shortcut 就是让网络"不忘初心"——它可能已经忘记输入本身是什么了，那就把输入直接再送一路进来，让它记起来。

这个"不忘初心"是老师对残差最形象的说法，也是后面所有结构细节的出发点：残差不是加了一个新模块，而是给信息加了一条不经过变换的通路。

接下来是结构。一个**残差块**（residual block）由三部分组成。老师用了"主干"和"旁枝"这对词来描述：输入先过一条主干网络（"你可以去过一个主干的网络"），同时另有一条旁枝，也就是 shortcut，"我会把在进网络之前那个输入直接拿过来"，然后把两路结果做一个相加。

这个相加不是拼接、不是相乘，而是**逐元素相加**（element-wise addition）：两个形状相同的张量，对应位置的元素各自相加。设输入为 $x$，主干（老师写作 $\mathcal{F}$，即若干卷积、归一化、激活的组合）的输出为 $\mathcal{F}(x)$，则残差块的输出为

$$
y = \mathcal{F}(x) + x .
$$

若旁枝上还带了变换（例如一个 $1\times 1$ 卷积 $\mathcal{W}_s$，用来把通道数对齐），则写为

$$
y = \mathrm{ReLU}\big(\mathcal{F}(x) + \mathcal{W}_s x\big),
$$

其中 $\mathrm{ReLU}$ 是在相加之后统一做的一次激活。老师特别指出，真正的实现里"相加之后再去过一些操作"，也就是说相加只是块的中间一步，后面还有激活和池化，不是块的终点。

主干内部到底是什么网络，老师明确说"你可以随便定义"：可以是 RNN，可以是 attention，可以是 convolution，都可以。也就是说，残差只是一种**连接方式**，它与"用什么层"是正交的两件事——这一点在后面看代码时会再次体现：ResNet-56 那样的标准实现，主干是两层 $3\times3$ 卷积加**批归一化**（batch normalization, BN），而我们自己写的 ResidualCNN，主干就只有一层卷积加一个 BN。

旁枝也不一定非得是"直接拿过来"。老师提醒，可以在旁枝上"做一些小型的卷积操作"，让旁枝承担一点变换，只要两路最后能逐元素相加即可。他自己在实验代码里就是这么做的：三个残差块的旁枝各放了一个 $1\times1$ 卷积，一方面做通道数的变换，另一方面把残差的"备份"变成一个可学习的小映射。

对这套思路，老师的评价是"总归这个思路是很有效的"，"它能够解决一些**梯度爆炸**（gradient explosion）的一些问题"。shortcut 的价值正在这里：它给梯度留了一条不必穿过所有层就能回传的通路，深层网络因此更容易训练。

### 9.2 残差版实验与结果

结构讲完就进入实验。老师先交代了实验设计：第三个实验是跟第一个实验做对比的，所以为了控制变量，实验 1.3 里**也不加数据增强**的操作，保持与实验 1.1 完全一致。这样两次实验唯一的差别就是网络结构——1.1 是普通的 SimpleCNN，1.3 是加了残差的 CNN。换句话说，数据增强的效果由实验 1.2 单独回答，结构的效果由实验 1.3 单独回答，两者不混在一起。

代码流程跟前面完全一样：先导入库，确认计算设备（GPU 走 CUDA），然后准备 transform。老师强调这里的 transform 只有 `ToTensor` 的转换和 `Normalize` 的操作，"并没有包括我们的数据增强一些操作"，目的是跟实验 1.1 保持一致。接着加载训练集和测试集，**批大小**（batch size）仍然设为 $64$。

模型定义这部分，老师给了一个很实用的读代码建议：先不用看上面的类定义，"上面这个可能比较复杂"，可以直接通过 `def forward`（前向传播函数）来获得直观认识。因为 `forward` 就是数据实际走过的路径，残差加在哪一步，看 `forward` 里哪一行出现了加号就一目了然。

老师的问题是"它具体在什么地方做残差呢"，然后带着大家把这个过程走了四步。

**推导**：

第一步，输入 $x$ 进来，先生成一个"残差"：旁枝上的 $1\times1$ 卷积把 $x$ 变成 identity，即 $\mathrm{id} = \mathrm{Conv}_{1\times1}(x)$。老师强调这一步"简单过了一个小型的卷积网络"，目的就是产生 identity。

第二步，identity 送进主干：先做 $3\times3$ 卷积，再过一次 BN，得到 $\mathrm{out} = \mathrm{BN}\big(\mathrm{Conv}_{3\times3}(\mathrm{id})\big)$。这是"主路"的输出，此时它已经不再包含原始的 $x$。

第三步，另一条路上把 identity 原样取过来——"没有做任何的就……他没有经过逐步的卷积操作"——与主路输出逐元素相加，再过 ReLU：$\mathrm{ReLU}(\mathrm{out} + \mathrm{id})$。加号所在的那一行，就是残差真正起作用的地方。

第四步，相加并激活之后，再做一次 $2\times2$ 最大池化把特征图降采样，得到这个残差块的输出，作为下一个残差块的输入。

把四步合起来，一个残差块的计算为

$$
x' = \mathrm{MaxPool}\Big(\mathrm{ReLU}\big(\mathrm{BN}(\mathrm{Conv}_{3\times3}(\mathrm{Conv}_{1\times1}(x))) + \mathrm{Conv}_{1\times1}(x)\big)\Big),
$$

整个网络把这样的块串三个，最后接分类器输出 $100$ 类的 logits。

与实验 1.1 对比，差别就非常清楚了。老师说在 1.1 里"就没有这个加 identity 的这一个"，1.1 的网络结构就是"过卷积、过卷积、过卷积……"一路卷积接卷积地往下走，类似于把上面第二步直接重复很多遍。到了 1.3，会在做完第一次卷积之后把结果保留下来——老师打了个比方，说是"做了一次备份"——再把这个备份拿到 `forward` 里做相加的那一行（老师说的是"第三行"）去用。这就是两个实验在网络结构上的全部区别：多了一条备份通路，多了一个加号。

**补充说明**：根据本节补充材料《实验1_3_网络结构优化.ipynb》第 2 个代码单元（`ResidualCNN` 的定义与其打印输出），三个残差块的具体配置如下；这些通道数与卷积核尺寸老师在课堂上没有逐个念出，但与他讲的"旁枝生成残差、主路做卷积加 BN、相加后池化"完全对应。

| 残差块 | 旁枝（产生 identity） | 主干 | 相加之后 |
|--------|----------------------|------|----------|
| 第 1 块 | `Conv2d(3→64, kernel=1×1)` | `Conv2d(64→64, kernel=3×3, padding=1)` + `BatchNorm2d(64)` | `ReLU(out + identity)`，再 `MaxPool2d(2, 2)` |
| 第 2 块 | `Conv2d(64→128, kernel=1×1)` | `Conv2d(128→128, kernel=3×3, padding=1)` + `BatchNorm2d(128)` | 同上 |
| 第 3 块 | `Conv2d(128→256, kernel=1×1)` | `Conv2d(256→256, kernel=3×3, padding=1)` + `BatchNorm2d(256)` | 同上 |

分类器为 `Flatten` → `Linear(4096→512)` → `ReLU` → `Dropout(0.5)` → `Linear(512→100)`；其中 $4096 = 256\times 4\times 4$，是三次 $2\times2$ 最大池化把 $32\times32$ 的输入降到 $4\times4$ 之后、$256$ 个通道展开的结果（同上）。

把模型打印出来看结构时，老师说"其实跟刚才是很类似的，只不过这次可能多了一个 shortcut"。结构打印出来之后，就直接执行训练代码和测试代码，和前面几次实验一样，大家可以去跑一下。

老师给出的结果是他上周跑出来的。在相同的设定之下，加了残差的版本最终**测试准确率**（test accuracy）到了 $46\%$ 和 $45.9\%$，而实验 1.1 是 $45.2\%$——"其实跟 1-1 的 45.2 并没有什么太大的区别"，"它就涨了不到一个点"。

这个结果本身就很值得追问，老师随后提出了两个思考问题。

第一个问题：模型加了残差之后，"它肯定是模型会变得更好"，那为什么最终的结果并没有明显提升？

第二个问题：上面看的是最终结果，如果看训练最初几轮的曲线，情况正好相反——"在最初这个 epoch，他其实是要比 1-1 要明显收敛更快的"，老师说的范围是第一个到第五个 epoch。老师把实验 1.1 的记录调出来做对比，具体数据是：实验 1.1 的前三个**训练轮次**（epoch）分别是 $16$、$24$、$28$；加了残差之后，第一个 epoch 就直接到 $22$，第二个到 $30$，第三个到 $35$。

| 训练进程 | 实验 1.1（SimpleCNN） | 实验 1.3（加残差） |
|----------|-----------------------|--------------------|
| 第 1 个 epoch | 16 | 22 |
| 第 2 个 epoch | 24 | 30 |
| 第 3 个 epoch | 28 | 35 |
| 最终测试准确率 | 45.2 | 46 / 45.9 |

**补充说明**：根据本节补充材料《实验1_3_网络结构优化.ipynb》第 4 个代码单元的训练输出，实验 1.3 前三个 epoch 的测试准确率精确值为 $22.1\%$、$30.1\%$、$35.3\%$，与老师口述的 $22$、$30$、$35$ 吻合；材料中未包含实验 1.1 的运行输出，故表中 1.1 一列全部按课堂口述记录（同上）。

老师对这个现象的解释是："由于他网络的能力更强，他学的明显要更快。"前三轮 epoch 就能拉开这么大的差距，说明残差确实让网络在同样步数里学到了更多，**收敛**（convergence）速度的提升是实打实的。

但两个问题合在一起就有一个矛盾：既然学得更快、能力更强，"为什么他最终还是没有能够更进一步"，最终仍然收敛在 $46$、$45$ 这个水平，并没有产生像前面数据增强那样的提升幅度？

老师的答案很干脆：问题不在残差，而在网络本身太浅。"这个其实主要是因为这个网络确实没有问题的"——残差这一套连接方式没有用错——"主要是因为它这个网络的层数还是不够深，它还是一个非常简单的一个网络"。

这里的逻辑值得说明白：残差解决的是深网络的训练问题，它给的是训练上的便利；网络本身很浅时，这个便利的施展空间有限，容量上限摆在那里，于是残差带来的就只是收敛更快，而不是最终精度更高。

> **老师强调**：这个网络本身没有问题，主要还是因为它这个网络的层数还是不够深。

所以老师给出的下一步非常明确：把网络的参数规模加深，加深完之后重新训练，"你可以看到它会产生一些明显的变化"。他还顺带给了一个工具层面的建议：这个时候可以用 Codex，或者用 GPT 去写代码，把网络加深。

### 9.3 层数计数与 ResNet-56

为了让大家看到"加深"到底有多大的差别，老师没有再让大家自己训一个深网络，而是直接调用一个预训练好的 ResNet-56。他说 ResNet-56 是一个很大的模型，所以不要求大家现场训练，在这里直接调用它**预训练**（pretraining）好的权重。这份权重是在 CIFAR-100 上预训练好的，老师也让大家自己去下载这份权重，加载好之后就可以直接做测试。

老师先带大家数了一下刚才自建网络的层数，因为这个数法正是理解 ResNet-32、ResNet-56 这些名字的关键。

**推导**：

第一步，数卷积层。三个残差块里，每个块有一个旁枝的 $1\times1$ 卷积和一个主干的 $3\times3$ 卷积，老师一边看结构一边数"一个、两个、三个、四个、五个、六个，一共就六个卷积层"，即 $3\times 2 = 6$。

第二步，数最后的分类器。分类器里有两个线性层，老师说的"再加上 1、2"就是指这两个线性层。

第三步，把带权重的层合起来计数：$6 + 2 = 8$。所以"如果按照专业的说法来说的话，它应该叫做 ResNet-8"。

第四步，确认 BN 不计入层数。BN 层本身也是带参数的（有可学习的缩放与平移），"不过这个它不算作一层"，所以上面只数卷积和线性层。

这就是 ResNet 系列命名的规则：名字里的数字表示网络中**带权重的层数**，也就是卷积层加上最后的线性层。老师举了大家可能听过的例子——ResNet-32、ResNet-56，"32 和 56 它表示什么意思呢？它表示的是在这个网络中有 32 个卷积层加上线性层"。

不过老师紧接着自己纠正了这个说法："这个现在写的不是很对，这个并不是很严谨。"原因就是上面第四步：BN 也带权重却不算层，所以"多少个卷积层加上线性层"这种顺口的说法并不精确，按第四步的说法，更严谨的表述应当是"带权重层的总数，BN 除外"。这段自我纠正很值得留意——它说明命名规则里唯一稳定的判据是"带权重的层、且 BN 除外"，而不是死记"卷积层数"。

ResNet-56 到底有多大？老师没有报参数量，而是用了一个更直观的办法：把打印出来的模型结构打开，往下滑，"你可以感受一下它一共有多少行呢？"——"一共有 210 行"。

然后他把刚才自己设计的那个小残差网络也打开来对比。小网络"只有这么点"，"这么加起来可能一共也就二十行"，而 ResNet-56 那边是 $210$ 行。$210$ 行对约 $20$ 行，差了十倍以上，这就是"加深"在结构上的直观体现。

> **老师总结**：这个 scale 上去之后、这个网络的规模上去之后，它确实还是能够对模型起到很强的一个作用。

### 9.4 模型规模带来的提升

接着是验证。老师这次不训练了，直接加载预训练权重去做测试。结果测试准确率提升到 $72.6\%$，相对前面 $45\%$ 左右的水平，"可以有一个质的提升"。

同一个模型下，老师又拿之前那张图做了测试——就是前面实验里被错认成骆驼的那张。

**例子**：在 $72.6\%$ 这个准确率水平下，那张图能够被正确预测了：模型知道它是一个海豹，而不再把它当成骆驼。同一张图、同一个数据集，仅仅换了网络的规模与权重，预测就从错误变成正确。

**补充说明**：根据本节补充材料《实验1_3_网络结构优化.ipynb》第 10 个代码单元，该样本取自 CIFAR-100 测试集，类别表中"海豹"与"骆驼"都是这 $100$ 类之一，预测输出为"海豹"、真实标签为"海豹"；第 9 个代码单元的测试输出给出准确率 $72.6\%$、平均损失 $1.294776$。老师课堂上把 $72.6\%$ 口述为 $72\%$（同上）。

### 10.1 超参数的 trade-off

实验 1-4 要换一个数据集，换成 FashionMNIST。在讲这个数据集之前，助教先把前面没有动过的一类东西补上：前面调的是数据增强，也调了网络结构，但还有一批超参数没有调，包括批大小（batch size）、轮数（epoch）和学习率（learning rate）。这些量该取多少，需要大家在课下自己动手实践，课堂上他只放几条基本结论。

他反复强调，这类操作本质上全都是一种 trade-off：必须找到一个合适的值，肯定不能太大，也不能太小。

先看 batch size。batch size 太小，一个 batch 里的样本噪声就会被放大：某些训练样本本身就是 bad case，这些 bad case 的影响可能很强，结果把本来训练得挺好的模型给带坏了。

但 batch size 也不能太大。假设只有 5 万个训练样本，把 batch size 开到 1 万，那么在一个 epoch 的训练里参数只能更新 5 次；哪怕每次见到的样本很多，也没有办法学得很好。所以这个量既不能太小，也不能太大，得维持在一个比较合适的数值上。

比较合适的取值：对于这两次的分类任务，64 左右就是合适的值；换成最后要做的语义分割（semantic segmentation）和目标检测（object detection），取值还会不同；而对于一般简单的分类任务，64 到 32 这样的数值会比较好。

换了不同的 batch size 之后，影响其实还是蛮大的。助教刚才一直用 64，因为在他的实验里它是最优的，能够达到 46% 左右的准确率；如果 batch size 只开 32，不论别的怎么选，都只有 36% 左右，一下就降了十个点。所以这个超参也是比较敏感的。

轮数（epoch）比较好理解：如果训练得不够多、训练得不够长，就会欠拟合（underfitting），模型还没有学习到位；如果训得太多，就会过拟合（overfitting），曲线上会出现一些抖动。

学习率则要看模型本身。现在大家如果去微调（fine-tuning）大模型，学习率通常都比较小，一开始可能只有 $10^{-5}$、$10^{-6}$ 这样的量级；比如分割任务里微调 SAM 2，它的默认学习率就是 $10^{-6}$。但对于简单的小模型，比如这节课的这个 simple CNN，$10^{-3}$ 左右才是最合适的数值。所以要根据模型的大小和参数量去选择合适的学习率，不能把大模型的设置直接照搬过来。

他强调，学习率必须跟着模型的大小和参数量走，不能拿大模型的设置来套小模型。

在 simple CNN 上这个现象很直观：把学习率调成 SAM 那样的 $10^{-6}$，它什么都学不到，准确率只有 13% 左右；反过来，如果把学习率调得很大，它可能一步就跨过了最优点，损失出现一个骤降，更加什么都学不到，最后退到 1% 左右——而 1% 正是最标准的盲猜，因为 CIFAR-100 有 100 类，100 类瞎猜就应该是 1% 的准确率。所以在本任务里，实际上是 $10^{-3}$ 到 $10^{-4}$ 是比较合适的学习率。

把上面几条结论汇总起来：

| 超参数 | 取得太小 | 取得太大 | 本任务中的合适值 |
|--------|----------|----------|------------------|
| batch size | 单批样本噪声被放大，个别 bad case 就能把好模型带坏 | 一个 epoch 内参数更新次数太少，见到的样本再多也学不好 | 64 左右（一般简单分类 64 到 32） |
| epoch | 欠拟合，没有学习到位 | 过拟合，曲线出现抖动 | 助教的 baseline 用 40 个 epoch |
| learning rate | 几乎学不到东西（$10^{-6}$ 量级只剩 13% 左右） | 一步跨过最优，损失骤降，退到 1% 的盲猜水平 | $10^{-3}$ 到 $10^{-4}$ |

### 10.2 FashionMNIST 与 CIFAR-100 的差别
