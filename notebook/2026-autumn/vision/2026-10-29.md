## 一、课程回顾与目标检测任务 [00:02:54–00:20:01]

上课前老师提醒同学取出话筒、确认设备连接，随后宣布开始上课。这节课的任务是把前面讲过的基础收束起来，正式进入目标检测（Object Detection）这个方向。

### 1.1 课程回顾与三大基础任务

前面几次课相当于把这门课要用到的基础过了一遍：神经网络、卷积神经网络（Convolutional Neural Network, CNN）、Transformer 这些。中间还安排了两次 PyTorch 的实战课，练了一下 Python 的主要代码。

老师随后回顾了一个更大的背景：AI 这个领域在之前其实一直是由计算机视觉（Computer Vision, CV）的贡献去牵引着大力发展的。很多神经网络的爆发，或者说它整个的设计、它的一些思想，早期都是由计算机视觉去牵引的；直到后来 NLP 那边出了 Transformer 之后，两边才开始往统一的方向收敛。

进入深度学习（deep learning）时代之后，早期计算机视觉的发展在网络设计上基本上有三个最 basic 的 task 在驱动：

1. **图像分类**（Image Classification）：给很多张图片，让模型告诉你这张图片是 1000 个类别中的哪一个。这是我们之前一直学的，也是上节课去练习的图像分类网络那一类任务。
2. **目标检测**（Object Detection）：要找到图像里的物体，并且用一个边界框（Bounding Box）把这个物体圈出来，说明它到底在哪里。老师用一句很直白的话对比了这两件事：分类只需要告诉你这张图是猫是狗，至于这个猫和狗在哪里，"I don't care"，不用关心。
3. **分割**（Segmentation）：做更 pixel-level 的识别。分类是 image-level 的——整张图是一个什么东西；分割需要知道每一个像素属于哪一个类别，对每个像素去做识别。

> **老师强调**：很多人认为计算机视觉就等于分类加检测加分割，这肯定是不对的。

这三类任务只是当时 CV 里最 basic 的三个核心技术任务。之所以由它们来驱动，是因为其他很多任务都跟这三类任务有关系——它们构成了其他很多任务的基础，其他任务是由此延伸发展出来的。而且在那些年深度学习、卷积神经网络快速发展的过程中，这三类任务极大地推动了整个深度学习和 AI 的工具发展，以及网络的设计概念。

计算机视觉涵盖的范围其实非常广：哪怕现在的多模态、多模态大模型里面跟视觉相关的生成之类，其实也属于 CV 的范畴。这周和下周，课程就进入 object detection 目标检测模型。

### 1.2 为什么要学这些"不带 Transformer"的检测模型

老师专门说明了为什么要学目标检测模型。这周要讲的很多模型跟 Transformer 没有关系，都不是基于 Transformer 的；下节课才会学一个基于 Transformer 的 object detection。

老师给了两条理由。

第一条是这些方法本身的价值。前面那个 CNN 还是比较简单的，是 end-to-end 的：输入一张图，输出一个 label 就行了。但 detection 不一样，它涉及输出很多个 bounding box，这时就会有问题——你是不能够直接把 bounding box 预测出来的。正是在这个设计过程中，涌现了很多非常好的思想，这些思想需要去体会。

第二条是工业界的现状。这节课讲的这些跟之前的一些 CV 方法不一样，比如 SIFT 现在真的很少用了；但这节课讲的这些，是目前主流市面上的一些设备——凡是涉及 object detection 的产品——背后基本上还是这节课讲的这些方法在做技术支撑。基于 Transformer 的反而未必用得上，因为它比较慢、比较耗算力；到了端侧，也就是移动端、手机、摄像头这类算力有限的情况下，用这节课的这些方法反而更快、更常见、更轻松。

### 1.3 目标检测的定义：分类、定位与检测的递进

这节课的组织跟以往一样，先回顾传统的方法，也就是在 deep learning 之前、在 CNN 之前大家是怎么做目标检测的；在 deep learning 之后，也就是那一轮爆发之后，object detection 的方法主要分为两阶段的目标检测和一阶段的目标检测。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 2 页的目录，本讲三部分依次是"传统目标检测""两阶段目标检测""一阶段目标检测"，与老师口述的顺序一致。

要解释什么叫目标检测，老师用了三张图，说明这是一个逐步递进的过程。

第一层是分类。给一张图，直接告诉它 label 是什么，是 cat 就输出一个 cat 就行。你把这张图揉成什么样、这个 cat 在哪里，我无所谓；分类完把原图扔掉都可以。

第二层是分类加定位（Classification + Localization）。这时需要定位，也就是要把这个 cat 框出来；在分类的基础上，要求你不只要把 cat 分类出来，还要把它定位出来。

第三层才是目标检测。

**定义**：目标检测要求在图像中找出感兴趣的目标，既给出每个目标的类别，又用边界框给出每个目标的位置；与只输出一个类别的图像分类相比，它多了定位，而且通常要同时输出多个目标各自的框与类别。

它其实是 classification 加 localization 的组合，但它跟前面不一样：之前 ImageNet 比赛的时候，选的图大部分图里面是一个主体，相当于单人拍照，拍的都是单人照；但日常生活中图片里肯定是有多个 object 的。比如那样一张图，我们要做 object detection，就需要 output 多个 bounding box——每一个 object 都要给它画出一个框来。图里两个 cat、一个 dog、还有一个 duck，都要把对应的框画出来；而且这个框对应的是哪一个类别也要标出来：红框是 cat、蓝框是 dog、绿框是 duck。这就是检测要做的事情。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 4 页，目标检测（Object Detection）的任务是找出图像中所有感兴趣的目标（物体），确定它们的类别和位置，是计算机视觉领域的核心问题之一；由于各类物体有不同的外观、形状和姿态，加上成像时光照、遮挡等因素的干扰，目标检测一直是计算机视觉领域最具有挑战性的问题。该页是对上面"分类＋定位、并且要处理多个目标"这一口述定义的正式表述，其中"光照、遮挡等干扰"一层课堂上未展开，此处按材料补全，补全的是 1.3 的目标检测定义。

### 1.4 检测难在哪：分类是简单映射，框却要预测

讲完定义，老师在这里停下来，让同学自己想一个问题：这件事为什么难？难在哪里？为什么后面要涌现出那么多的设计？

先看分类为什么不难。像 ImageNet 分类，最终只是需要一个 label：之前的 CNN 设计，最后经过全连接层（Fully Connected Layer, FC）之后，从一个 feature（比如 2048 维）映射成 1000 类，这是一个天然的、简单的映射；然后挑出概率最大的那个，输出它的类别就行了。用符号写就是 2048 维的特征向量经过一次映射得到 1000 个类别的得分，取最大者作为输出类别。

但 object detection 里面需要给出一个框。这个框要怎么输出？怎么预测出这样的一个 bounding box 出来？老师提醒，四个坐标就可以表示它——这就是上次给大家提过的：左上、右下，其实是两个点、四个数字。于是一个框就可以写成 $\mathbf{b}=(x_1,y_1,x_2,y_2)$，其中 $(x_1,y_1)$ 是左上角坐标、$(x_2,y_2)$ 是右下角坐标。问题随之变成：用左上、右下这四个数去做预测，基于我们之前学的 CNN，你怎么预测它？

为了把问题问清楚，老师把任务简化了：他不再用那张多物体的图，换一张只有单个物体的图，并且假设"给你们的一个任务，所有的图里面都一样，只有一个物体，希望你们把这个物体的 bounding box 预测出来"。要求同学在没有接触任何目标检测方案设计之前，先自己想想怎么把这个 box 预测出来。

### 1.5 单目标情形的课堂设计：一个并行的回归头

**课堂问答**：老师把问题抛给全班——在没有接触任何目标检测方案设计之前，想一下怎么把这个 box 预测出来。课堂上给出的思路是"两个并行的 head"。老师先追问了一句：虽然 output channel 等于 4，那你那你不还得给他分类吗？随后评价"这个其实是一个很好的一个设计思路"，并把这位同学讲的复述了一遍。字幕只记录了这段对话的片段，学生的完整表述未记录。

老师的复述是这样的。我们不是有一个 feature 吗？比如说是一个 2048 维的 feature，老师用一根线来表示它。原先做分类的时候，直接把它映射成 1000 个类别，假设我们有 1000 类，就从这 1000 个里面挑个最大的——取 max，得到比如说 cat 这个类别。

现在想同时预测它的 box，怎么办呢？做一个并行的 head，复用一下这个 feature：这个 2048 维的 feature，我们又没说它表示什么，它完全可以被复用。给它预测 4 个 channel，也就是左上、右下这四个数字坐标。这四个数字预测出来，是不是直接就能画出一个 bounding box？

这样安排下来，我们既有了 class 类别，又有了 box。老师用一句"明白了吧"确认了这条思路，随后把问题推进到下一层：那这张图怎么办？

### 1.6 从 1 个到 2 个：难度陡增与类别-框对应问题

多目标带来的第一个困难，是数量和位置的未知。刚才只有一个物体，很简单；到这张图怎么办？你不知道它有几个物体，你也不知道它在哪里。

老师给了一点时间让大家思考，同时插了一段话：

> **老师提示**：要自己思考，尤其在这个 AI 时代，ChatGPT 都这么强了，你们现在要自己学着敲代码，这个回头肯定比不过人家的；所以一定要在这四年过程中加深自己思考问题的能力，要主动去培养这方面能力。

思考之后会发现，难度陡增了：直接照搬单目标那套做法似乎解决不了。把多目标的图放进这个结构里，拿两组输出去套也不行——我也不知道这 2048 维的 feature 到底对应哪一个 object、它在哪里。

于是老师把难度再降一档，给出一个简化设定：已知图里面有两个 object，每张图用来做 object detection 都有两个 object；不上升那么大难度，就是有两只猫（两个 object 也不一定是猫和别的东西）。这样能解决吗？就两个，我就加一个、加一组输出——现在能解决吗？

> **老师强调**：这个问题很值得想。只有你们想一下这个，才能体会到后面别人设计的那些方法为什么是这样。我们不着急推进后面，因为后面那些东西更重要的是思想。

正式一点的设定是这样的：假设收集了一个非常特殊的数据集（Dataset），每个里面都有两个物体，但是两个物体在哪里不知道、什么类别也不知道；就让你们做这个 object detection，现在已经有 CNN、进入 CNN 时代了，怎么设计？原来那套做法是不是也用不了。

跟着这个思路往下想，最简单的做法是让它直接预测出两个：既然你已经告诉我有两个了，那我就 top-1、top-2 输出，是不是相当于出了两个类别？分类这一半好像有办法了。

但 object detection 这一半怎么办？比如现在不是预测一组四个数，我们预测两组——四个就有八个 channel：第一组四个数出来一个 bounding box，第二组是不是也能出一个 bounding box？

到这里立刻碰上另一个问题：你这两个类别和这两个 bounding box 怎么对应？是不是你对应不上。

> **老师总结**：有没有发现，只是把 object 从一个增加到 2 个之后，object detection 的难度就陡增了。更别说 3 个、4 个、10 个、100 个。

### 1.7 上节课埋下的伏笔：2020 年 ECCV 那篇论文

在把问题摆清楚之后，老师补了一段与本问题直接相关的回顾。上节课讲 CNN 的时候说过，有一个做 object detection 的工作把 CV 这边带入了 Transformer 时代。因为当时大家的想法很简单：Transformer 就输出一个简单的东西；但 CV 里面很多 task 的接口是不一样的，像 object detection 这样的接口，你是没有办法处理的。但那篇论文把这个 object detection——最复杂的一个接口，用老师自己的更正说，是"最复杂之一的一个接口"——解决了，所以它是一篇非常成功的论文，2020 年的 ECCV。

最后老师又给了一点时间：可以再给大家 10 秒钟思考一下，看我们班有没有天才。

到这里，问题已经被立住了：单目标情形可以靠"分类 + 回归四个坐标的并行 head"直接解决；一旦目标数变成两个以上、位置与类别都未知，简单地"多预测几组"就会立刻卡在"两个类别和两个框怎么对应"上。

## 二、传统目标检测：滑动窗口、SIFT/HOG 与分类器 [00:20:01–00:35:01]

### 2.1 从单目标到多目标：三步流程的由来

老师在进入传统目标检测之前，先用一段话收束了前面的讨论。他说，如果谁能设计出后来那一系列引用量十几二十万的工作，现在至少是创业公司的 CEO，混得最"没钱"的也在 MIT 教书。这番话说得夸张，落点却很明确：让学生体会"为什么我们要学目标检测"。

> **老师启发**：目标检测看起来不过是几个框，很简单；但即使你现在带着 CNN 时代的认知穿越回 2013 年、2014 年，甚至放到 2015 年、进入 ResNet 时代，也未必抓得住机会，做出那篇惊世骇俗、引用量十万的论文。

带着这个思想实验，老师回到传统方法：传统的目标检测其实就分三步。

1. **区域选择**：在图像中挑出可能含有目标的候选区域。
2. **特征提取**：把候选区域转换成特征向量，传统做法是用 SIFT、HOG 这类人工设计的描述子。
3. **分类器分类**：用分类器判断该区域的类别，并给出目标的四个坐标。

为什么非要拆成这三步？因为我们不知道目标在哪里，图像里哪里都可能有。如果整幅图里只有一个目标，问题其实非常简单：直接做分类，再预测四个坐标值，定位和分类就一起完成了。老师特意回顾了刚才课上同学举的那个最简单的例子——"只有一个目标的时候是不是很简单"。

但一旦有多个目标，这套"一个类别＋四个坐标"的输出就不够用了，两个目标它都处理不了。于是想法很朴素：既然一个目标能处理、多个目标处理不了，那就在图里枚举，把多目标问题拆成一堆单目标问题。

具体做法是画大量不同大小、不同长宽比的边界框（bounding box）。老师说"我可以画 1 万个"：大的、小的、长条状的都撒到图上去，反正都能落在图像范围内。然后每个框都检查一遍——这个框里是不是只有一个目标？是，就按单目标那一套处理；如果框里有两个，这个框就不要了。这一步就是确定图像中感兴趣的区域（Region of Interest, RoI），说白了，就是挑出那些"只有一个目标、好处理"的区域。

区域确定之后，第二步对它做特征提取，传统方法用的是 SIFT 之类的描述子；第三步再分类。这样每个候选区域又回到了"一个类别＋四个坐标值"的问题上。老师提到，早期这一环用过的分类器有 SVM、AdaBoost、随机森林等。

老师把整个流程概括为模块化的设计：先选出哪些区域是感兴趣区域，再提特征，再分类。三步各自独立，可以分别替换。

### 2.2 区域选择：滑动窗口的穷举代价

第一步的"枚举"落到具体算法上，最初用的是滑动窗口（Sliding Window）：拿一个窗口在整幅图像上逐个位置地滑动遍历，并且换不同的尺度、不同的长宽比各做一遍。

老师描述了它的实际做法：先用一个框从头遍历一遍，如果没有框住一个完整的目标，就换一个大一点的框再遍历一遍；长条状等不同比例的框也要各撒一遍。为什么要这么麻烦？因为目标可能出现在图像的任何位置，它的大小和长宽比也都不确定。

代价是显而易见的：光是第一步就要花掉大量时间——候选框越密、尺度越多，计算量就越大。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 6 页，这种穷举策略的优势是"理论上包含了目标所有可能出现的位置"；幻灯片在这一页反问"那么缺点呢？"，课上给出的答案就是时间开销。

> **老师总结**：这套流程听起来很笨，但这是当年最直接、最有效的方式——处理不了多个目标，那就去处理一个目标。

### 2.3 第二步：SIFT 关键点特征

区域选定后，第二步是特征提取。传统流程用的是人工设计的特征描述子，最典型的是**尺度不变特征变换**（Scale-Invariant Feature Transform, SIFT）。老师说这是 90 年代的算法，它会在图像上提取一批关键点，而这些关键点使得图像在发生旋转等变化时仍然能够匹配上。

用老师的话说，SIFT 在传统流程里"相当于 CNN 的一个作用"——负责把一块区域变成特征。

但 SIFT 很快就被抛弃了：进入 CNN 时代后它基本退场，所以这一节讲得很快，老师说 SIFT 现在用得确实很少。它能很好地描述局部特征，但能力有限：适合做局部匹配，不擅长做复杂推理。

### 2.4 SIFT 的能力边界：猜卡通人物的例子

为了说明"不擅长复杂推理"是什么意思，老师举了一个猜卡通人物的游戏。

**例子**：游戏只给出一个黑白的形状——只有剪影，没有颜色和细节——让你猜这是哪个卡通人物，老师随口举了赛罗、哆啦A梦。玩家往往越猜越笃定，可翻到最后一页、彩色照片打开时，答案一定会有反转。老师说，如果用 SIFT 这类提取关键点的方法去处理这种图，它提取到的只是轮廓和边缘的形状：你看着这个轮廓，觉得"大概长得像火影忍者里的鸣人"，彩色照片一打开却是小樱。老师还顺带调侃：班里是不是已经没人看火影了，"我跟你们已经差了年代了"。

这个例子的落点是：SIFT 提取的是局部边缘特征，它的"整体认知"是有限的。由此老师列出三条局限：速度慢；对无纹理的目标效果差；难以处理类别泛化。猜人物这个例子正是"无纹理"的典型——只能靠轮廓去猜，而对方其实只是"凹了那么一个造型"。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 10 页，这三条局限被写得更具体：速度慢指特征提取慢、匹配是 $O(N^2)$ 级别；"无纹理目标"指光滑物体、纯色物体、塑料、球体；类别泛化难指 SIFT 更擅长识别"这个具体物体"，而不擅长判断"这是一个人／一辆车／一只猫"。

### 2.5 HOG：梯度方向直方图

另一类常用的手工特征是**方向梯度直方图**（Histogram of Oriented Gradients, HOG）。老师把它拆成四步：

1. **计算梯度**：对图像中每个位置的像素求梯度。
2. **划分 cell 并统计方向直方图**：把图像划分成很多很小的区域（cell），在每个方向上累积梯度直方图，把梯度按方向投到对应的 bin 里。
3. **block 归一化**：把相邻的 cell 组成 block，对 block 做归一化。
4. **拼接**：把所有 block 的特征拼成一个 HOG 特征向量。

关于维度，老师给了一个大概的计算过程：先数一张图被划成多少个 cell，再数这些 cell 能组成多少个 block，每个 block 里有 4 个 cell、每个 cell 统计 9 个方向的 bin，据此先算出单个 block 的维度，再乘出整张图的总维度。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 13 页，幻灯片用一个 $64\times128$ 的行人图像把这一步算完了：cell 取 $8\times8$ 像素，水平方向 $64/8=8$ 个、垂直方向 $128/8=16$ 个，cell 网格为 $8\times16$；block 覆盖 $2\times2$ 个 cell 且以 1 个 cell 为步长滑动，水平方向可放 $8-2+1=7$ 个、垂直方向 $16-2+1=15$ 个，共 $7\times15=105$ 个 block；每个 block 的维度是 $4\times9=36$，总维度为 $105\times36=3780$。

老师还带着看了 HOG 的可视化。理解它的关键是一句话：HOG 算的是像素梯度。图像内部平坦的地方，一个像素和它周围的像素值一样，梯度为零；只有边缘这类灰度有变化的地方才有梯度。所以 HOG 的可视化图描绘出来的，基本上就是物体的边缘。

顺着这一点，老师指出：光靠描绘边缘，肯定不足以刻画一个对象。他举了个例子：把在座任何一位的照片交给 AI，都能生成出一模一样的轮廓剪影——也就是说，轮廓本身并不足以确定"这是谁"。

HOG 的局限也列了四条：只描述边缘方向，信息有限；对各种形变不鲁棒；是高维特征，非常依赖人工设定的参数；背景干扰也大。

### 2.6 SIFT 与 HOG 的对比

老师把 SIFT 和 HOG 放在一起做了对比。

| 对比点 | HOG | SIFT |
|---|---|---|
| 特征类型 | 稠密特征 | 稀疏特征 |
| 是否基于关键点 | 否，逐位置统计梯度 | 是，先检测关键点 |
| 特征维度 | 高维，由各 block 整体拼接 | 每个关键点固定 128 维 |
| 速度 | 更快 | 更慢 |
| 典型组合 | HOG + SVM | SIFT + RANSAC |

一句话概括：HOG 是稠密特征，逐像素统计，得到的是一个整体拼接的高维向量；SIFT 是稀疏特征，先检测关键点，每个关键点给出一个固定的 128 维描述子。速度上 HOG 更快、SIFT 更慢。两者的典型搭配也不一样：HOG 常配支持向量机，SIFT 常配 RANSAC（Random Sample Consensus）。

### 2.7 第三步：AdaBoost、SVM 与 DPM

到这一步，三步已经走过两步：先枚举出候选区域，再提特征，最后一步是把特征送进分类器。老师顺带回顾，刚才这两个点过得很快：一是怎么提特征，用的是 SIFT、HOG 之类，提出来的特征都是有限的；二就是分类器。他接着说明，早年用的这些分类器今天几乎不可能再用，所以只要求快速知道有这些名词：**AdaBoost**（Adaptive Boosting）、**支持向量机**（Support Vector Machine, SVM）、**可变形部件模型**（Deformable Part Model, DPM）。

三者里 SVM 反而是最常用的一个。它们的大致分工：AdaBoost 属于集成学习；SVM 一般做二分类，思路是在两个类别之间找一条距离两类都最远的边界线，再取它的中间线作为分界；DPM 则是基于图像金字塔（image pyramid）加上改进的 HOG 特征来做分类。

老师把三者的方法类型对了一下：AdaBoost 是集成学习，SVM 是判别式分类，DPM 是结构化模型；三者都需要训练。

> **老师提示**：这些早年的分类器现在几乎不可能再用，大家快速知道有这些名词就行，感兴趣的可以自己下去深入。

老师还补了一句 SVM 的训练开销：它训练起来其实挺慢，是在 CPU 上直接训练的，而且只能训练二分类的东西。

### 2.8 站在 2013 年：把后两步换成 CNN

讲完传统流程，老师把时间锚定回 2013 年。2012 年 CNN 刚刚夺冠，很多人可能还反应不过来；但到 2013 年，你已经可以充分判断 CNN 有前景。老师把提问摆在这个节点上：你知道前人是怎么设计的，现在手里有了 **卷积神经网络**（Convolutional Neural Network, CNN），你会怎么做？他说，这就是后面那一系列工作的"开山鼻祖"——人家 2014 年就把论文发出来了。

老师给了一个很直接的提示：SIFT 和 HOG 是干什么的？是提特征的；AdaBoost、SVM、DPM 是干什么的？是做分类的。这两个功能 CNN 都有。老师特意提醒，不要一步想得那么远，就站在这一步上想；他还反问了一句：这些传统特征和分类器，"我们这节课都没给你细讲"，你还用它们吗？

这里的停顿是在等学生回答：老师问"有同学想回答一下吗"，说提示已经很明显了；字幕没有记录学生的作答。

老师随后把答案一步步带出来：既然特征提取和分类这两个功能 CNN 都能做，那就可以把后两步整体替换掉——至少 SIFT 那一步的特征要换成 CNN 提取的特征，分类器则直接用 CNN 自带的分类输出。老师把这套替换收在一句话上：把枚举出来的那些 bounding box 直接交给 CNN 处理。

至于这套"枚举＋CNN"的想法具体怎么搭成一个可用的检测器，就是后面要展开的内容。

## 三、R-CNN：区域提议与卷积特征 [00:35:02–00:47:45]

### 3.1 出发点：每个候选框里只有一个目标

上一页留下的是一个很具体的设问：现在已经有 CNN 了，传统流程里"提特征"和"做分类"这两步还要不要用手工的那一套？如果不用，该怎么替换？上一段的结论其实已经说定了一半——SIFT 那类手工特征肯定要用 CNN 替换掉，分类器也可以交给 CNN 自带的那一套。

老师给出的回答很直接："我直接拿 CNN 去处理不得了吗？"他随即让大家回到第一步去看那些框是怎么来的。之所以要用滑动窗口一类的办法在图上切出一堆小框，是因为一个模型同时处理两个 object 是处理不了的；退一步的办法，就是让每个框里只装一个 object、一个 target。这个前提一旦确定，问题的性质就变了：既然每个 bounding box 里只有一个目标，那就把框从原图里裁出来送进 CNN，此时要回答的只是"框里的东西属于哪一类"，是一个普通的单目标分类任务——不存在一张图里多个目标互相干扰的情况，直接塞进去、调一下就能用。

这个判断是整堂课的枢纽。R-CNN 之所以能成立，并不是因为它另起了一套框架，而是因为"框里只有一个目标"这个前提，让 CNN 可以当作分类器直接插进原有流程的后半段。后面讲到的所有具体设计，都是围绕"怎么把框选得更好"和"怎么把框变成网络吃得下的输入"展开的。

### 3.2 为什么值得用 CNN 换掉手工特征

传统方法的问题首先在它依赖的线索。它依赖边缘、依赖关键点这类很低层的特征，而明明是一张彩色图，流程却非要先把它看成黑白的，颜色信息在第一步就被主动丢掉了。更要紧的是，这些特征全部是人手工设计出来的：人觉得边缘关键、关键点关键，就照这个想法设计一个提取器——所以它天然带着设计者眼光的边界，是有局限性的。

CNN 的特征不是这样来的。它是从数据里学出来的，我们其实并不清楚它到底学到了什么，但它的表达能力强，学了一堆特征之后反而就能拿来做分类。把手工特征整体换成 CNN 特征，就等于用表达能力更强的特征去淡化"手工特征不泛化"这个弱点：原来那些永远学不会的目标，现在有机会被学会。

老师用一个段子把这层意思讲得很具体。

**例子**：老师举了短剧《万万没想到》里贞子从电视机里爬出来的那个段子——贞子被"我党"救了，经过一番教育培养，成了一个坚定的我方人员，还很热爱生活。他要说的是：像这样靠一个轮廓、一个姿态立住的目标，没有常规的纹理和部件，用 SIFT、HOG 那套手工特征"怎么也识别不了"；换成 CNN 就可以。这个例子说明的不是某个具体类别的识别率，而是手工特征的能力边界——它描述的是人预先认定重要的东西，而 CNN 的特征是从数据里学出来的，人并不知道它具体学了什么，但它的表达能力更强。

### 3.3 两条路线：两阶段与一阶段

有了 CNN 之后，传统目标检测就可以往前迈一步：把后两步换成 CNN，做一个基于 CNN 的目标检测。在展开具体方法之前，老师先把这个方向分成两类——两阶段的与一阶段的，并说明两者各有优劣，而且在当时的实际产品和设备里两类都在用。他同时交代了讲法：先讲清什么叫两阶段、什么叫一阶段，再分别展开。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 21 页，两阶段目标检测是"先生成候选区域，再进行分类与回归"（如 R-CNN 系列），一阶段目标检测是"直接进行目标分类与位置预测"；同一页把传统方法的局限概括为依赖人工特征、难以处理复杂场景、泛化能力有限，把 CNN 的优势概括为自动学习特征、强大的非线性表达能力、端到端训练。这一页正好对应本段"为什么要基于 CNN 做目标检测"的设问。

### 3.4 R-CNN：在老框架上换掉后两步

> **老师启发**：这就是我刚才问你们的——你现在有 CNN 了，站在那页的节点上，你到底要怎么办？

这一系列工作的开山之作叫 R-CNN。老师念的全称是 Region Convolutional Neural Network，并特别强调 R 是 region（区域）的意思，不是别的词。他随后用作者的口气复述了这篇工作的出发点：以前做 detection，大家要用那么麻烦的一整套步骤，SIFT 这类特征这也识别不了、那也识别不了，连"会飞的猪"这种说法都用上了；2012 年 Alex 他们把网络做出来并且夺冠之后，这件事就有了解法——2013 年动手设计，把这些环节直接替换掉。论文是 2014 年发表的。

具体怎么替换？R-CNN 并没有换掉第一步。它还是那张图、还是之前那个方式：在图上枚举很多 bounding box，比如两千个，各种长宽比、各种大小随机地撒上去。

> **老师比喻**：两千个框撒下去，就跟套圈儿一样——我也不知道哪个圈能套中哪个，只能各种各样的大小圈都撒下去，套上哪个是哪个。

撒完框之后，每个框都会被当成一个 region 单独处理：把框里的内容裁出来，送进 CNN。可这里马上出现一个现象——从原图裁出来的框大小、长宽比各不相同，有的是长方形，送进网络之前却都被压成了同一个形状，看起来像"突然变形了"。

**课堂问答**：老师问："为什么突然变形了？"学生作答（字幕未记录学生原话），老师确认："对，输入大小要一样。"

为什么输入大小必须一样，原因在 AlexNet（也就是前面说的 2012 年夺冠的那个网络）那一代模型的硬性规定上。那个网络规定输入必须是 $224\times 224$ 的固定尺寸，并且经过若干次卷积与池化、总共 32 倍下采样之后，特征图必须正好是 $7\times 7$，否则直接报错：

$$
\frac{224}{32}=7
$$

也就是说，想直接用人家的网络，就得接受人家这个设定；不接受也可以，自己重写一个网络，但重写的代价太大，所以大家都会选择接受。接受之后的做法很朴素：不管框原来多长多扁，一律 resize——压一下、拉一下，让形状变成网络要求的尺寸。这个操作在当时的电脑、手机上随便就能做，缩放完再往前送。

网络输出的就是一个分类结果：这一步后面是普通的分类（classification），最终判定它到底属于哪一个类别就行了。

至于其余的框怎么办？处理方式完全一样：一个个裁出来、缩放、送进网络跑一遍。所以回头看，R-CNN 跟之前的方法相比其实什么都没改——还是"撒下两千个框、提特征、再分类"这套骨架，唯一的改动是把"用 SIFT 提特征、用 SVM 做分类"那一套，整体换成了 CNN。

> **老师总结**：就这么一个简单的、非常著名的工作。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 22 页，R-CNN 的完整流程分为四步：一是候选区域生成，一张图像生成 1K~2K 个候选区域；二是特征提取，对每个候选区域用深度卷积网络提取特征；三是类别判断，特征送入每一类的 SVM 分类器判别是否属于该类；四是边界框回归，用回归器精细修正候选框位置。课堂这一段讲到的是前两步以及接在后面的分类，第三、四步的具体做法在后面的章节展开。

### 3.5 第一步也要改：用 Selective Search 代替滑动窗口

R-CNN 在第一步上也做了改进，改用 Selective Search 来生成候选区域（区域提议，region proposal），代替原来的滑动窗口。之所以非改不可，是因为第一步的质量直接决定后面：如果框根本没有把目标框住，后面的分类器再强也永远分不出来。

而用滑动窗口（sliding window）去框住目标，代价大得离谱。多尺度枚举要按 $2\times 2$、$4\times 4$、$8\times 8$ 这样不断放大窗口，一路扫下来差不多要两万到四万个框才能枚举完。更麻烦的是，做检测是一个批量化的流程：每张图进来都要用同样的方式处理一遍，而处理之前并不知道这张图里有什么、目标有多大。要按每张图的情况逐一去枚举框，框的数量就太多了。

所以 R-CNN 换成了 Selective Search。这个算法主要包含两部分内容：一部分是层次分组（Hierarchical Grouping），另一部分是多样化策略（Diversification Strategies）。

先看层次分组，它的操作很朴素：先把图像切成很多很多的小区域，再把相邻且相似的区域不断地合并，一层一层往上合，一直到最上面合成整幅图。老师顺带说明，演示用的那张示意图是拿分割图来做的，目的就是让"一块一块往上合"这件事更容易看懂。

老师用两个随手画的例子说明"合并"是怎么发生的：把一个人用一个框切成八块，拼回去的时候发现上下两块看起来一样，那这两块就该合并；再看两个框，比较之下发现它们很相似，那它们大概率属于同一个区域，就可以合成一个大框；合成出来的大框再和旁边比，发现还能合就继续合，但合到再大之后跟上面比，发现差异大了，就停下来不合了。

把这一过程整理成循环，就是：

1. 先初始化一堆很小的区域；
2. 对每个区域，在它周围检索有没有和自己相似的区域；
3. 长得一样（相似）的，就把它吞并、合并进来；
4. 在所有相邻区域对里找出相似度最高的一对，做合并（merge）；
5. 把合并后重复、冗余的框去掉；
6. 重复第 2 步到第 5 步，直到无法再合。

这套做法和传统的枚举式方法形成了直接对比。以前的办法是"我就傻了，就这么多我也不管了，你就给我挨个去分、挨个去检查"——框有多少就查多少。Selective Search 则是先撒下大量小区域，第一步就做合并、把相似冗余的去掉，这样框的数量可以大幅减少，后面的 CNN 也就不用去跑那么多框。

### 3.6 多样化策略：只按一种相似度会漏目标

Selective Search 的第二部分是多样化策略，也就是"为什么要多样化"的问题。原因很直接：如果只按一种相似性标准去合并区域，就很容易漏掉目标。

那么"多样"体现在哪里？前面讲合并的时候只说了"相似"，并没有说清楚是哪方面相似。而相似其实有很多种方式——颜色可以相似，纹理可以相似，大小也可以相似。尤其要注意，这一步还拿不出 CNN 那样的特征，所以不能说"特征相似"，只能说在颜色、纹理这些属性上相似。

这些相似度本质上也是一种特征，只不过不是 CNN 提出来的那种 feature：颜色本身就是一种特征。所以 Selective Search 要算的是全方位的相似度，把颜色、纹理、大小这些相似度综合到一块，再判断这两个区域到底像不像。

为什么非要把它们揉在一起？因为只用一种会出问题——比如只看颜色相似度。老师拿自己举例：他身上这件衣服跟黑板其实并不像，但假如穿一件颜色和黑板接近的衣服，往黑板前一站，只按颜色合并的话，上半身就要和黑板并成一块了。所以单一的颜色相似度不足以支持"合并不合并"的判断，必须把几种相似度综合起来看。

这也是这一步设计的内在逻辑：候选框的质量直接决定后面几步能做到什么程度，而候选框的质量又取决于"什么样的区域该被合成一个"，所以合并标准本身就成了需要精心设计的对象。

## 四、R-CNN 的关键细节：Selective Search、SVM 与边界框回归 [00:57:53–01:10:03]

### 4.1 R-CNN 的四步流程：骨架没变，中间换掉了

**R-CNN**（Regions with CNN features）是把卷积神经网络引入目标检测的开山之作。它并没有推翻传统目标检测"先找候选区域、再提特征、再分类"的三段式骨架，而是把其中能替换的部件逐个换成深度学习时代的做法。整个方法可以拆成四步：

1. **候选区域生成**：一张图像先生成一批候选区域（课上按 2000 个来算）；
2. **特征提取**：对每个候选区域，用深度卷积网络提取特征；
3. **类别判断**：把特征送入每一类的**支持向量机**（Support Vector Machine, SVM），判别是否属于该类；
4. **边界框回归**：用回归器精细修正候选框的位置。

课堂上是按这四步的顺序讲的，四步讲完后再用一张总览图把它们串起来（见 4.7）。需要先记住一个判断：R-CNN 与传统目标检测在流程上是同构的——"它的特点都是……第一步我先选出一批**感兴趣区域**（region of interest, ROI）"，也就是先把那"一堆框"选出来。两者的差别不在骨架，而在骨架里各部件用什么实现；也正因为第一步只是"选出一批框"，这一步的质量会直接限制整条流水线的上限。

### 4.2 候选区域生成：Selective Search 的相似度是设计出来的

先看 R-CNN 在候选框初步选择这一步做了什么设计。它默认用的是**选择性搜索**（Selective Search），合并哪些区域、按什么顺序合并，都是按 similarity（相似度）来算的。老师强调，这个相似度不是随手拿一个指标凑出来的，"它也是设计了一套的方案"，由几类相似度共同组成：

- 颜色相似度；
- 纹理相似度；
- 大小相似度；
- 吻合相似度。

这四类相似度不是各算各的，而是"综合去考量"，最后由综合相似度决定合并。老师用一个反证说明为什么不能只按颜色来：如果简单按颜色判断，那"太好办了"——直接根据像素去分块就行，60 年代、70 年代、80 年代的算法就能搞定。正因为单一线索既太容易做到、又太不可靠，才需要把颜色、纹理、大小、吻合程度放在一起考虑。

这样做的收益有两条：一是候选框更少，二是选出来的框质量更好、性能更好。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》p24，Selective Search 由层次分组算法（Hierarchical Grouping Algorithm）与多样化策略（Diversification Strategies）两部分组成；老师在课上点到的"设计了一套的方案"属于后者中的相似度计算。同材料 p27–p28 给出了这些相似度的具体定义（课堂只报了名称，没有展开公式）：

1. 颜色相似度。每个区域在每个颜色通道上做 25 bins 的颜色直方图并作 L1 归一化，三个通道共 75 维，即 $C_i=(c_i^1,c_i^2,\dots,c_i^n)$，$n=75$。两个区域的相似度取逐维最小值之和：

$$s_c(r_i,r_j)=\sum_{k=1}^{n}\min\left(c_i^k,c_j^k\right)$$

两个区域合并成 $r_t$ 后，颜色直方图按面积加权，新区域大小为两块之和：

$$C_t=\frac{\operatorname{size}(r_i)\cdot C_i+\operatorname{size}(r_j)\cdot C_j}{\operatorname{size}(r_i)+\operatorname{size}(r_j)},\qquad \operatorname{size}(r_t)=\operatorname{size}(r_i)+\operatorname{size}(r_j)$$

2. 纹理相似度。对每个区域，在每个颜色通道的 8 个方向上用 $\sigma=1$ 的高斯微分滤波器做卷积，每个通道的每个方向取 10 bins 的纹理直方图并作 L1 归一化，最终得到 240 维纹理向量，即 $T_i=(t_i^1,\dots,t_i^n)$，$n=240$。相似度同样取逐维最小值之和：

$$s_t(r_i,r_j)=\sum_{k=1}^{n}\min\left(t_i^k,t_j^k\right)$$

3. 大小相似度。它促使较小的区域尽早合并，公式为：

$$s_{\text{size}}(r_i,r_j)=1-\frac{\operatorname{size}(r_i)+\operatorname{size}(r_j)}{\operatorname{size}(im)}$$

其中 $\operatorname{size}(im)$ 表示整幅图像的像素大小。

4. 吻合相似度。它衡量区域 $r_i$ 与 $r_j$ 合并之后在空间上的紧凑程度，公式为：

$$s_{\text{fill}}(r_i,r_j)=1-\frac{\operatorname{size}(BB_{ij})-\operatorname{size}(r_i)-\operatorname{size}(r_j)}{\operatorname{size}(im)}$$

其中 $\operatorname{size}(BB_{ij})$ 是能同时包围 $r_i$ 与 $r_j$ 的最小外接矩形的面积。

5. 综合相似度。最终的综合相似度是四项的加权和，权重 $a_i\in[0,1]$：

$$s(r_i,r_j)=a_1 s_{\text{colour}}(r_i,r_j)+a_2 s_{\text{texture}}(r_i,r_j)+a_3 s_{\text{size}}(r_i,r_j)+a_4 s_{\text{fill}}(r_i,r_j)$$

讲完候选区域的做法，老师回到 R-CNN 与传统方法的关系上：两者在流程上其实是一样的，第一步都是先选出一批感兴趣区域、也就是那"一堆框"。这个环节是地基，所以候选区域的质量直接决定整条流水线的上限：

> **老师强调**：第一步如果都选错了，后面的怎么可能会正确。

### 4.3 特征提取：把候选区域塞进 AlexNet

候选区域选出来之后，就进入特征提取。R-CNN 在这里用的是 **AlexNet**。老师解释了作者为什么选它：这就是"站在那个时间节点上，看到 AlexNet 夺冠之后"的"下一个选择"——网络夺冠之后，做检测的人自然会想到把它搬到自己任务上。

但直接搬会碰到一个现实问题：AlexNet 当年是经过大量工程调优才调出来的网络，"在我们现在看来很简单"，在当时却来之不易。作者不愿意改动它（老师顺口打了个比方：就像现在的同学也不想重写 PyTorch 一样），于是只能反过来让外围的方法去适配网络：

> **老师强调**：你不想改变它，那你就要去适配它，就要为它把一些方法做一个折中。

R-CNN 里很多今天看起来"有点怪"的设计，本质上都是在给 AlexNet 做折中，其中最直接的一处就是输入尺寸。CNN 只接受固定尺寸的输入，而候选区域的形状、大小五花八门，所以每个候选区域都要先 resize 一下。R-CNN 把这个尺寸定成 $227\times227$。老师在这里还纠正了一个容易记错的数字：有人记成 $224\times224$，实际是 $227\times227$，两者的差别来自第一层卷积没有 padding。

用这个输入过一遍 AlexNet，尺寸是这样一步步变化的：$227\times227$ 先经过 $11\times11$ 的卷积（第一层没有 padding）得到 $55\times55$，再往下到 $27\times27$，最后到 $13\times13$，一层层得到网络最终的特征。

这一步同时留下了一个问题：把任意长宽比的候选区域硬拉成固定尺寸的方图，会引入什么新问题？老师把这个问题抛给同学自己想，然后先转去说明另一个判断：R-CNN 对前面"候选区域选择"这一步的改动其实并不大，真正被换掉的是中间的特征提取。为什么候选区域这一步改动不大？这要回到那个时代的技术条件。

### 4.4 老师插话：那个时代的技术是手搓出来的

要理解"为什么改动不大"，得先理解那个时代。老师先提醒同学不必羡慕那个时代：每一代人面前都有刚出来、影响力大的东西。今天这些 AI 工具能力已经这么强，"你们没有想过用它做点什么吗"。他接着说，十年后的学生坐在这间教室里，同样不会知道十年前那批学生在干什么——那个东西刚出来的时候，他们也不知道；所以当时的人要赶紧做点有影响力的工作。

那个时代的技术条件则是另一回事：技术栈都是人手写的，"纯纯手搓的"。老师回忆自己读 PhD、在 top 公司工作时，程序员之间经常讲一句话：

> **老师强调**：talk is easy, show me the code.

意思是别整天张着嘴、上嘴唇一碰下嘴唇就说"这个功能实现了"，能把它写出来才算本事。而现在反过来了：

> **老师总结**：现在是 code is easy, show me the talk。

把需求讲给 Codex 这类工具，哪怕要一段汇编，它也能给你写出来。再往后是 show me the idea，而 idea 好像也很 cheap，于是又变成 show me the inside。

这个反转对照的是两种不同的瓶颈。过去是"很多东西大家有想法"，但个人的代码能力有限，实现不出来：老师自述，让他累死累活写一个库的底层，真的要搞很久，要查这个查那个，查完可能才能改一点点。现在的同学可能都不知道库的底层怎么写，跟 Codex 随便交流一下就能把事情解决。

当然，这不是说不用写代码，也不是让大家停在原地：老师说要随时代逐步增强自己该有的能力。

> **老师提示**：不是说让你们不写 code……只有你自己手动过了一遍，你知道它底层大概的写的一个逻辑是什么，你在调 **氛围编程**（vibe coding）的时候，你的那个思想才能够正确。

这也正是这门课仍然要求大家把最基本的东西手动过一遍的原因：自己写过，才知道底层的大概逻辑。老师还补了一个更朴素的理由：万一以后断网断电，本地还能工作几天。

> **老师比喻**：你都不知道车是用轮子跑的，你告诉他两个腿倒腾快一点就行了。

不知道底层原理，就算让 AI 去做，也只能给出"把两条腿倒腾快一点"这种方案。

### 4.5 类别判断：一个类别一个 SVM

特征提取之后，每个候选框都变成一个高维向量。老师给的维度是 $4096$：每个候选框都要单独过一遍 CNN，得到一个 4096 维的向量。如果一张图最终有 2000 个候选框（bounding box），那就有 2000 个 4096 维的向量。

接下来的问题是：怎么判定类别？R-CNN 没有用 AlexNet 自带的那套分类头（softmax），而是给每个类别训练一个 SVM。老师说这还是"受到了时代的一个局限"：那时候大家习惯用 SVM，作者没有沿用网络里现成的那一套。

具体做法是：一个框选出特征之后，要把这个特征送到不同类别的分类器里分别打分，看它像哪个类别。SVM 本身是二分类器，所以"多类"是靠"一类一个二分类器"拼出来的。

**例子**：假设数据有 20 个类别，就训练 20 个 SVM。每个 SVM 对送进来的框回答一个是/否问题：dog 的 SVM 判断"是 dog 还是非 dog"，cat 的 SVM 判断"是 cat 还是非 cat"。R-CNN 就是用这样的方式解决多类判定。

### 4.6 边界框回归：给盲选的框补一次修正

分类之外，R-CNN 还有一步**边界框回归**（bounding box regression）。动机很直接：第一步那批框是"纯粹第一批的时候随便盲选出来的"，位置可能不准、可能有问题，所以要再做一次回归把它修正过来。

**例子**：一个本该框住人的框，如果左边把肩膀框出去了一点，另外一边又多加了一点，那就需要一个固定的、与偏差对应的修正量，把框拉回正确的位置。

做法上，回归用的特征同样是 CNN 的特征，具体取的是 pool5 层的特征（AlexNet 的某一层）。用这组特征去学一组参数，这组参数用来预测四个变量——$x$、$y$、$w$、$h$。候选框本来有一种表示，回归之后给出新框的一种表示，两者算一个差异，据此对原框做一个简单的修正。

老师说，这跟刚才上节课讲过的那套回归做法比较像。

### 4.7 四步连起来：一次完整的 R-CNN 检测

四步讲完，老师用一张总览图把整个过程复盘了一遍：

1. 输入一张图像。
2. 先"撒一堆框"：用 Selective Search 之类的各种方法，得到很多候选框，也就是 ROI。示例图里这次很幸运，选出来的框不多，只有三个区域。
3. 把区域送进 CNN。因为我们和作者站在同一个年代，也没有能力改变 AlexNet，所以直接调用它；而 CNN 只接受固定 size 的输入，所以要先把区域变换一下，resize 成规规矩矩的正方形。
4. 调 CNN 提取特征。
5. 分类：CNN 本身是用 softmax 的，但这里受时代局限，改用 SVM 做分类，而 SVM 是二分类。
6. 再加一路 box regression：每个框过 CNN 之后都提了特征；比如这个框本来应该框住一个人，但有点不准、这边应该再往下拉一下，于是把框连同特征送进回归器再做一次微调。回归器知道初始框的位置，也会根据特征学一下要不要调整、怎么调整，最后对框做一点修正。

### 4.8 与传统方法最核心的区别：CNN 换掉了手工特征

流程走完，老师抛出本节的问题：R-CNN 跟之前传统的目标检测（object detection）方法有什么不同？最核心的改变是什么？他特意要求"不用说那么多，只说最显眼的那个"。

**课堂问答**：老师请同学只回答最显眼的那一个改变。有同学先答的是"框"这一侧的内容（字幕未记录完整作答），老师反问那是不是最显眼的；随后答案落到"CNN"上，老师才松了口气："我还以为我一节课的努力白费了。"

答案就是 CNN。传统方法中间那一步提的是人工设计的特征，而 R-CNN 把这一步整个换成了卷积网络自动学出来的特征；候选区域、分类器、回归这些环节都还在，但中间"提特征"的部件换了。这正是本节标题所说的"用卷积特征替换手工特征"。

## 五、R-CNN 与 Fast R-CNN：分类、回归与共享卷积 [01:10:04–01:25:01]

上一节末尾，老师把问题交给全班：R-CNN 与传统目标检测方法相比，最核心的改变是什么？有同学回答“CNN”，老师半开玩笑地说，他还以为一节课的努力白费了。这一节就从这句回答接着往下讲：先把 R-CNN 与传统方法逐项对照，再顺着对比表里“计算效率较低”这一栏，让全班自己推出 Fast R-CNN 的共享卷积结构。

### 5.1 R-CNN 相对传统方法改了什么

老师先让大家看名字——R-CNN。传统目标检测的流程是三步：先撒一堆候选框，中间用 SIFT 提特征，最后交给**支持向量机**（Support Vector Machine, SVM）分类。R-CNN 保留了这个三步骨架，改动集中在两处。最显眼的一处在中间一步：用**卷积神经网络**（Convolutional Neural Network, CNN）替换 SIFT 来提特征。所以老师把“用 CNN 替换 SIFT”称为最明显的改变，其余都算小的修改——两类方法的骨架是一样的，真正的分水岭就在特征提取这一环。

第二处改动在“先找框”这一步。传统方法可能一下子上来两万个框；R-CNN 则用**选择性搜索**（Selective Search）把一些区域合并起来，用合并后的区域当候选框。这一步的目的是提升候选框的可靠性：框给得准一些，后面提特征、分类才有意义。

### 5.2 逐项对比：手工特征、候选区域、分类器与定位

老师把两种方法逐项摆在一起对照。按课堂口述整理，对比表如下：

| 对比点 | 传统目标检测 | R-CNN |
|---|---|---|
| 特征提取 | 人工设计的特征（HOG、SIFT） | CNN 学习到的特征 |
| 特征与分类 | 分离设计 | 由 CNN 统一提取特征 |
| 候选区域 | 滑动窗口 | Selective Search |
| 分类器 | SVM | SVM |
| 定位方式 | 模板匹配 | 边界框回归 |
| 表达能力 | 以低层特征为主 | 高层语义特征 |
| 对复杂场景 | 适应能力有限 | 鲁棒性更强 |
| 检测精度 | 较低 | 显著提升 |
| 计算效率 | 较高 | 较低 |

这张表里有几处是老师特意停下来讲的。

**特征提取。** 传统方法用的是人工手设计的特征，比如 HOG、SIFT；R-CNN 用 CNN 去学特征。但老师在这里做了一个纠正：“其实也不算自动学习”——R-CNN 用的是 AlexNet 已经学出来的特征，拿过来用了一下。也就是说，这一版的“自动”是站在别人预训练好的网络上，并不是从零为检测任务学一套特征。

**特征与分类。** 传统方法是特征提取和分类器分离设计，各做各的；R-CNN 则由 CNN 统一提取特征。不过看分类器那一行会发现，两边都是 SVM——R-CNN 换掉的是特征，分类器这一步并没有换。SVM 本身是二分类器（上一节已经交代），R-CNN 的分类这一环就交给它来做。这一点在对比时容易被“CNN 特征”盖过去，老师专门点出来。

**候选区域。** 传统方法用滑动窗口，R-CNN 用 Selective Search。

**定位方式。** 传统方法靠模板匹配，R-CNN 在分类之外又加了一个**边界框回归**（Bounding Box Regression），用特征去学一个对候选框的微调量：候选框的位置先给出来，再看要不要把它调整一下。

**表达能力与复杂场景。** 用 SIFT 时以低层特征为主，用 CNN 则是高层语义特征，表达能力更好。老师举了“会飞的猪”这个例子：换成 CNN 特征之后，会飞的猪也能被识别出来——如果只靠手工设计的低层特征，设计者怎么也想不到猪还能长翅膀。特征层面一变，对复杂场景的适应能力和检测精度都跟着显著提高。

**计算效率。** 这一栏老师讲得最干脆：R-CNN 计算效率较低，传统方法较高。而且他强调，这是一个非常公平的评价——不是在贬低传统方法，早期的 R-CNN 就是这么慢。

> **老师强调**：计算效率这一栏要如实写——传统方法较高、R-CNN 较低，这是一个非常公平的评价。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上)》第 41 页，这张对比表原表还列有：特征提取一行中的 Haar 特征、候选区域一行中的“规则搜索”、分类器一行中的 AdaBoost、定位方式一行中的“简单回归”，并在“计算效率”的“较高”“较低”后分别注有“但效果有限”“早期方法”。课堂口述时老师只点了 HOG、SIFT、滑动窗口、SVM、模板匹配和边界框回归作代表。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上)》第 32–33 页，边界框回归之所以必要，是因为目标检测的衡量标准是重叠面积：很多看起来准确的检测结果，往往因为候选框不够准确，重叠面积很小。补全的做法是用候选区域 $P=(P_x,P_y,P_w,P_h)$ 的高层语义特征 $\phi_5(P)$（取自 AlexNet 的 pool5 层，是一个 4096 维向量）学习一组权重 $w_i$，预测几何变换量

$$d_i(P)=w_i^{\mathsf T}\phi_5(P),\qquad i\in\{x,y,w,h\},$$

再由候选框和变换量得到新框：

$$\hat G_x=P_w d_x(P)+P_x,\qquad \hat G_y=P_h d_y(P)+P_y,$$
$$\hat G_w=P_w\exp\bigl(d_w(P)\bigr),\qquad \hat G_h=P_h\exp\bigl(d_h(P)\bigr).$$

上述材料补全的是对比表中“R-CNN 用边界框回归定位”一行；课堂在这里只点到“用了一个 bounding-box 回归”，公式本身没有展开。

把这几行合起来看，R-CNN 对每个候选区域最终要回答两个问题：它是什么类别，由 SVM 给出；它的框要不要修正，由边界框回归给出。这个“分类＋回归”的两件套，正是 Fast R-CNN 后来并进同一个网络的那两个头。

### 5.3 站在 2015 年的时间节点：为什么要共享卷积

讲完对比表，老师把大家拉回历史现场：现在你又站在一个时间节点上。当年 AlexNet 的风口你没抓住，R-CNN 论文一放出来，你一拍大腿——怎么就没想到用 CNN 把 SIFT 替换一下？可等你看完这篇论文，人家已经把这件事做完了，还顺手把问题分析给你看，尤其是“计算效率较低”这一条。老师还提前透露：下一篇的引用量比这一篇高得多。

于是老师给出设定：你手里已经有 R-CNN 的代码，论文也刚读完，假设你是全球第一个看到它的人，就坐在作者旁边，代码也拿到了；但出于同门情谊，你不能剽窃人家的成果。那么，你的下一篇论文怎么写？

约束是刻意收紧的：只给你“效率较低”这一条线索——就这一套流程效率较低，让你去提升；不要一下子飞跃得太远，一定要考虑自己手里的能力。

> **老师提示**：不要一下子飞跃得太远，一定要考虑自己手里的能力——当时没有现在这样的 AI 辅助编程（vibe coding），代码全靠手写，主流框架还是 Caffe，而不是现在大家熟悉的 PyTorch。

在这个设定下，老师让全班想：如果是你，会先动哪一步？

**课堂问答**：有同学回答“先做 CNN”。老师认可这个方向（“这个是对的”），但让他先给其他同学留出思考时间，然后追问：为什么可以先做 CNN？字幕未记录该同学对“为什么”的进一步作答，老师随后自己把理由讲了出来。

老师给了三条提示。第一条，看 PPT：图上为什么画了三个 CNN？因为画了三个框，每个框都单独调了一遍 CNN。

> **老师比喻**：PPT 上画了三个 CNN，是因为画了三个框，每个框都单独调了一遍 CNN——这三个 CNN 是三次真实的前向计算，“不是影分身”。

第二条，CNN 处理的到底是一整个大图，还是每个框里的小图？这两者有区别吗？第三条，CNN 不是不计时间的：这么大的算力，每跑一次都是实实在在的开销，老师调侃说“他家的电费掉了一次又一次”。

把这三条拼起来，思路就出来了：

**推导**：

第一步，先把这一步的目的说清楚：不管框画在哪里，中间这一步最终都是“从一个区域取出这个区域对应的特征”。

第二步，看 R-CNN 的做法：它先用候选区域在原图上把区域割出来，再对每个小区域单独跑一遍 CNN 提特征。

第三步，既然目的只是区域特征，就可以把顺序反过来：先用 CNN 对整张图跑一遍，得到整张图的特征图。

第四步，特征图虽然比原图小，但候选框的坐标可以映射过去，仍然能在特征图上“选”出对应的区域。

结论：CNN 只需要跑一次，所有候选区域共享这一份卷积特征。

这正是 Fast R-CNN 名字的由来——它就是冲着 R-CNN 的“慢”去的。老师顺势调侃了一句“各位都没有抓住时代的风口”。慢的原因也很直接：一个 CNN 本来就昂贵，还要占 GPU 来调，有多少 GPU 经得起这样一遍又一遍地跑；示意图上只画了三个框，实际有两千个候选框，等于要把 CNN 调两千次。而这两千个框之间大量重叠，很多区域被反复计算，算力就这样一遍遍地耗掉——老师又拿电费打趣，说这样跑下去，一年的电费都要耗完了。

换个做法，代价立刻降下来。有了整图特征，再取区域特征即可：在 $512\times512$ 的原图上画区域，和在约 $128\times128$ 的特征图上画区域，本质上没有区别，坐标一样能映射过去。老师算了一笔账：假设一次 CNN 前向要 10 秒，R-CNN 这边是 $10\times2000$ 秒；Fast R-CNN 只跑一次，就算整张图大一点、一次要 20 秒，也远远小于前者。

### 5.4 Fast R-CNN 的整体结构：共享卷积加两个预测头

落到结构上，Fast R-CNN 做的事情可以概括为：先共享整张图的卷积特征，再把候选区域映射到这份特征上裁剪出来，这样 CNN 只调一次。

具体到每一步：输入整幅图像，先过一次骨干网络，得到整图的卷积特征；Selective Search 选出的每个**感兴趣区域**（Region of Interest, RoI），按其坐标在特征图上裁剪出对应的特征区域，并把大小调整到统一尺寸；然后在这块 RoI 特征上再叠一个小网络。这里要注意，后面这个“CNN”只是起了这个名字，它不是把一个大网络完整地再调一遍，而是接在特征后面的一个小网络；到这个年代，作者的 coding 能力也强了，不再只是套用 AlexNet，自己就能写一个网络出来。

小网络的输出分成两个头：一个头预测 box，一个头预测类别（class name、category）。为什么可以这样做？因为前面已经用选定区域的方式锁定了一个区域，一个区域就对应一个 object；既然“这里有一个物体”已经确定，剩下的无非就是两件事——它是什么类别，它的框在哪里。这其实又回到了单目标检测的思路：分类加回归，只不过这次两个输出由同一个网络的两个分支给出。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上)》第 42–44 页，Fast R-CNN 的结构是：输入整幅图像，先经过主干网络（backbone，如 AlexNet、VGG、ResNet）得到整图卷积特征；对选出的每个区域（RoI），把区域坐标映射到特征图上，裁剪出对应特征并调整大小；统一尺寸的 RoI 特征送入后面的小网络，再分成两个分支——一个 Linear + softmax 输出物体类别（Object category），一个 Linear 输出框的偏移量（Box offset）。

补充材料第 42 页同时标出了与“Slow” R-CNN 的对照：R-CNN 是每个候选框各自过一遍 CNN，Fast R-CNN 是整图只过一次、所有候选区域共享这份卷积特征。按第 44 页的结构图，类别和框都由同一个网络的两个分支给出，这与 R-CNN 把特征交给外部 SVM 分类的做法不同；课堂在这里讲的是“出一个头预测 box、一个头预测类别”，两个分支的具体形式来自该页。

对照两种方法的前向过程：

| 环节 | R-CNN | Fast R-CNN |
|---|---|---|
| 卷积特征 | 每个候选框单独过一次 CNN | 整图过一次，所有 RoI 共享 |
| 区域特征来源 | 原图上裁出的候选框图像块 | 特征图上映射出的 RoI 区域 |
| 输出 | SVM 分类，另有单独的边界框回归 | 同一网络的两个头：类别 + box |

> **老师总结**：Fast R-CNN 的关键就一句话——整图只过一次卷积，所有候选区域共享这份特征。

### 5.5 RoI 映射：从原图坐标到特征图坐标

结构看起来已经顺了，但老师马上指出一个比较棘手的问题：我们得把区域从原图映射到特征图上。

原因在于，Fast R-CNN 里的候选区域仍然是用 Selective Search 在原图上找出来的，还是两千个框。原图可能是 $512\times512$，而特征图一般没有特别大，比如 $32\times32$ 比较常见。原图上的框，必须换算到这张小得多的特征图上。

映射“说得好听”，做起来会出问题。老师用尺寸举例：一张 $640\times480$ 的输入，到特征图上只剩 $20\times15$；候选框（比如一只猫，尾巴露在框外也没关系）的坐标要落到这张 $20\times15$ 的图上，并在图上画出它对应的特征区域。这一步的目标很明确：让不同大小的候选区域，最终变成一个统一尺寸的特征表示。

### 5.6 RoI Pooling：把任意大小的区域压成统一尺寸

为什么非要统一尺寸？因为后面接的那个小 CNN 规定了统一尺寸的输入。所以哪怕 RoI 在特征图上是 $5\times4$ 的一块，也必须变成 $2\times2$；问题于是变成：怎么把一个 $512\times5\times4$ 的区域，变成一个 $512\times2\times2$ 的张量。

这里的核心矛盾是坐标对不上格子。原图尺度大，映射到特征图之后，坐标往往不是整数，而是一个小数——比如 3.45。可特征图上的一个格子并不是可以随便切割的连续区域：它是一个数（严格说是一个 512 维向量），老师把它形容成“一串数字”。坐标落在 3.45，总不能把那个数切下四分之三。所以必须对每个格子明确判定：它到底算不算在这个 RoI 里——算进去就参与计算，不算就不算。这一步就是取整与对齐。

> **老师比喻**：特征图上的一个格子就是一个数，坐标落到 3.45 时，总不能把那个数切下四分之三——“我又不是切蛋糕”。

**RoI Pooling**（RoI 池化）的做法就是先按上面的规则把格子归属定下来，再在 RoI 内部划分子区域、对每个子区域取平均。

**例子**：把特征图上 $5\times4$ 的 RoI（共 20 个格子，每格一个 512 维向量）池化成 $2\times2$。按 $2\times2$ 切成四块时，四块并不能均分，课上举的分法是四块分别含 6、6、4、4 个格子（合起来正好 20 个）。然后在每一块内部对格子取平均：六个格子平均得到一个 512 维向量，另一块六个平均得到一个，剩下两块各四个平均得到两个；四个平均结果拼起来，就是 $512\times2\times2$ 的特征，可以送进后面的小网络。老师同时指出，这种分法没有办法做到完全均衡，只能“大概均衡”——它本身是一个近似做法，这一点在后面会变成 RoI Pooling 的误差来源。

至此 RoI Pooling 的作用可以说清楚了：它把不同的 RoI 变成固定大小的特征。但它的问题也在这里——它需要取整和对齐，而取整、强行对齐会带来位置误差。RoI Align 的思路就是不再做这种粗糙的对齐：映射到特征图之后，不强行把采样点偏移到格点上。老师用一句话概括了这个动机：“我都没卡上，非要强行对齐一下？”有没有更优雅的方式——这正是 RoI Align 要做的事，具体怎么做（采样点怎么撒、特征怎么插值）留到下一节。

## 六、RoI Pooling 与 RoI Align [01:25:02–01:34:59]

上一节停在 Fast R-CNN 的结构上：整张图先过一次卷积网络得到**特征图**（feature map），每个候选框再到特征图上去"裁"出自己那一块区域。麻烦在于，候选框大小不一，裁出来的区域在特征图上也就是 $5\times4$、$4\times5$、$8\times7$ 这些互不相同的尺寸，而它后面接的全连接层只认固定大小的输入。这一节讲的就是把"任意大小的区域特征"变成"固定大小的区域特征"的两种做法：**RoI 池化**（RoI Pooling）与 **RoI 对齐**（RoI Align）。这里的 **感兴趣区域**（Region of Interest, RoI）指的就是特征图上的那一块候选区域。

> **老师强调**：RoI Pooling、RoI Align 背后的这些做法和思想，是必须知道的，不能只知道名字。

这一节的后半段，老师借着幻灯片上的图把**卷积神经网络**（Convolutional Neural Network, CNN）提特征时的空间关系讲开了：一个特征位置到底"看到"原图多大一块、映射误差为什么必然存在、物体小到什么程度就检测不到。这些讨论不是旁枝，它解释了 RoI Pooling 和 RoI Align 的差别为什么重要。

### 6.1 RoI Pooling：区域映射、网格划分与子区域池化

RoI Pooling 的目标只有一句话：不管喂进来多大的一块区域，都吐出一个固定大小的张量。这个目标拆成四步。

**第一步，把区域映射到特征图上。** 区域框给的是原图坐标，而特征图已经被下采样过，所以要按**步长**（stride）把原图坐标系换算到特征图坐标系。本节幻灯片给的例子是：输入图 $3\times640\times480$，特征图 $512\times20\times15$（p45）。这两个尺寸之间的比例是

$$
\frac{640}{20}=32,\qquad \frac{480}{15}=32,
$$

也就是 32 倍**下采样**（downsampling），步长 $s=32$。把框的四个坐标各除以 32，就得到它在特征图上的位置。除出来一般不是整数，框的边界落在格点之间——后面所有的麻烦都是从这里来的。

**第二步，把这个区域在特征图上划成规则网格。** 网格是 $2\times2$ 还是 $7\times7$，由我们想要的输出尺寸决定：本节例子用 $2\times2$，实际实现里常用 $7\times7$（p50）。（这一步也是老师说的"每个区域我给你平均格子"。）

**第三步，把网格边界对齐到格点上。** 因为区域的边界是浮点坐标，而特征值只存在整数格点上，所以要把每个子区域的边界挪到最近的格点，幻灯片上把这一步叫"对齐到网格单元"（p47），老师说这就是"强行让他挪一个位置对上去"。

**第四步，在每个子区域内做一次池化。** 每个子区域里的所有格点被压缩成一个数，于是 $2\times2$ 个格子给出 4 个数。幻灯片 p50 把这一步标为"在每个子区域内进行最大池化"，老师口述时用的是"average 一下""平均一下"。两种说法指的是同一件事——用子区域内的所有值算出一个代表值；具体用最大值还是平均值是池化方式的选择，而"每个子区域只留一个数"这个结构是两种方式共有的。

几步合起来，输出就是 $512\times2\times2$（p50）。注意通道维 512 前后没有变，说明池化只在空间的两个维（高、宽）上做，512 个通道各自独立地做一遍空间池化。

这个输出有一点特别值得记住：**它的尺寸只由网格数决定，和输入区域的大小无关**。老师换着说法强调了三遍——不管进来的是 $5\times4$、$4\times5$ 还是 $8\times7$，最后都要变成 $2\times2$。幻灯片 p50 的最后一句话就是"即使输入区域的大小不同，区域特征始终保持相同的大小"。这正是 Fast R-CNN 能把不同候选框塞进同一个全连接层的原因。

### 6.2 数值复算：$512\times5\times4$ 的区域如何变成 $512\times2\times2$

幻灯片 p48、p49 直接把这个问题写了出来："我们如何将 512 × 5 × 4 的区域变为 512 × 2 × 2 的张量？"这里把账逐项算一遍，因为"取整"到底取掉了什么，只有算过才清楚。

区域是 $512\times5\times4$：512 个通道，高 5 行、宽 4 列，共 $5\times4=20$ 个格点，每个格点是一个 512 维向量。目标是 $2\times2$。

1. 行方向：$5/2=2.5$，不是整数。取整后只能分成 2 行和 3 行两段。
2. 列方向：$4/2=2$，正好是整数，分成 2 列和 2 列两段，没有取整损失。
3. 于是四个子区域含的格点数分别是 $2\times2=4$、$2\times2=4$、$3\times2=6$、$3\times2=6$。
4. 校验：$4+4+6+6=20$，与 $5\times4$ 相等，说明四个子区域把区域盖满且互不重叠，没有格点被丢掉或被算两次。
5. 每个子区域在 512 个通道上各池化成一个数，得到 4 个 512 维向量，重新排成 $512\times2\times2$。

| 子区域 | 行范围 | 列范围 | 含格点数 | 池化后 |
|---|---|---|---|---|
| 左上 | 第 1–2 行 | 第 1–2 列 | $2\times2=4$ | 512 维 |
| 右上 | 第 1–2 行 | 第 3–4 列 | $2\times2=4$ | 512 维 |
| 左下 | 第 3–5 行 | 第 1–2 列 | $3\times2=6$ | 512 维 |
| 右下 | 第 3–5 行 | 第 3–4 列 | $3\times2=6$ | 512 维 |

老师对这一步的判断是：这样划分只能做到"近似均衡"，做不到完全均衡。原因就在第 1 步——5 行要分给两个子区域，一边 2 行一边 3 行，无论怎么分都不可能一样多。这不是实现没写好，而是整数格点本身的性质。

换一个输入，结论不变，只是四个格子更不均匀。比如 $8\times7$：行 $8/2=4$，两段各 4 行；列 $7/2=3.5$，两段是 3 列和 4 列。四块含 $4\times3=12$、$4\times4=16$、$4\times3=12$、$4\times4=16$ 个格点，合计 $12+16+12+16=56=8\times7$，输出仍然是 $2\times2$。若把网格改成 $7\times7$，同样的区域输出就是 $512\times7\times7$（p50）——变的是网格数，不是输入。

注意区分 $2\times2$ 里的 2 和 $5/2=2.5$ 里的 2.5：前者的 2 是**网格数**，是整数、由我们指定；后者的 2.5 是**子区域的浮点宽度**，是被除出来的。取整就发生在后者往前者的转换上，RoI Pooling 的位置误差也产生在这一步。

### 6.3 "强行对齐"为什么带来位置误差

候选框是**边界框**（bounding box, bbox）回归或区域提议给出的，坐标是实数，不是格点编号。把框的坐标除以 32 之后，它的边界一般落在两个格点之间。老师的原话是"我的这个 bounding box 映射过来之后，它可能并不对齐"。

对齐的操作很直接：把边界挪到最近的格点上。老师把它称作"一种简单粗暴的方式"——"我们让他强行跟最近的那个对齐"。用 6.2 的例子说，行边界 $2.5$ 被挪成 2 或 3，四条边各挪一次，整个框的形状和位置就都变了。

这个偏移有多大？按本节的比例，特征图上的 1 个格点对应原图 $32\times32$ 像素。强行对齐最多把边界挪动约半个格点，折算到原图上就是十几个像素（$0.5\times32=16$）。对一个几十像素宽的小目标来说，这个量不能忽略。

更要紧的是这个误差不会自己消失：池化出来的特征接着就是全连接层的输入，框的位置和它实际读到的特征从此对不上。老师后面回答同学提问时也承认这一点——"映射过去之后一定是有误差的"。

既然误差来自"把边界挪到格点上"，一个自然的想法就是：能不能不挪？老师的处理是给出第二种做法——RoI Align，它在映射之后不再做这种粗糙的对齐，而是换一种方式取得格子里的值。

### 6.4 RoI Align：不对齐，改在规则采样点上取值

RoI Align 的前半段和 RoI Pooling 完全一样：先把区域映射到特征图上（p51）。分岔出现在下一步——老师说这一种"先不管"对齐这件事，"我们就这么一个区域"，幻灯片 p51 对应的写法是"不进行对齐操作"，也就是子区域的边界保留浮点位置，不往格点上靠。

边界不落在格点上，子区域里就没有现成的格点特征可读。RoI Align 的办法是在每个子区域内按规则的位置布置采样点（p52 的"在规则点上进行采样"）。老师说得很形象："我是不是能按照我这个区域去给你打上一些采样点上去""撒一些采样点上去"。

采样点落在格点之间，它自己的特征从哪来？从它周围最近的四个格点算出来。老师的描述是："我周围有这么四个数字，那么我这个点就是临近的这四个数字的一个线性组合"，"我是不是能从这几个线性组合出我这个点的一个特征"。幻灯片 p53 把这句话写成了正式的表述：点 $(x,y)$ 的特征 $f_{xy}$ 是其四个邻近网格单元特征的线性组合。这就是**双线性插值**（bilinear interpolation），具体算式在 6.5 节。

区域内的每个采样点都这样算一遍，整个区域就得到一整组"插值出来的特征"；再按子区域把这组特征聚合成一个值（老师说"我是不是照样把这四个特征给它 average 一下"），四个子区域合起来又是一个 $2\times2$。幻灯片 p54 在这一步同样标的是"最大池化"，输出同样是 $512\times2\times2$（实践中同样是 $512\times7\times7$）。

把两种做法放在一句话里对照：**RoI Pooling 挪的是"区域的边界"，让它去贴格点；RoI Align 不动边界，挪的是"读数的位置"——该读哪里就读哪里，读到格点之间就用插值把值算出来。** 前者只做取整，后者要多做插值，但换掉了取整带来的位置误差。

老师把这一组设计归入 Fast R-CNN 的新设计：RoI Pooling 是它让不同候选框共享特征图的关键部件，RoI Align 则是对其中取整误差的修正。

### 6.5 双线性插值的计算过程

设某个采样点落在特征图坐标 $(x,y)$ 上，$x,y$ 都是实数。取

$$
x_1=\lfloor x\rfloor,\quad x_2=x_1+1,\quad y_1=\lfloor y\rfloor,\quad y_2=y_1+1,
$$

并记四个邻近格点的特征为

$$
f_{11}=f(x_1,y_1),\quad f_{21}=f(x_2,y_1),\quad f_{12}=f(x_1,y_2),\quad f_{22}=f(x_2,y_2).
$$

再记两个小数部分

$$
\Delta x = x-x_1\in[0,1),\qquad \Delta y = y-y_1\in[0,1).
$$

插值公式是

$$
f(x,y)=(1-\Delta x)(1-\Delta y)\,f_{11}+\Delta x(1-\Delta y)\,f_{21}+(1-\Delta x)\Delta y\,f_{12}+\Delta x\,\Delta y\,f_{22}.
$$

这个式子可以按"先横向、再纵向"两趟一维线性插值算出来，这也是"双线性"这个名字的来历：

1. 在下边那一行（$y=y_1$）上沿 $x$ 插值一次，得 $g_1=(1-\Delta x)f_{11}+\Delta x f_{21}$。
2. 在上边那一行（$y=y_2$）上沿 $x$ 再插值一次，得 $g_2=(1-\Delta x)f_{12}+\Delta x f_{22}$。
3. 在 $g_1$ 与 $g_2$ 之间沿 $y$ 插值一次，得 $f=(1-\Delta y)g_1+\Delta y\,g_2$。
4. 把第 3 步展开，四个系数正好是 $(1-\Delta x)(1-\Delta y)$、$\Delta x(1-\Delta y)$、$(1-\Delta x)\Delta y$、$\Delta x\Delta y$，与上面的公式一致。

四个系数有两个性质可以直接用来验算。一是它们相加恒为 1：

$$
(1-\Delta x)(1-\Delta y)+\Delta x(1-\Delta y)+(1-\Delta x)\Delta y+\Delta x\Delta y=\big[(1-\Delta x)+\Delta x\big]\big[(1-\Delta y)+\Delta y\big]=1,
$$

所以插值结果是四个邻点特征的加权平均，一定落在这四个数的最小值与最大值之间，不会插出一个"不存在的值"。二是若四个邻点特征都等于 $c$，则 $f=c\cdot1=c$；若采样点正好落在格点上（$\Delta x=\Delta y=0$），系数变成 $1,0,0,0$，插值退化为直接取该格点的值。这两个特例说明公式在边界情形下与"直接读格点"衔接得上。

**数值算例。** 设采样点落在 $(x,y)=(2.3,\,1.7)$，则 $x_1=2,x_2=3,y_1=1,y_2=2$，$\Delta x=0.3,\Delta y=0.7$。四个系数是

$$
\begin{aligned}
w_{11}&=(1-0.3)(1-0.7)=0.7\times0.3=0.21,\\
w_{21}&=0.3\times0.3=0.09,\\
w_{12}&=0.7\times0.7=0.49,\\
w_{22}&=0.3\times0.7=0.21,
\end{aligned}
$$

相加 $0.21+0.09+0.49+0.21=1.00$，与上面的恒等式吻合。若这四个格点特征依次为 $1,2,3,4$，则

$$
f=0.21\times1+0.09\times2+0.49\times3+0.21\times4=0.21+0.18+1.47+0.84=2.70,
$$

落在 $[1,4]$ 之间。用两趟一维插值核对：$g_1=0.7\times1+0.3\times2=1.3$，$g_2=0.7\times3+0.3\times4=3.3$，$f=0.3\times1.3+0.7\times3.3=0.39+2.31=2.70$，两条路结果相同，说明公式与拆解没有矛盾。

采样点的位置只由区域划分决定，与通道无关，所以 512 个通道用的是同一组四个系数，只是每个通道代入自己的 $f_{11},f_{21},f_{12},f_{22}$，每个通道各插值一次。

### 6.6 RoI Pooling 与 RoI Align 的对照

两种方法在"映射—分格—聚合"这条骨架上完全一致，差别集中在两处：边界要不要量化，格子里的值怎么取。

| 环节 | RoI Pooling | RoI Align |
|---|---|---|
| 区域映射 | 原图坐标除以步长（32） | 同左 |
| 子区域边界 | 取整对齐到最近格点（p47"对齐到网格单元"） | 保留浮点位置，不对齐（p51"不进行对齐操作"） |
| 格内取值 | 直接读子区域内已有的格点特征 | 在规则采样点上做双线性插值（p52、p53） |
| 子区域聚合 | 每个子区域池化成一个值（p50 标"最大池化"，老师口述"average 一下"） | 同左（p54 标"最大池化"，老师口述"average 一下"） |
| 输出尺寸 | $512\times2\times2$（实践 $512\times7\times7$） | $512\times2\times2$（实践 $512\times7\times7$） |
| 位置误差 | 有，来自边界量化 | 无量化误差，插值本身是近似 |

从表里能看出，RoI Align 改的只有"格内取值"这一行，以及为保证这一行成立而取消的量化。输出尺寸、聚合方式、通道数全都没变，所以它可以直接替换 RoI Pooling 而不改动网络其余部分。

### 6.7 课堂追问：从 R-CNN 到 Fast R-CNN 最明显的区别

讲完这一组图，老师把 Fast R-CNN 的结构收住，转而拿它和 R-CNN 对比："我们对比一下，R-CNN 里面最明显的区别是什么？"他让同学举手回答，说想"体验一下这 20 分钟的成果"，又说不必害羞；随后点了一位坐在前面、头发很酷的男生，并说旁边那位也可以回答，两位谁答都行。同学没有答上来，老师半开玩笑地说"你不知道，我有点伤心"，然后指着图上"从这儿到这儿"的两处，自己讲了下来。

差别就在两处画面上。R-CNN 那一侧，是每个 region 先单独过一次 CNN，每个 region 各自提取完特征之后再做后续处理；Fast R-CNN 这一侧，是整张图先过一遍 CNN，拿到特征图之后，每个候选框再在这张特征图上去做一个裁剪。于是——

> **老师总结**：你 box 选取这一步，跟用 CNN 提特征这一步，先后顺序被颠倒过来了。

这两步一颠倒，速度的变化就很大。原因很直接：R-CNN 里 CNN 被调了很多次——每个候选框都要过一遍，而 CNN 本身很浪费时间和算力，重复跑这么多次代价极大；Fast R-CNN 只调一次，把整张图的特征提出来之后再做选择，所有候选框共用同一张特征图。

### 6.8 特征扩散、邻域交互与"一个点代表多大区域"

同学接着追问的方向是：区域映射过去本来就有误差，特征会不会因此扩散到别的格子上、甚至扩散到别的区域去。

老师先承认这一半：映射过去一定是有误差的，特征也确实可能扩散到相邻位置，"你说那种扩散到其他位置，这是肯定的"。但他强调另一半：CNN 提特征的时候，是以这个位置为中心在提。

> **老师强调**：不能只靠一个像素——一个像素自己是没有语义的，它一定要和周围的特征发生交互。

为了说明这一点，老师用看图打了个比方。一块黑，你判断它是眼睛；另一块黑，你判断它是草地上的一块阴影。你能判断，是因为眼睛"迅速把它跟周围的特征做了一个融合"；如果单独把这两小块 RGB 抠出来放到一起看，它们其实是不一样的。同理，CNN 提某个位置的特征时，既要向周围扩散，也一定要去收集周围位置的信息。

所以"映射误差"和"邻域交互"并不矛盾：位置不可能精确到格点，这是事实；而特征的语义本来就建立在邻域之上，这也是事实。老师并没有把这当成要修补的缺陷，而是把它当成卷积提特征时本来就存在的性质。

### 6.9 下采样倍率、映射关系与小物体检测的下限

顺着"一个位置对应原图多大范围"，一位同学提出了更实质的疑问：特征扩散的范围如果不受限制，那原图上很小的一块会不会在特征图上牵涉到很大的一片，这样是不是就很难做？

**课堂问答**：老师先复述确认自己理解得对——"就是我这一个位置、一个像素，放到图上可能有这么大"——然后分几层回答。

第一，特征图相对原图差不多是三十几倍的下采样，而且这个下采样是一定存在的。

第二，真正的问题不在下采样本身，而在物体不能过小。如果物体在原图上就只有 $10\times10$ 那么大一块 patch，那它放到特征图上以后落在哪儿都说不清，老师举的例子是"比如这根草……你放到这儿之后在哪，我也不知道"。

第三，实际要找的物体一般不至于这么小，不会是 $10\times10$ 或者十几乘十几的 patch。老师给的数是：一张 $640\times480$ 的图，这只猫大概占 $300\times200$ 像素；按三十几倍折算，$300/32\approx9$、$200/32\approx6$，它下采样之后仍然占住大约 $9\times6$ 个格点，还是一片有内容的区域。

第四，只有物体过小时才会出现同学担心的那种情况。老师问"不知道我有没有理解到你的意思"，同学回答"对"，确认了这个理解。

接着老师把幻灯片上的画法和实际情况对了一下。幻灯片为了让大家看得方便，把原图上的框和特征图上的框画成了一样大；实际不是这样：原图是 $640\times480$，特征图是 $20\times15$（p45），如果把特征图按原图的尺寸画出来，它在图上只占很小的一块。两者之间只有一个大概的映射关系，也就是"多少倍的下采样"。

这个倍数决定了一个硬下限。一个特征格点覆盖原图 $32\times32$ 像素，所以如果原图上有一只很小的迷你猫，小到连一个格点都填不满，那它在这张特征图上根本不足一个区域，"这样的小物体，我们大概率是检测不出来的"。

> **老师总结**：一般情况下，人类正常感兴趣的那些图，不会出现这么小的物体。

蚂蚁的例子把这条判断说透了。就算拍的是一只蚂蚁，如果是在大范围里拍了一张图、地上有一群蚂蚁，大家的关注点肯定也不在蚂蚁上，而是想找别的东西；如果你真的对蚂蚁感兴趣，一定会走近了近距离拍一张。近距离拍完之后，蚂蚁本身在图上就比较大，差不多是一个大于 $32\times32$ 像素的物体，也就回到了检测器能处理的范围里。换句话说，小物体检测的困难不是被算法"解决"掉的，而是被拍摄方式绕开的。

## 七、Fast R-CNN 的速度来源与 Faster R-CNN 的提出 [01:35:00–01:49:40]

上一节把 Fast R-CNN 的结构拆到 RoI 池化为止。这一节的讲法是一条连续的问句链：先把 R-CNN 和 Fast R-CNN 的训练时间、测试时间摆到一起，问"快是快在哪里"；再问"把重复的卷积省掉之后，还剩下哪一步最慢"；最后顺着这个最慢的步骤，把 Faster R-CNN 和区域提议网络引出来。

### 7.1 训练与测试时间的量级差异

屏幕上给出的是 R-CNN 与 Fast R-CNN 的速度对比，训练时间和测试时间分两栏看。

先看训练时间：Fast R-CNN 明显比 R-CNN 快很多。再看测试时间：两者的差别比训练时间更大，已经不是差几倍的问题，而是整整差了一个数量级。

测试时间还有两种算法，区别在于要不要把生成候选框这一步算进去：

| 计时口径 | R-CNN | Fast R-CNN |
|---|---|---|
| 训练时间 | 作为对照 | 明显更快（课上未给具体数值） |
| 测试时间（含区域提议） | 49 s | 2.3 s |
| 测试时间（不含区域提议） | 47 s | 0.32 s |

也就是说，计入区域提议那一步时，整幅图的测试时间从 49 秒降到 2.3 秒；如果暂时把候选框生成这一步拿掉、只比较网络本身，则从 47 秒降到 0.32 秒。老师连着问了两次"是不是降了很多""这个速度加速很多"，用这两行数字来说明提速的幅度。

> **老师强调**：这在当年是很划时代的。当年的摄像头检测人很慢，一卡一卡的；突然来了一个能在高清视频上跑到 60 FPS（每秒 60 帧）、还能把人实时追上的算法，非常牛。

### 7.2 速度来源：卷积只跑一次

老师没有直接把答案说出来，而是把"速度来源"当成刚才那个问题再问一遍，并且另外叫了一位同学回答。

**课堂问答**：老师问：Fast R-CNN 比 R-CNN 快了很多，它节省的主要是哪一部分时间？一位同学回答："跑 CNN 的时间——一个调一次，一个调几千次。"老师肯定了这个回答，说这一项省下了很大一块时间。

这位同学说的"一个调一次，一个调几千次"，正是 R-CNN 与 Fast R-CNN 在计算组织上的根本区别。R-CNN 的做法是：每拿到一个候选框，就把该框在原图上对应的图像区域裁出来，单独送进 CNN 前向一次；一张图通常有几千个候选框，于是同一张图要被卷积网络重复算几千次。Fast R-CNN 反了过来：先对整幅图跑一次卷积，得到一张特征图，所有候选框都在这同一份特征图上取 RoI 特征，再做池化和后面的分类、回归。卷积只做一次，几千个候选框共享这一份计算结果，重复计算的那几千次就被省掉了。

老师说，这个速度来源和刚才那个问题是同一个。两处指向的都是"卷积只算一次"这件事：正因为特征只算了一次、必须从同一张特征图上把各个区域抠出来，上一节才需要 RoI 池化把不同尺寸的 RoI 特征变成统一尺寸。

### 7.3 新的瓶颈：跑在 CPU 上的区域提议

Fast R-CNN 把 R-CNN 里重复调 CNN 这一步解决了，但它自己还有瓶颈。老师又把大家放回"站在一个时间节点上"的位置：你们现在手里已经有 Fast R-CNN 了，而且它的作者把代码和论文都公开给了你，起点就摆在这里，那么接下来该怎么办？

老师先让大家回头看"刚才几个耗时间的点"：Fast R-CNN 已经解决了重复调 CNN，那还剩下哪些地方比较耗时间？

**课堂问答**：一位同学回答"bounding boxes"。老师顺着这个回答讲下去：候选框的数量确实很多，而且"选框"这件事本身也要花时间。证据就是上面那两行时间——包括区域提议时是 2.3 秒，不包括时是 0.32 秒，两者差出接近 2 秒。在一个已经快到 0.32 秒的前向过程之外，光生成候选框就要花掉差不多 2 秒，说明这一步耗掉了相当多的时间。

更关键的一点是：这一步是在 CPU 上进行的。网络前向可以在 GPU 上并行加速，而区域提议仍然是一段跑在 CPU 上的传统算法，没有办法跟着网络一起被 GPU 加速。所以网络本身越快，这一步在总时间里的占比就越刺眼。

> **老师总结**：这一步选框的方式，是从遥远的传统目标检测时代带过来的，是从 SIFT、SVM 那个时代带过来的。带到今天还带着它，就有点不合适了，有点拖速度，是不是该抛弃它了。

老师顺着这个结论问下去："那我们是不是可以把这一步也挪个地方做？"于是就有了 Faster R-CNN。

### 7.4 Faster R-CNN 改的只是选框这一步

R-CNN、Fast R-CNN、Faster R-CNN 这三个名字是一脉相承的。老师顺带评价说，作者敢起这样的名字，说明他非常 confident（自信）。老师还提到，接下来的下一篇比 Fast R-CNN 更强，而由那一篇再延伸出来的后一篇才是真正更高的，那一篇拿到了 best paper，这几篇的含金量都非常高。不过这些是题外话，重点是让学生先自己想：站在这个节点上，你打算做什么。

Faster R-CNN 的做法是：前面没有动。网络的输入仍然是图像，中间仍然是 CNN 特征，后面仍然是 RoI 池化加分类、回归。它改的是选取 bounding box 的方式。

老师的讲法是一串追问，把"为什么必须改"逼出来：

- 你之前是不是在图像（image）上去选框？
- 你现在都已经有 CNN 特征了，为什么还要在图像上选？
- 而且还要拿 RGB 颜色相似度、纹理相似度这种传统的、落后了几个年代的特征去选这个框，是不是很不合理？
- 你都有 CNN 特征了，为什么不拿 CNN 特征来选这个框？

这条脉络讲清楚之后，Faster R-CNN 的思想其实很简单。有了特征之后，这份特征本来只用来做这一串事：把一个 RoI 区域抠（crop）出来，然后做分类，再做这个框的回归预测。既然特征已经在手上了，能不能拿同一份特征再做点别的事情？以前是根据 RGB 特征去选择候选框，现在就在 CNN 特征上，让网络自己去 proposal（提议）一些框。

### 7.5 区域提议网络（RPN）的作用

由此，Faster R-CNN 里设置了一个叫**区域提议网络**（Region Proposal Network, RPN）的结构。

> **老师提示**：RPN 这个我建议你们记住。等你们想去大厂面试的时候，那批面试官如果还是跟我差不多同年龄段的，他会认为你懂 RPN 是一个很正常的事情，随口就问一句"RPN 是什么"；你说不知道，这个就有点……

老师还补充说，这个时代可能会变：昨天看到有人说，他们公司以后不面 LeetCode 的那些题了。老师说自己当年准备面试的时候也觉得不该面，因为刷那些题的时候觉得跟学的东西没有任何关系；但到你们这个时代，可能真的会完全取消掉。

RPN 起的作用，要和以前的做法对着看才清楚。以前是在图像上随机撒一大堆框上去，再从这些框里获取、筛选候选区域；RPN 换了一个位置：先拿到特征，在特征上提取，也就是拿这份特征去 proposal 一些 region。

这样做更准，老师给了三条理由：

1. 以前第一步就是随机撒的，起点本身就不准；
2. 以前生成默认框的时候，依据的也是一些 RGB 特征，同样不特别准；
3. CNN 特征比 RGB 特征要准得多；而且在特征上做区域提议时，这份特征本来就带着语义信息，所以提议可以做得更好。

### 7.6 特征图上的一个位置对应原图的一大片区域

讲到提议具体怎么做，老师先让大家看清特征图和原图之间的尺度关系。假设从一张图像提取到了这样一份特征图，老师在特征图上圈出了一个小块，并强调：他画出来的这块看着是一小片，实际上只是特征图上的一个位置——猫的整个这一片区域，全都被压缩到了这一块里；而把这一块映射回原图时，它对应的是原图上很大的一片区域。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 59 页，这张图给出的具体尺寸是输入图像 $3\times640\times480$，经过卷积得到特征图 $C\times H\times W = 512\times20\times15$。这正是老师"一个位置对应一大片区域"这句话的数值依据：$640/20 = 32$、$480/15 = 32$，特征图的长和宽各缩小到原来的约 $1/32$，所以特征图上的一个位置对应原图上约 $32\times32$ 像素的一片区域，整只猫的区域被压缩进一个位置并不奇怪。这一条补全的是老师在此处未口述的具体尺寸。

正因为一个特征位置对应原图的一片区域，提议才有可能直接在特征图上做；至于在这个位置上具体怎么摆框、怎么定正负样本，是下一节的内容。

讲解到这里，老师宣布先休息一下。

## 八、RPN：锚框、正负样本与两阶段流程 [01:53:07–02:04:59]

### 8.1 从“在图上撒框”到“在特征图上撒框”

上一节留下的问题是候选框从哪里来。老师接着往下讲：照样是拿 CNN 把这幅图的 feature 提出来，提到这里，我们就有了一份特征。有了特征之后拿来干什么？这正是 RPN 要回答的问题。

先回头看以前的做法。以前那个 bbox 是直接撒在图上：在 RGB 图像上撒一堆框，然后让后面的流程自己去手工选。老师特别点出这一步的性质——框是“随机地往图上撒”的，撒在哪里、撒多大，与图里目标实际在哪儿没有关系，只能靠后面的分类器去筛。

有了特征图之后，做法换成另一种：在特征图的每个位置，设定一个固定大小的**锚框**（anchor box）。老师指着画面上一个蓝点说，以这个点为中心，我是不是就可以设一个框出来？既然以这个点能设，那么以每个点为中心，我都可以设一个框出来。

这样换的依据是：原来的做法本来就是在图上随机撒，靠撒得足够密来覆盖目标；现在改成“每个位置都撒一个”，覆盖候选区域的思路没有变，只是把撒框的平面从图像平面换成了特征平面。前面讲 RoI 映射时已经交代过，特征图上的一个位置对应原图上的一片区域，所以在这个平面上设框，和在原图上设框在“把目标圈进候选区域”这件事上作用相同。

那么这样设出来的框，能不能做和以前一样的事情？能。于是关键的一步是：我们不要在 image 上做，直接在 feature 上做。

把新旧流程并排起来看会更清楚。以前是：在图上先预设 box，提了 feature 之后，再把 box 映射到特征上、把对应的那一片特征抠出来，然后再问它是不是目标物体。现在在 RPN 里面，我直接在 feature 上弄这个 box，然后做同样的判断和校正。区别只在于框是在哪张“图”上生成的，以及生成之后还要不要再做一次映射。

> **老师强调**：这一步的关键，是把撒框这件事从图像上搬到特征上——“我们不要在这上面做，直接在 feature 上做”。

### 8.2 RPN 的两个输出：目标性二分类与边界框校正

在特征图的每个位置设出框之后，接下来要做的事情很自然，就两件：第一，判定这个框到底是不是目标（object）；第二，对这个框做一次校正。

老师把承担这件事的模块叫作**区域提议网络**（Region Proposal Network, RPN）。它的定位可以直接和上一代对比：Fast R-CNN 的候选框来自图像上的**选择性搜索**（selective search），RPN 的候选框则直接来自特征图；框的“选择”和“生成”都放到了同一份卷积特征上，不再是一个独立于检测网络的工序。

判断的顺序很关键：先不判断类别，只判断有没有 object。所以 RPN 里的分类是一个二分类，判断的是这个框里到底有没有包含目标，这个二分类输出通常称为**目标性**（objectness）分数。老师强调的正是这一点：先不管你是猫还是狗，先回答“这里有没有东西”。

正因为只做二分类加一个框修正，RPN 里面有两个损失：一个是 classification loss，另一个是**边界框回归**（bounding box regression）损失——前者判有无目标，后者把框的位置和大小往真实框上拉。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 61–62 页，RPN 在这两个分支上的输出是逐位置给出的：目标性分类的输出通道数为 1，形状为 $1\times 20\times 15$；边界框校正的输出通道数为 4，形状为 $4\times 20\times 15$，也就是特征图上每个位置回归 4 个数值，对应框的修正量。这里的 $20\times 15$ 是第 59 页给出的特征图空间尺寸（示例输入为 $3\times 640\times 480$，特征为 $512\times 20\times 15$）。

判完之后就分流：有 object 的，送到下一步；没有 object 的，直接在这一步淘汰。老师补了一句操作上的说法：判定完之后，把没有 object 的那些直接过滤掉，过滤掉之后剩下的才送到下一步。这一步的分流带来了整个流程最大的一笔时间节省，因为进入第二阶段的区域数一下子少了一个数量级。

以往 Fast R-CNN 的流程里，selective search 给出的候选框大约有两千个，这些框都要送进后面的分类与回归。老师问：根据新的特征判完之后，还会留下 2000 个 proposal 吗？肯定不会了，剩个 200 个就已经够多了。

> **老师总结**：这一步其实已经节省了非常多的时间，主要就节省在这里。

### 8.3 三个阶段回顾：框到底是在哪里选出来的

老师把这条演进线索完整重讲了一遍，因为“框在哪里选”正是三代方法的分水岭。

传统方法是三步：先在 RGB 图像上选 bbox，选完 bbox 之后用某种方式提特征，然后再做分类。在这种做法里，框和特征是两件互不相干的事：框在图像上选出来，特征在框里提出来。

R-CNN 把提特征这一步换成了 CNN：特征不再是手工设计的，而是学出来的。但代价是 CNN 要跑好多遍——因为每个候选框都要单独过一次卷积网络，框有多少个，网络就要前向多少次。

Fast R-CNN 换了顺序：先把整张图的特征提出来，再在特征上拿这些 box 去做对应的映射、把每个框对应的特征抠出来，然后再做分类。这样 CNN 只跑一遍，节省了很多时间。但老师指出它遗留的问题：这个里面它的 box 还是在 RGB 图上去选的——候选框仍然由图像上的 selective search 产生，与特征无关。

Faster R-CNN 做的就是把这最后一块也搬过去：把 box 的选择跟生成放到了特征上。而且它已经不是在随机选择了：它以特征图上的每一个点作为中心，去生成预设好大小的框；每个点生成的是九个不同的框。于是候选框的产生第一次变成了网络内部的一步，而不是图像上的一个外部算法。

九个框乘以位置数，量级是可以算的。老师举了个例子：假如特征图是 $8\times 8$，那就是 $8\times 8=64$ 个位置，再乘以 9，也就是五百多个框，也没有很多。这个数量级说明“每个位置都撒”在计算上是可行的，不必像以前那样只撒两千个然后全靠筛选。

当然，框撒出来之后仍然要判断：这个位置到底有没有前景、到底有没有 object。这一步就是 8.2 讲的二分类与过滤，也是 RPN 存在的意义。

### 8.4 锚框的形状与数量：九种预设与“金箍棒”

预设固定大小的框会立刻遇到一个问题，课上就有同学提出来：老师，你预设同样大小的 box，万一出现一个孙悟空的金箍棒那样长条状的物体，你弄个正方形的 box 怎么能行呢？老师把这个提问复述了一遍，说这么长条状的东西，拿一个正方形的框去套，怎么可能套得住。

老师的回答是：那就去预设不同形状的框。我们可以在同一个位置上预测出很多个不同形状的框出来——各种各样形状都备着，因为一开始谁也不知道这个物品长什么样子。老师把常见的形态归了归类：要么是瘦长的，要么是宽扁的，要么是正正方方的，大概就是这些样子。

具体到数量，课堂上的取法是每个位置预设 9 个锚框：大小不一样，长宽比也不一样，有的长、有的宽、有的扁。这 9 个框的作用不是直接给出答案，而是“大概先能把你框住”——先用一组覆盖典型形状的框把目标大致圈进去，再由 8.2 里的框回归把这个粗框修正准。这也是为什么回归分支在 RPN 里是必需的：预设框只负责覆盖，精度靠回归补。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 63 页，实践中在每个位置使用 $k$ 个不同大小/尺度的锚框，因此两个分支的输出通道数分别变为 $1k\times 20\times 15$ 与 $4k\times 20\times 15$；课堂上的取法即 $k=9$。同页与第 60 页都强调锚框是在特征图的每个点上设置的，这与老师课上“每个点为中心设一个框”的说法一致。

锚框设计留下了一个具体问题：这 9 个框的大小和长宽比到底怎么定。老师把它列为 RPN 的两个关键细节之一——就是 anchor 怎么去确定。

### 8.5 正负样本失衡与负样本采样

RPN 的另一个关键细节是训练时的正负样本采样。老师说，这个采样是一个很关键的问题，原因是数据分布本身极度不均衡。

论证是从日常拍照经验出发的：一张图里，正常人类拍出来的照片大概率没有那么多 object，不会说是密密麻麻的全是人——人正常拍不出那样的图。所以特征图上撒出来的大部分框，其实都没有框住 object，都落在背景上。

放到二分类的框架里看：一类是有 object，这是正样本；另一类是没有 object，这是负样本。既然大部分框落在背景上，负样本的数量就远远高于正样本，这样训练的时候就会失衡。所以负样本怎么采样，就成了训练 RPN 必须专门设计的一个问题。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 66 页，除去模型细节，Faster R-CNN 有三个关键设计问题：锚框是如何确定的、如何为训练 RPN 采样正负样本、如何参数化边界框回归；同页还说明，训练时不需要特别考虑互相重叠的框，重叠框由后处理中的**非极大值抑制**（Non-Maximum Suppression, NMS）解决。老师课上明确点到的是前两个问题。

### 8.6 计算方式对比：CNN 算几遍、proposal 从哪来

把三代方法放在一起，老师让大家看计算方式上的差别。这些差别可以归到五个维度上。

| 模型 | CNN 计算方式 | Proposal 方法 | 是否共享特征 | 主要瓶颈 | 速度 |
|---|---|---|---|---|---|
| R-CNN | 每个 RoI 各算一次 | 选择性搜索（selective search） | 不共享 | CNN 重复计算 | 极慢 |
| Fast R-CNN | 整图算一次 | 选择性搜索（selective search） | 共享 | proposal 阶段 | 较快 |
| Faster R-CNN | 整图算一次 | RPN | 共享 | 基本消除 | 快 |

这张表逐行读下来就是一条完整的因果链。R-CNN 里 CNN 对每个 RoI、每个 box 都要算一遍，这是它极慢的根源；Fast R-CNN 和 Faster R-CNN 都属于整图只计算一次，所以后两个直接就共享特征了。proposal 方法上，前两个用 selective search，第三个直接用 RPN。瓶颈也因此逐级转移：R-CNN 的瓶颈是 CNN 重复计算，Fast R-CNN 把重复计算消掉之后，瓶颈落到了 proposal 阶段，而 Faster R-CNN 用 RPN 把这块基本消除。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 68 页，这条演进的本质是“消除冗余计算，将目标检测流程逐步端到端化、网络化”。

时间上的效果，老师让大家直接看对比：从 R-CNN 往后几代看下来，region proposal 这一段的耗时“都没有了”，时间近乎等于零——因为 proposal 已经不再是一个独立的、要额外跑一遍的工序，而是长在检测要用的那份特征上。

那 Faster R-CNN 为什么比 Fast R-CNN 快？老师给的答案是：因为它的 bounding box 的选取更精细，而且更准也更少。更少这一点和 8.2 的数字对得上——不再是两千个候选框送进第二阶段，而是两百个左右；进入第二阶段的区域少了，后面的分类和回归自然就省了。

课上还插了一句题外话：R-CNN、Fast R-CNN 这几篇论文的引用量都是非常惊人的，老师建议同学自己去搜一下。

### 8.7 两次分类、两次回归：RPN 与检测头的分工

RPN 过滤之后剩下的框会被送到下一阶段。下一阶段做的事情，其实就是上一代 Fast R-CNN 做的事情：把框对应的特征选取出来，再做 classification，再做 bounding box regression。Faster R-CNN 并没有换掉检测头，它换掉的只是“框从哪来”。

因此整个网络里出现了两次分类和两次回归，它们的性质并不相同，这是老师特别提醒的地方。

> **老师强调**：虽然这两步都有 classification，但要注意，这一步（RPN）的 classification 是一个二分类，我只分类你有没有 object；而那一步的 classification 是一个多分类，直接给出具体是哪一类，你是 cat 还是 dog。

框回归同样是两次，但精度要求不同。RPN 那一次是“大概 regression 一下”，目的是把这个框提得大概准一点，够用就行；到检测头这一步，我已经确定你有这个 object 了，回归就会更精细一点。可以把它理解成由粗到精的两级修正：第一级负责把候选框从“勉强套住”拉到“大致对准”，第二级负责在已确认有目标的前提下把框修准。

| 阶段 | 分类 | 回归 |
|---|---|---|
| RPN | 二分类：有无目标（object / 非 object） | 把预设锚框修正到大致对准目标 |
| 检测头 | 多分类：具体类别（如 cat / dog） | 在已确认有目标的前提下精细修正框 |

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 64 页，Faster R-CNN 的联合训练目标包含四个损失：RPN 分类物体/非物体、RPN 回归框坐标、最终分类分数（物体类别）、最终框坐标。结合第 67 页给出的流程——第一步每张图像运行一次 backbone network 与 region proposal network，第二步对每个区域运行一次——可知这四个损失训练的是同一套共享特征，而不是两套彼此独立的网络。

### 8.8 为什么叫“两阶段”：流程总结与一阶段方法的提出

把上面几步合起来，就能回答“它为什么叫两阶段”。老师让大家自己先想一下，然后给出答案：所谓两阶段，就是我先要找到 box——也就是先确定感兴趣区域（region of interest, RoI）在哪里——再对这个 box 进行一个分类跟回归，所以分成了两个阶段。

> **老师总结**：虽然这几个方法都有改进，但它绝对都是这样的一个范式——我得先确定我的 RoI 在哪里，然后再在这个 RoI 的基础上，对这个区域进行一个分类，以及 box 的一个回归。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 67 页，Faster R-CNN 的两步分工可以写得很具体。第一步，每张图像运行一次，包含 backbone network 与 region proposal network；第二步，每个区域运行一次，包含三件事：裁剪特征（RoI pool / align）、预测物体类别、预测边界框偏移量。这与老师讲的“先找框、再对框分类回归”完全对应。

讲完这个范式，老师马上提出了反问：但有没有可能我们不要这种方式？每次都要设计一堆的 box 撒上去，然后去选哪个 box 是准的，你不觉得很烦吗？我们能不能不要这种方式——就像 classification 一样，整张图直接出它是哪个类别；那我整张图直接出你的 box 在哪，行不行？

这就引出了后面要讲的**一阶段**（one-stage）检测方法。它的开山鼻祖，老师相信大家一定听过：**YOLO**，全称 You Only Look Once。老师点评说，当年这个作者起名也很大胆，是一个非常文艺的名字，简写就叫 YOLO，并顺口把它念成了“优秀”。YOLO 做的就是这样一个一阶段的方法。

那么一阶段方法和两阶段方法大概差在哪里？老师把判别标准说得很干脆：关键点在于是否生成这个 proposal。两阶段方法要先生成 proposal——也就是你的那一群 box——先生成，再进行分类和回归；YOLO 不需要做这一步，也不需要这么麻烦，它直接给你统一回归，预测方式是一种密集（dense）的预测。

到这里，两阶段这条线就收束了：从 R-CNN 在图上选两千个框、逐个跑 CNN，到 Fast R-CNN 整图算一次特征、再把框映射上去，再到 Faster R-CNN 把框的生成也交给特征图上的锚框与 RPN，冗余计算被一步步消掉，最后只剩下“每个位置一组锚框、一次前向出分类与回归”这一件事。而下一节要讲的 YOLO，正是沿着“把这件事一次做完”的方向再往前走一步。

## 九、YOLO：一阶段检测与网格分配 [02:05:00–02:20:01]

### 9.1 一阶段与两阶段：proposal 是分水岭

**YOLO**（You Only Look Once，你只看一次）是**一阶段检测**（one-stage detection）的代表性方法。老师说这个名字起得很大胆，也很文艺——把"只看一次"直接写进了名字。与之相对，前面讲的 R-CNN 系列属于**两阶段检测**（two-stage detection）。

两条路线的差别不在名字，而在**是否生成 proposal**。两阶段方法要先产生 proposal——也就是**区域提议**（region proposal），本质上是一批候选框——再对这些框做分类和回归：先生成框，再判断框里是什么、把框调准。YOLO 不做这一步，它把类别和框一起"统一回归"出来。用老师的话说，两阶段是"先生成再进行一个分类回归"，而 YOLO 是"我直接给你统一回归"。

这决定了两种方法在预测形式上的区别：两阶段的预测是**稀疏**的，只在 proposal 覆盖的那些位置上做判断，整张图的绝大多数位置并不参与；YOLO 的预测是**密集**的，图上每一个位置都要给出自己的预测。课件第 71 页用一张表把这几个维度并列起来：

| 维度 | R-CNN 系列 | YOLO |
|---|---|---|
| 检测范式 | Two-stage | One-stage |
| 是否生成 proposal | 生成 | 不生成 |
| 建模方式 | 分类 + 回归 | 统一回归 |
| 预测形式 | 稀疏 RoI 预测 | 密集预测 |

### 9.2 速度从哪来：去掉"先产框"的多步流程

讲 YOLO 的速度之前，老师先让大家回想 R-CNN 这一路都在解决的一个瓶颈：proposal 怎么来。Fast R-CNN、Faster R-CNN 一路改进，始终绕不开"必须预先产生 proposal"这件事——要先把一堆候选框提出来，再做后面的分类和回归。这个"预先产生框"的方式**很耗时间，也很不优雅**。

对比一下分类就很容易看出问题。分类网络多简洁：设一个 CNN，input 一张 image，直接输出一个 classification 的结果就行了，一步到位。而做目标检测，中间还要插"先扫一遍""先把车大概框出来""再去做分类"这些步骤，这是一步、那是一步，设了很多步。

于是自然的问题就是：有没有更优雅的一些方式？能不能把"先产框再分类回归"的多步流程，压成一次前向就出结果的过程？这就是 YOLO 要回答的问题。后面老师放网络结构图时也给过提示：这个网络看起来和分类网络很像，并没有额外延伸出什么特别的分支。所以 YOLO 的关键并不在于网络结构上多加了什么分支，而在于把框的预测也并进了这一次端到端的前向里。

### 9.3 代价是精度：快而不准的取舍

课件第 72 页是一张二维图，一个轴是精度，一个轴是速度。YOLO 在刚被提出来的时候，直接一步对标了当时速度最快的检测器：它的速度一下子上去，但精度也一下子掉了很多。

> **老师总结**：这就是 YOLO 的特点——我很快，我虽然不准，但是很多情况下你不需要那么精准。

"不需要那么精准"不是一句搪塞，老师给了很具体的场景：你不需要一定把这个人的左边胳膊和右边胳膊都分别框出来，只要把他大概这个主体框出来就行了；框得差一点也没事；小一点的东西漏掉就漏掉了。在这类"只要知道有这个东西、大概在哪"的场景下，用 YOLO 就会快很多。这也正是它拿精度换来的速度真正值钱的地方：很多任务要的不是把每个细节都框准，而是足够快地知道"有这个东西、大概在哪"。

### 9.4 一段插曲：逐像素分类为什么替代不了目标检测

在正式给出 YOLO 的做法之前，老师先把一条"看起来更优雅"的路讨论掉了：既然两阶段的瓶颈是产框，那能不能干脆不要框，直接分类特征图上的每个特征？特征图上的每个特征相当于一个像素，所以这就等于对每个像素做分类。老师说这条路真的可以，但它属于几周后要讲的**语义分割**（semantic segmentation）；而且它一出来就带着一个问题。

这个问题被老师称为**接口**问题。

> **老师启发**：你把每个像素都分类了，你知道这个像素是猫；可是我要的是这只猫的准确位置——你怎么把这只猫的位置告诉我？

这不是修辞，老师带着大家实际走了一遍：你问我这个像素是不是猫，我告诉你是；再问我另一个像素，我告诉你不是；可我一问你"猫的位置"，让我描述一下——就描述不出来了。

老师接着复述了刚才课堂上一位同学的想法（字幕未记录学生原话）：我清楚地知道哪些像素是猫、哪些像素不是。老师说这个想法很直观，因为人的大脑会自动完成从 mask（掩码）到位置的那一步转换——看到这一片像素是猫，位置自然就在脑子里了。但计算机不知道：你把这么一组像素标签存在它那里，它也不知道该怎么描述这只猫的位置。

检测的输出不是这样。检测直接告诉你坐标位置：左上角坐标在这里，右下角坐标在这里，你记住这四个数就行了。所以分割即使已经具备了这个任务的能力，也没有完全替代掉目标检测——两者的接口不一样：一个交给你一张 mask，一个交给你四个数。

现实中的理由还有两条。第一，比如车在路上走的时候，需要清楚地知道每个目标的坐标在哪里；如果用分割那种方式，坐标转换有点问题。第二，把每个像素都分类，要付出的计算代价是几倍的增加，速度会很慢。而这里想要的正是一个非常快、而且轻量化的检测方式。

### 9.5 答案：把图像划成 S×S 网格

老师说"逐像素"这个思路已经很接近了，然后把问题收回到 proposal 上：以前要先把 proposal——也就是一个个 box——预设出来，再去做对应的分类；现在不想这样做了，那怎么办？

这里先插一句 YOLO 的分量。YOLO 大概是 2017 年提出来的，到这门课上课时已经过去了近十年，还有人在研究 YOLO，还有人在靠 YOLO 发论文，从这一点就能看出这篇论文的影响力。

YOLO 的答案是把这张图划成 $S\times S$ 个区域。老师展示的例子是一个 $7\times7$ 的区域；无论哪一张图，都可以给它划成这样一个区域。划完之后，最终想要的输出仍然是那个样子——车、自行车、狗分别被一个框框出来。

这一步老师没有先讲，而是把答案先放在屏幕上，给大家 5 秒思考，看能不能看懂。

答案是"粗糙的区分"。但粗糙的区分只解决了"这个位置大概是什么"，还没有解决框。老师用自行车说明这一点：自行车的形状大概是那个样子，可你只能告诉我这个位置是自行车、那个位置也是自行车，你还是没法把 box 输出给我。所以网格分类只是把定位问题变粗了一层，最终还是要每个格子给出一个"最明显的位置"的 box——这就引出每个格子要回归四个数。

### 9.6 训练：把每个 ground truth 分给中心所在的网格

在 R-CNN 系列里，proposal 是 box 的一个初始值，后面再对这个框做分类和回归。YOLO 的主张更进一步：box 也应该作为网络端到端（end-to-end）去预测的一部分。那么这件事怎么做？

关键在于训练时手里有**真值**（ground truth，下称 GT）。老师强调，它不像之前那样"我先扫一遍，把车大概框出来，然后再去做分类"；训练时我们本来就有 GT，于是可以事先规定好谁负责谁：

看这个方格——它大概是不是这个自行车的一个中心（老师也说"质心"）？规定这个位置之后，对应的那个 feature 负责的任务就是输出这个 box；我们把 GT 的那个值，也就是 bounding box 的 GT 值，直接分给这个位置。狗也一样，分给狗中心所在的格子，由它来预测这个 box 是什么。

为什么需要这样一条人为的规则？因为以前虽然手里有 GT 的 box，却不知道这个 box 该跟哪个 feature 对应——box 框的是这一整块区域，不像分割里一个像素可以直接对应到某个类别。也就是说，"把 feature 和 GT 关联上"本身就是一个需要设计的问题，不是数据里天然带着的。

> **老师比喻**：这就像一个家庭里有很多人要继承遗产，之前没有规定好到底由谁来继承，那你去分配的话，每个人都可以去争；现在只有一个 ground truth，那就规定站在这个家最中心的那个人，由他直接来继承。

分配清楚之后，被选中的这个格子要预测两件事：一件事情是类别是什么，另一件事情是 box 长什么样。这其实又回到了前面讲单目标检测的情形——一个 object、一张 image，出来一个 2048 维的 feature，它既预测类别，又预测 bounding box。区别只在于：现在虽然 GT 框有这么大，但其他位置不要争，就用这个中心位置去预测它的类别和框；其他地方你就不要管了，不要瞎掺和——至少在训练的时候，我们可以这样给他规定好。

**例子**：一张图里有车、自行车、狗三个目标，于是就有三个 label。每个 label 是四个数字（框的坐标）加一个 class（类别），三个 label 要在这张图的 $7\times7$ 网格上分配：车、自行车、狗各自中心落入的格子，分别拿到对应目标的四个坐标和类别；其余格子什么都不分配。这样，"整张图只有一个目标"的单目标检测，就被拆成了"每个格子最多负责一个目标中心"的密集预测。

### 9.7 推理：每个网格都输出类别与框

训练时靠 GT 决定谁负责谁；等 inference 的时候，也就是真正拿它来用的时候，我们就没有这种映射关系了，因为我们没有 GT。

那推理时凭什么决定哪个格子该输出？老师的理由是数据分布：在整个数据集里面，自行车可能在哪里都会存在，每个点都可能成为那个中心点。既然如此，推理时每个小方块都可以去 output 一个预测、一个 box。

于是每个位置都有两个输出：一个是分类，一个是 box。输出里还带一个**置信度**（confidence）——它对自己这个判断有多自信。采信的逻辑很直接：我选了你、我相信了你，把你的类别选下来之后，你的 box 我也同样去选，你去输出你的 box 就行了；因为这里输出的 box 就是一个四数字，直接再画出来就行。

训练得好不好，会直接反映在这份 confidence 上。如果没训练好，那些高亮的格子会全都"很 confident"，都是 0.99999999 这样的值，于是我们就会在同样的位置输出好多 box——老师说，这个就属于没训练好。训练好的话，情况应该是：目标中心那个格子的 confidence 是 0.99，而它周围的格子可能是 0.6、0.5、0.2 这一档。这时按 confidence 卡一个阈值，把高的选出来，剩下的就过滤掉，大概是做这样一个事情。

回到整体，老师收束说这套方法其实很直接，就是刚才那位同学讲的思路：每个位置都输出一个类别；但检测最重要的是 box，所以每个位置在输出类别的同时，也要让它输出一个 box。也就是说，每个位置预测两件事——一个预测它的 box，一个预测它的类别。至于训练时怎样把这套"谁负责谁"的分配写成一个可优化的目标，就是紧接着的损失函数要处理的事情。

## 十、YOLO 的损失函数 [02:20:01–02:25:01]

上一节把 YOLO 的网格分配讲完了，这一节看它的训练目标到底怎么写成一条损失。老师用一句话把上一节的落点接了过来：每个网格位置都负责“既输出类别、又输出 box”这一整套事情——每个位置输出类别的同时也要让它输出一个 box，所以它其实是在预测两件事，一件是 box，一件是类别。剩下的问题就是：训练的时候，怎么用一条损失把这些位置的输出管起来。

老师接着交代了这条损失的来路：刚才讲训练的时候，重点就是“这个怎么分配”，而接下来要给大家看的就是损失函数。

### 10.1 公式很长，但要记的是思想

老师把损失函数摆出来时的第一句话是“长这个样子，很长”，紧接着就交代了态度：不用担心，也不用去记，主要是记这个思想——这一点他反反复复强调过。理由也讲得很直接：这门课不考试，但他希望学生真的从里面学到一些东西，成绩之类的没有什么好去担心的。

> **老师强调**：这个 loss 很长，不用担心，也不用去记，主要是记它的思想。

所以下面按老师讲解的顺序看这条公式：先看那几个乘在各项前面的 0/1 指示函数是怎么切分责任的（谁负责谁），再看含目标和不含目标的两类 confidence，最后看真正做坐标回归的那一项、以及它前面挂的那个权重。

### 10.2 损失函数的整体形式

幻灯上给出的训练损失是一个五项相加的平方误差和：

$$
\begin{aligned}
L=&\ \lambda_{\text{coord}}\sum_{i=0}^{S^{2}}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\text{obj}}\left[(x_i-\hat{x}_i)^{2}+(y_i-\hat{y}_i)^{2}\right]\\
&+\lambda_{\text{coord}}\sum_{i=0}^{S^{2}}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\text{obj}}\left[(\sqrt{w_i}-\sqrt{\hat{w}_i})^{2}+(\sqrt{h_i}-\sqrt{\hat{h}_i})^{2}\right]\\
&+\sum_{i=0}^{S^{2}}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\text{obj}}\left(C_i-\hat{C}_i\right)^{2}\\
&+\lambda_{\text{noobj}}\sum_{i=0}^{S^{2}}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\text{noobj}}\left(C_i-\hat{C}_i\right)^{2}\\
&+\sum_{i=0}^{S^{2}}\mathbb{1}_{i}^{\text{obj}}\sum_{c\in\text{classes}}\left(p_i(c)-\hat{p}_i(c)\right)^{2}.
\end{aligned}
$$

记号的含义先摆清楚：$i$ 遍历 $S^{2}$ 个网格，$j$ 遍历每个网格里预设的 $B$ 个框；带 hat 的量是网络的预测，不带 hat 的量是训练目标的真值；$(x,y)$ 是框的中心，$(w,h)$ 是框的宽高，$C$ 是 confidence，$p_i(c)$ 是类别 $c$ 上的预测概率；$\mathbb{1}$ 是指示函数，条件成立取 1、不成立取 0。

这套 $\mathbb{1}$ 是整条公式里最要紧的地方：它决定了某一项在某个位置上到底算不算——也就是老师反复讲的“分配”。下面按幻灯片上标注逐步加上去的顺序（先中心判断与类别，再不含目标与含目标的 confidence，再 box 级责任，最后边界框预测）逐项看。

### 10.3 谁负责：中心落在网格里才算

公式里最先出现的判断是“是否有 object 的中心落在网格中”，也就是乘在类别项前面的 $\mathbb{1}_{i}^{\text{obj}}$。老师讲得很直白：我们要求每个 object 由它的中心去负责这个 object。

反过来的一面，老师用一只狗讲清楚了：训练时可能出现这种情况——那只狗的中心并不在这个格子里，只是它的左前爪伸进来、落在你这个网格里；那这个格子就不要去干扰，你就不要去负责预测它。所以这一项判断的实质是：这个格子是不是目标中心所在的位置。中心落在里面，$\mathbb{1}_{i}^{\text{obj}}=1$；只是被目标的某一部分压到，$\mathbb{1}_{i}^{\text{obj}}=0$，这个格子对那个目标既不算类别误差，也不算“这里有东西”的 confidence 误差。

最后一项就是把这条规则用在类别上：

$$
\sum_{i=0}^{S^{2}}\mathbb{1}_{i}^{\text{obj}}\sum_{c\in\text{classes}}\left(p_i(c)-\hat{p}_i(c)\right)^{2}.
$$

老师在这里问过一句“我们判断类别这步干的是什么”，答案就是他刚讲的那条分配规则：不是每个格子都各自猜一遍图里有什么，而是只有中心落进来的那个格子，才被要求对类别负责。式子里的求和次序也说明了这一点——先按网格求和、乘上网格级的 $\mathbb{1}_{i}^{\text{obj}}$，再在类别的维度上逐个类别算平方误差。

### 10.4 不含目标的框：confidence 要压下去

幻灯片在“中心判断”和“类别预测”之后加上的下一条标注，是“不含 object 的 box 的 confidence 的预测”，对应公式的第四项：

$$
\lambda_{\text{noobj}}\sum_{i=0}^{S^{2}}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\text{noobj}}\left(C_i-\hat{C}_i\right)^{2}.
$$

老师解释这一项时反复用的词是“你有多 confident”：这一项要模型回答的是“这个 box 里到底含不含 object”。对不含目标的框来说，正确答案是“不含”，所以训练就是把它输出的 confidence 往 0 上压——压得越接近 0，说明网络越清楚这里是背景。

这一项管的框在一张图里占了绝大多数，这也正是它前面挂了一个权重 $\lambda_{\text{noobj}}$ 的原因（见 10.9）。

### 10.5 含目标的框：confidence 要顶上来

紧接着的一条标注是“含 object 的 box 的 confidence 的预测”，对应公式的第三项：

$$
\sum_{i=0}^{S^{2}}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\text{obj}}\left(C_i-\hat{C}_i\right)^{2}.
$$

老师对它的说法是：“你有多 confident，你这个 box 里面包含了 object。”也就是说，被指定负责的那个框要很自信地表示“我这里确实有东西”，训练目标就是让这个 $C$ 往 1 上靠。

这一项和 10.4 的那一项合起来，其实是同一个数 $C$ 的两面：有目标的框要把 confidence 顶上去，没有目标的框要把 confidence 压下去。两边的监督都到位，检测时一个 $C$ 就能把绝大部分背景框挡在门外——按 confidence 卡阈值筛选候选框，是上一节已经讲过的事。

### 10.6 哪个框负责：网格里的第二层判断

幻灯片最后补上的一条标注是“判断第 $i$ 个网格中第 $j$ 个 box 是否负责这个 object”，它指向的正是坐标项前面的 $\mathbb{1}_{ij}^{\text{obj}}$。

老师强调这里是两层判断叠在一起：10.3 讲的 $\mathbb{1}_{i}^{\text{obj}}$ 只回答“这个网格要不要管”，而 $\mathbb{1}_{ij}^{\text{obj}}$ 还要回答“这个网格里的哪一个框来管”。一个网格预设了 $B$ 个框，而一个目标最终只由一对 $(i,j)$ 负责——具体是哪一对，由上一节讲的训练分配决定，公式里只把这个结果写成一个 0/1 系数。

这也解释了坐标项为什么乘的是 $\mathbb{1}_{ij}^{\text{obj}}$ 而不是 $\mathbb{1}_{i}^{\text{obj}}$：只有负责的那个框才参与坐标回归，同一个格子里其他的框不去拟合这个目标的坐标，免得一个目标被几个框同时“抢着”回归。

### 10.7 五个加项其实在做同一件事：分配

看完整条公式，老师给了一个整体判断：这里面反反复复出现的很多 loss 项，都是在强化、或者说在实现他刚才讲的那种分配思想。他把话说得更具体：我这里就只有三个 ground truth，但是有这么多位置要去继承这个 ground truth，所以我要分配好——只有你能继承这个，只有你能继承那个。这里说的“三个 ground truth”，是指一张图里真正的目标只有三个。

> **老师强调**：损失函数来来回回做的就是这件事——只有三个 ground truth，却有这么多位置要去继承它，所以要把“只有你能继承这个”分配好。

所以读这条长公式的顺序应该是：先看乘法前面的那些 0/1 指示函数怎么切分责任，再看每一项在各自被分配到的责任范围里算什么。五项不是五个互不相干的误差，而是同一条分配规则在五个位置上的重复：哪些格子管中心、哪个框管坐标、哪些框该报“没有东西”，都由 $\mathbb{1}$ 事先定好，然后才轮到平方误差去算。

### 10.8 边界框坐标项与宽高开根号

讲到“到这步才是我们正常的那个 box 的一个预测”，对应的就是公式的前两项：

$$
\lambda_{\text{coord}}\sum_{i=0}^{S^{2}}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\text{obj}}\left[(x_i-\hat{x}_i)^{2}+(y_i-\hat{y}_i)^{2}\right],
$$

$$
\lambda_{\text{coord}}\sum_{i=0}^{S^{2}}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\text{obj}}\left[(\sqrt{w_i}-\sqrt{\hat{w}_i})^{2}+(\sqrt{h_i}-\sqrt{\hat{h}_i})^{2}\right].
$$

前面几项都在处理“谁负责”和“有没有目标”，到这两项才真的在拟合框的位置和大小。老师让学生注意一个细节：$w$ 和 $h$ 上面是不是加了根号？加了，为什么要加？

答案是为了防止有些 box 过大、有些 box 过小。直接拿宽高算平方误差，过大和过小会在损失里造成一个不平衡（unbalance）。

**例子**：老师用两个尺寸极端的框来说明这件事。一个 box 是 $100\times 100$，另一个是 $0.01\times 0.01$。直接对宽高算误差时，两者的量级相差 $10^{4}$ 倍；开根号之后，大的那个变成 $10$ 和 $10$，小的那个变成 $0.1$ 和 $0.1$，差距一下子被拉到 $10^{2}$ 倍。老师说“它会极快地拉近”——这样大框和小框的宽高误差在损失里就能落在比较接近的量级上，不至于被大框那一方完全主导。

老师也补充了一句：实际检测中不会出现这么极端的 box，举 $100\times 100$ 和 $0.01\times 0.01$ 只是把“为什么要开根号”讲到看得见。

另外从公式结构上可以看到，开根号只加在 $w$、$h$ 上，$x$、$y$ 是直接做平方误差的。

### 10.9 两个权重：放大坐标项、压低背景项

整条公式里只有两处乘了额外的系数，都用 $\lambda$ 表示：

| 权重 | 出现位置 | 作用 |
|---|---|---|
| $\lambda_{\text{coord}}$ | 两个坐标项前面（$x,y$ 项一次，$\sqrt{w},\sqrt{h}$ 项一次） | 把坐标误差在总损失里的份量整体调高 |
| $\lambda_{\text{noobj}}$ | 不含目标的 confidence 项前面 | 把背景 confidence 项的份量整体调低 |

为什么要多加这两个系数，老师前面那套“分配”的说法已经给了背景：一张图里真正的目标只有三个，绝大多数框都是不含目标的背景框。如果五项按同样的份量直接相加，数量上占绝对多数的背景项就会把总损失主导，坐标项那点误差相对显得无足轻重；把坐标项放大、把背景项缩小，才能让“把框的位置和大小分对”这件事在总损失里保有足够的分量。

需要说明的是，幻灯片上这两个权重只写了符号，并没有给出具体数值，所以这里只讲它们各自管哪一项、往哪个方向调，不写具体取值。

### 10.10 讲完损失：YOLO 快到什么程度

讲完损失函数，老师转到对 YOLO 的整体评价上，这里先说的是它的优势——检测速度非常快。

具体数字是：GPU 上的增强版能跑到 45 FPS，简化版可以到 155 FPS。为了让人对这两个数字有感觉，老师花了不少篇幅讲人眼对帧率的要求：

1. 人眼看一个视频，大概 3 到 5 FPS 就已经觉得它是一个连续视频了；
2. 如果非要追求电影院那种级别，那就得上到 60 FPS；
3. 一般情况下，即使抽帧抽得很严重、掉帧掉得很厉害，只要还在 3 FPS 上下，眼睛也能接受。

原因是人眼会自动脑补：一个画面被看到之后，在眼睛和大脑里是有一个停留时间的；只要在这个停留时间消失之前把下一张换上来，眼睛就会觉得这是一个连续的视频。

所以 45 FPS 对人眼来说已经应接不暇，155 FPS 更是远远超出需要——老师反问了一句，你每秒怎么可能看到 155 个 FPS。他顺带把这个缩写讲清楚：FPS 是 frame per second，就是每秒能处理的帧数；155 FPS 就是每秒处理 155 帧、也就是 155 张图。作为参照，手机正常拍视频一般会预设 30 FPS 的帧率。

更往下关于 YOLO 优势与劣势的讨论，由下一节接着讲。

## 十一、YOLO 的优缺点与系列演进 [02:25:01–02:29:59]

前面把 YOLO 的检测框架和损失函数讲完之后，这一节要回答两个问题：这样一个一阶段检测器到底好在哪、差在哪；以及它从 2016 年之后是怎么一路演进到今天的。讲完这两点，才能说清 YOLO 在检测方法版图里的位置。

### 11.1 速度的量级：45 FPS 与 155 FPS 对人眼意味着什么

YOLO 的卖点首先是速度：增强版在 GPU 上能跑到 **45 FPS**，简化版能跑到 **155 FPS**。

**FPS**（Frames Per Second）就是每秒能处理的帧数，也就是每秒能处理多少张图。155 FPS 表示一秒能吃进 155 张图像。而人的眼睛根本用不到这个速率：45 FPS 人眼就已经应接不暇了，每秒怎么可能看得了 155 帧？

人眼之所以“看不出”掉帧，是因为视觉有停留时间：一张画面进到眼睛里，大脑里会有一段停留时间，只要在这段时间消失之前把下一张换上来，大脑就会自动把它**脑补**成连续的视频。所以掉帧、抽帧抽得很严重的时候，肉眼往往也察觉不到。

把这条常识放回实际的视频帧率，就很容易理解 45/155 FPS 为什么算得上实时：

| 场景 | 常见帧率 | 课堂说明 |
|---|---|---|
| 手机正常拍视频 | 30 FPS（预设） | 手机默认的预设帧率 |
| 运动相机 | 可设 60 FPS | 追求运动相机时的设置 |
| 短视频平台 | 常被抽帧到十几 FPS | 为降低存储而抽帧，用户看不出差别 |
| YOLO 增强版（GPU） | 45 FPS | 人眼已经应接不暇 |
| YOLO 简化版 | 155 FPS | 每秒 155 张图，远超人的感知需要 |

这也解释了为什么“每秒 155 张”这样的数字在检测任务里是可以被接受的：手机正常拍视频预设的帧率就是 30 FPS，短视频平台为了省存储还会把帧率抽到十几 FPS，而模型每秒能处理 155 张，处理速度已经远高于视频本身播放的速度。

### 11.2 优势一：利用整张图的上下文，而不只是框内的特征

YOLO 作为一个整体做全图预测的模型，检测时是“做一个全图的内容”——它一次前向就把整张图的特征算出来，再用这些特征给出所有框和类别。

这一点正好是它与两阶段方法（R-CNN、Fast R-CNN、Faster R-CNN）在信息使用上的分水岭。两阶段方法是先把 box 框出来，再在这个 box 区域里面用该区域的 feature 去做分类：物体框之外的像素，对这次分类基本没有贡献。YOLO 不是这样——它看到的永远是整张图，某个 box 之外的内容虽然不直接属于这个物体，但它会通过整图的卷积特征**间接**地参与到预测里。

这个“间接使用”带来的直接好处是：模型在判断某个位置有没有物体时，手里握着的是整幅画面的证据，而不是孤立的局部纹理，所以它不容易在背景上预测出错误的物体。

### 11.3 优势二：学到更泛化的物体特征，非自然图像上的检测率更高

正因为 YOLO 是在整图上下文中学习物体，它抓住的更像是“物体这个概念本身”，而不是某个固定窗口里的局部纹理，所以老师用一句话概括：它**可以学到物体的泛化特征**。泛化特征带来的结果是，它对非自然图像（不是相机实拍得到的图像）的检测率要远远高于之前那个检测系列。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 84 页，YOLO 的三条优势被概括为：检测速度非常快（增强版 GPU 上 45 FPS、简化版 155 FPS）；检测时能很好地利用上下文信息，从而不容易在背景上预测出错误的物体信息；可以学到物体的泛化特征，对非自然图像物体的检测率远远高于 DPM 和 R-CNN 系列检测方法。此处用来补全字幕中“之前的这个检测系列”的具体所指。

### 11.4 不足一：早期版本的精度远低于两阶段方法

YOLO 的劣势也很明显。首先是精度：早期 YOLO 的精度**远低于** Fast R-CNN 这类两阶段方法。

这个差距在当年的论文写法上留下了一个很有意思的痕迹。YOLO 系列在 CVPR 2017、2018、2019 上发论文时有一个共同特点：结果表一定要拆成上下两部分——上面那一部分是 two-stage 方法，下面那一部分是 one-stage 方法。为什么要这么拆？因为它比不过 two-stage 的精度，没有人家方法的结果高，于是干脆**单拉一个赛道**：one-stage 的卖点就是我速度快，那只跟速度快的这一批方法比；在速度快的这批里面，如果我的精度最高，那就可以说我的方法更好。

所以看 YOLO 早期的实验表，它的“最好”通常是在“同为实时方法”这个子集里的最好，而不是在所有检测方法里的最好——这个拆分不是排版习惯，而是由精度差距逼出来的自我定位。

### 11.5 不足二：容易产生定位错误

除了整体精度，YOLO 早期版本还有一个具体的短板在“框得准不准”上：它容易产生定位错误，也就是类别判对了、但框的位置或大小有偏差。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 85 页，“容易产生定位错误”被列为 YOLO 的一条不足。课堂口述在这条上只讲到精度远低于两阶段方法，以及后面密集小物体、重叠目标两点，没有逐句展开定位误差；此处按材料补全“YOLO 的不足”这一知识点。

### 11.6 不足三：密集的小物体几乎无法处理

第二条明显的短板是密集的小物体。这个结论不是经验之谈，而是可以从 YOLO 的预测分配方式直接推出来的。

YOLO 的训练方式是：物体落在某个网格单元的中心上，就由那个落在中心的单元来负责它的预测。也就是说，一个网格单元要同时承担“落在它中心的那些物体”的类别预测和边界框预测。这套机制里其实已经悄悄假设了这个物体比较大——老师给出的尺度下限大致是 $32\times32$ 像素这个量级。

一旦物体小到、密到超出这个假设，问题就来了。老师举了两个夸张但很直观的场景：

- 一只狗的狗腿子踩进一个蚂蚁窝，那一小块地方有 1000 只蚂蚁；
- 一辆车的车顶落了一堆鸟，假设落了 100 只鸟，全集中在这一块。

这两种情况在画面上的共同点是：成百上千个目标全部挤在同一个很小的区域里。按 bounding box 的 ground truth 分配方法，这一千个（或一百个）小目标都得分给那一个区域，于是这个区域就要负责 1000 个 object 的类别和 1000 个 bbox 的预测。而一个网格单元能输出的预测数量是固定的，它根本不可能同时把这些全预测出来。

所以结论很硬：物体如果过小、过于密集，YOLO 是没有办法处理的。这不是调参能解决的问题，而是它的训练方式、它的 ground truth 分配方式决定了它处理不了这类目标——它要求物体本身必须比较大。

### 11.7 不足四：重叠目标的中心冲突

还有一类情况也不好处理：两个目标的中心恰好落在同一处。

老师用两只狗来说明。假设这里站了两只狗，差不多重叠在一起；或者让另一只狗跟它镜像一下，两只狗这样交叉着站。这时候它们的中心位置是不是都在这一个点上？那么这一个中心位置对应的单元，就必须要预测两只狗——既要给出两只狗的类别，又要给出两个各自的框。

> **老师比喻**：这就像分家产——别人家是好多人去争一份家产，这里是让一个人去继承两份家产。

这个比喻点出的是“容量冲突”：一个预测单元被要求承担两份彼此独立的输出。

有一点值得注意：这类失败只在中心**恰好**重合时才严重。如果其中一只狗稍微往旁边偏一点，它的重心就落到另一个单元上，两只狗就能分开处理了。可如果它们就是很完美地这样交叉着、甚至是重叠着，两个中心压在同一处，那就不好处理了。老师最后的判断是：YOLO 有它明显的缺点。

### 11.8 系列演进：从 v1 的端到端到 v5 之后的工程化

YOLO 这个系列并不是停在 v1。老师特意强调，它其实真的是一直一直在发展，到现在还有 YOLO26——而且要注意，这个“26”不是第二十六代，它是 2026 的 26，是按年份命名的版本。

从实际使用看，这个系列在工程圈里非常常见：早年学院组织个小比赛，或者去外面参加个小比赛，大家用得最多的一般是 YOLOv7、v8。版本序号一路排下来是 v1 → v2 → v3 → v4 → v5 → v6，中间还有过 YOLO9000 这样的名字。

几代关键技术变化可以按顺序理清：

1. **YOLOv1：端到端回归预测。** 第一代 YOLO 就是一个端到端的回归预测模型：输入图像直接回归出框和类别，不需要先做区域提议，这也是它能做得这么快的根本原因。
2. **YOLOv2（YOLO9000）：把锚框（anchor）机制引回来。** 第二代把锚框机制重新引回一阶段框架里。之所以要“引回来”，原因很直接：它的精度一直比不过前面的方法，于是把两阶段方法里这套已经被验证过的锚框机制拿回来用。同时这一代还支持大规模类别。
3. **YOLOv3：多尺度预测 + Darknet-53。** 第三代做了多尺度预测——在不同尺度的特征图上分别预测；主干网络换成了 Darknet-53，这也是一个很有名的网络。Darknet 本身是一种纯粹的 CNN 设计，里面全是卷积。
4. **YOLOv4 / YOLOv5：工程化。** 从这一代往后，大部分工作是在做工程化：提高速度、提高精度、做轻量化结构设计。也因为工程化做得好、用起来方便，v5 及之后的版本在社区里被广泛使用。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上).pdf》第 86 页的“YOLO 系列发展时间线”，各版本与主要特点对应如下（该表把口述的版本序补齐为带年份的时间线；“YOLO26”只作为最新版本出现在序列里，它的技术要点不在本节展开）：

| 年份 | 版本 | 主要特点 |
|---|---|---|
| 2016 | YOLOv1 | 第一代 YOLO，端到端回归检测，实时检测 |
| 2017 | YOLOv2 / YOLO9000 | 引入 Anchor 机制，支持大规模类别 |
| 2018 | YOLOv3 | 多尺度预测、Darknet-53 主干网络 |
| 2020–2021 | YOLOv4 / YOLOv5 | CSPDarknet、更加工程化，社区广泛使用 |
| 2022–2023 | YOLOv6 / YOLOv7 | 提高速度和精度，轻量化结构优化 |
| 2023–2024 | YOLOv8 | 更简洁的架构和统一 API |
| 2025–2026 | YOLO26 | 最新主流版本（Ultralytics 版本迭代），更快更稳更好部署 |

把这条线连起来看，YOLO 的演进方向其实很清楚：v1 用端到端回归换来速度，v2 用 anchor 把精度补回来，v3 用多尺度预测和更深的主干继续改善，v4/v5 之后则转向工程化与轻量化。这个系列一直在被更新，一直有人做，到现在还有 YOLO26——老师用它来说明这条技术路线的生命力。

## 十二、YOLO26、NMS 与课程总结 [02:30:00–02:42:37]

### 12.1 系列演进的收尾：anchor 回归、多尺度与工程化

**YOLO**（You Only Look Once）系列讲到第二代时，老师先交代了一个转折：YOLOv2 把**锚框**（anchor）机制又引了回来。原因是一阶段（one-stage）的方法在精度上一直比不过前面的两阶段（two-stage）方法，所以只好把两阶段里已经在用的 anchor 拿回来。

到 YOLOv3，多尺度预测被加了进来，网络用了很有名的 DarkNet-53。再往后，这个系列的大部分工作就不再是提出全新的检测框架，而是工程化：提高速度、提高精度、做轻量化。

老师对这个系列的评价是生命力很顽强——一直一直有人做，今年（2026 年）照样有人做。

> **老师总结**：这个系列的生命力其实很顽强，非常顽强。

从结构上看，YOLO 内部是纯 CNN 的，DarkNet 本身就是一种纯粹的 CNN 设计。老师也展示了不同版本的对比：一代代下来，速度的提升和精度的提升都非常快。

接下来，老师说明要简单介绍 YOLO26——当时最新的 YOLO——的核心创新点，并把它概括为“四部分”。

### 12.2 NMS：非极大值抑制

YOLO26 的第二项改动是端到端、不使用 NMS 的推理。要理解这项改动为什么能成立，得先知道 NMS 是做什么的，老师在这里插进来把 NMS 讲了一遍。

老师先算了一笔账：刚才讲的 Faster R-CNN 一次会输出两千个 proposal，即使强如它也要出几百个框；而大部分图像里只有三四个 object。上百个框密密麻麻堆在图上，根本没法用。NMS 就是为这件事准备的，它不参与预测，只是检测器输出之后的一道后处理。

**定义**：**非极大值抑制**（Non-Maximum Suppression, NMS）是检测器输出之后的一道纯后处理：在同一个类别内部，先取 confidence（置信度）最高的框作为保留框，再计算其余框与它的**交并比**（Intersection over Union, IoU），把 IoU 超过阈值的框视为对同一目标的重复预测而丢弃。

**例子**：老师用 person 这一类举例。假设一张图里 person 类预测出十个框，其中 confidence 最高的一个是 $0.99$，就先把这一个定下来，认为它一定对，以它为准；它旁边还有一个位置几乎重合的框，confidence 是 $0.98$。老师问这两个框是不是都该保留，随即自己给出结论：只保留第一个就行，第二个大概率是重复的。

判断重复的依据是两个框的 overlap，也就是交并比。交并比是两个框的交集面积与并集面积之比：

$$
\mathrm{IoU}(B_1,B_2)=\frac{|B_1\cap B_2|}{|B_1\cup B_2|}
$$

两个框的 IoU 算出来只要大于阈值，这个框就直接扔掉。课堂上举的阈值是 $0.5$；而例子里这两个框的 IoU 已经到 $0.9$ 几，属于明显重复，第二个就被直接扔掉。

这套后处理不是 YOLO 独有的：Faster R-CNN 系列一直在做这件事，更早的目标检测（object detection）也一直用 NMS——不用的话输出的图根本没法看。

> **老师强调**：NMS 是纯粹的做后处理用的；早先的检测器一直要用它，否则出来的图根本没法看——同一个人身上会叠出十几个框。

### 12.3 移除 DFL

讲完 NMS，老师回到 YOLO26 的第一项改动：移除**分布焦点损失**（Distribution Focal Loss, DFL）。这一项老师只要求大家知道有这么回事，没有展开 DFL 本身。

老师把改动前后的结构做了对比。按传统做法，回归分支先输出一个分布，再做 softmax，然后做积分或者求和，最后才得到**边界框**（bounding box, bbox）的预测。也就是说，框的坐标不是由回归分支直接给出的，中间多了一道“分布到坐标”的计算。

把 DFL 拿掉之后，老师给出两个好处。第一，结构变简单了：回归分支不需要再做额外的计算，网络头部也更轻。第二，推理更快：在边缘计算或者这种敏感场景下，这一步被拿掉之后可以减少很多负担。

### 12.4 端到端无 NMS

第二项改动是把 NMS 从推理流程里去掉，做成端到端无 NMS 推理。老师的出发点是传统流程的冗余：检测器先得到一批原始预测框，框的数量多、重复多，所以一定要用 NMS 再筛一遍；如果每次推理都要跑一次 NMS，既麻烦又冗余。

YOLO26 的思路是把这一步交给网络本身：输入图像之后，模型直接输出更干净的最终检测框；去重——也就是从许多重复的框里选出一个——不再由外部后处理完成，而是让网络自己学，学哪些框不应该输出。这样推理时就不需要 NMS 了。

| 环节 | 传统检测器 | YOLO26 |
|---|---|---|
| 输出 | 一批原始预测框，数量多、重复多 | 直接输出更干净的最终检测框 |
| 去重 | 推理后接 NMS 后处理 | 由网络自己学习哪些框不该输出 |
| 推理流程 | 检测与 NMS 两步 | 端到端一步 |

### 12.5 MuSGD 优化器

第三项改动落在优化器上。老师的说法很简短：它是在 SGD 上又做了一个更新，所以 loss 下降的速度更快一点。

**补充说明**：根据本节补充材料《第7周-目标检测模型(上)》第 93–94 页，这一项的名字是“MuSGD 优化器”，第 94 页为“MuSGD 的作用分析”；录音只讲到它是在 SGD 基础上做更新、下降更快，具体的更新公式课堂没有展开。

### 12.6 ProgLoss 渐进式监督

老师讲到的最后一项改动在损失函数上。老师讲了训练过程中损失权重的变化：训练初期，分类损失的权重更高，模型优先去学语义（semantic）信息；随着训练推进，语义信息学得比较好之后，模型转向学几何（geometric）的部分，开始关注边界框的定位。用老师的话说，就是先关注类别分得准不准，再关注框做得好不好。

**补充说明**：根据本节补充材料第 97–98 页，这一项名为“ProgLoss 渐进式监督”，第 98 页为“ProgLoss 的作用分析”。录音只讲了“先分类、后定位”的权重变化，具体的权重调度课堂没有展开。

这两项讲完，老师概括说 YOLO26 的更新大概就是这样，后面更新的基本上都是工程上的优化点。

> **老师提示**：这些改动大家大概知道他们做了一些什么就行了。

### 12.7 STAL 小目标感知分配

**补充说明**：根据本节补充材料第 95–96 页，幻灯片把 STAL 列为第 4 项创新，名称为“STAL 小目标感知分配”，第 96 页为“STAL 的作用分析”；ProgLoss 被幻灯片列为第 5 项。按幻灯片给出的名称，STAL 针对的是小目标的分配（assignment）环节；但录音中老师没有展开这一项——老师在这一部分开头把核心创新概括为“四部分”，随后讲的是 DFL、无 NMS、优化器与损失权重，没有讲到 STAL。这里只按材料标出条目，不补写它的分配规则与效果数值。

### 12.8 速度与稳定性、精度的权衡

把这些改动放在一起看，录音里老师只逐项讲了改动本身，没有口述它们之间的代价与补偿关系；这层关系由本节的三页总结幻灯片给出。

**补充说明**：根据本节补充材料第 99 页，移除 DFL 与引入端到端无 NMS 这两项“加强了速度，但是模型训练的稳定性与精度下降”；第 100 页把 MuSGD 优化器与 STAL 小目标感知分配归为另一组，称其“保证了模型训练的稳定性，并提升模型精度”（第 100 页与第 101 页都把 STAL 重复列了两次，也没有把 ProgLoss 列入这一组，此处按原文照录）；第 101 页的总结是“加强速度的同时，保证了模型训练的稳定性，并提升模型性能”。

也就是说，YOLO26 不是靠单点改动同时拿到速度和精度：前两项负责换速度，另一组改动负责把训练的稳定性与精度补回来。这个分组关系来自幻灯片总结页（第 99–100 页），不是老师在录音里的原话。

| 幻灯片编号 | 改动 | 录音中的讲解 | 总结页给出的作用（p99–p101） |
|---|---|---|---|
| 1 | 移除分布焦点损失（DFL） | 结构更简单、头部更轻、推理更快 | 加强速度，但训练稳定性与精度下降 |
| 2 | 端到端无 NMS 推理 | 去重交给网络学习，推理不再跑 NMS | 加强速度，但训练稳定性与精度下降 |
| 3 | MuSGD 优化器 | 在 SGD 上做更新，下降更快 | 保证训练稳定性并提升精度 |
| 4 | STAL 小目标感知分配 | 课堂未展开 | 保证训练稳定性并提升精度 |
| 5 | ProgLoss 渐进式监督 | 初期重分类、后期重定位 | 总结页未列入该组 |
