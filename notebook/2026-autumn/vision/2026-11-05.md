## 一、从手工设计到端到端：DETR 的提出 [00:02:26–00:11:14]

### 1.1 本节的位置：CNN 时代之后

上节课讲的是基于 CNN 的目标检测，也就是从传统算法一路到 CNN 出现之后的 detection 时代。老师把这个脉络压缩成一句话：从 2012 年进入 deep learning 时代以后，目标检测一直都是基于 CNN 的 object detection 方法。转折发生在 Transformer 被提出之后——2017 年 Transformer 问世，2020 年被引入计算机视觉，此后 CV 这边很快出现了一大批基于 Transformer 的方法。

其中第一篇把 Transformer 整体地、完整地引入到计算机视觉某一个任务里的工作，做的正是目标检测，就是 ECCV 2020 的那篇论文。本节要看的就是三块内容：

1. 基于 Transformer 的目标检测，即 DETR 本身；
2. 基于 CNN 加 Transformer 的混合架构；
3. 后来在 Transformer 基础上、基于 diffusion 扩散模型的目标检测。

老师提醒先回忆上节课的落点：做 detection 时最难的地方在哪里。答案不是分类，而是怎么把那个框找出来，因为框的表现形式跟分类任务很不一样。

### 1.2 目标检测任务：定位加识别

给定一张图，要把图里的 object 找出来。这里的 object 一般指能移动的东西，也就是前景物体，比如车、人、狗，它们能走来走去；背景里的树之类一般不算 object。不过这不是硬规定，不同数据集的定义不一样，做自己的小项目时完全可以自己定义——比如去苹果园里检测哪个苹果是红的，这也是一个目标检测任务。

任务本身包含两件事：先定位，找到它在哪儿；再识别，判断它是哪一个类别。所以一张图上的每一个检测结果都同时带着两样东西：一个 bounding box，以及这个框附带的类别标签。框上还会打一个置信度，比如标着 1.000，意思就是百分之百确信这是一辆车。

老师特别指出两者难度不对称：分类那一部分其实跟普通的分类任务类似，接一个 softmax 的 classification head 就够了；真正难的是 bounding box 怎么来。

### 1.3 传统检测框架里的四类手工设计

之前的目标检测基本都是同一种设计思路，无论是 R-CNN、Fast R-CNN 还是 Faster R-CNN，它们都依赖大量手工设计的组件。老师把这些手工痕迹归成四类：

1. **候选框的产生方式**（box proposal）。最开始每个位置上的那几个初始 anchor box 一定得预定义好：一个正方形的、一个横长方形的、一个竖长方形的，就这几种，是人先定下来的。
2. **正负样本／真值怎么分配**。哪个预测该对哪个真值负责，这是一个关键问题，也是 Transformer 进来之后一直要被重新回答的问题。
3. **后处理**。最后还要做 NMS，即非极大值抑制。
4. **大量调参**。换一个数据集，box 的大小和 NMS 的阈值可能都要重新调。

即使到了 Faster R-CNN、已经引入 CNN 之后，情况也没有根本改变：RPN（Region Proposal Network，区域候选网络）里面仍然有大量手工设计的痕迹。

### 1.4 DETR 的出场与命名风潮

正是基于这个动机——能不能找一个端到端（end-to-end）、不需要人为去设计框的框架——课堂引入了 DETR 这篇论文。老师要求论文标题必须熟悉：*End-to-End Object Detection with Transformers*，出自 Facebook AI，发表在 ECCV 2020。

> **老师强调**：这篇论文的 title 大家一定要熟悉。别人回头问你 Transformer 是哪篇论文的、DETR 是哪篇论文的，你讲不清就不行。

这篇论文之后，计算机视觉里很多模型和任务大面积地进入了 Transformer 时代，留下了一个很明显的印记：几乎每一个方向都会出现一篇“什么什么 with Transformers”或者“什么什么 Transformer”。老师形容那两年最流行的做法就是，谁能以最快的速度把 Transformer 引入自己所在的领域，那篇论文就会获得非常好的关注度。

### 1.5 DETR 的四条主张

老师把 DETR 的贡献拆成四点，后面整节课基本都在兑现这四点：

1. 它是第一个完全端到端的目标检测方法，把中间各种复杂的手工设计全部消除了。
2. 它把目标检测视为一个集合预测（set prediction）问题，用来解决真值框的分配问题——也就是“哪个预测该对哪个真值负责”。
3. 它采用 Transformer 的编码器—解码器架构。Transformer 2017 年就已经提出，这里是直接拿来用。它通过一组可学习的 object query，让 DETR 能够推理目标之间的关系以及全局上下文信息，从而直接输出最终的预测结果。
4. 损失函数也是它最重要的贡献之一：采用基于集合的全局损失，通过二分图匹配去强制“一个目标只由一个预测负责”的唯一性。

此外，DETR 在推理时运行得很快——这一点后面还要和“训练很慢”区分开。

## 二、必要的前置：把 Transformer 再回顾一遍 [00:11:15–00:23:06]

### 2.1 self-attention：QKV 同源与 shape 推演

Transformer 最早来自 NLP，是为机器翻译做的 sequence-to-sequence 模型，想把法语翻译成英语；整体是编码再解码的架构，中间有多头注意力机制。编码器里有 self-attention、前馈网络等内容；解码器比编码器多了一个 cross-attention，用来把两路 QKV 关联起来。

self-attention 的计算从一个输入 $X$ 开始。$X$ 经过不同的变换分别得到 $Q$、$K$、$V$，这里最关键的一点是：self-attention 的 Q、K、V 来自同一个特征、同一个输入。得到 QKV 之后就可以算注意力：

$$\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V$$

这个公式必须记住。老师带着大家把 shape 走了一遍。

**推导**：设一共有 2 个 token、每个 token 的特征维度为 3，即 $Q,K,V$ 都是 $2\times3$ 的矩阵。

第一步，算 $K^{\top}$。$K$ 是 $2\times3$，转置之后变成 $3\times2$。
第二步，算 $QK^{\top}$。$Q$ 是 $2\times3$、$K^{\top}$ 是 $3\times2$，相乘得到一个 $2\times2$ 的矩阵，其中第 $i$ 行第 $j$ 列就是第 $i$ 个 token 与第 $j$ 个 token 的相似度打分。
第三步，除以 $\sqrt{d_k}$，这里 $d_k=3$，目的是把打分的量级压回可控范围。
第四步，对每一行做 softmax。得到的结果仍是 $2\times2$，但每一行的两个数都被归一化到 $0$ 到 $1$ 之间、并且这一行加起来等于 1。
第五步，用这个 $2\times2$ 的注意力权重去乘 $V$（$2\times3$），得到输出 $Z$，仍然是 $2\times3$，与输入 token 的个数和维度都对得上。

所以 QKV 和输出 $Z$ 的 shape 是一致的，中间那个“注意力矩阵”是“token 数乘 token 数”的正方形。老师强调，$V$ 前面那一整块算的就是注意力权重；softmax 的作用是把注意力的值归一化到 $0$ 到 $1$ 之间，并且总和为 1；最后才去乘 $V$。

这样算完之后，$X$ 里任意两个元素之间都发生了一次信息交互，因为这是一个全局的注意力（global attention）。

### 2.2 cross-attention 与多头注意力

cross-attention 跟 self-attention 的唯一区别在于 Q 的来源。这里 $Q$ 来自另一个输入，$K$ 和 $V$ 仍然来自同一组特征：比如 $X$ 经过变换产生 $Q$，$Y$ 经过变换产生 $K$ 和 $V$。剩下的计算与 self-attention 一模一样，公式没有变，还是 $QK^{\top}/\sqrt{d_k}$ 过 softmax 再乘 $V$。所以判断标准很简单：Q 与 KV 同源就是 self-attention，不同源就是 cross-attention。

多头注意力（multi-head attention）解决的是“一心多用”的问题：把输入向量投到 8 个不同的子空间里，每个头独立地计算注意力。有的头可能关注局部的注意力，有的头可能关注全局的关系；最后把这 8 个头的结果 concat 起来，再通过一次线性变换融合，把尺度维持回原来的样子。这样模型就能从多个角度去理解输入。

> **老师比喻**：多头注意力有点像现在这个教室——我给你们一个 input，告诉你们每个同学“大家现在去江湾，前提是不要坐校车，剩下的你爱怎么走怎么走”。我相信你们一定会走出不同的路线。我要的就是从不同路线去收集不同的特征，最终达到目的；中间你们怎么走我不管、也不控制。多头注意力就是这个意味：让每个头自己决定要关注哪一部分特征，最后把不同头收集到的信息 concat 起来。

### 2.3 位置编码：为什么必须有

位置编码（positional encoding）当时是反复强调过的内容。它出现的原因要从 RNN 和 LSTM 说起：RNN／LSTM 是 sequence-to-sequence 的输入，按序列一个一个喂，$T_1$ 一定先输入、处理完了再输入 $T_2$，所以在 RNN 和 LSTM 里不存在时序关系被打乱的问题。

Transformer 不一样：它把整串序列一起输入，而且做的是全局注意力，那它怎么知道哪一个是 $T_1$、哪一个是 $T_2$？顺序信息就会丢掉。而 NLP 处理的恰恰是序列，单词换个顺序，意思就完全不同——“知道”“不知道”“知不道”，随便换个顺序就是不同的意思。

解决办法是给每个 token 打一个位置特征：你是一号、你是二号、你是三号。课堂展示的是典型的正弦余弦位置编码，一万个位置也能编码出来。位置编码本身也是一种特征，可以把它跟 RGB 或者别的 feature 一样看待；把这个位置编码的结果跟原来的特征 concat 到一块就行。concat 是从 channel 维度上堆叠，前提是两者的 H、W 一样；放到 Transformer 里时 H、W 一般都是 $1\times1$，所以直接 concat 即可。

### 2.4 编解码结构与“只能吃序列”的硬约束

Transformer 是编码器—解码器架构。编码器这边只有一个输入，就是任务本身的 input。解码器有两个输入：一部分来自编码器的输出，另一部分来自它自己的一个 query，也就是一个外部的 query。这两个部分都加了位置编码。

在解码器内部，先做 self-attention，接着做 cross-attention：cross-attention 的 K、V 来自编码器的输出，Q 来自那个外部 query。

> **老师强调**：这张图一定要能说出出处——*Attention is All You Need*，2017 年。现在这些大模型背后基本上都是这个架构，ChatGPT 的 T 就是这个 Transformer。

从这张图里还要带出一个关键限制：它的输入都是一个一个 sequence、一个一个 token，不能把一张图片的 H×W 直接塞进去；它的输出也是一个序列，是一堆 $1\times1$ 的输出，不会是 H×W 那样的东西。这个限制正是 DETR 必须回答的第一个技术问题。

## 三、DETR 的结构：怎么把图像塞进 Transformer [00:23:07–00:36:06]

### 3.1 第一次读 DETR 时的四个疑问

老师先坦白自己当年读这篇论文的状态：论文出来时他也看了半天，很多地方都很疑惑，因为他是从 Faster R-CNN 那一系列走过来的，突然到 2020 年有人说“我不需要 anchor 了，我也不需要 NMS 了，我也不需要这些设计了”，第一反应就是——那你 bounding box 怎么产生？

于是留下了一串具体的疑问：

1. 不要 anchor、不要 NMS，bounding box 到底怎么产生？分类要分出来，框也要产生出来，用一个 Transformer 就能解决？图上画得好看，框从哪来？
2. CNN 提 feature 我理解，attention 我也理解，但一个 H×W 的 feature 怎么就塞进 Transformer 里了？
3. 输出了一堆 box，为什么这个红框就对应这个目标、那个黄框就对应那个目标？位置到底怎么对上的？
4. 机器翻译里 query 有实际意义，这里的 object query 到底是什么、要它 carry 什么？凭什么一个外部的 query 就能 query 到东西？

还有一个更技术性的疑问：以前那些设计——ROI align、ROI pooling——都是为了解决从原图到 feature map 的框映射关系。512 降到 64 的映射，好歹大概还能映射过来，只是不准而已；可现在整张图被打乱成一个序列了，这又是什么映射关系？

### 3.2 为什么还留着 CNN

DETR 里仍然用了 CNN，而且这也是目前大部分视觉模型的基本架构。原因是 CNN 用来提取图像的二维特征。论文里会说这提取的是“底层的二维特征”，但老师提醒不必纠缠“底层”这个词——底层是一个相对概念，你非要说在 CNN 的基础上才用它、所以它更底层，也可以。这就是一个架构设计选择。

更实质的理由是：到目前为止，提取图像特征最好的方式还是 CNN。虽然已经有了 ViT，可以用 Transformer 直接处理图像，但把 RGB 图 patchify 之后直接塞进 Transformer，性能未必比 CNN 好，所以现在很多模型还是用 CNN 来提特征。

### 3.3 把特征图拉平成 token 序列

CNN 输出的是一个三维特征图 $H\times W\times C$。举一个具体例子：输入 $512\times512$ 的图，经过 8 倍下采样，就变成 $64\times64$；先不管 batch 这一维，特征就是一个 $64\times64\times C$ 的张量。

而 Transformer 只能接受一个一个 token，当然每个 token 本身是有 channel 的。这就产生了一个“坎”：怎么把 $H\times W$ 变成一串 token？

DETR 的做法非常直接：把它拉平。$64\times64$ 的特征图上，每个 $1\times1$ 的位置上都有一根长度为 $C$ 的向量，这根向量本身就已经符合一个 token 的定义——它的 channel 数就是 $C$。于是把整个 $64\times64$ 的方阵按队列展开成一列：原来这些 token 是排成一个方阵的，现在让它们“站成一列”，就得到长度为 4096 的 token 序列。老师形容这一步“简单粗暴”，就是把二维的图像展平成一个序列。

### 3.4 位置编码：展开之前先发一张牌

展平之后立刻出现前面讲过的位置编码问题。图像原本排列得整整齐齐，这个排列是有含义的：这个像素放在这儿是当眼睛用的；你把这个像素挪到别的位置，RGB 值虽然一样，它肯定就不是眼睛了。

所以 DETR 在展开之前先做一件事：让每个位置记住自己的编号——你是 00，你是 01，你是 02、03……一直到 $63\times63$ 那一格，然后带着这个编号一起进序列。这就是位置编码。

> **老师比喻**：展开之前我先告诉大家“我们要展开了，你们记住一下自己的位置”。然后我给你发一张牌，你拿着，这就是你的位置编码，你就贴在自己身上。贴好之后你随便怎么调整顺序都行。眼睛那块黑像素即使被挪到了别的地方，它身上还带着自己原来的位置标签，凭“像素值加上位置编码”我大概还能推断出你是那只眼睛；另一个位置上的黑点，凭它的特征和位置编码，我就能推断出你只是背景里的黑色。

这样处理之后，每个位置就成了一个带位置信息的 token，后面按 Transformer 正常处理即可，Transformer 原本的架构一点都没有变。

### 3.5 object query 到底是什么

这是老师说自己“困惑了好久”、也是全场最“神奇”的一步：object query 到底是个什么？

他回忆，刚看到论文、还没拿到代码的时候，看了半天也没能理解它到底是什么。后来顿悟了：不要管它是什么，它就是一个能够让这套 Transformer 代码跑通的值。去看代码就会发现，它就是一组 shape 与 Transformer 原本的 query 完全一致、随机初始化的 parameter。

顺着这个理解，训练过程就变得很好想象。模型刚开始的时候，这些 query 和图像特征放到一起做 cross-attention，QK 问这个 query“你要 carry 什么”，query 说“我也不知道要 carry 什么，先随机 carry 一下”。学习了一段时间、第一次完成之后，监督信号传回来说“你们这样不对”，于是 QKV 各自反思：QK 反思自己的特征对不对，query 反思自己这样查询可能不对，就换一种查询方式。整个机制就是这样被训练出来的。

后来也有很多人试图解释这组 query 到底有什么含义、到底 query 了什么。有人会说某个 query 一定是在找左上角、某个一定在找右下角、某个一定关注前景、某个一定关注背景——这些说法都有可能。

> **老师强调**：这组 query 甚至换一台机器训练，相同位置上学出来的东西都不一样，它到底学出了什么每次都可能不同。所以大家要知道，这里的 query 其实也是一种特殊的 feature，是让网络自己决定要 carry 什么。

还有一个必须记住的性质：Transformer 解码器的输出与它的 query 输入是一一对应的，画在图上就是红对红、绿对绿、黄对黄，shape 也完全一样。“你 query 了什么，它就输出什么。”

### 3.6 每个 query 出一个类别和一个框

输出之后的 FFN 不用太在意，就是几层一维卷积，可以理解成一种线性的映射变换。真正要看的是它之后做了什么：每个 head 预测一个 class 和一个 box。

这里接上了上节课的一个提问：如果一张图里只有一个 object，你怎么预测 bounding box？答案是预测一个 class、一个 box，因为只有一个目标。DETR 这里是类似的功能：让每个 object query 只负责找一个 object。既然只关注一个 object，那它就直接输出这个 object 的类别和它的框——类别是一个类别，框就是四个数字，每个 query 都承担这样一个任务。

## 四、集合预测与匈牙利匹配 [00:36:07–01:06:13]

### 4.1 为什么真值分配是核心难题

现在每个 query 都输出了一个 class 和一个 box，而手上有一堆真值框——比如图里只有两个目标，一个黄框、一个红框。老师先开玩笑提醒：不要因为颜色碰巧一样，就自动给它匹配上。

问题在于：这 100 个输出里，哪一个该对哪一个真值负责？设置监督信号、算 loss 的时候，你的真值一定要跟你的预测匹配上。

以前的做法都是靠位置关系一一对应。Faster R-CNN 系列里，对应位置上的那个 bounding box 一定分配给对应位置上的预测，是一一对应的关系。老师补了一句这种对应的前提：即使 feature 的尺寸比原图小了一点，它大概仍然是一个能够一一映射的关系——这个区域的特征放到这儿，它预测出来的 box 就要跟这个位置去对应。分割任务更简单：每个像素都要预测，那就逐像素一一对应——人为打的标签说你这里是一只猫，那我不管你这里预测出什么，都用这只猫去监督这个位置；其他位置同理。

YOLO 用的是画格子的办法：把图划成格子，看这个 object 的中心有没有落到某个格子里；落进去了，就把这个 object 的真值分配到中心所在的那个位置，其他地方不分配。

所以老师把话收回到一句：真值框的分配本身就是一个很关键的问题。

### 4.2 从一一映射到二分图匹配

DETR 的做法是二分图匹配（bipartite matching）。以前是一一对应，但这里它认为：我的真值是一个集合，我的预测也是一个集合，现在要做的事情就是在这两个集合之间连线——到底哪个跟哪个应该连上。

**例子**：假设图里有 2 个真值框，DETR 输出 100 个预测框。把两边的线全部连上，一共是 200 条连线：第一个真值跟这 100 个预测各连一条，第二个真值也跟这 100 个各连一条。而最终我们只愿意承认其中的两条线。于是任务就变成：从这 200 条连线里找到那两条。这就是一个经典的二分图匹配问题。

匹配上之后是什么意思？假设第一个真值和某一个预测匹配上了，那这个真值的坐标 $(x_1,y_1,x_2,y_2)$ 就分配给这个预测；第二个真值同理分配给另一个预测；剩下的 98 个预测就直接告诉它们“你们是空的、没有目标”。

### 4.3 二分图与匈牙利算法

老师先补了二分图的背景知识，说这些在离散数学里应该学过。

**定义**：二分图。二分图是指所有的顶点都可以分成两组，每一条边都只连接两组之间的顶点。

**定义**：匹配。匹配是指找到一组边，使得任意两条边都没有公共的顶点。

也就是说，把一个图分成 $U$ 和 $V$ 两个不相交的集合，然后从这些本来存在的边里面找一组出来，使得它们互不共享顶点。可以认为这是要找一条代价最小的路径，代价怎么设计可以自己定。老师还提到，最终要找的是不含奇数条边环（奇环）的那种图结构。

这套匹配用的算法叫匈牙利算法（Hungarian algorithm）。老师对这个算法的评价很高。

> **老师总结**：这其实是这篇论文我认为最伟大的一个贡献——匈牙利匹配算法，他把这个问题分成了两个集合。

为什么需要它？老师又回到 R-CNN 与 YOLO 的对比上：那些方法本质上都是一个对应关系的映射。他打了个比方：假如这个教室有一个微缩模型，缩到只有这么大，这位同学放到里面，他大概还在这个位置——这是一种关系、位置的映射。但到了 DETR 里面，这个关系被打乱了，因为 Transformer 出来之后整个是乱的，尤其 query 也不知道是为了什么。所以就把它转成两个集合之间的一种映射、一种匹配。

具体到匈牙利算法本身，它是通过 DFS 和 BFS 来做的，也就是深度优先搜索（depth first search）和广度优先搜索（breadth first search），用它们在这个二分图里寻找增广路径。增广路的定义是：一条未匹配边、匹配边、未匹配边交替出现，并且首尾均未匹配的路径。每找到一条增广路，就把这条路径上的匹配状态取反；一直重复，直到不存在增广路为止。

**算法**：匈牙利算法求二分图最大匹配。

1. 把顶点分成 $U$、$V$ 两个不相交的集合，只保留连接两组顶点的边。
2. 从任意一个未匹配的顶点出发，用 DFS 或 BFS 在图中搜索增广路：路径上的边按“未匹配边—匹配边—未匹配边”交替出现，且起点与终点都必须是未匹配的顶点。
3. 若找到一条增广路，把路径上所有边的匹配状态取反（原来的匹配边变成未匹配，原来的未匹配边变成匹配），匹配数加一。
4. 重复第 2、3 步，直到再也找不到增广路为止，此时得到的匹配就是最大匹配。

> **老师提示**：交替路、增广路这些概念，离散数学或者概率论里面都学过；如果忘了，回去复习一下，或者自己上网查一下，都是一些数学问题，也都比较简单，没有你们想的那么难。

### 4.4 带权匹配：代价矩阵与 $O(n^3)$

休息回来后，老师把这个问题重新说了一遍，并往前推了一步：DETR 的输出是一个集合，是一组 bounding box，我们不知道该把它对应到哪里去，真值也不知道该分配给谁，所以问题变成二分图匹配。但关键是，要匹配就得有一个匹配的规则——你最终要找到谁跟谁匹配，这得有依据，而且我们肯定希望找到“最匹配”的那一种方案。

于是它变成了一个带权二分图匹配问题：每一条边上都有一个 cost（代价），目标是找到使总代价最小的那套匹配。

**算法**：DETR 中一次真值分配的执行流程。

1. 模型输出 100 个预测的 bounding box；图里只有 2 个真值框。
2. 构造一个代价矩阵，计算这 100 个预测与这 2 个真值之间两两的“不匹配度”代价，矩阵大小是 $2\times100$。
3. 在算法执行过程中，通过调整顶标等方法，在 $O(n^3)$ 的复杂度内找到一个总代价最小的完美匹配。
4. 挑出与两个真值最匹配的那两个预测，把真值分配给它俩。
5. 剩下的 98 个预测直接告诉它“你是空的，这次没有成功预测到 object”。

这里有一个容易被忽略的细节：每次匹配的结果可能都不一样。同一张图在训练过程中会被用到很多次，每次它被分配的预测可能都不同，“每次可能都不一样”。

### 4.5 匹配之后的损失：分类、L1 与 GIoU

匹配确定之后才算损失。老师把这一部分的结构讲得很清楚：匈牙利损失对每一个匹配上的配对包含两项——一项是分类损失，一项是 bounding box 的损失。

**推导**：最优匹配的定义与损失的算法。

第一步，把“最优匹配”定义成一个在所有排列中取最小值的优化问题：设预测集合为 $\{\hat y_i\}_{i=1}^{N}$、真值集合为 $\{y_j\}$，则最优分配为
$$\hat\sigma=\arg\min_{\sigma\in\mathfrak{S}_N}\sum_{i=1}^{N}\mathcal{L}_{\mathrm{match}}\bigl(y_i,\hat y_{\sigma(i)}\bigr),$$
其中 $\mathfrak{S}_N$ 是 $N$ 个预测的所有排列构成的集合，$\mathcal{L}_{\mathrm{match}}$ 是配对代价。
第二步，说明为什么不能暴力枚举：排列的数量是 $N!$，预测有 100 个时这个数量无法计算，所以要用前面讲的匈牙利算法去求这个最小值。
第三步，用匈牙利算法求出 $\hat\sigma$ 之后，把这个匹配固定下来，再在这个固定匹配上计算真正的训练损失。每个匹配上的配对贡献两项，结构上写成
$$\mathcal{L}=\sum_{i=1}^{N}\Bigl[\mathcal{L}_{\mathrm{cls}}\bigl(c_i,\hat c_{\hat\sigma(i)}\bigr)+\mathbb{1}\{c_i\neq\varnothing\}\,\mathcal{L}_{\mathrm{box}}\bigl(b_i,\hat b_{\hat\sigma(i)}\bigr)\Bigr],$$
其中 $c_i$ 是真值类别、$\hat c$ 是预测类别、$b$ 是框的坐标，$\mathbb{1}\{\cdot\}$ 表示只有真值非空时才计入框的损失。
第四步，逐项落实：分类项拿预测的类别与真值类别算分类损失；框的回归项只在真值非空（$c_i\neq\varnothing$）时才算，其余被标成“空”的预测只承担分类项。
第五步，框的损失本身又由两部分组成：一个 IoU 损失、一个 L1 损失。

老师特意解释了 IoU 这一项。IoU 就是交并比（Intersection over Union）：

$$\mathrm{IoU}=\frac{|B_p\cap B_g|}{|B_p\cup B_g|},$$

也就是两个框交集面积除以并集面积。当预测框与真值框完全匹配时，IoU 是 1；当预测得特别离谱、两个框完全没有重叠时，IoU 是 0。所以这一项的作用就是让 IoU 最大化。

L1 损失就是两个值相减取绝对值，神经网络那节课讲过。

这两项为什么要一起用？老师给的理由是它们互补：IoU 的一个特点是尺度不变——他画了两个大小完全不同的框对，IoU 的值可以一样，因为它是面积之比，跟框本身多大没有关系，所以 IoU 对框的大小不敏感。但 L1 损失对框的大小是有敏感度的。于是两者形成互补：IoU 负责对大小不敏感的匹配质量，L1 负责精确地回归坐标值。

再往后是 GIoU（Generalized IoU，广义交并比）。它的算法就是在正常 IoU 的基础上减去一个惩罚项——具体说，是取一个能把这两个框都包住的外接区域，把这个区域里不属于两框并集的那一块当作惩罚项减掉。为什么要这么做？因为普通的 IoU 在两个框完全不相交的时候值为零，零就没有梯度信号、没有监督信号了。用了 GIoU、减去一个惩罚项之后，即使两个框不相交，也仍然存在惩罚损失，可以用来辅助提供监督信号。

> **老师强调**：一开始那个 query 是随机初始化的，我也不知道要 carry 什么，输出来的是一堆乱七八糟的框，跟真值完全不匹配，没有一个 IoU 大于零。如果只用普通 IoU，那就一直没有信号，这个监督一直训练不起来。所以要用 GIoU 这种方式。

## 五、DETR 的实验结果与两个硬伤 [01:06:13–01:11:41]

### 5.1 AP 分档与实验数字

先看实验效果。衡量的指标是 AP，也就是平均精度（Average Precision, AP）。这个指标还会按目标大小分成三档：$AP_S$、$AP_M$、$AP_L$，分别对应 small、medium、large。老师解释为什么要这样分：在那个数据集里，小物体和大物体的检测难度差异非常明显——小目标那一档的数值都是二十多，大目标那一档都是五十多，差了一倍以上。所以数据集特意把它拆成三部分，用来展现不同算法在不同尺度上的能力。

把 DETR 和 Faster R-CNN 放在一起看，结论很清楚：DETR 显著的优势在大物体上，也就是 large 那一档比之前的方法好了很多；但小物体上它是下降的——Faster R-CNN 在小物体上最好已经到 27，DETR 直接降到了 23。所以它在小物体上表现得没有那么好。

### 5.2 训练代价与推理速度

第二个问题是训练时长。DETR 需要 500 个 epoch 才能训练好，这个训练代价非常大。

> **老师强调**：这里一定要区分两个概念——一个是训练速度，一个是使用时的 inference 速度。训练速度是我拿 GPU 把你这个模型训好要多久；但我实际用的时候，模型已经训完了，能跑就行。DETR 的 inference 速度还是很好的，但它的训练代价很大，需要长得多的时间才能收敛。

老师顺带澄清数据集的名字：这里说的是 COCO 数据集，不是那部叫《寻梦环游记》的电影，就是数据集叫 COCO；而且这个 COCO 比那部电影早太多了，2014 年就叫这个名字了。

具体对比是：在 COCO 上 DETR 需要 500 个 epoch 才能训好，而 Faster R-CNN 大约只需要 50 个、甚至 10 个 epoch。

### 5.3 两个硬伤与归因

于是 DETR 的问题被归结为两条：训练收敛时长很长；检测小物体时性能比较差。老师指出，这两部分其实都可以归咎于同一件事——Transformer 架构在处理图像时本身有一些不足。

这个归因值得展开。Faster R-CNN 系列虽然冗余，但它有一个保底性质：除非那个物体小到 $32\times32$ 像素以下，否则它一定能把框映射过去，它是有这个能力的。但放到 Transformer 里处理这个问题，它就会出问题。

### 5.4 留给学生的四个思考题

讲到这里，老师停下来留了几分钟，给了四个问题让大家想，并说明未必会在这节课上完全解决：

1. DETR 为什么能够省略 RPN 和 NMS？DETR 里 object query 的作用是什么？
2. DETR 和传统检测里的先验概念 anchor box 有什么不一样？
3. object query 应该怎么理解——它是一个区域还是一个点？更进一步：object query 是全局设置的、是跟网络相关而跟图片没关系的，设置它的时候并没有去看具体的图片，那它为什么能够回归到图片上的一个具体位置？
4. 代价矩阵的计算跟损失函数是什么关系？

> **老师提示**：这些问题你们也可以去问一下 ChatGPT、问一下豆包、问一下 DeepSeek、问一下千问，看看它们的答案是什么，我们这里就不再赘述了。

## 六、为什么慢、为什么贵：注意力在图像上的两个失效 [01:11:46–01:20:12]

### 6.1 归一化约束与初始均匀分布

转入改进工作之前，老师先把 DETR 的病根拆开。要分析的是注意力的计算形式：对于每个 query，都需要跟所有的 K 计算一个注意力权重，然后聚合所有的 value；而这些注意力权重必须满足归一化条件——权重之和为 1。

### 6.2 收敛慢：25 万个像素上的均匀注意力

第一个问题是收敛慢。原因在训练的初始状态：刚开始的时候，注意力的权重是均匀分布的。

Transformer 真正厉害的地方在于，QKV 算完之后，它的 attention weight 能够集中到有意义的信息点上。但一开始它是分散的，它也不知道哪个更重要，所以刚开始的注意力矩阵是一种分散的形态。

在 NLP 里这种分散还行，因为 NLP 里一个 token 就是一个单词，每个词都有意义。但图像不一样，图像是一种高度冗余的图。

> **老师比喻**：什么叫高度冗余？我一张图给你下采样 100 倍，我相信你还能认出它来。再抽象一点，这张图我拿线条给你描述一下，把其他元素都丢掉，你还能认识。这就像当年中国乔丹和乔丹打官司那场，那个 logo 明明是一个经典姿势，他非说那是拿着乒乓球拍——这就是图像高度冗余的体现：简化成那样简单的像素之后，人还能靠自己的脑补认出来，而它携带的信息量跟原像素其实差不多。

于是问题就来了。一张 $500\times500$ 的图是 25 万个像素点。你要在这 25 万个像素点上均匀地分布 attention，再让它最终收敛到关键的那几个像素点上去，那真的要很长时间——因为这个里面它能够去关注的点非常多。

对图像而言，K 通常就是图像像素，$N_K$ 会变得非常大，所以它很难收敛；而且每一个 K 分到的权重还很小。

**推导**：为什么均匀分布的注意力会让收敛变得很慢。

第一步，注意力的权重必须归一化，即对每个 query 有 $\sum_{j}\alpha_{ij}=1$。
第二步，训练刚开始时权重近似均匀，于是每个位置分到的是 $\alpha_{ij}=1/(HW)$。即使把 $64\times64$ 简化成 $60\times60$，那也是 3600 个点，每个位置分到的权重就是 $1/3600$，是一个非常小的数。
第三步，权重是以 softmax 输出的形式参与计算的，权重本身量级很小，回传到 logits 上的梯度也就同阶地很小，参数一次更新能移动的幅度有限。
第四步，因此模型需要学很长时间，才能学会把这个 attention weight 从“平均分摊”挪到“集中分配给有关键信息的那些像素位置”上去。这就是 DETR 收敛慢的直接原因。

### 6.3 计算量大：分辨率的两难

第二个问题是计算量过大。注意力的计算复杂度里包含三项：

$$N_Q C^2 + N_K C^2 + N_Q N_K C,$$

其中 $N_Q$、$N_K$ 分别是 query 和 key 的数量，$C$ 是特征维度。在图像里，query 和 K 都是像素，所以 $N_Q$ 和 $N_K$ 远远大于 $C$，计算复杂度就主要集中在这一项 $N_QN_KC$ 上。

而检测小目标恰恰要求高分辨率的特征图。老师算了一笔账：如果要检测到一些小目标物体，就需要一个高精度、高分辨率的特征图，不能下采样到 $32\times32$，甚至不能下采样到 $16\times16$，必须维持一个比较高的分辨率。可是分辨率一高，$N_Q$ 和 $N_K$ 就跟着增长；$N_Q$、$N_K$ 一增长，计算量就会爆炸。

归根结底，核心问题是 Transformer 的注意力要对空间的所有位置进行一次全局计算，于是同时造成了两件事：收敛慢，计算量大。再加上图像里 QKV 的那几个值分布都很广——都是以像素为单位铺开的——计算量自然很大。

### 6.4 稀疏性：训练好之后注意力本就稀疏

不过老师接着给出一个关键观察：在实际任务上，无论是 NLP 还是 CV，注意力在训练好之后通常都是稀疏的。

他举了两个已经算好的注意力矩阵作例子：一个是 NLP 里把法语翻译成英语的翻译任务，一个是 CV 里的 video understanding 任务。两个矩阵都很稀疏，大致集中在靠近对角线的那些位置上，而 video 那个更稀疏。

稀疏到什么程度？如果把 video 那个注意力矩阵按同比例放大铺开，这间教室可能都得铺满。NLP 那边总共就十来个单词；但 video 里一个 $500\times500$ 的像素点，本该去关注 25 万个位置，一条边就从十几个延伸成了 25 万，横边也差不多是 25 万；而且这还是抽帧之后的结果，如果按 32 fps 去处理，整个就要爆掉。

所以注意力搬到 CV 里，确实有它现实的问题。但同时也能看到：注意力一旦收敛，它关注的东西其实很离散——这一个像素真正关注的并不是那 25 万个像素，而只是这些线连上的那些点；只要这些点的信息能被它获取到，它就足以完成这个任务。把其余部分截掉一块，或者把分辨率弄得很低，也不影响。这就是图像的特点。

## 七、Deformable DETR：把全局注意力换成稀疏采样 [01:20:17–01:38:43]

### 7.1 从 deformable convolution 借来的思想

基于上面的观察，后面出现了一篇比较著名的工作，叫 Deformable DETR，核心是 deformable attention。它的思想是从 CNN 里的 deformable convolution 借来的。

先回顾普通的卷积：正常的卷积是一个 $3\times3$ 的固定区域，是一个排得整整齐齐的阵列，放在那儿不动。deformable convolution 的想法是：这 $3\times3$ 的九个点，我不要排得这么整齐，我还是这九个点，但我让每个点各自学一下自己该往哪里跑。

于是它给每个位置都学了一个 shift，也就是一个可以移动的像素位置。这样它就不再是一个 $3\times3$ 阵列式的排列——卷积本来是拿一个阵列去扫的，而 deformable convolution 在扫的过程中放到某个位置时，不是严格按阵列排列，而是每个点自己能够变动一下位置：想往上挪一下、想往下挪一下，想去左上角看一下、右下角看一下，都行。当然，跑的范围是有限的，不可能让它从这里跑到那里，大概只能在一个有限的范围里挪动。

这样做的目的是让它更关注语义（semantic）层面的关系。因为用 standard convolution 时是阵列排列，以这个点为中心画一个区域：如果这个点正好落在羊头上，那么这个 $3\times3$ 的区域里可能大部分都是草，甚至是另一只羊；而 deformable 之后，这个点应该散到与这只羊相关的其他区域上去。

### 7.2 deformable attention：只算 K 个采样点

作者想把这个思想引入到注意力里，把稀疏采样的思想跟注意力结合起来。

deformable attention 的做法是：给定一个 query 和它的一个参考点，模型通过一个线性层去预测 K 个采样点的偏移量，以及对应的注意力权重，然后只在这 K 个采样位置上做采样、加权求和。

用式子写出来就是

$$\mathrm{DeformAttn}(z_q,p_q,x)=\sum_{k=1}^{K}A_{qk}\,x\bigl(p_q+\Delta p_{qk}\bigr),$$

其中 $z_q$ 是这个 query 的特征，$p_q$ 是它的参考点，$\Delta p_{qk}$ 是线性层预测出来的第 $k$ 个采样点的偏移量，$A_{qk}$ 是对应的注意力权重，$x(\cdot)$ 表示在给定坐标处取到的特征。多头的做法就是每个头各自预测一套偏移和权重、各自算一遍，最后再合起来。

这个改变的意义在于对比：以前算 QKV 的 attention 时，是一个全图的计算，Q 和 K 是全图到全图的稠密计算；现在则是“我关注这个位置，就通过这个位置预测一下我可能要采样哪几个点”，然后只在这几个点上算 attention，其他点我不管。

于是计算量就有一个很大的下降。放到前面的例子里：本来这一个像素、这一帧要关注全图 $500\times500$ 这样一个量级；现在有了 deformable 的机制，先把它拿出来预测一下大概的采样点——初始时这些采样点大概就落在那个球附近，于是只在球附近的这几个离散点上采样。K 是可以设置的，比如只让它采九个点，那就只在这九个点上算 attention 权重。

这个好处还体现在：因为它只关注采样点周围一小部分关键的采样点，所以无论特征图有多大，它的计算量都是固定的——就是对 K 个采样点的计算。而 K 肯定远远小于原来全图的 $H\times W$：$60\times60$ 也有 3600 个点，而 K 就算设得多一点，也就 32 个点。

### 7.3 多尺度采样与特征金字塔

在单尺度上做完，再扩展到 multi-scale。做法是在 L 层的特征上，每层都采 K 个点；具体实现上把多个尺度上这 K 个点的坐标归一化到 $[0,1]$ 区间，然后再映射到各个层级实际的坐标系中去。这样就能天然地支持多个层级的多尺度特征，采集到 multi-scale 的 feature。

为什么要采 multi-scale 的 feature？老师补了一段 CNN 特征图的基本性质：在 CNN 里，特征图会随着层数加深而越来越小；做分类时一个简单的做法是只用最后一层去算。但后来有人试过，不只拿这一层，而是把其他层也都拿出来 concat 起来——尺寸不一样没关系，upsample 统一到同样的尺寸，再 concat 到一起。

这样做的理由是物体的尺度不一样。这张图里有些物体可能很大，大到一定程度时，你可能要到深层才能把它的关键信息提取出来；有些物体可能很小，小到在深层特征图上它已经没有了，那就得靠浅层那些还保留着细节的特征才找得到它。所以“一定要在多个 CNN 层之间去提取 multi-level、multi-scale 的 feature”，这是一个通行做法。这里的 multi-scale 指的就是：采样的时候虽然采了 K 个点，但不只从这一层采，也从其他层去拿。

### 7.4 参考点的两种来源与两个工程优化

参考点在编码器和解码器中的来源不同。

编码器里很简单：每个像素的参考点就是它自己的坐标。

解码器里，参考点是对应的 object query 通过一个线性映射、再加一个 sigmoid 函数预测出来的。也就是说每个 query 都有一个初始的关注区域。用这样的 multi-scale deformable attention 和 cross-attention 去处理特征，每个解码器层都会根据前一层的预测去细化它的 bounding box 预测。另外要注意，检测头预测的是相对于参考点的偏移量。

除此之外还有两个比较重要的优化。

第一个是迭代式的边界框细化。它受了光流估计的启发：每一层的解码器都在上一层的基础上继续优化这个框，一层一层往前推。

第二个是 two-stage 方案。它先用编码器生成 region proposal，再把这些 proposal 作为 object query 输入到解码器里去 query。老师特别提醒注意这一点的意味：它的思想跟 DETR 不一样了。DETR 里那个 query 是一个随机初始化的 parameter，让它自己去学，这也是 DETR 显著区别于 Faster R-CNN 系列的地方；但这里又把 Faster R-CNN 的做法拿回来了——先预测出一组 region proposal，再把这组 proposal 当作 object query 送进解码器。

这个做法其实很实际。刚开始 proposal 出来的那些 region、那些框是比较粗糙的，但它大概能够 cover 住目标：比如对一个人，最离谱也应该把人框住了一半。所以它有一个很好的初始位置；拿这个初始位置去 query 特征，就能更好地关注到最终目标，收敛得更好。

### 7.5 收敛曲线与实验结果

先看与 DETR 的对比。deformable 这一版的收敛明显更快：从收敛曲线上看，DETR 要 500 个 epoch 才到 43.6，而 deformable 版在 50 个 epoch 的时候就超过了它的性能，收敛快了一个量级。

作者还做了一系列消融实验（ablation study）：多尺度输入、多尺度注意力、增加 K 的采样数。值得注意的是，最终它每个位置只采了四个点——即便初始是均值注意力，每个点的权重也是 0.25。随着这些设计逐项加上去，性能逐渐增加到 43.8。

加上 two-stage 的 deformable attention 之后，性能又有进一步提升：从 43.8 到 46.2；小目标上的提升更明显，$AP_S$ 从 26.4 增加到 28.8。

这组数字也解释了 DETR 那个毛病的来源：在 DETR 里 query 是随机初始化的，很多时候因为监督的问题，它关注不到小目标；而大家都愿意去预测大目标，因为预测大目标更容易成功，在二分图匹配里也更容易被选中。

至于 deformable attention 为什么收敛快，老师给了直接的量化对比：DETR 的 attention 是 $HW\times HW$ 的，权重摊在几千个点上，$1/3600$；deformable 只预测这几个离散点，哪怕假设是 16 个离散点、初始完全是均值注意力，那也是 $1/16$，比 $1/3600$ 大得多。权重更大，求导回传的梯度也就更大，收敛速度自然更快。

> **老师总结**：Deformable DETR 是一种高效且收敛速度快的端到端目标检测模型，它的核心是采用了 deformable attention 这种处理图像时高效的注意力机制。跟 DETR 相比，它可以在少十倍的 epoch 训练下达到相同的效果，尤其是小目标上的性能更强。

### 7.6 关于 ablation study 与 SOTA 对比

讲消融实验时，老师插了一段论文方法论，因为这是他反复强调的东西。

> **老师强调**：做论文的时候一定要加 ablation study。因为你不能说“我把各种乱七八糟的东西全部加进去之后，性能超过你了”就报告完事。作为一篇论文，你一定是那种控制变量法，去体现一下到底加了哪个有用、加了哪个没用。

具体怎么做？先报你的 baseline：你的方法什么都没加的时候是多少，先报一下。万一你的 baseline 就已经超越了别人最终的方法，那说明你的 baseline 本身更强。然后从 baseline 出发，把你的各种方法一点一点加上去，看每加一个方法它的提升是多少，最终通过这个来证明你提的方法到底有没有效。老师还补了一个反面情形：万一你提的方法根本没效果，把你提的方法去掉之后发现还涨了两个点，那就更说明问题了。

除了 ablation study，另一个常见项是跟 SOTA 对比，也就是 state of the art，当前最先进、最好的方法。课堂展示的那张表就是与之前整个一系列方法的对比。当然这张表现在都可以更新了，但在当时它的效果是非常好的，AP 可以达到 52.3，已经跟 Efficient DETR 那一类方法比较接近，甚至有所超过。

## 八、RT-DETR：CNN 与 Transformer 的混合架构 [01:38:44–02:11:47]

### 8.1 RT-DETR 的目标与混合编码器

老师先说明：后面很多工作都是 CNN 跟 Transformer 的一种结合。其实 DETR 本身已经是 CNN 和 Transformer 的结合了——它把 CNN 直接当成一个特征提取器，特征提出来之后直接送进 Transformer 处理。后面的这些工作要解决的是“怎么把 CNN 和 Transformer 结合得更好”。

例子是 RT-DETR。老师说这个名字起得挺有个性，那段时间一度因为 YOLO 的影响，论文 title 和名字都起得很有个性。它的目标正如它的 title：想全面地超过 YOLO，能够实现一个实时的推理速度。从右图可以看到，它的速度确实够快，性能也确实超越了 YOLO 的各个版本；图中红色的是他们的结果，越靠左上角越好——也就是在相同的速度下，它的性能更好。

它是怎么做到的？核心是设计了一种高效的混合编码器。它不像 DETR 那样用纯粹的 Transformer 去处理所有尺度的特征，而是把 Transformer 跟 CNN 有效地结合起来：

- 高层特征用 AIFI 架构，也就是基于 Transformer 去处理，做尺度内（intra-scale）的交互；
- 跨尺度的特征则基于 CNN，用 CCFM 去处理融合；
- 也就是说它做了两种处理，各有分工。

简单点讲：DETR 可以认为没有“Transformer 出来这一块跟这一块再去结合”这回事；而 RT-DETR 从 S5 到 F5 这一段用 Transformer 做了类似全局 attention 的处理，得到特征之后又 reshape 回 $H\times W$ 的形状，去跟其他特征做融合；融合完之后再拉开、展平重排，进入后续流程。

它一共设计了从 A 到 E 五种不同的方案，核心差别就在三件事上：到底怎么 concat、怎么 fuse、怎么去选取 cross-scale 的特征。

### 8.2 五种 neck 方案 A–E

老师带着把这五种方案挨个看了一遍，并说明这些实验未必对每一个任务都成立，重点是看它的思想——知道我们有哪些选择、可以怎么做；以后自己做研究，万一也遇到 CNN 跟 Transformer 结合的问题，就可以做类似的选择。

| 方案 | 做法 | 代价与效果 |
|------|------|------------|
| A | 最简单的轻量级 neck，作为 baseline；没有选取也没有融合，直接暴力 concat | 参数最少，但精度最低 |
| B | 用一个 Transformer，把 backbone 提取的多尺度 feature 都输进同一个 Transformer；融合就是简单 concat 起来，让 Transformer 去处理特征之间的交互 | 把不同尺度 feature concat 之后计算量相当大 |
| C | 先把 backbone 的 feature 都 concat 起来，再送进 Transformer 内部，让 Transformer 同时做特征的选取与融合 | 成本最高的一种 |
| D | 跟 B 一样共享一个 Transformer，先用 CNN 把它们的 Transformer 融合起来，这样能用 Transformer 拿到比较好的特征，再用轻量化的方式融合 | 参数量下降比较多，速度也更快 |
| E（SS5 思路） | 只把 backbone 最高阶的特征送进 Transformer，其余低阶特征用 CNN 处理 | AP 最高；参数量增加不大；速度较快（未达到最快的 7.9），是精度与速度权衡后的选择 |

最终它采用的是跟 SS5 类似的方式：用 Transformer 模块把其中中间某一层特征提取出来，再用基于 CNN 的特征去做融合。这样 Transformer 的输入维度就大幅减小了。用了 E 之后，它的 AP 其实是最高的，参数量相对而言没有增加那么大，latency 虽然没达到最快的 7.9，但它是在精度和速度之间权衡之后，选择了牺牲一点速度去拿到最高的精度。

### 8.3 low level 与 high level 特征

讲到这里，老师额外补了一段关于 low level 与 high level 特征的说明，因为这是理解“为什么要混合”的前提。

特征图是逐级下采样、channel 逐级增加的，画出来像一个金字塔：更靠近 RGB 的那些 feature 叫 low level feature，更靠近预测 head 的那些 feature 叫 high level feature。如果画成图像金字塔，它一直要到塔尖——塔尖上只剩一个点，上面可能还立了个柱子（避雷用的）；其他任务里金字塔尖可能要消掉一部分。

所有任务里大家发现的一个共同结论是：我要把 low level 的 feature 跟 high level 的 feature concat 起来、都要用上，才能做一个更好的预测。这篇工作同样在解决这个问题。

这两类特征有一个很鲜明的区别。先不说物体大小，只说整张图：low level feature 的分辨率更大一点，HW 更大，比如还是 $256\times256$、$128\times128$ 这种比较大的；但它的语义性（semantic）会小一点，因为它离 RGB 还比较近——它大概知道你这里有一个 corner、有一条线、有某一种特征，但最终是不是一匹马，它还没有看到那么全局，没有提取到那么抽象的特征。

high level feature 则相反：它的尺度变得很小，$32\times32$、$16\times16$、$8\times8$、$4\times4$ 都有可能；但它已经比较 high level，而且靠近最终的分类头，所以是一种比较抽象的特征，是具有高度语义的特征——它可以拿来直接预测“这是一只狗”“这是一匹马”。

再把物体大小这个考量加进来：不同尺度的物体，到底在哪一层才达到所谓的 semantic，是不一样的。小物体可能提取几层就够了；大物体可能需要很多层——这就是感受野的问题，大物体要很多层才能把这个物体看完。

### 8.4 为什么只需要在高层做注意力

那么为什么需要这种混合特征？老师把 DETR 的做法和 RT-DETR 的判断摆在一起对比。

DETR 是把所有尺度的特征都 flatten、拉平之后“慷慨地”放在一起算这种全量的注意力机制。问题在于，底层特征的分辨率更高，你 flatten 拉平之后它的 token 数量就特别大，计算量自然爆炸。

RT-DETR 的判断是：并非所有的特征都要用 Transformer 去做全局交互。可以做的事情是分工——把高层特征交给 Transformer，因为它包含了丰富的 semantic feature，这些特征回答的是“到底什么是物体”“是哪一个类别”；而更 low level 的一些特征，比如纹理、细节这类局部特征，就交给 CNN 去处理，因为它更适合 CNN。这样就是在利用两者各自的长处。

从图上可以这样读：CNN 处理到某一层之后，用 Transformer 处理出一层 semantic 的 feature，把 CNN 的 feature 和这层 semantic feature 在这里做一次融合。老师提醒不必过于关注那些方块和各种 fusion 的细节，只要知道它最终要把这几个特征融合起来，中间采用了一些过渡步骤。

> **老师总结**：这里可以 takeaway 的要点是——Transformer 适合处理 semantic 的 feature，也就是 high level 的 feature；而 token 计算量过大的情况下，可以用 CNN 去处理，low level 的 feature 可以交给 CNN。最后把 high level 的 semantic feature 与 low level 的 feature 再做融合。这样既利用了 Transformer 能提取 high level 特征的特点，也利用好了 CNN 能够很好做局部处理、减少计算量的特点。

### 8.5 一个类比：语言是抽象的，图像是具象的

老师又给了一个更根本的类比，来解释 CNN 与 Transformer 为什么会有这种分工。

Transformer 本来是处理 NLP 的。人类的语言本身就是一种高度抽象的特征：为什么“话筒”这两个字能代表这个东西？为什么“屏幕”两个字能代表那个东西？如果人类没有发明语言，或者我现在就告诉你“AB 代表屏幕”，你们都记住，那这节课以后我们就说 AB 是屏幕，这节课流传下去，从那节课训练出来的人都知道 AB 叫屏幕——这就是一种非常抽象的对应关系。

图像不一样。图像是在人类还没发明语言之前就最直观的东西：你看到长这个样子，就知道它是屏幕，你不需要把它跟“屏幕”这个词建立映射。

> **老师比喻**：CNN 就适合处理这种具象的图像表征；Transformer 本来就是处理 NLP 那种特别抽象的东西，它设计之初就是处理语言的。它可没有说“我的杯子一定要对应出一个什么出来”“一根红色的粉笔一定要对应出这样一个具象的图像”，它就是一个红色粉笔，你输进去就行了。所以 CNN 和 Transformer 各有优缺点，我们要知道怎么去利用好这些，这样后面自己设计的时候也就知道怎么设计。

顺着这个思路，老师又补了两点。第一，现在的大模型大部分都采用一种混合的架构。第二，CNN 目前基本上可以默认用来提取图像的 feature，这样可以保持它的高分辨率；虽然 ViT 那种做法是把图像划成小块再输进去，但那种做法一是分割的方式会有问题，二是处理特别高分辨率的图像时——手机、美图秀秀这类应用都要处理 1K、2K 的图——你再把它划分成 16 块，它也还是很大。所以在这种情况下，用 CNN 有它自己天然的优势。

### 8.6 一张表的写法

看完结果，老师特意停下来讲那张表格是怎么设计的，因为这是一个可以学的论文写作技巧。

看这张表最后一行，尤其看小目标那一列：它在小目标上实现了一个很好的性能提升。而整张表的分组也很明显：上面一类是 real-time object detection，这一边是 end-to-end object detection，再下面是 real-time end-to-end object detection。老师反问了一句：“你说真的有区别吗？”

但这样划分对他而言是有优势的。这张表肯定是精心设计过的——各种用色、用色块去加深，都是设计过的。为什么这样设计？因为论文写作里，他先强调的是“这些是 real-time 的 detector”，速度快，FPS 能到多少；然后他又强调“这边是 end-to-end 的”，端到端也是一个优点。而 real-time 的那些没有实现 end-to-end，end-to-end 的那些没有实现 real-time，于是他就给自己起了一个名字：real-time end-to-end detector，把两边上面的优点都占住了。

> **老师提示**：他这样划分之后，能让 reviewer 很明显地看到他 claim 的东西是什么。这是一个 paper 的写作技巧，一个写作上的 trick。

### 8.7 课堂提问：能不能在 S3、S4 上加注意力

讲完这些，老师抛了一个小问题让大家想：如果我们在 S3、S4 上强行引入 attention 层，虽然计算量增加，它是否会给小目标的检测性能带来实质性的提升？我们这里是在 S5 上做 Transformer 的，现在问的是小目标——小目标是不是在更高分辨率的特征上更能体现？如果直接在低层这儿做，行不行、会不会有提升？换做是你，你会不会这么做？

课堂上一时没有人回答，老师鼓励说“大胆一点，想到什么说什么，说不定你就猜对了”。随后他自己给出了分析。

答案是有可能会提升，但你要注意到，它的提升可能小到在指标上都体现不出来，而由此你会引入大量的计算。这笔账很好算：这一块如果是 $8\times8$，flatten 拉平之后是 64 个 token；但如果是 $16\times16$ 就是 256 个，$32\times32$ 就是 1024 个 token 要送进 Transformer，计算量一下子就变大了。

还有一个更实质的问题：小目标所在的那一层，本来 attention 是做全局注意力的，但这一层收集到的特征，它的上下文语义并不强。用前面那个类比说，到了高层，“AB 是屏幕”这个对应已经形成了；而在低层，连个 A 都还没写出来，你让它拿 AB 去指屏幕，它可能就形不成那样一种好的特征。

所以结论是：它有可能会提升，但在这里让它提升，代价过大——计算量会显著增加，而提升会很微小，甚至不如其他一些设计来得更实在。

> **老师启发**：这也是这篇论文做了大量实验之后给我们的启示——Transformer 应该在有 semantic feature 的 high level layer 上去做；其他的一些 layer 应该用 CNN 的方式去处理、去 concat，或者用 multi-scale 的 feature 去处理。

## 九、DiffusionDet：把检测变成框的降噪 [02:11:48–02:26:23]

### 9.1 DDPM 的正向与反向

最后一块内容是基于 diffusion 扩散模型的目标检测。老师说扩散模型这个词大家应该多多少少在很多地方都听过；这些模型本身有一定的争议，这里只看一件事：当年有了 diffusion 之后，大概 2020 年、2021 到 2022 年左右，大家是怎么把它用到检测里的。

先看 DDPM，也就是去噪扩散概率模型（Denoising Diffusion Probabilistic Models, DDPM），它是 diffusion 模型的原型。它的核心思想是有两个过程，一个正向、一个反向：

- 正向是逐步给一张图片随机加噪声。一直随机加、一直加，任何一张图片，你给它加噪点，总有一步能加到你都认不出来了——它跟随机产生的一张噪声图片已经没什么区别了。到那一步，如果我把这张图单独拿出来给你看，你会知道它是由一张人像产生的吗？不会。
- 反向则是逐渐去噪，把它逆回来，恢复出它的原始图像。

所以它整体是一个“加噪—去噪”的过程。在这个过程里，每一步要做的事情是去预测“从这一步到下一步”的那个噪声；当然数学上最终证明了，任意一步都可以直接去预测回 $x_0$，不必真的走完所有中间步骤。这里的公式比较复杂，老师建议感兴趣的同学自己下去推一下，尤其概率论学得好的更可以去推。

在 DiffusionDet 之前，diffusion 大部分是用在生成上的。道理很直接：既然能训练出这样一种加噪到去噪的过程，那么训练完之后，我随机拿一个噪声、再给它加一个条件“这是一张人脸”，它是不是就能反向产生出一个东西出来？所以它一般是在生成上用得很多。当然现在已经不只有 diffusion 了，还有 flow matching 之类的各种方法。

### 9.2 把框当作噪声：DiffusionDet 的核心转换

于是就有人想：我是不是能用它来做 object detection？这就有了 DiffusionDet，论文题目就叫 *Diffusion Models for Object Detection*。

它的做法是把目标检测构建成一个“从带噪框到目标框”的降噪过程。回想刚才的 DDPM：那是一个全图的加噪到去噪过程，是对图片做的一个过程。而检测这里想的就不一样了——做检测最终最重要的是不是预测那个 bounding box？那我就假设你这个 bounding box 的四个数字，是一组带噪的、随机的数字，我要学的就是逐步地从这种带噪的框里面，学出最终的真值框到底在哪里。它也是一种加噪、去噪的过程。

从数学上讲得很直白：一个框就是 $x_1$、$y_1$、$x_2$、$y_2$ 四个数字，那你就给这四个数字加噪，一直加到跟这个框完全都没关系了，然后再逐步地去找、把四个数字还原出来就行了。

课堂上用一张图做了很好的类比：原本的 DDPM 做的是上面那条路——逐步从噪声里复原出一张清晰的 RGB 图片；而 DiffusionDet 做的是下面这条路——假设这张图刚开始是一堆噪声框，然后逐步去找，找出这两个目标框。也就是说，它用 diffusion 的去噪能力去优化我的检测。

这个转换的巧妙之处在于动机：刚开始我的目标框预测本来就不准，是一种随机的框预测；那我就把这个框认为是一种噪声框，认为是真值框加了噪声之后产生的那种乱七八糟的框；然后我从这个噪声框到目标框（图中的蓝框、红框），认为它是一个降噪的过程。

> **老师总结**：这个思路很新颖。本来 diffusion 出来的时候，大家都是在做图像的生成；而目标检测本来是一个“说一是一、说二是二”的绝对预测性任务。结果他把这个思想转变了一下，认为检测也是一个从噪声框到最终目标框的降噪过程。

### 9.3 训练：给真值加噪，让 decoder 去噪

具体流程可以分成三步来看：先用编码器提取图像特征；然后从标准的高斯分布中采样、给真值框加上噪声；最后由 detection decoder 去降噪。

老师强调，这里重要的不是他 claim 了一个多玄的概念，而是他建立了这个思想之后怎么去实现它。

实现方式是这样的。先有这两个真值框、两个真值、各四个值。这里他用的是 XYWH 的表示，也就是中心位置加上宽和高——这是另一种真值表示形式，跟前面用的左上、右下顶点是一样的，四个数字都能表示一个框。

由这四个数字，他给它们加上高斯噪声；四个数字都会相应地变化，变化完之后就又是一个新的 bounding box。于是他造了很多这样的噪声，造出一堆服从高斯噪声的 bounding box 出来。然后他训练一个 detection decoder 去接受这些噪声，去恢复出这个 bounding box 的初始值，并且同时去预测类别。

所以 detection decoder 的输入，就是一堆乱七八糟的 bounding box，让它拿着这一堆框作为初始，逐步去噪，找到跟真值最匹配的那个 bounding box。

**算法**：DiffusionDet 的训练步骤（依课堂展示的伪代码）。

1. 用编码器（CNN 或 Transformer）提取图像特征。
2. 把真值框的坐标做 sigmoid 缩放，映射到 $[-1,1]$ 的范围内，让框的四个数字处在一个适合加噪的数值区间。
3. 随机采样一个时间步 $t$。
4. 按 DDPM 的加噪公式，由真值框和采到的 $t$ 生成一个带噪的框。
5. 把带噪框（以及图像特征、时间步）送进 detection decoder，让它预测噪声／预测去噪后的框。
6. 与真值计算训练损失。真值与预测之间的分配同样用匈牙利匹配算法来做，跟前面 DETR 的做法一样。

### 9.4 推理：没有真值时从高斯分布采样

推理的流程就清楚了：用编码器提取特征，然后从标准的高斯分布中产生边界框。

这里有一个必须注意的差别。训练的时候，那个噪声是怎么产生的？是给真值框加噪产生的，因为训练的时候你有真值。但推理的时候、实际用的时候，就没有真值了，初始那个“真值加噪”的来源就没有了。

可是 detection decoder 必须要一组“由框加噪后得到的噪声框”作为输入，怎么办呢？它这里没有真值，于是直接从高斯分布里随机产生一些 bounding box——一组跟这张图完全没关系、乱七八糟的框。

老师顺带把三种情形区分清楚，因为这是很多人容易混的地方：

1. 训练（training）时当然可以用真值，你知道 ground truth 是什么样，可以拿它对照着做监督。
2. 验证（validation）时不能用真值，但你在算指标、算准确率的时候，可以拿真值来对比一下。
3. 实际部署（比如装到摄像头里）时，那是一个全新的场景，没有人给你标真值，它完全没有真值；但要运行，模型要求的这个输入还是得有，所以就从标准的高斯分布里直接产生一堆跟这张图无关的框。

有了这组随机框之后，接下来就是 diffusion 标准的去噪过程：从 $T$ 到 $0$，把特征跟时间步逐步输入 detection decoder，逐步恢复出初始的边界框。

### 9.5 实验与“生成式方法做判别任务”

看实验效果：在 COCO 上，DiffusionDet 用 ResNet-50 就能达到 45.8 的 AP，超过了之前的一些性能；与 DETR 相比，AP 也是逐步有一个增加，从 43.5 增加到了 47.5。

这组数字说明的是这个模型的灵活性，以及它在处理复杂场景时的能力。更重要的是它示范了一件事：diffusion 能够被用在预测性的任务上。它原本是 generative AI 的方向，是生成式的、从无到有造出来的；而检测在我们看来是一个绝对的任务——你预测出来，我可以人为地判定它对还是不对：是猫就是猫，是狗就是狗，在哪里就是在哪里。现在我们发现 diffusion 也可以在这个里面去使用、去做这样一件事。

## 十、全课回顾与课堂问答 [02:26:23–02:37:17]

### 10.1 检测范式的主线：框从哪来、真值怎么分

到这里，基于 Transformer 的目标检测就基本讲完了。老师带着把整条线又串了一遍，回到上节课的 R-CNN。

R-CNN 系列一开始做的是：先产生出一堆 box 的 proposal；然后拿 CNN 在每一个 box 上去提特征——注意是每个框都提一次，提很多次；当时还用 SVM 去做分类；最后再对每个 proposal 去回归它的框。

有了这个基线，老师开始点名提问，把这几个模型之间的差别当场过了一遍。

### 10.2 课堂问答：Fast R-CNN 与 R-CNN

**课堂问答**：老师点名一位同学，问 Fast R-CNN 和 R-CNN 的区别。

学生回答的大意是：R-CNN 原来是在每个框上分别去做，Fast R-CNN 是把整张图放到网络里做；它主要的提速是因为调用次数减少了。老师确认“对”。

这里的逻辑值得写清楚：R-CNN 是对每个候选框单独跑一次 CNN，几千个候选框就是几千次前向；Fast R-CNN 改成先对整张图跑一次卷积得到特征图，再把各个候选框映射到这张特征图上做 ROI pooling。卷积只算一次，所以调用次数大幅减少，这是它提速的主要原因。

### 10.3 课堂问答：Faster R-CNN 与 Fast R-CNN

**课堂问答**：老师又换了一位同学，问 Faster R-CNN 和 Fast R-CNN 的区别。同学一时没答上来，老师就给提示：你想 Fast R-CNN 的时候，它的那个 region proposal 是在哪里产生的？

老师自己把这条线补全了：Fast R-CNN 的候选框是在 RGB 上产生的——根据 RGB 的特征、纹理、RGB 相似度，先产生一堆候选框。而 Faster R-CNN 的 region proposal 是从 RPN 产生的，也就是 region proposal network。

> **老师强调**：一定要记住，如果别人问你 Faster R-CNN，你一定要能反应过来：这个 RPN 是在 CNN 的 feature 上提出了一堆 proposal。因为之前 Fast R-CNN 的初始 box、也就是它的 proposal，是在 RGB 的图像上去初筛的。

相对而言，这种“先出候选、再分类回归”的结构叫 two-stage。

### 10.4 课堂问答：YOLO 为什么是 one stage

**课堂问答**：老师再换一位同学，问 one stage 的方法叫什么。同学答 YOLO，老师追问全称，同学答 you only look once。

接着问 YOLO 为什么是 one stage。老师把答案归结到真值分配上：YOLO 也会生成很多框，但它是用中间那个（格子）来算最后一次；它在分配真值的时候，是把物体落在的那个位置分配给它对应的真值。也就是说，它不需要中间先 proposal 出一个初始的 bounding box、再在这个框上做后续处理，它是直接在最后一步出 bounding box 的。这就是它的优势。

这段问答之后，老师做了一个很有价值的总结：从 R-CNN 一路看到这里，大家一直在解决的问题其实就是那么几个——bounding box（真值）怎么分配、怎么分配过去；这个框怎么预测出来；以及怎么产生一个最初始的 bounding box。

还有一个上节课讲过的问题也在其中：一张图里如果有多个 object，哪怕只有两个，用同一张图的一个 feature 都不太好去找到每一个 bounding box。所以 Faster R-CNN 系列一直的做法是：我先找到一个初始的、只包含一个 object 的区域，在这个区域上我再去预测 bounding box。而 YOLO 相当于把每一小块都强行处理——因为你把图划成很小的一个块，这一小块里就只有一个 object，它还是强行去做一个真值的分配。

### 10.5 课堂问答：DETR 的三个关键点

**课堂问答**：进入 Transformer 时代后，老师随口提问：DETR 是发表在哪一年的什么论文，title 叫什么，还有人记得吗？

同学答出了 end-to-end object detection with transformers、发表在 ECCV 2020。老师确认，并补充这是划时代的一篇，是 Facebook 做出来的。

它的特点是直接用 Transformer：CNN 成为一个 feature extractor，特征提出来之后直接送到 Transformer 里，Transformer 的架构改都没改，用的就是原本的架构。而在“送进去”的这个过程中，有三个问题必须回答：

1. CNN 的 feature 是 $H\times W$ 的，而 Transformer 要接受一个序列的 token，所以要把 CNN 的 feature flatten、拉平成一个 sequence 的 token。但拉平会导致失去图像原本的排列特征——举的还是那个例子，一个黑色像素在人的脸上你就是眼睛，在别的地方你可能是背景。为了维持住这种特征，它加了一个 position encoding；因为 Transformer 里的 attention 如果不加位置编码，它对所有位置都是同样的处理，会打乱特征的分布。
2. Transformer 的 decoder 需要一个 query，需要一个 Q。DETR 里这个 Q 是怎么来的？是随机初始化的，但要记住它是一个 learnable parameter，它自己本身也是能更新的。
3. 输出之后，预测的 bounding box 跟真值又会出现匹配问题。因为在 YOLO 和 Faster R-CNN 里面，我们基本上是依据一种位置映射关系去分配的；但在 DETR 里，这个位置映射关系经过 Transformer 之后就没有了。没有之后怎么分配？解决方法是把它变成一个集合与集合之间的匹配预测问题，也就是二分图匹配，用的算法是匈牙利算法。

接着老师又把这个第一条工作的缺点与后续改进串了一遍：DETR 的收敛速度慢，对小目标物体也不太友好。为什么收敛慢？老师提问，同学答了一半，老师补全：因为它要对全图算 attention，全部 flatten 之后 token 的数量有 $H\times W$ 个；刚开始 query 是随机初始化的，attention weight 相当于一个均值的 attention，它没有特别注意到哪里；这种情况下，attention weight 要收敛到“去关注有意义的信息”，就会非常慢。所以它需要 500 个 epoch——这真的是一个很大的数字，当你回头自己去训练的时候，就会体会到什么叫 500 个 epoch 的巨大训练代价。

Deformable DETR 怎么解决这个问题？靠采样。之前的 attention 是 $HW$ 乘 $HW$ 的，deformable 只采 K 个点，后来那一版里 K 只有四个点；这是一种稀疏的 attention，通过它极大地降低了 attention 的计算量，也就可以更快地收敛。

再往后是 CNN 与 Transformer 的联合架构 RT-DETR，它给的启示是：high level 的 feature 更适合用 Transformer 去处理，low level 的 feature 可以用 CNN 去处理，这两个联合起来的混合架构更有优势一些。最后则是 diffusion——扩散模型也能做目标检测。

## 十二、课后答疑 [02:38:12–02:42:40]

### 12.1 图片特征在框降噪中起什么作用

**课堂问答**：下课后有同学追问：DiffusionDet 这个时候是怎么把图片的特征用进去的？因为传统的 diffusion 是直接在图像上做采样、做加噪去噪的，而这里似乎只有框的信息，没有图片的信息。

老师解释：它在降噪的过程中，实际上一直处理的是这个框。图片还是正常的一个处理，并没有给图片加噪，加噪是加在框上。DiffusionDet 在预测这个框的噪声的时候，是需要图片的 feature 的；图片的 feature 只是一种参与降噪、辅助它去噪的特征。它并不像之前那个 diffusion 一样，是根据图像特征直接去预测噪声——之前的 diffusion 噪声是加在图像上的，所以它需要根据图像上的分布去预测噪声该往哪里去；而这里是加在框上、在框上去找，图像特征起的是辅助作用。

老师也坦白了自己的观感：他一开始也觉得这件事有点奇怪，所以这篇工作刚出来时是有一定争议度的——他 claim 了这个概念，但后来大家实际去可视化，发现它所有初始的框其实都是一个全图的 box，并不是真的一个随机 box 的展示；不过最终出来的效果还可以。

### 12.2 patch token 与特征图上的点

**课堂问答**：另一位同学问：ViT 里面是把 patch 作为 token，为什么后面的这些工作就直接拿一个像素、一个特征图上的点当作一个 token？

老师先解释 ViT 为什么那样做：因为当时大家都觉得 CNN 是不可替代的，ViT 想证明一下 CNN 可以被替代——不要 CNN，全部用 Transformer 也能处理。但它要适配 Transformer 的架构，就必须把图像映射成一个个 token，于是它把图像划成 $16\times16$ 的格子，每个 patch 用一次 linear 映射变成一个 token。

但回过头想：CNN 提了一系列特征之后，本身也已经降维成了一个比如 $16\times16$ 的特征图；那把这个特征图上的点拿去做 token，跟直接 patchify 那种硬分割相比，是不是更好一点、更优雅一点？

老师的结论是：其实这两种做法都是为了去适配 Transformer 的结构，只是为了让输入输出能够匹配上；但提取出来的特征质量，肯定是经过 CNN 之后的更高——因为 ViT 里直接划完格子之后，是把 RGB 的像素拉平，再拿一个 linear 映射一下，就那么几层映射，它的质量能有多高。

### 12.3 视觉模型与多模态大模型

**课堂问答**：还有同学问：这一类的视觉模型和现在那些很大的多模态大模型，在现在的任务上有什么区别？
