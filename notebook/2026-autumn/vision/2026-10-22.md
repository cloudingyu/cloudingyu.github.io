## 一、ResNet50 与 Food101 迁移学习 [00:02:14–00:39:37]

### 1.1 Food101 与 ResNet50 的结构

上课一开始，老师先交代数据准备的事情：如果 Food101 数据集还没有下载好，可以现在就下载一下，然后把它放到自己的路径上。之所以要提前说，是因为 Food101 数据集比较大，有 4 GB，下载需要时间，如果还没下载好就可以趁现在下载。

交代完数据，就进入本次第二次实验课的内容。今天讲的是图像分类。实际上上一节课在讲 CIFAR100 的时候，就已经涉及到分类任务了；不过那个时候做的分类，更多的是让大家去熟悉一下整个 PyTorch 的流程——比方说怎么去建模型、怎么样去做数据预处理等等。今天则会把重点放在三款具体的模型上，由浅入深地讲这三个模型之间的区别，以及它们在做分类任务时的使用方式。

本次课使用的数据集是 **Food101**（Food-101）。它是由 ETH 发起的一个非常经典的图像分类数据集。这个数据集的分辨率比较高，一般来说它有三种分辨率：$512\times512$、$512\times384$，也有 $384\times512$。这样的分辨率才是计算机视觉这个 task 中比较常见的一种分辨率。

对比上一节课碰到的 CIFAR100 和 FashionMNIST，如果大家还记得的话，它们的分辨率是 $32\times32$ 和 $28\times28$，所以图像会很模糊、看不太清；而今天这个数据集看起来就会很清楚。

数据量方面，Food101 差不多有 101,000 张图像，并且划分成训练集和测试集，这是常规做法。它一共有 101 个类别。

Food101 的一个特点是它是细分类别，包含非常多外观极度相似的东西。为什么呢？因为它的图像都是食物：比方说都是牛排，那肯定有不同种类的牛排，长得都很像，甚至我们人眼可能都分不出来；这个时候就需要让模型去帮我们分辨出它究竟是哪一种牛排。

所以这个数据集的特点可以归纳为三条：

1. 它是高分辨率的；
2. 它有很多的类别（101 类）；
3. 类别之间比较相似——存在一些类别，它们之间是比较相似的。

今天会涉及三款不同的模型。

第一款是非常经典的 ResNet，我们选择的是 **ResNet50**（Residual Network，残差网络，50 层版本），它是基于残差网络的卷积神经网络的分类结构。

第二款是 **ViT**（Vision Transformer），讲它是如何去做图像分类任务的。

第三款会讲到 **CLIP**（Contrastive Language–Image Pre-training）；CLIP 严格来说不是一个分类任务，它更像是一个开放式的检索任务，这一点之后也会提到。

先回到 ResNet50 本身，看它究竟在做一件什么事情。首先在这里输入一张图像，它也会经过一个入口层，然后经过四个 stage（Stage 1、Stage 2、Stage 3、Stage 4），最后它们再进入线性层（linear），去得到它的一个分类结果。

如果把四个 stage 和整个入口层放在一起看，它实际上就是一个很强大的 backbone（主干网络），也就是说它的特征提取器非常大。但它本身的架构跟上节课讲的那个 CNN 其实是大同小异的：本质上它就是一个 backbone 再加上最后的一个线性分类器，这么一个结构；它只是把主干部分做得更深、更强了而已。

从 shape 上可以感受一下它是如何提取特征的。比方说我们在这里输入这个原图，它是 $3\times224\times224$：3 表示它有三个通道，也就是 RGB；224 和 224 表示的是 H 和 W，它的高和宽都是 224。

然后它经过这个入口层——"入口层"只是老师给它起的名字，实际上可以把它理解成是一个浅层特征提取器——经过入口层之后，出来的 feature map（特征图）的 shape 是 $64\times56\times56$：特征的通道维度从 3 变成了 64，但是分辨率从 224 减到了 56，是这么一个过程。

继续往下看：经过第一个 stage 之后，它变成 $256\times56\times56$；经过第二个 stage 变成 $512\times28\times28$，到这里通道维度再次 double，并且分辨率再次砍一半；第三个 stage 之后是 $1024\times14\times14$；最后是 $2048\times7\times7$。最后它把这个 $7\times7$ 又做一个处理，把它变成 $2048\times1\times1$；最后再经过一个线性层，就得到 101 类的分类预测结果。

整个过程的 shape 变化可以列成一张表：

| 位置 | 特征图 shape（$C\times H\times W$） | 变化 |
| --- | --- | --- |
| 输入图像 | $3\times224\times224$ | 3 个 RGB 通道，高宽均为 224 |
| 入口层 | $64\times56\times56$ | 通道 $3\to64$，分辨率 $224\to56$ |
| Stage 1 | $256\times56\times56$ | 通道 $64\to256$，分辨率不变 |
| Stage 2 | $512\times28\times28$ | 通道翻倍，分辨率减半 |
| Stage 3 | $1024\times14\times14$ | 通道翻倍，分辨率减半 |
| Stage 4 | $2048\times7\times7$ | 通道翻倍，分辨率减半 |
| 对 $7\times7$ 再处理 | $2048\times1\times1$ | 把 $7\times7$ 压成一个点 |
| 线性层 | $101$ | 输出 101 类的预测结果 |

所以可以看到，它其实是一个通道维度在不断上升、并且分辨率在不断降低的过程。

**补充说明**：根据本节补充材料《实验2_1_resnet50_学生.ipynb》cell 2 的模型结构说明，入口层由 `Conv` → `BN` → `ReLU` → `MaxPool` 组成；结合《resnet50.md》可以确认，入口层是 `Conv2d(3, 64, kernel_size=7, stride=2, padding=3, bias=False)` 接 `BatchNorm2d(64)`、`ReLU`，再接 `MaxPool2d(kernel_size=3, stride=2, padding=1)`。这两步的 stride 都是 2，所以 $224\to112\to56$，正好对上课堂上说的"分辨率从 224 减到 56"。材料中把这种"$1\times1$ 卷积 → $3\times3$ 卷积 → $1\times1$ 卷积"的 block 称为 **Bottleneck**（瓶颈块），课堂上老师只称它为 block。

看到这里可以思考一下：为什么会这么设计？因为我们要提取特征，老师说自己刚接触这个模型的时候也会觉得，我要去学习更多的特征，那为什么特征图的分辨率是在不断减小的？应该不断增大才对，因为如果不断增大的话，我才能够获得更多的信息。

实际上这就要提到卷积网络领域里深层和浅层的一个任务分配。

一般来说，对于一个卷积网络来说，它的浅层就是它这个入口层，这个网络主要是提取图像的一些表层信息，比方说它的颜色、再比方说它的纹理、它的形状等等。

举例来说，假设这张图是一只猫，在这个阶段的 feature map 里，它其实不知道这是一只猫：它只知道这是一个黄色的东西，然后这个地方有耳朵、有眼睛、有身体，但它不知道这具体是什么。越往后走到最后一层这个地方，"它是一只猫"这个判断就感觉越来越清楚了。

原因在于，由于后面的 feature map 很小——比方说在这个地方它可能就只有 $7\times7=49$ 个特征像素点——那么它的每一个特征像素点就可以对应到原图里非常大的一个区域。所以因为它可以从一个小的特征点对应到非常大的一个范围，它就能够有更强大的一个全局的感受。

反过来，如果你这个特征图还是很大的话，那么每一个点对应的可能还是原图里的一两个点，在这种情况下，它就只能提取一些表层的信息。

这也就是为什么在所有的卷积网络中，随着层数的加深，一般来说它的通道维度是在不断上升的，但是它的特征图的尺寸是在不断降低的——这就是它为什么要这样去设计。

> **老师总结**：通道维度不断上升、特征图尺寸不断降低，是卷积网络里深层和浅层任务分配的结果：浅层看颜色、纹理、形状这些表层信息，深层靠小特征图上的大范围对应关系获得更强的全局感受。

另外还有一个点：为什么 shape 是写成 $3\times224\times224$，而不是写成 $224\times224\times3$？这实际上是大家之后在整个使用 PyTorch 的时候会碰到的一个常用规则。

我们直观地读取一张原图时，读取的方式应该是"长、宽、高"：比方说它长 224、宽 224，然后高（也就是通道的维度数量）是 3。也确实如此：如果你只是用普通的读图方式，比如用 OpenCV 里面的 `cv2.imread`，或者用 PIL，去读取一张普通的图（还不涉及到网络的时候），那么它的格式确实是 HWC，也就是高、宽、通道。

但是在 PyTorch 的所有网络中，为了能够更好、更直观地去显示通道维度的变化，我们一般把通道维度（channel）放在第一位，所以在所有的 PyTorch 模型中，张量（tensor）的表达形式、它的 shape 都是 CHW。比方说输入这里 C 是 3，H 和 W 都是 224；而到后面这里，C 是 256，H 和 W 就都是 56 和 56 了。

> **老师提示**：这一点比较重要。之后会经常看到一些 reshape 的操作，它其实就是把一张图从刚读进来的 HWC 经过 reshape 转成 CHW；shape 是在不断变化的，大家要注意它为什么这样去表示。

再具体看它的设计结构。模型叫 ResNet50，这里可以思考两个问题：首先为什么叫 ResNet？其次为什么是 50？

先介绍第一个问题。ResNet 大家都知道是残差网络，那它的残差在什么地方呢？它其实就残差在这四个 stage 里面。

可以看到 Stage 1 这里有乘以 3，Stage 2 写的是乘以 4，Stage 3 写的是乘以 6，Stage 4 写的是乘以 3。这个意思就是：这里有三个相同的 block 堆叠在一起，然后它们统称为 Stage 1；这里有四个相同的 block 堆叠在一起，统称为 Stage 2；后面也是一样的。

以 Stage 2 作为一个例子：可以看到它有四个完全长得一样的卷积块——做出一个之后，在编辑器里 Ctrl+C、Ctrl+V 再复制三遍，所以它一共有四个，看过去 1、2、3、4 长得一模一样。

它的每一个 block 是由三层、也就是三个卷积的 module 组成。老师补充说，这个只是它当初刚好就是这么设计的，并不是严格必须这么干。

比方说在第一个 block 里面，它是有三个卷积的模块组成，分别是一个 $1\times1$ 的 convolution、一个 $3\times3$ 的 convolution 和一个 $1\times1$ 的 convolution。那么这就是一个 block，然后把它复制粘贴，四个 block 都是一样的。

**补充说明**：根据本节补充材料《实验2_1_resnet50_学生.ipynb》cell 2，四个 stage 的 block 数与每个 block 内的通道配置为：Stage 1 有 3 个 block，每个 block 是 $1\times1$（64 通道）→ $3\times3$（64 通道）→ $1\times1$（256 通道）；Stage 2 有 4 个 block，为 $1\times1$（128）→ $3\times3$（128）→ $1\times1$（512）；Stage 3 有 6 个 block，为 $1\times1$（256）→ $3\times3$（256）→ $1\times1$（1024）；Stage 4 有 3 个 block，为 $1\times1$（512）→ $3\times3$（512）→ $1\times1$（2048）。《resnet50.md》进一步显示，每个 stage 只有第 0 个 block 带 `downsample` 支路，其余 block 没有。课堂只以 Stage 2 为例讲了通道从 256 到 128、128、512 的过程，其余 stage 的通道数字是对照材料的补全。

再以 Stage 2 为例看它里面的结构。它的输入 tensor 的 shape 是 $256\times56\times56$，也就是说通道数是 256，特征图（feature map）的尺寸是 $56\times56$。然后它经过这三个卷积的 module，可以看到这三个卷积 module 变化的不是分辨率的尺寸，而是它的通道：比方说是 $256\to128$、$128\to128$、$128\to512$。

所以这也就是为什么我们会把 channel 的维度写在最一开始：因为这样看起来会更加清楚；如果你把 256 写在最后的话，看起来就比较别扭。

那么残差体现在哪里呢？这个特征图进来经过这个主干——我们说"有残差就一定会伴随着主干，如果你没有主干，就不存在残差的概念"——所以这就是它的主干部分，它会经过三个卷积。

然后它的残差，就是它会把浅层的这个输入直接一条线连过来，去跟经过三个卷积之后的这个 tensor 做逐个元素、也就是逐个位置的相加，这个就是它的残差的过程。

> **老师强调**：大家在做逐个位置相加的时候，一定要保证你的这个 tensor 的 shape 是一致的。

下面把 Stage 2 这个 block 的 shape 变化逐步推一遍。

**推导**：以 Stage 2 的一个 block 为例，设输入特征图为 $256\times56\times56$，并设该 block 内部的分辨率保持不变。

第一步：第一个 $1\times1$ 卷积把通道从 256 压到 128，输出 $128\times56\times56$。

第二步：$3\times3$ 卷积在"分辨率不变"的假设下进行，通道仍是 128，输出仍是 $128\times56\times56$。

第三步：第三个 $1\times1$ 卷积把通道从 128 升到 512，输出 $512\times56\times56$。

第四步：残差支路要把最浅层的输入 $256\times56\times56$ 与主干输出 $512\times56\times56$ 逐元素相加，两边通道数不同、无法直接相加，因此在支路上用一个 $1\times1$ 卷积把输入从 256 通道升到 512 通道（分辨率保持 $56\times56$），使两边 shape 对齐。

结论：block 的输出为 $512\times56\times56$；支路上那个卷积（材料中称为 `downsample`）的唯一作用就是让残差相加时两边的 shape 对得上。

老师还补充说：当然也可以把主干输出的通道就设成 256，那这个支路上就不用做这个卷积，所以它并不是必须的；在这个支路上做一个卷积的目的，就是为了让它在相加的时候能够对得上。

后面几个 block 也是一样的，一共四个部分，直接复制过去，这就是 Stage 2；Stage 1、Stage 3、Stage 4 也是相同的一个道理。整个网络里可以看到，它每一次的输入输出都是不断地把 channel 维度在提升、把 feature map 的尺寸在降低，就是这么一个过程。

再回答第二个问题：为什么叫 ResNet50。老师直接给出答案：在 ResNet 当初的定义里面，这个 50 表示在整个网络结构中一共有 50 个卷积层和全连接层。

大家注意，是 50 个卷积层加全连接层——不是只有 50 个卷积层，也不是只有 50 个线性层。因为大家知道 BN（batch normalization，批归一化）层其实也是有参数的，但它不包含在这 50 里面；这个 50 只是表示卷积层和线性层的个数。

**推导**：按照"每个 block 三个卷积层"来数，50 这个数字可以这样加出来。

第一步：入口层里有 1 个卷积层（$7\times7$ 卷积，通道 $3\to64$），计 1 个。

第二步：Stage 1 有 3 个 block，每个 block 3 个卷积层，共 $3\times3=9$ 个。

第三步：Stage 2 有 4 个 block，共 $3\times4=12$ 个。

第四步：Stage 3 有 6 个 block，共 $3\times6=18$ 个。

第五步：Stage 4 有 3 个 block，共 $3\times3=9$ 个。

第六步：最后还有一个线性层，计 1 个。

合计：$1+3\times3+3\times4+3\times6+3\times3+1=1+9+12+18+9+1=50$。这就是"50"这个命名方式的设计动机。

老师还提到，大家可能还看到过 ResNet 的其他版本，比如 ResNet-101 等等，那都是同样的道理：只不过把网络再多叠几个 block、或者多加几个 stage，其实没有什么特别神奇的地方。

ResNet50 的概念部分基本上就讲到这里。接下来进入代码部分，可以打开实验 2-1，这个代码可以跟大家一起执行一下，因为今天这个代码也是有一些 TODO 的部分。

### 1.2 数据预处理、搭建网络与加载预训练权重

训练集上的**数据增强**（data augmentation）沿用了上一节课讲过的做法，即水平翻转、旋转（`RandomRotation`）这一类随机扰动。测试集则不再做这些随机变换，仍然只保留最常规的两步操作——`ToTensor` 和 `Normalize`。`ToTensor` 有两个作用：把图像转成 tensor 类型，并且把像素值除以 255 做归一化；`Normalize` 负责的是按通道减均值、除标准差，也就是**标准化**（Normalization）。

老师特别指出，这一节课 `Normalize` 用的参数就是标准的 ImageNet 参数：其中一组数表示 RGB 三个通道的均值，另一组数表示 RGB 三个通道的标准差。

**补充说明**：根据本节补充材料《实验2_1_resnet50_学生.txt》cell 1，`Normalize` 的均值取 `(0.485, 0.456, 0.406)`、标准差取 `(0.229, 0.224, 0.225)`；训练侧的完整变换是 `Resize((224, 224))` → `RandomHorizontalFlip()` → `RandomRotation(10)` → `ToTensor()` → `Normalize(...)`，测试侧只有 `Resize((224, 224))` → `ToTensor()` → `Normalize(...)`；两个 `DataLoader` 的 `batch_size` 都是 64，`num_workers` 都是 10。

这一段代码直接正常运行就行。老师顺带说明 batch size 这些也是常规设置，与之前一样，没有改动。数据处理这一段之后，就进入第二部分——ResNet 的网络结构。

接下来老师快速过一遍整个 ResNet 的结构，并说明和刚才讲的内容是一样的。数据在网络里的走向是：

1. 先经过入口层，做浅层特征提取；
2. 再依次经过 Stage 1、Stage 2、Stage 3、Stage 4，每个 stage 内部由若干个 block 堆叠而成；
3. 最终输出的 feature 形状是 $(2048, 7, 7)$，也就是 2048 个通道、$7\times 7$ 的 feature map。

这个 $7\times 7$ 的 feature map 虽然已经很小了，但要转成最终的分类结果，还要再做一次池化（代码里是 `avgpool`），把它压到只有一个空间位置，变成 $(2048, 1, 1)$；然后再经过一个线性层，输出 101 个类，这就是整个网络的结构。老师同时把结构图打印了出来，让大家在写代码时对着看。

我们的网络结构定义其实分成了两部分。之所以这样拆，是因为前面提到网络有四个 stage，而每个 stage 里 block 的数量还不一样；如果把这些全都塞进一个类里，这个网络类会非常大。这也是定义模型时经常会用到的一个点：有相同的模块，就把它单独抽出来。

> **老师提示**：定义模型的时候，遇到相同的模块就单独拿出来定义，避免整个类定义得太大。

于是这里先在 notebook 里单独定义了一个 block 模块，即**瓶颈块**（bottleneck，代码里的类名是 `Bottleneck`），它表示的是"每一个 block 该如何设计"，实际上就是每个 stage 里面的一个 block。这个 block 由三段卷积组成：一个 $1\times 1$ 卷积、一个 $3\times 3$ 卷积，再用一个 $1\times 1$ 卷积做升维；除此之外还包括 ReLU、BatchNorm 这些函数，以及残差分支上的 `downsample`。

**补充说明**：根据本节补充材料《实验2_1_resnet50_学生.txt》cell 4 与《resnet50.md》，`Bottleneck` 中的 `expansion = 4` 表示升维后输出通道数是输入通道数的 4 倍、只在该 block 的最后一个卷积层使用；`downsample` 只会在每个 stage 的第一个 block 中使用；`forward` 的最后一步是 `out += identity` 之后再过一次 `self.relu(out)`，即残差相加之后还要再做一次 ReLU。

前向传播的写法是这样的：函数的输入 `x` 就是这一层的输入；代码里先把 `x` 复制一份赋给 `identity`，这个 `identity` 就是**残差连接**（residual connection）里要用到的残差——之后会把它逐元素（element-wise）加回主干的输出上。也就是说代码里对应着两条支路：一条是主干部分，一条是残差。

> **老师强调**：这个 `identity` 就是后面要 element-wise 加上去的残差，这一步很重要。

主干部分依次经过：

1. `conv1` 加 `bn1`，再过 ReLU，这是第一个 $1\times 1$ 卷积；
2. `conv2` 加 `bn2`，再过 ReLU，这是 $3\times 3$ 卷积；
3. 第三个 $1\times 1$ 卷积：这一行老师留给学生自己写，并说这一行也比较简单，和前面是一样的写法，都是先经过卷积、再经过 BN。

**补充说明**：根据本节补充材料《实验2_1_resnet50_学生.txt》cell 4 的 TODO 提示，第三行应实现为 `conv3` → `bn3`，先卷积再 BN，不需要 ReLU。

主干部分得到输出之后，再把这个输出与残差相加：残差这条支路本身也要经过一个 $1\times 1$ 卷积 `downsample`，把两者的通道数对齐，然后按元素位置逐个相加，得到这个 block 最终的输出。

block 定义完之后，就可以定义主干网络了。老师认为这个主干网络类看上去还是蛮清晰的，它由三部分组成：入口层、四个 stage 和输出层。

入口层的定义就是浅层特征提取那一部分。`self.layer1` 到 `self.layer4` 就是四个 stage，在每个 stage 里直接调用前面已经定义好的 block 来堆叠——因为 block 已经单独定义过了，这里不用再重写一遍。老师在这里说明这就是他的四个 stage，有不懂的可以随时打断。

输出层也一样：`avgpool` 把最后那个 $7\times 7$ 的 feature map 压成一个空间位置，然后再经过一个线性层，最终输出 `num_classes` 维，也就是 101 个类别。至此网络结构就定义完了，它包含两件事：每一个 block 如何定义，以及这些 block 组成 stage 之后整个模型该如何定义。

这里留了一个练习：框架已经给大家写好了，只需要补上从 Stage 1 到 Stage 4 的前向传播过程。老师给出的提示是：`x` 先后经过 `self.layer1` 到 `self.layer4`，然后经过 `avgpool` 拉平（flatten），再经过 `fc` 这个**全连接层**（fully connected layer, FC）做线性变换。

再往下是把模型实例化。代码里写的是 `[3, 4, 6, 3]`，这就是每个 stage 的 block 数量：第一个 stage 3 个 block，第二个 stage 4 个，第三个 stage 6 个，第四个 stage 3 个。定好这个列表，就能把模型实例化出来。

模型定好之后，接着是权重的问题。老师先解释为什么不从头训练：这个模型很大，一方面输入的分辨率本身就比较大，另一方面 ResNet50 本身就是一个很大的模型，所以它不是一个简单的 CNN 就能解决的问题；如果让大家在课上从头训练，会非常耗时，而且性能也不会特别好。因此课上直接提供一份**预训练权重**（pretrained weights）——这份权重在昨天的压缩包里都有，大家直接 load 就行；把权重载进来之后，再对它做一些修改。

本地加载这份权重有一个还蛮关键的地方：它是在 ImageNet 上预训练出来的，而 ImageNet 有 1000 个类别，所以这份权重里最后一个全连接层的输出是 1000 个 channel；但我们的 Food101 任务只有 101 类。老师做的操作是：

1. 先把这个权重文件加载好，用 `load_state_dict` 把它载入到自己的模型里；
2. 这时网络其实是不适配的——权重里最后一层是 1000 维，而任务要的是 101 维；
3. 于是把模型的最后一层人为地从 1000 改成 101：重新定义 `model.fc`，用 `model.fc = nn.Linear(model.fc.in_features, 101)` 覆盖掉原来的全连接层。

也就是说，这一步做的事情可以概括为：加载一个预训练权重，并且修改最后的线性层来适配我们具体的分类任务。

**补充说明**：根据本节补充材料《实验2_1_resnet50_学生.txt》cell 6，预训练权重有两种取法——联网下载可用 `models.resnet50(weights=models.ResNet50_Weights.IMAGENET1K_V1).state_dict()`，本地加载则用 `torch.load("10_21/ckpt/resnet50-imagenet-pretrained.pth")`；两种方式都是先得到 `pretrained_state_dict`，再 `model.load_state_dict(...)`，最后才执行 `model.fc = nn.Linear(model.fc.in_features, 101)` 并把模型 `.to(device)`。

载入并改好之后，可以把整个模型打印出来看一眼——这一步同样要 load 一下权重，本地加载应该是很快的。老师提醒：这个模型架构打印出来应该是很大的，不用管它有多大，感兴趣的话可以看；真正要关注的是最后一层，它输出的必须是 101，而不是 1000。

> **老师强调**：模型架构有多大不用管，只要保证最后一层输出的是 101、而不是 1000 就可以了。

要理解这个小实验，得先把刚才做的事说清楚：刚才那次微调是**全量微调**（full fine-tuning），也就是说，模型的主干（backbone）部分——四个 stage 加上前面的浅层特征提取——以及最后的那个线性层，全部都参与训练，全部都会被更新。

现在要做的是一件类似**消融实验**（ablation study）的事情。逻辑是这样的：既然加载预训练权重之后，我们只改动了最后一个线性连接层，那么反过来问一句——能不能干脆把最后这个线性层前面的整个主干都固定住、一点都不动它，只训练最后这一层？在这种情况之下，训练速度肯定会快得多（要更新的参数少了一大截），但性能会变成什么样？这就是老师想让大家动手做的小实验。

> **老师强调**：你们之后写论文、写 ablation study 的时候，这种消融/对照实验其实就类似于这样——一次只改一个变量，看性能怎么变。

所以这里有两套方案摆在一起对照：一套是刚才已经做好的全量微调；另一套是不做全量微调，只对最后一个线性层（也就是被改过的那一部分）做微调。后者的效果如何，需要大家自己跑出来看。

代码方面，老师已经把最关键的那些函数都写好了，整体流程是：

1. 定义模型。注意定义的时候类别数仍然写 1000 类，目的是让 ImageNet 预训练的 `state_dict` 能够正常、正确地加载进来；
2. 加载预训练权重；
3. 再把分类头换成 101 类（`model.fc` 换成输出 101 维的线性层），这里有一个“先 1000 类、后转 101 类”的转换过程；
4. 冻结主干——这一步老师留成了 TODO，需要大家自己完成：怎么写才能把整个网络的主干冻结（freezing）住，只让它去适应最后那个线性层；
5. 优化器老师已经定好了，不需要大家改。

**补充说明**：根据本节补充材料《实验2_1_resnet50_学生.txt》cell 11，这个 block 里的具体写法是：先用 `resnet50(num_classes=1000)` 建模型并 `load_state_dict` 加载预训练权重，接着是一个 `for param in head_only_model.parameters():` 的循环供学生填冻结逻辑，循环之后才执行 `head_only_model.fc = nn.Linear(head_only_model.fc.in_features, 101)`；损失函数为交叉熵，优化器为 `optim.Adam(head_only_model.fc.parameters(), lr=1e-4)`（只把分类头的参数交给优化器），轮数复用前面设定的 `epochs`。同一 cell 给出的 `train_head_only` 函数在每轮开始时先把整个模型置为 `model.eval()`、再单独把分类头置为 `model.fc.train()`，也就是只让分类头处于训练模式。

课间回来后，老师先把上节课 ResNet50 这条线的最后一个点收尾：冻结到底是怎么实现的。

实现上，冻结就是加一行代码：遍历 `model.parameters()`，把每个参数的 `requires_grad` 置成 `False`。它的意思很明确——这部分参数不要梯度回传了，反向传播走到这里就可以直接跳过去，参数也就不会被更新。

> **老师提示**：冻结其实就是这么一行代码的事，但这个东西你以后会经常碰到。

老师举了一个后续课程里会遇到的场景：有些课程作业会用到 SAM（Segment Anything Model）这一系列模型，比如 SAM 1、SAM 2、SAM 3。很多时候做微调，它的 backbone 可能根本不需要训，或者你也没有那个算力去训，更没有那个必要去训。在这种情况之下，你就可以把它加载过来直接 freeze 掉，用的是一模一样的操作：把 backbone 那些权重找出来，把它们的 `requires_grad` 设成 `False` 就可以了。

训练函数本身比较常规，和前面一样：设 5 个 epoch 或者 2 个 epoch，每个 epoch 里训练一下、测试一下。

真正值得看的是它的输出。老师在训练输出里打印了两样东西：**总参数量**和**可训练参数量**。ResNet50 的总参数量非常大——老师逐位往下数（十万、百万、千万），最后给出的是有两千三百万个可学习参数。但是把它的整个 backbone（四个 stage）全部冻结住，再加上前面的浅层特征提取器也全部冻结住，只训练最后那个线性层的时候，可训练参数就从 2300 万直接降到了只有 20 万左右。老师评价说，这一下基本上把参数砍掉了非常大的一个比例。

| 方案 | 参与训练的层 | 总参数量 | 可训练参数量 | 测试准确率 |
| --- | --- | --- | --- | --- |
| 全量微调 | 主干（四个 stage + 浅层特征提取）+ 最后线性层 | 约 2300 万 | 约 2300 万（全部参与训练） | 1 epoch 约 73.6%，2 epoch 约 78%，3 epoch 约 79% |
| 只训练分类头 | 只有最后那个线性层 | 约 2300 万（不变） | 约 20 万 | 约 50% 一线；老师明确说达不到 70%–80% |

**补充说明**：根据本节补充材料《实验2_1_resnet50_学生.txt》cell 11 与结构材料《resnet50.md》，被替换的分类头是 `Linear(in_features=2048, out_features=101, bias=True)`，因此只训分类头时的可训练参数就是这一层的权重与偏置，即 $2048\times 101 + 101 = 206{,}949$ 个，约 20.7 万，与课堂上“只有 20 万”的数量级一致。

老师还教了一个检查手段：把可训练参数打印出来，看它到底包含哪些。打印出来会看到，可训练参数确实只有最后的 `fc.weight` 和 `fc.bias` 两项——没有别的层混进来。用这个方法就能确认自己是不是真的只训了最后一层，还是不小心把前面某些层也一起训了。

> **老师提示**：把可训练参数打印出来看名字，是一种很好的 check 方式——你能立刻知道自己到底只训了最后一层，还是把前面也训了。

随后老师在这里跑了一个 epoch 看结果。这就是一个消融实验：当参与训练的模型量（可训练参数量）上去的时候，整体的性能确实就会跟着上去；反过来，如果只让最后一个线性映射层去适应这个新数据集，那性能肯定不会特别高。

> **老师总结**：这就是一个消融实验——当我训的模型量上去的时候，整体性能它就会上去；如果我只适应最后一个线性的映射层，那这个事情肯定不会特别高。

## 三、视觉 Transformer（ViT） [01:01:22–01:46:28]

### 3.1 ViT 的基本想法：patch、CLS token 与位置编码

老师从 transformer 在自然语言里的用法讲起，用它来对照图像。一句话 "this is a dog" 可以被拆成 this、is、a、dog 这几个词，连里面的空格、句号等等也都会各自作为一个 **token**（词元）。把这些 token 全部输入进去之后，它们会经过一些 attention 层；attention 让不同的 token 之间做交换，模型因此就能很好地理解这句话的意思。这就是 transformer 的基本信息单位。

那么对于图像，怎么把它转成 token 呢？老师说这部分其实非常有意思，不了解 **视觉 Transformer**（Vision Transformer, ViT）的同学可以重点看一下。

做法是把一幅图先处理成 $224\times224$，然后像切披萨饼一样把它切成不同的块。每个块比方说可能是 $16\times16$ 的一个 **patch**（图像块），一般来说都是 $16\times16$ 或者 $14\times14$ 的这么一个大小。这个块就叫做一个 patch，等于说把那张"披萨饼"切成的一个小的部分。

> **老师比喻**：整张图就像一张披萨饼，按固定大小横竖切下去，切出来的每一小块就是一个 patch；后面重讲块数时老师又把它换成了"切蛋糕"的说法。

老师顺带把两种常见尺寸各能切出多少块数了一遍：

- 图取 $224\times224$、每个 patch 取 $16\times16$：一边是 $224/16=14$ 个，整张图就是 $14\times14=196$ 个 patch；
- 每个 patch 取 $14\times14$：一边是 $224/14=16$ 个，整张图就是 $16\times16=256$ 个 patch。

切完之后做什么操作呢？把这些 patch 排成一行——就跟 language token 一样，跟语言里的那些 token 一样，排成一行。排成一行之后，对每一个小的 patch 做**嵌入**（embedding），也就是对每一个小的 patch 去提取它的特征。把这些特征都提取出来之后，再像文本一样给它们加上位置编码，然后送进 transformer 的 input 里面去做后面的操作。

对于图像来说，位置编码对 ViT 可能比普通的文本 transformer 更加重要。因为模型需要知道这个 patch 在整张图里处于什么位置：比方说图上是一座欧洲的建筑物，那这个 patch 是在左上角还是在右下角，这其实是很关键的一个信息。所以说顺序是重要的，这也是为什么需要对每一个 patch 都做一个位置编码。老师说这是第二个要点，第一个要点是把图像切成 patch 当成 token。

第三个要点，是 ViT 跟之前的 **残差网络**（Residual Network, ResNet）不一样。在 ResNet 里面，它是把整张图不断地抽象、不断地抽象，最终得到的那个特征本身表示的就是整张图的信息；但是在 ViT 里面，图已经被拆成了 $14\times14=196$ 个 patch，每一个 token 只表示它自己那一小块局部的特征，还没有任何一个 token 能够表示整张图的特征。所以就需要在 ViT 中去人为引入一个所谓的 **CLS token**（classification token，分类标记），也可以把它直观地理解成一个**全局 token**（global token），它表示的就是整张图的信息。

老师用一张建筑照片来说明每个 patch 各自表示什么：某个 patch 表示建筑物左上角这一块，某个表示建筑物的第二个 patch 块，某个可能表示建筑物的主体，某个可能表示道路，某个表示行人——这就是每一个 patch 所表示的内容。但是必须得有一个 global token、CLS token 去表示"这张图它是一座欧式的建筑物，在一个蓝天白云下"，这个是最重要的、最最重要的一个全局信息。

至于为什么叫 CLS：早期的时候我们用这个 token 做分类（classify），所以就叫 CLS token。

到这里，ViT 的三件输入准备工作就讲完了：如何对图像做 patch、如何做位置编码，以及引入一个全局的 CLS token。这样基本上就把它的输入部分讲完了。

再往下，transformer encoder 部分跟普通 transformer 其实长得一模一样，也就是**多头自注意力**（multi-head self-attention）的这么一个形式。在 transformer 里面，会让这些所有不同的 token 互相做交换。以本课这个 case 为例：图是 $224\times224$（长宽都是 224），每个 patch 切成 $16\times16$，一共 $14\times14=196$ 个 patch，也就是 196 个 token；每个 token 会有一个嵌入，本课是 768 维；再加上一个统一的全局 token，所以一共就是 $196+1=197$ 个 token。

这 197 个 token 会在 transformer 里面互相做交换、充分融合，然后再统一输出。老师提醒 transformer 的一个特点：输入是什么，输出一般也是什么——它不会像 **卷积神经网络**（Convolutional Neural Network, CNN）那样输入输出的形状会变。所以输入的是 197 个 token、每个假设是 512 维或者 768 维（这是比较常见的维度），输出就还是 512 或 768 维的信息。这里输入是 196 个 patch token 加一个全局 token、一共 197 个，那么输出也是同样这 197 个 token 的信息。

不过 ViT 本身可以做很多很多事情，在本课这个 case 里我们要把它做图像分类。既然要做图像分类，输出的时候每一个 patch 的局部信息就不需要了，只需要一个全局信息。所以在输出的时候，就把那个全局 token 拿出来：它这个时候可能是 768 维的，而分类是 101 类，于是再给它接一个轻量级的 head（一个轻量级的全连接层），把它从 768 维或者 512 维转成 101 维，因为要输出 101 类的分类结果。这就是整个 ViT 做图像分类的过程。

老师还补充说，如果对 ViT 比较清楚就知道，它更多不是用于图像分类：早期的时候可以用分类去证明它确实有这个能力，但在证明了能力之后，ViT 一般只是当作 backbone 用来提取特征而已。本课这个 case 需要做分类，所以要把这个 CLS token 拿出来，然后再经过一个简单的全连接层，把它映射到最终的维度——这就是整个 ViT 在干的事情。

讲完整个结构后，老师问大家有没有问题，随后自己说"可能刚刚解释有点快"，于是把切 patch 的数又慢慢数了一遍：这张图是 $224\times224$，每个 patch 是 $16\times16$，那么 $14$ 就是 $224$ 除以 $16$，所以一边是 14 个；对这张图来说一共有 $14\times14$ 个 patch，也就是 196 个 patch，再加上一个 global token，所以一共有 197 个 token 进入这个 transformer；输出的时候，由于在这个里面已经进行了充分的交换，只需要把 global token 拿出来，经过一个简单的全连接层，就可以得到它的类别信息。这就是 ViT 的图像分类。

如果大家都 OK，就进入实验部分，打开实验 2-2。数据集还是 Food101，先照老规矩做预处理，这几步可以直接执行。老师特别说，因为 ViT 这个结构跟以前不一样了，所以有必要讲一讲它的一个 config、一个配置。在以前 CNN 的那些网络里面，无论是简单的 CNN 还是 ResNet 这一类，整个家族都是比较经典的卷积网络；而 ViT 是完全换了一种范式，用的是 transformer 的范式，所以它跟之前的都不太一样。

本实验的配置参数如下：

| 配置项 | 老师的解释 |
| --- | --- |
| `image_size` | 表示图要变成多大。不管你输入的原图是什么尺寸、H 和 W 是多少都无所谓，都会统一转成 $224\times224$ 的 image size。 |
| `patch_size` | 每个切出来的小块（老师说的"小蛋糕"）的边长，本课是 16，也就是 $16\times16$。ViT 一般都会处理成正方形，长和宽一般都是一样的；因为如果长和宽不一样，就不好切了，这是一个约定俗成的规矩。 |
| `embed_dim` | 每一个 patch 切完之后，要经过一个 patch embedding 的卷积层，把它从 RGB 三个通道变成 `embed_dim` 个通道。一般会定成 512 或者是 768。这个卷积层就负责对每一个小的 patch 去提取特征。 |
| `depth` | transformer 里面的参数，表示这个 transformer 有 12 层。 |
| `num_heads` | 每一层有多少个头：本课每层是 12 个头，也可以把它改成 8 个头。 |
| `mlp_ratio` | 同样是 transformer 内部的参数，对应 transformer 里的 MLP 操作。 |

老师说 `depth`、`num_heads`、`mlp_ratio` 这三个都是 transformer 里面的参数。类别数量是 101，也就是说最终会输出 101 维。老师还强调，这里面比较重要的可能是前面三个：根据 image size 224，把它切成 $16\times16$ 的每一个小块，然后每一个小的 patch 出来之后，它的 embedding 维度是 768——这三个是比较重要的一些指标。数据处理和预处理就不再说了，还是跟之前一样。

**补充说明**：根据本节补充材料《实验2_2_ViT_学生.txt》cell 1 的 `config` 字典，本实验取值为 `img_size` = 224、`patch_size` = 16、`embed_dim` = 768、`depth` = 12、`num_heads` = 12、`mlp_ratio` = 4、`num_classes` = 101，与老师口述的 224、16、768、12 层、12 个头、101 类一致。同一材料 cell 4 中，patch embedding 用 `nn.Conv2d(3, embed_dim, kernel_size=patch_size, stride=patch_size)` 实现（卷积核与步长都等于 patch 边长），因此 patch 数按 `num_patches = (img_size // patch_size) ** 2` 计算，位置编码参数的形状为 $(1,\ \text{num\_patches}+1,\ \text{embed\_dim})$，即 $(1, 197, 768)$，正是"196 个 patch token 加 1 个 CLS token"这一计数。

接着老师开始讲 transformer 内部的操作：刚才你输入进去的可能是 768 维的一个通道，它可能会先经过 self-attention 的操作，之后 MLP 部分的细节老师在后面继续展开。

### 3.2 ViT 的网络搭建

一个 token 进入 Transformer 层之后，先做**自注意力**（self-attention），出来之后还要经过一个 MLP：其中一个线性层把 768 维先提升 4 倍变成 3072 维，之后可能还会再变回来。老师说这是 Transformer 内部的一些操作，"这个大家知道就行"，不需要自己动手写。

这里的类别数量是 101，也就是 Food-101 的 101 个类，所以模型最终会输出 101 维。

在整套配置里，老师认为真正重要的可能是前面三个指标：图片尺寸是 224；把图片切成 $16\times 16$ 的每一个小块；每一个小块出来之后，它的嵌入维度（`embed_dim`）是 768。这三个是比较关键的指标。至于数据增强和预处理，老师不再重复讲了，还是跟上一节（ResNet50）完全一样。

把这些配置放进模型、把类定义好之后，老师把整个模型结构打印出来看了一遍。屏幕上就是这次要搭的 ViT（Vision Transformer）结构，接下来看它的主干部分：一张 $224\times 224$ 的图先做 patch 嵌入，拼上 CLS token 和位置编码，再走过 12 层 Transformer 编码器，最后取出 CLS token 过一个分类头。

进入类内部之后，先看 `self.` 这一层都定义了哪些东西。老师先把任务分配清楚：这一节先讲整个 ViT 模型里定义了哪些部件，而 `self.forward` 这个前向函数是要由大家自己完成的。老师逐个点名这些部件：首先有一个 `patch_size` 参数，有一个嵌入维度 `embed_dim` 的参数；然后有一个 patch 嵌入模块，它对每一个小 patch 起作用，把每一块提成一个特征向量；此外还有 CLS token 和位置编码两个可学习参数，最后是 Transformer 骨干和一个分类头。

patch 嵌入（patch embedding）是这一节第一个需要讲清动机的部件。为什么要专门给它设一层？老师用切蛋糕来打比方。

> **老师比喻**：我有一整个大蛋糕（整张图），把它切成不同的小蛋糕（一个个 patch）。切出来的每一块小蛋糕，肯定不能就那么当成一张小图直接送进去，你肯定得把它提取成一个特征，所以这里就是"对每一个小 patch 如何去提取特征"。

实现上，这一步一般用一个卷积完成：把三维（RGB 三个通道）的小块升维转换成 768 维，也就是一次升维操作。对应到代码就是 `self.patch_embed = nn.Conv2d(3, 768, kernel_size=16, stride=16)`——卷积核大小和步长都取 `patch_size = 16`，于是互不重叠的 $16\times 16$ 小块各自被映射成一个 768 维向量。

那到底有多少个 patch？老师现场算了一遍：原图是 224，每个 patch 是 16，那么 $224 \div 16 = 14$，也就是说长和宽方向上各有 14 块；因为图有长有宽，还要再乘一次，$14\times 14 = 196$，所以一张图一共切出 196 个 patch。这个数目在代码里就是 `num_patches = (224 // 16) ** 2`。

除了 196 个图像块，模型里还有一个全局 token，也就是**类别标记**（class token，即 CLS token）。老师强调它的特殊之处：这个 token 是从外部人为引进来的全局 token，它跟图像本身、跟图像内部的内容没有任何关系；正因为它不是从图里算出来的，所以必须人为定义它。定义的时候一般给它做零初始化——形状对齐成 `(1, 1, 768)`，里面每一个元素塞的值就是 0；至于它最后具体应该是什么值，让它自己去学就行了。

再往下是**位置编码**（positional embedding，代码里的 `pos_embed`）。它同样是一个可学习的参数矩阵：因为一共有 $196 + 1 = 197$ 个 token（196 个图像块加 1 个 CLS token），所以把它定义成 $197\times 768$ 的形状，里面的数值也让网络自己去学。

这里老师专门解释了一个容易被新手误解的地方：既然叫"位置"编码，是不是必须显式把坐标喂给它？比如告诉它"这一块在左上角 $(0,0)$，那一块在右下角 $(14,14)$"，在位置编码里显式加入一些位置信息。老师说自己没有这么做——也可以那么做，但他这里直接给了一串可学习的参数，让网络自己学。

> **老师强调**：很多的东西我们定义好、初始化好之后，其实不用管它具体是怎么弄的，让它自己去学就行了。而且它学的肯定比我们好。

这正是老师说的 ViT 的精髓所在：很多部件只要把形状和初始化定好，具体的数值交给网络自己学。

接下来定义主干网络。老师指出主干一共 12 层，而现在要定义的是其中一层，然后把它叠 12 次：代码里先构造一个 `nn.TransformerEncoderLayer`，再交给 `nn.TransformerEncoder` 配上 `num_layers = 12`。

这一层不需要手搓代码——因为 torch 里本来就有这个类，直接调用它就行，我们只需要给它填一些参数：模型的维度 `d_model` 是 768 维，**多头注意力**（multi-head attention）的头数 `nhead` 是 12 个头，MLP 部分的隐层维度是 $768\times 4 = 3072$。这些数字写好之后，其余按正常方式定义就可以了。

**补充说明**：根据本节补充材料《实验2_2_ViT_学生.txt》cell 4，`nn.TransformerEncoderLayer` 实际传入的参数为 `d_model=768`、`nhead=12`、`dim_feedforward=768*4`，另加 `activation="gelu"`、`batch_first=True`（张量排布为 `(bs, num_tokens, C)`，即 `(64, 197, 768)`）、`norm_first=True`；patch 化之后用 `x.flatten(2).transpose(1, 2)` 把 $[B, 768, 14, 14]$ 拉直成 $[B, 196, 768]$；`self.cls_token` 用 `torch.zeros(1, 1, 768)` 初始化，`self.pos_embed` 用 `torch.zeros(1, 197, 768)` 初始化；`self.norm` 是一个 `nn.LayerNorm(768)`，在取出 CLS token 之后、进入分类头之前调用。这些细节老师在课上只讲到"一个卷积升到 768 维""12 层、12 个头、MLP 乘 4""已经过了一个 LayerNorm"这一层粒度，具体写法以材料为准。

12 层 Transformer 定完之后，就要取出它的全局 token，也就是那个 CLS token。取出来之后还要再经过一个**分类头**（classification head）：类里对应的是 `self.head`，而在它之前 CLS token 已经过了一个**层归一化**（LayerNorm，代码里的 `self.norm`）。经过这一步，就把 CLS token 从 768 维映射到 101 维，这就是最终的分类结果。

> **老师总结**：所以它其实核心的网络只有两个：一个是 patch 嵌入，一个是 Transformer；最开始先对每一个 patch 做一次嵌入操作，把它变成 768 维的 embedding，然后过主干网络（Transformer），过完之后把属于 CLS token 的第一个 token 的那个 embedding 拿出来，再过一个线性层交给 head，得到分类结果。

`__init__` 里的部件都定义好之后，`self.forward` 这个函数就交给学生自己写。老师把这件任务拆成一段一段来讲：patch 嵌入这一步已经替大家写好了，剩下的拼接 CLS token、加位置编码、过骨干、取 CLS 再分类这四件事要自己填。老师自己也用"第二步""第三步""最后一步"给其中几件事编号，下面按他的顺序列出。

1. 先看清楚输入是什么。输入是一张图，要想明白这张图的 shape 是什么，也就是 $[B, 3, 224, 224]$——批大小、三个通道、高、宽。
2. Patch 嵌入。这一步（patch 嵌入）老师已经写在代码里了，不用大家写；它把图变成 $[B, 196, 768]$。
3. 拼接 CLS token。这一步要自己完成：因为模型里本来是没有 CLS token 的，这个 token 是额外引入的，所以必须手动把它拼到 196 个 patch 前面，用 `torch.cat` 函数拼接，拼完变成 $[B, 197, 768]$。
4. 加位置编码（老师口中的"第二步"）。拼完之后还没有加位置编码，要把它加到 $x$ 上，直接相加即可，注意维度要匹配（$197$ 个 token 对 $197$ 行位置编码）。
5. 过核心网络（"第三步"）。有了全局 token、也有了位置编码，就可以把它送进主干网络，也就是直接调用 `self.transformer(x)`。
6. 取 CLS 再分类（"最后一步"）。所有 token 都处理完之后，把第一个 token（CLS token）的输出拿出来，过一个 LayerNorm，再送进线性层 `self.head` 得到结果。

这就是这个 ViT 最基本的实现。老师让大家按上面这个顺序先自己动手实现一遍。

**补充说明**：根据本节补充材料《实验2_2_ViT_学生.txt》cell 4 与 cell 5，`forward` 里带 `verbose` 打印，按 0–6 编号输出每一步的张量形状，可用来核验上面的维度流转：0 号是输入 $[1,3,224,224]$；1 号是 patch 嵌入之后 $[1,196,768]$；2 号是拼接 CLS token 之后 $[1,197,768]$；3 号是加上位置编码之后 $[1,197,768]$；4 号是过完 Transformer 骨干之后 $[1,197,768]$；5 号是取 CLS token（`x[:, 0]`）并归一化之后 $[1,768]$；6 号是分类头输出 $[1,101]$。cell 5 用一个 `torch.randn(1, 3, 224, 224)` 的随机张量把这条流程走了一遍，就是用来演示这个张量流转过程的。

### 3.3 ViT 的训练、推理与 patch 相似度可视化

代码补完、能正常跑起来之后，这一轮实验就进入训练阶段。老师说 `train` 和 `test` 这两个函数跟前面 ResNet50 那轮完全一样，不需要改动，直接拿来训练就可以；这一轮同样预计只跑两个 **epoch**（训练轮次，即把整个训练集过两遍），并且给大家 10 到 15 分钟时间自己动手做一下这个尝试。

> **老师强调**：虽然现在很多时候这些步骤可以用现成的封装去实现，但这几个步骤应该算是 ViT 的一个精髓，所以大家还是尽可能自己把它写出来。

训练的时候有个细节要注意：那些 `print` 一定要注释掉。老师说明这些 `print` 只是打给大家看每个张量的 shape 是怎么变化的，真正跑训练的时候肯定要把它们注释掉，否则输出会全部都是打印信息，把训练日志冲掉。

训练在后台跑的时候，老师把刚才写的这几个核心步骤又完整讲了一遍——从一张图进网络，到最后变成 101 维的分类结果。

第一步是 patch 化：一张图进来之后，首先要把它切成不同的 **patch**（图像块），也就是把每个 patch 先取出来。这里张量的第一维是 $B$，表示 batch size——训练的时候是一个 batch 一起进去的；在这个 case 里这个 $B$ 是 64。老师说这个维度可以先不管，把它当成 1 来看，也就是先只关心"对每张图来说"这件事。

每个 patch 本身相当于一张小图：它的形状本来应该是 $3\times14\times14$，也就是 14 高、14 宽、3 个通道。经过 **patch embedding**（图像块嵌入，把每个 patch 映射成一个向量）之后，每个 patch 变成 768 维。

接下来要把二维的 patch 网格拉直成序列：**视觉 Transformer**（Vision Transformer, ViT）处理的不是像素网格，而是一串 token，所以这一步必须做。老师说明长宽是 $14\times14$，也就是一共 $14\times14=196$ 个位置，因此要把它们变成 196 个 token，每个 token 是 768 维，于是做了一次形状转换（`flatten(2).transpose(1,2)`，把 $[B,768,14,14]$ 变成 $[B,196,768]$）。

接下来拼接 **CLS token**（classification token，分类标记，一个可学习的全局 token）。核心就是那一行 `torch.cat`：CLS token 在前，$X$（196 个 patch token）在后——也就是把最开始的那个全局 token 拼在所有 196 个 patch token 的最前面。拼完之后一共是 197 个 token，形状是 $[B,197,768]$，本实验里就是 $[64,197,768]$。老师说这种把 token 拼起来的 `cat` 操作是非常常用的。

再下一步是加**位置编码**（positional embedding）。老师特意把这一步和上一步区分开：`torch.cat` 是把两个张量 A、B 拼在一起，拼成 $[A,B]$ 这种形式，类似于沿维度做矩阵拼接，它**不是相加**；而位置编码用的是相加，叫作 element-wise（逐元素）相加。逐元素相加的前提是 A 和 B 的 shape 完全一样，$A+B$ 的意思是 A 和 B 完全叠加在一起，结果出来还是 A 的形状，只不过 A 的数值被 B 改变了。所以加位置编码，就是把 token 序列 $X$ 和与它形状完全一样的位置编码直接逐元素加起来。

关于位置编码本身，老师前面提过：可以给模型引入一些 $x,y$ 位置的信息，也就是位置的先验。但在本实验里，位置编码没有用手写的公式，而是直接初始化成一个可学习参数（实际写成全零初始化），再把它加到 token 上，让模型在训练中自己把它学出来。

加完位置编码就过核心的 Transformer：代码上就是一行 `self.transformer(x)`。老师说这行看起来非常简单，但它里面包含完整的 12 层 Transformer block，也就是 12 层的**自注意力**（self-attention）加 MLP 结构。

处理完之后来到最后一步：把 CLS token 取出来（`x[:, 0]`），过一个**层归一化**（Layer Normalization, LayerNorm）保持 768 维，再送进分类头，得到 101 维的分类结果。所以整个前向就是"切 patch → 映射成 768 维 token → 拼 CLS token → 加位置编码 → 12 层 Transformer → 取 CLS token → 归一化 → 分类头"。

| 阶段 | 课堂讲的操作 | 形状 |
| --- | --- | --- |
| 单个 patch | 每个 patch 相当于一张 $3\times14\times14$ 的小图 | $3\times14\times14$ |
| patch embedding 之后 | 每个 patch 被映射成 768 维 | 每个 patch 768 维 |
| 拉直 + 转置 | $14\times14$ 变成 196 个 token，每个 768 维 | $[B,196,768]$ |
| 拼接 CLS token | CLS 在前、196 个 patch token 在后 | $[B,197,768]$，本实验 $[64,197,768]$ |
| 加位置编码 | 逐元素相加，形状不变 | $[B,197,768]$ |
| 12 层 Transformer | `self.transformer(x)` | $[B,197,768]$ |
| 取 CLS + LayerNorm | 取出第 0 个 token 并归一化 | $[B,768]$ |
| 分类头 | 768 维映射到 101 类 | $[B,101]$ |

**补充说明**：根据本节补充材料《实验2_2_ViT_学生.txt》cell 1 的 `config` 与 cell 4 的 `ViTBase.forward` 注释，上面这些形状对应 `img_size=224`、`patch_size=16`、`embed_dim=768`、`depth=12`、`num_heads=12`、`mlp_ratio=4`、`num_classes=101`；patch embedding 用 `nn.Conv2d(3, 768, kernel_size=16, stride=16)` 实现，输出为 $[B,768,14,14]$（$14=224/16$），`num_patches = (224 // 16) ** 2 = 196`；`cls_token` 与 `pos_embed` 都声明为 `nn.Parameter(torch.zeros(...))`，其中位置编码形状为 $[1,197,768]$；骨干网络是 `nn.TransformerEncoder(encoder_layer, num_layers=12)`，`batch_first=True`，所以张量按 $(B,\text{num\_tokens},C)$ 排列；分类头是 `nn.Linear(768, 101)`，前面接 `nn.LayerNorm(768)`。

写完 forward、跑完训练之后就可以看训练结果了。因为加载了 ImageNet 上的预训练权重，只要很短的训练就能有不错的效果：这个 case 里只训练了 2 个 epoch，第一个 epoch 的测试准确率是 77.5，到第二个 epoch 就是 84.0 了。

总的来说，ViT 的表现要比 ResNet50 更好；老师说这两个模型相比，ViT 的参数量还要更大一点，所以它的表现也会更好一些，这就是最终的结果。在这个 case 里是加载预训练权重之后把整个 ViT 全部重新训练一遍，也就是**微调**（fine-tuning）全部参数、没有冻结任何层，做法跟前面 ResNet50 那个实验是一样的。

**补充说明**：根据本节补充材料《实验2_2_ViT_学生.txt》cell 8，这一轮训练用的损失函数是 `nn.CrossEntropyLoss()`，优化器是 `AdamW(model.parameters(), lr=5e-5)`，`epochs = 2`（注释说明因课堂时间原因减为 2 个 epoch，但仍能看到不错的性能），训练结束后用 `torch.save(model.state_dict(), 'ViT.pth')` 保存权重。

接下来是老师额外做的一个小实验。老师说这个实验会有些难度，所以他直接把答案输出来给大家看了。

前面讲到过，在 ViT 里面核心的部分其实是不同的 patch 之间互相做 attention：第一个 patch 可以看第二个 patch，第二个 patch 也能看第一个 patch，第一个 patch 也能看第九个 patch，第九个也能看第五个、第五个也能看第六个——它们之间没有前后关系，是完全平等的关系，在自注意力里互相去做关注、互相去做注意力。

这个实验就是把这个 **attention map**（注意力图）可视化出来。老师用的是一张薯条的照片（图里有背景、有桌子），在这张图上取了一个点，老师提醒说那个红点可能大家看不清，那是他特意打上去的一个点：这个点表示它所在的那个 patch，把它作为参考。然后把这张图切成不同的 patch，去看有哪些 patch 跟红点所在的那个 patch 的 feature **余弦相似度**（cosine similarity）比较高，也就是它们的语义关联度比较高。这里比较的是两个 token 的 768 维 feature 向量之间的余弦相似度，按标准定义就是两个向量夹角的余弦：

$$\cos(\mathbf{a},\mathbf{b})=\frac{\mathbf{a}\cdot\mathbf{b}}{\lVert\mathbf{a}\rVert\,\lVert\mathbf{b}\rVert}$$

值越大说明两个向量的方向越接近，也就认为它们的语义越相关。

**演示**：老师展示了这个实验输出的结果——跟红点所在 patch 相似度最高（数一数二）的 patch，正好落在薯条这些 token 上；而图上桌面的位置同样也有 patch，那些 patch 表示的只是桌面的信息，跟红点所在的这个 patch 没有关系，所以相似度就会很低。老师据此说明：在热力图里相似度越高的地方用红色标示，相似度越低的地方用蓝色标示。

**热力图**（heatmap）式的 attention map 可视化，是很多论文喜欢展示的一种方式，用来证明网络确实学到了东西。

**补充说明**：根据本节补充材料《实验2_2_ViT_学生.txt》cell 10，可视化的具体做法是：先重建 `ViTBase` 并用 `torch.load('ViT.pth')` 载入刚训练好的权重，然后手动把 patch 化、拼 CLS token、加位置编码写一遍，再逐层跑完 12 层 `model.transformer.layers[i]`，取出中间结果；接着取去掉 CLS 之后的 196 个 patch token（`x[0, 1:, :]`，形状 $[196,768]$），选第 `ref_idx = 80` 个 token 作参考，用 `F.cosine_similarity(ref_token, tokens, dim=-1)` 得到 196 个相似度，再 `reshape(14, 14)` 回 patch 网格，用 `cv2.resize` 放大到 $224\times 224$，做 min–max 归一化到 $[0,1]$ 后以 `cmap='jet'`、`alpha=0.5` 叠加在原图上；红点画在参考 patch 的中心，坐标为 $(x\cdot16+8,\ y\cdot16+8)$，其中 $(y,x)=\mathrm{divmod}(\text{ref\_idx},14)$。

## 四、CLIP 与图文对比学习 [01:46:56–02:12:58]

### 4.1 CLIP 的对比学习目标与双塔结构

老师先给上一节课最后那个汉堡包案例收尾：这个案例大家能跑出来就行，它没有标准答案，只要求把 `test` 跑通、能够把预测跑对就可以。随后课程直接进入第三个部分，也就是 notebook `2-3` 的 CLIP 实验。

CLIP 在整门实验课里的位置比较特殊。它是本课程遇到的第一个"不大不小"的模型——严格来说还不算大模型，但它确实是第一个靠在互联网上爬取海量数据去做预训练的模型。因为这个模型大家多半只是听说过、对它到底怎么工作还不太清楚，所以老师先不急着打开 notebook，而是先把 CLIP 的原理讲一遍。

这里最容易被误解的一点是：CLIP 本身并不是一个分类模型，它是一个基础的视觉-语言模型（vision-language model）。

> **老师强调**：CLIP 本身它不是一个分类模型，它是一个基础的视觉-语言模型。

它的名字已经把做法写清楚了：**CLIP**（Contrastive Language-Image Pre-training，对比语言-图像预训练）。字面意思就是"通过对比式的学习，把图像的语义和文字的语义在一个**隐空间**（latent space）里做对齐"。下面这幅"对齐"的图景，是理解 CLIP 全部细节的出发点。

**例子**：假设手头有一张狗的图片，同时有一句话 `a photo of a dog`。老师在课上特别说明，这句话写 `a dog` 也可以，甚至写 `an animal` 也可以——文本这一侧用哪种措辞并不影响整体机制。图像这一侧走的是 ViT（Vision Transformer）：CLIP 里面全部都是 Transformer，没有 CNN 的结构。这张图经过 ViT 之后，输出里会有一个全局的 token（也就是原本用来给出分类结果的那个位置），用它来表示这张图的语义信息；句子那一侧经过 Transformer 编码，同样得到一个全局的 token。CLIP 的要求是：图像端的这个全局 token 和句子端的这个全局 token 应该在同一个隐空间里互相对齐，也就是说二者要 share 同一个隐空间。做到这一点，模型就知道"所展示的画面"和"所描述的内容"是一个意思。这就是 CLIP 训练方式的整体图景。

把上面这张单图单句的例子扩到一个训练 batch，就得到 CLIP 真正的训练目标。

**例子**：老师用 batch size 等于 64 来举例（并强调实际训练时要大得多）。这 64 张图内容各不相同：第一张可能是狗的图，后面可能有一张猫的图、一张人的图，或者一张建筑物的图；配上来的 64 句话也一样，第一句是 `a photo of a dog`，第二句是 `a cat`，第三句是 `a building`……训练时把所有这些图都经过 ViT 去做 embedding，把所有文本也都经过 Transformer 去做 embedding，这样就得到一个图像-文本的相似度矩阵。设矩阵元素 $S_{ij}$ 表示第 $i$ 张图与第 $j$ 句文本的相似度，老师的要求是：只有对角线位置上的那些图文是匹配的，不在对角线上的都不匹配。

| 在相似度矩阵中的位置 | 图像 | 文本 | 样本类型 | 训练要求 |
| --- | --- | --- | --- | --- |
| 对角线位置 $i=j$ | 第 $i$ 张图 $I_i$ | 第 $i$ 句文本 $T_i$ | 正样本对（positive） | 相似度拉近 |
| 非对角位置 $i\neq j$ | 第 $i$ 张图 $I_i$ | 第 $j$ 句文本 $T_j$ | 负样本对（negative） | 相似度拉远 |

接下来的动作是网络学习：通过 ViT 和文本 Transformer 更新它们各自的权重，让对角线上的正样本对的相似度拉近，同时让非对角线上负样本对的相似度拉远。这个"既有正样本又有负样本、既拉近又拉远"的过程，就是**对比学习**（contrastive learning）。就结构而言，CLIP 只是图像侧一个 ViT 加文本侧一个 Transformer，真正决定它行为的是上面这个图文配对的目标，所以老师说 CLIP 很有意思。

也正因为如此，老师特意回顾了 CLIP 刚出来时的冲击：他 2021 年看到这类 paper 的时候，觉得还是很震撼的，这等于是一个新的范式。原因在于它是一个完全 open-world（开放世界）的能力——你不需要把类别局限在 `dog` 上面。你可以想怎么说就怎么说，也可以换一种说法，甚至直接说"人类的宠物"等等，随便说，它都能知道这个意思和这张图是对齐的。

> **老师总结**：open-world 这件事情，也是我们在通向更高级的人工智能上必须走过的一路，因为分类终究是最简单、最基础的一个任务。

讲清"图文要对齐"之后，老师翻到下一页。他强调这一页讲的其实还是上一页那个东西，只是把它再更加具象化一些，分别讲图像和文本这两侧到底是怎么编码的。图像这一侧的做法是：把这张图切成一个个小的 patch，再额外加一个 CLS token 作为全局 token，然后把这些 token 放在一起送进 ViT。这里用的还是前面讲 ViT 时已经提到过的那条性质——Transformer 的结构是不改变 shape 的，输入是什么形状、输出还是什么形状。所以如果 patch 网格是 $14\times 14$，就有 $14\times14=196$ 个图像 token，再加 1 个全局 token 一起输入；经过 ViT 之后，输出仍然是 196 个图像 token 加 1 个全局 token。此时那个全局 token 表示的就是这张狗图的全局信息。图像就是这样切的。

文本这一侧的道理完全一样。以 `a photo of dog` 为例，首先对它做**分词**（tokenization），分词之后得到很多个 token；序列的两端还有两个特殊符号，一个是 SOT（start of text，句子开头），一个是 EOT（end of text，句子结尾）。这些 token 同样经过 Transformer，得到文本侧的表示。两边的"全局"取法略有差别：图像里面通常对应的是 CLS token 作为全局 token；文本这边，一般来说——老师强调这只是一个通用习惯——会用 EOT（end of text）这个 token 去表示整句话的全局含义。到这一步，"图文分别如何编码"就讲完了。

文本侧还有一个不得不处理的技术细节，就是 padding。不同句子的长度差别很大：像 `a photo of dog` 这样很简单的句子，可能一共只有五个单词，算上两端的特殊符号，一共是 7 个有效 token；但有的句子比它还短，有的句子很长，甚至可能是一整个段落。而训练的时候要让一个 batch 里的文本在 shape 上对齐，所以必须给它们做填补，也就是 padding。CLIP 里面规定的上限是每句话最多 77 个 token，超过 77 个 token 就不再支持了。上面这个例子只有 7 个 token，离上限还远得很，于是它会被强行补到 77 个 token，多出来的位置填的都是 padding token。CLIP 的基本原理就讲到这里。

接着老师说明这些自由度具体体现在哪些地方：当时 OpenAI 提供的 CLIP 不止一种，而是有很多版本。差异首先体现在 embedding 维度上，可能是 768，也可能是 512；其次体现在 ViT 的规模上，可以大、可以小、也可以中等；再就是每个 patch 切多大也是可变的，可以切成 $14\times14$，也可以切成 $28\times28$，还可以切成 $32\times32$。这些都对应着刚才那张框架图里画的一个 ViT 加一个文本 Transformer。

patch 大小这个自由度背后是一个明确的 trade-off。一方面，对一张图来说，每个 patch 切得越小，你收到的信息就越好，因为信息变得更密集；但你的计算量也会随之变大。另一方面，如果把 patch 切得很大，比如每个 patch 就是 $32\times32$，那你这张图一共就没多少个 patch，在这种条件下学到的信息可能就不是很好；但好处是模型更小、速度更快。所以这就是一种权衡（trade-off），patch 大小是可以变的，取舍就落在这里。

正因为有这种 trade-off，CLIP 才提供了非常多的版本。我们读的那个模型名参数就能把配置读出来，比如 `ViT-B/32`：其中 `B` 表示这里选的 ViT 是 base 规模，除此之外还有 `T`（tiny）、`B`（base）、`L`（large）；斜杠后面的 `32` 表示每个 patch 的大小是 $32\times32$。所以 `ViT-T/16` 就是 ViT-tiny 加 $16\times16$ 的 patch，`ViT-B/32` 就是 ViT-base 加 $32\times32$ 的 patch。再加上 embedding 维度这一列，取值有 192、512、768——维度越高，包含的信息越丰富。层数这一列，一般来说默认是 12 层或者 24 层。

### 4.2 CLIP 的 tokenizer、编码与相似度计算

老师先用四幅图作为素材：一张汉堡包、一只猫、一个比较杂乱的房间、一张城市街景。接下来要在这些图和若干句自然语言之间互相匹配，而不是只在固定的类别表里挑一个标签。老师把这一部分拆成两个任务，先讲第一个。

第一个任务是图文匹配（image–text matching）：给定一张图像，让它去匹配一句话。老师选定的是汉堡包这幅图，然后看着图、自己随手写了几条候选文本当作标签（labels）：

1. `a photo of a room`
2. `animal`
3. `a photo of a hamburger`
4. `a photo of a city`

这四条就是一张房间的照片、一个动物、一张汉堡包的照片、一张城市的照片。老师说，因为自己是看着图写的标签，所以心里很清楚：对汉堡包这幅图来说，一定是第三条"汉堡包的照片"跟它最匹配。

**补充说明**：根据本节补充材料《实验2_3_CLIP_学生.txt》CELL 4 的注释，这四幅图全部取自网络，大概率没有在 CLIP 的训练数据里出现过，因此这一组实验本身就是在做零样本（zero-shot）测试；材料里这四幅图对应的键名分别是 `hamburger`、`cat`、`room`、`city`。

那具体怎么做？做法是把这一张图和这四句话分别送进 encode：图像一路走图像编码器（image encoder），文本一路走文本编码器（text encoder）。老师特意点出，图像这一支跑的是 ViT，文本这一支跑的是 Transformer。两路输出的是**相同维度**的 embedding，只有维度对齐了，才能拿去做下面的比较。

整个流程可以拆成四步：

1. 图像预处理：`preprocess(target_img).unsqueeze(0)`，把一张图变成 batch 大小为 1 的输入张量，送进 `model.encode_image`，取出这张图的图像特征向量。
2. 文本预处理：`clip.tokenize(labels)`，把四条句子分词、补齐成同样长度的张量，送进 `model.encode_text`，取出四条文本特征向量。
3. 两边都做归一化，把每个向量的模长统一成 1，即 $\hat{\mathbf{I}}=\mathbf{I}/\lVert\mathbf{I}\rVert$、$\hat{\mathbf{T}}_j=\mathbf{T}_j/\lVert\mathbf{T}_j\rVert$。
4. 归一化之后把文本特征转置，与图像特征做矩阵相乘——老师强调这是整个流程里最核心的一步。老师口述这些特征是 768 维的，几个 768 维的向量两两相乘一下，就得到了它们之间的相似度。

用式子写出来，一张图对 $n$ 条文本（本例 $n=4$）得到的就是一个 $1\times n$ 的相似度矩阵：

$$
\mathbf{S}=\hat{\mathbf{I}}\,\hat{\mathbf{T}}^{\top}\in\mathbb{R}^{1\times n},
\qquad S_{j}=\hat{\mathbf{I}}\cdot\hat{\mathbf{T}}_{j}=\cos\bigl(\mathbf{I},\mathbf{T}_{j}\bigr).
$$

因为两个向量都已归一化，内积就等于**余弦相似度**（cosine similarity），所以这一步给出的就是"这张图和每句话有多像"的图文匹配度。

**补充说明**：根据本节补充材料《实验2_3_CLIP_学生.txt》CELL 5，代码里在相似度矩阵前还乘了一个 `logit_scale = 100` 的缩放系数（`logits_per_image = logit_scale * (image_features @ text_features.T)`），随后再对最后一维做 `softmax` 得到概率；这一步在老师口述里对应的是"在这四个里面做一个归一化"。

跑出来的结果和预期一致：对汉堡包这幅图，`a photo of a hamburger` 这一项最高，剩下三项——城市、动物、房间——都几乎没有相似度、完全匹配不上。老师据此点评：这说明 CLIP 预训练出来的表征能力是很好的，它确实把"图"和"这句话在说什么"对到了同一个空间里。

老师接着提醒，标签完全可以自己改：可以写成 `a hamburger`，也可以写成美式快餐、快餐店里的东西之类的说法，随便怎么写都行。只要描述得对，CLIP 就能把它和汉堡包对上。

> **老师总结**：这更像检索的一个工作，而不光是分类；也可以把它理解成开放词汇分类（open-vocabulary classification）。

这里说的开放词汇，指的就是候选文本不是事先固定的类别表，而是任何现场写出来的自然语言句子。

接下来是第二个任务，方向反过来：给定一句话，让它去匹配图像。老师也说明，这一段结束之后会给大家时间去把前面这些信息整合一下。代码里有两个候选查询串（`search_query`），一条是注释掉的 `busy street`，当前用的是 `great food`，也就是"很好的食物"。老师先用 `great food` 跑，图像库还是那四幅图，所以这是"一句话匹配多个图像"。老师先带大家看运行结果，讲清结果之后再回头讲 shape。

结果是：`great food` 这句话和汉堡包的匹配度是 93%，猫是 6.6%，城市是 0.3%，房间是 0.1%（老师念到房间那一项时确认了一下，是 0.1%）。四个数加起来正好是 100%，因为它们是在这四个候选里做过归一化（softmax）之后的概率。

老师解释了这 93% 是怎么来的：算的是两个 global embedding 之间的余弦相似度——一个是汉堡包这幅图的 global embedding，也就是 CLS token 对应的那个 embedding；一个是 `great food` 这句话的 EOT 对应的 embedding。这两个 embedding 相乘（内积）得到余弦相似度，再在四幅图之间归一化，就得到 93% 这个数。老师由此说明，CLIP 能够知道 `great food` 这句话更多对应的是汉堡包那幅图。

这里取的是两侧各自的"整句 / 整图"表示：图像一侧用 CLS token，就是 ViT 里专门用来汇总整幅图信息的那个位置；文本一侧用 EOT，就是句子最后一个结束标记位置的输出。也就是说，CLIP 并不是逐词去和图像对齐，而是把一整幅图和一整句话各压成一个向量，再比这两个向量的方向是否一致。

**演示**：老师把查询词从 `great food` 改成 `my pet`（我的宠物），改完直接再跑一遍——这一次猫这一项到了 100%，其余三项完全不相关。再把查询词改成 `busy street`（也就是代码里本来就写好的那条）跑一遍，城市街景那一项也是 100%，对应的正是那张看起来像纽约或美国某个城市道路的照片。

老师让大家先直观感受一下：这种图文匹配的性能是很强的，它把开放词汇这件事做得很好。感受完之后，再回到具体的 shape 上去理解它内部是怎么做的。

回到第一个任务的位置：给定汉堡包的图，给四句话（房间、动物、汉堡、城市），看它打印出来的输入张量。图像输入打印成 `torch.Size([1, 3, 224, 224])`：第一个 1 表示 batch size 是 1，因为现在就一张图；后面的 $3\times224\times224$ 才是这张图的输入尺寸，也就是前面提过的 CHW 排布（通道在前）。

文本输入打印成 `torch.Size([4, 77])`。第一维 4 同样是 batch，因为这次有四句话；第二维 77 表示每句话被切成了 77 个 token。老师说这一点前面也提到过：CLIP 会把每句话的最大长度限制在 77 个 token。

**例子**：像 `a photo of a dog` 这样一句话，可能一共只有 7 个 token，那么剩下的 70 个位置就完全用 padding 填满，$7+70=77$，凑齐这 77 个位置。

结合老师后面念的第一句编号可以看出，这 77 个位置里是包含首尾两个特殊标记的：`a photo of a dog` 的 `a`、`photo`、`of`、`a`、`dog` 这 5 个词，加上句首的 SOT 和句末的 EOT，正好就是老师说的 7 个 token。

| 对象 | 打印出的形状 | 含义 |
| --- | --- | --- |
| 图像输入 | `(1, 3, 224, 224)` | 1 张图；后三维是 $3\times224\times224$ 的 CHW 尺寸 |
| 文本输入 | `(4, 77)` | 4 句话；每句固定 77 个 token 位置 |
| 图文匹配度 | `(1, 4)` | 这张图与四条候选句各算一个相似度 |

老师接着念了第一句话 `a photo of a room` 对应的那串编号，并解释了其中几个关键位置。这里 320 对应的是句子里的 `a` 这个词；`49406` 表示 SOT（start of text），也就是这句话的开始；`49407` 表示 EOT（end of text），也就是这句话的结束。SOT 和 EOT 是特殊标记，不是句子里的普通词。

顺带还能从 `49407` 反推词表规模：老师说，如果要"灵敏"一点，就可以通过 `49407` 发现 CLIP 里包含的文本词表（vocabulary）数量大概就是 49407 这个量级——因为一般来说 SOT 和 EOT 就是整个词表里最后的两个 token，编号最大的那个数自然就给出了词表有多大。

至于句子结束之后的位置，padding 用的 token 就用 0 表示。所以从某个位置开始往后全是 0，一直补零补到这里，下标是第 76 个；因为下标是从第 0 个算起的，第 76 个就是最后一个位置，所以一条文本输入一共有 77 个位置。

讲到这儿，老师把这件事推广到一般情形：像 GPT 这类大模型做 encode 的时候都是同一个思路——先有一个非常巨大的词表，然后每一个 token 都有它对应的一个编码（编号）。

## 五、CLIP 零样本分类演示与课堂事务 [02:12:59–02:44:19]

老师先把输入这一侧的说明收尾。他强调前面讲的这些都只是针对文本这一路：现在的大模型，不管是 GPT 还是别的，做 encode 的时候都是同一个思路——有一个非常巨大的词表，每一个 token 都有它对应的一个编码。所以可以自己去查：`photo`、`room` 这样的词分别落在哪个 token 编号上；也可以拿"复旦"去试，复旦大概率不是一个 token，如果它不在词表里，那它就只能拆成 F、U、D、A、N 五个不同的 token；而 `university` 这种词很可能本身就是词表里的一个 token，可以去查它对应哪个编号。老师说这件事其实挺有意思，鼓励大家自己去对一对。

由此两路的预处理就是完全对称的两件事。图像这一路的预处理，是把它统一 resize 到 $3\times 224\times 224$（3 个通道、224×224 像素）；文本这一路的预处理就是 `clip.tokenize`，也就是给它做 token 化，把一句话变成一串带有 token 序号的 ID。两边做完预处理，就可以各自送进编码器。

**演示**：第一个 case 是"给定一张图，在几句话里挑出最匹配的那句"。图先送进图像编码器：这里用的是 ViT（Vision Transformer），编码之后给出图像特征，而这一版 ViT 的 embedding 维度是 512，所以一张图就是一个 $(1,512)$ 的特征。文本这一边，四句话 tokenize 之后是 $(4,77)$——四句话、每句话补齐到 77 个 token——再经过文本 Transformer，变成 $(4,512)$，也就是四句话、每句话 512 维。

之所以要这样对齐，是因为只有图像和文本的 embedding 都是 512 维，两者才能直接相乘：$(1,512)\times(512,4)$ 得到 $(1,4)$。这个 $(1,4)$ 就是这幅 hamburger 的图分别与四句话的相似度。把它画出来放到屏幕上，可以看到第三个候选文本（`a photo of a hamburger`）的得分是最高的。老师借此说，通过这个输出，大家应该能大概 get 到 CLIP（Contrastive Language-Image Pre-training）在做一个什么事情了。

**补充说明**：根据本节补充材料《实验2_3_CLIP_学生.txt》CELL 4 的注释，演示用的四张图（`hamburger`、`cat`、`room`、`city`）全部来自网络，大概率没有出现在 CLIP 的训练数据中，因此这一组实验被材料明确称为零样本（zero-shot）测试。

**演示**：第二个 case 把方向反过来——一句话对四张图。查询句例如 `busy street`，tokenize 之后是 $(1,77)$，因为只有一句话，同样补齐到 77 个 token；图这一边有四幅，每幅都是 $3\times 224\times 224$，拼起来就是 $(4,3,224,224)$，也就是说文本的 batch size 是 1，图像的 batch size 是 4。两路分别过编码器：图走 ViT（Vision Transformer），文本走普通的 Transformer。得到的图像特征是 $(4,512)$，文本特征是 $(1,512)$；相乘 $(1,512)\times(512,4)$ 仍然得到 $(1,4)$，这就是这句话与四幅图各自的相似度。老师提到这个结果前面其实已经说过了。他点评说，看到这里大家可能会觉得这件事并没有很难。

**演示**：第三个 case 换成了细粒度匹配。老师先说明为什么还要再做一个：前两个 case 实际上都比较简单，因为那四幅图的差别本来就很大——城市、房间、汉堡和动物，随便匹配都能分开。现在就假设四幅图都是房间，只是各有特点：有干净的房间，有脏的房间，有一个酒店的房间，可能还有一个小房间；对应的四句话就是这四种描述。这一次锁定的是那张比较脏、比较杂乱的房间图，四条文本分别是 `a clean room`、`a chaotic and dirty room`、`a luxury hotel room`、`a small room`。四条文本 tokenize 之后是 $(4,77)$，过编码器得到 $(4,512)$；图像是 $(1,3,224,224)$，得到 $(1,512)$；同样相乘得到 $(1,4)$，再归一化成概率后画成横向柱状图。跑出来的结果与预期一致：`a chaotic and dirty room` 与这幅图的匹配度最高。老师由此点评，这正是他想通过这个 case 展示的 CLIP 的性能。

> **老师总结**：它不仅可以去做一些完全不同的、很明显的一些简单的区别，它甚至对同一个类别里的细分类依然可以做得很好。

**补充说明**：根据《实验2_3_CLIP_学生.txt》CELL 5、CELL 6、CELL 7，三个 Task 的文本候选与查询句原文如下。Task1（图 → 文）的四条候选是 `a photo of a room`、`animal`、`a photo of a hamburger`、`a photo of a city`；Task2（文 → 图）的查询句先写作 `busy street`（该行被注释掉），实际启用的那一行是 `great food`；Task3（图 → 细粒度文）的四条候选是 `a clean room`、`a chaotic and dirty room`、`a luxury hotel room`、`a small room`。

讲完这三个 case，老师接着布置了一个当堂小实验，同时也是一个留给大家的小作业。场景是这样的：给出一个 gallery（图像库，也就是一个数据库），里面放了一百来张图，来自 Food-101 数据集；再给一句话 `spring rolls`，要求大家在整个 gallery 里通过图文匹配的方式找出哪幅图是春卷。

老师顺手把 gallery 里的图翻了几张给大家看：这一张可能是鱿鱼卷，这一张像是蒜香面包，这一张应该是寿司，还有一张是一道菜——反正这里面是有春卷的。gallery 就是"图像库、画库"的英文说法，检索就在这个 gallery 里做。他也提醒这个数据集大家应该都有，就在课程给的那份数据里面。至于库里到底是一张春卷的图还是三张，老师自己也没记准，说待会儿一起看结果。

> **老师提示**：如果你找不到的话，也可以改这句话——可以叫 `a spring rolls`，或者叫 `the spring rolls`，换个说法试试。

具体的要求是：能检索出来的同学，要把那幅图的索引拿到，然后把这张图展示出来；可视化的代码老师已经写好，只要把索引对齐上去就行。找到并可视化出来之后跟老师说一声，会有记录。老师说离下课还有 20 分钟左右，先给大家 15 分钟自己动手，做完了再一起看。

**演示**：老师先放了一份示例输出——他找到了这幅图，就是春卷，similarity 显示 95.2%。他强调这只是示例，大家得到的结果不一定就是这幅图，因为这里展示的只是所有匹配的图里面最符合的第一幅（top-1）。

等到大家基本做完，老师把这道题的做法完整讲了一遍。他先交代规模上的差别：前面几个 demo 都是一张图对四句话，或者一句话对四张图，数量都很少；而这次 gallery 里有一百张图左右，所以第一件要做的事，是把目录下所有的图片合并到一起，拼成一个 batch，再把它变成一个 `gallery_images` 列表——这个名字可以自己起。

**算法**：整个检索流程可以写成下面几步。

1. 把 gallery 目录下的所有图片读进来，拼成一个 batch，得到 `gallery_images`；
2. 准备查询文本，例如 `spring rolls`，到这里"话也有了、图也有了"；
3. 分别做预处理：图片走 `preprocess`，变成 $224\times 224$ 并做归一化、标准化；文本走 `clip.tokenize`，得到 $(1,77)$；
4. 送进模型：图像侧得到 $(100,512)$（100 张图、每张 512 维），文本侧得到 $(1,512)$（1 句话、512 维）；
5. 让两者做相似度匹配，得到 $(1,100)$——这一行数值就是这句话与这 100 张图各自的相似度；
6. 对这个相似度做处理（归一化成概率），用 `np.argmax` 取出概率最高那一项对应的 index；
7. 用这个 index 把那幅图取出来展示，并显示它的 similarity。

老师专门解释了第 6 步：`np.argmax` 的意思就是在这一串概率里找出最大的那个概率以及它对应的 index，拿到 index 就能把对应的图展示出来，示例里这张图的 similarity 是 95.2%。他说这其实是比较简单的一个事情。

**补充说明**：根据《实验2_3_CLIP_学生.txt》CELL 5，Task1 中先分别调用 `model.encode_image` 与 `model.encode_text` 得到特征、各自做 L2 归一化后相乘，并乘了一个缩放系数 `logit_scale = 100` 再做 softmax；CELL 7 的注释说明 Task3 与小实验可以直接调用 `model(image_input, text_inputs)` 得到图像-文本相似度，不必再分别编码。

最后老师解释为什么 95.2% 这个数已经算是相当高。他提到同学交上来的结果并不完全一样：有的同学展示出来是 96.2%，还有的是 94 点几；他不确定这些数字具体是怎么得到的，因为一般来说 CLIP 用的都是固定的权重，所以大家的方法可能不完全一致。他的态度是总归能够找到就行，也欢迎同学跟他说明各自的写法。

至于 95% 左右这个数量级，老师的推理是这样：他在讲的时候还顺带自问了一句，自己这里到底有没有对相似度做归一化；如果确实做了归一化，那么这一百张图上的概率加起来是 1，95% 落在春卷这一张上，就等于说其余 99 张图加起来都不到 5% 的 similarity，所以它匹配得还是相当准确的。

老师用一句话收束本节的内容：这就是这节课主要的内容。还没弄出来的同学可以继续做。
