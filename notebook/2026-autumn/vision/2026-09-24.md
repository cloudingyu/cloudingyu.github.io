## 一、课前准备与上节课回顾：为什么需要卷积神经网络 [00:00:05–00:05:41]

### 1.1 课前与上课开始

课前时间主要用于确认日期与调试话筒设备。字幕记录显示课程日期为 9 月 24 日，老师提示"请取出话筒""话筒会正确放置"。随后老师在 00:02:41 宣布继续上课，进入"继续这个卷积网络"的内容（字幕原文为"全现金网络"，按上下文应为卷积网络／全连接网络，**原文待核实** [00:02:46]）。

### 1.2 上节课的问题：全连接网络用在图像上会爆炸

上节课主要讲的是神经网络。神经网络本质上是一种全连接层的样式，也就是每一层的每个神经元都要和前一层的所有神经元相连。这种结构放到图像上就会出问题，原因在于图像本身的像素特性。

**例子**：一张 $1000 \times 1000$ 的图像，如果把每个 pixel 都当作一个神经元的输入，那就需要一个 $10^6$ 量级的向量作为输入（字幕原文说成"16 次方"，实际应为 $10^6$，**原文待核实** [00:03:28]）。在这样的输入规模下，即使不升维、只是维持原有维度，也需要 $10^{12}$ 量级的参数。

这样的网络就过于庞大了，我们根本没有办法存储。于是老师提出，要根据图像自身的特性重新思考处理方法。

### 1.3 从图像特性出发：冗余性与局部特征

图像有两个可利用的特性：

1. 图像本身具有大量冗余，相邻像素之间高度相关；
2. 同一个 object 出现在图像的不同位置时，它的特征是相同的，也就是局部特征在空间上会重复出现。

基于这两点，一个自然的想法是用切割的方式提取局部特征：把图像切成若干局部区域，对每个局部区域分别做分类，再根据这些局部结果得出整张图像的分类。

但这样做仍有问题：目标的大小以及单元格的切分方式都会影响最终性能。切得太粗会漏掉小目标，切得太细又会带来类别碎片化。因此，我们还需要进一步设计一个对**尺度缩放**和**平移**都不敏感（尺度缩放、平移不变）的网络结构。

### 1.4 卷积神经网络的整体结构与引入动机

在这种情况下，我们引入了**卷积神经网络**（Convolutional Neural Network, CNN）。老师回顾了它的整体结构，并逐层说明每一层存在的理由：

- **卷积层**（convolution layer）和**池化层**（pooling layer）配合，用来覆盖不同尺度的目标；
- 每次卷积只与图像的一部分像素相连，用来提取局部的图像特征，这就是局部连接；
- **池化层**实现特征的降维，压缩数据、减小维度，从而减轻过拟合；
- 最后接一个全连接层，完成从局部到全局的映射，综合多个部分的信息做最终的识别。

老师接着点出：这就是上节课讲的"为什么我们要用卷积神经网络"，以及"为什么卷积神经网络是由视觉这边去推动的"。

## 二、卷积运算与一维卷积演示 [00:05:32–00:09:31]

### 2.1 反直觉之处：信号系统里的卷积要翻转，这里不翻转

接下来我们看卷积神经网络最核心的部分——卷积（convolution）。老师给出了卷积运算的基本构成：一个输入特征（input feature），中间一个卷积核（convolution kernel，字幕中出现"conclusion kernel"等误识别），卷积核在输入上做平移，然后做一个逐点相乘（point wise multiplication），依次得到输出。

**课堂问答**：老师问同学"你们信号系统学过吗？"，并指出信号系统里也有一个卷积，但**信号系统里的卷积是需要反转一下的**（先翻转再平移），而这里的卷积核是不需要反转的。

> **老师强调**：你看这里面的这个核是不需要反转的。

关于"要不要反转"，老师补充了一段历史：当时也有人做过实验，结论是**反转不反转无所谓，最终它都会拟合到一种特定的情况**。原因是这里的核是一个可学习的参数（learnable parameter），既然它是学出来的，你给它做不做反转都没有什么影响。

### 2.2 一维卷积的四步流程

**定义**：**一维卷积**（1D convolution）的基本操作。给定一个一维输入向量（input vector），用一个较小的卷积核在上面滑动，每一步做对应位置的逐元素相乘再求和，得到一个输出值，重复直到扫完整个输入。

老师把整个卷积过程总结为固定的四步：

1. **sliding window**：滑动卷积核，每次只覆盖输入的一小部分；
2. **element-wise multiplication**：逐元素相乘，也就是对应位置相乘；
3. **summation of all the multiplication results**：把所有的乘积结果相加，得到一个结果，填入对应的输出位置；
4. **repeat**：重复上述步骤。因为卷积每次只能连一小部分，必须重复才能把所有的 input feature 处理完。

> **老师提示**：大家注意去体会两件事，一个是中间这个 element-wise 的 multiplication，一个是他怎么去 sliding window 然后去做这个卷积。

老师同时说明，真实的卷积核一定是远小于 input feature 的；这里的演示图里两者几乎一样大，只是为了给大家做直观展现。

### 2.3 一维卷积的完整计算演示

**演示**：输入向量为 $[1,2,3,4,5,6]$，卷积核为 $[2,2,2]$，步长为 1。

老师强调，在整数意义下这个演示是最简版本，所以先给出最简单的数字 $2,2,2$；真实的卷积核不会是整数，但是计算方式完全一样，仍然是乘与加，用小学的算术就可以完成。

第一步，把卷积核放到第一个位置。因为要做 element-wise 的 multiplication，位置一定是**对齐**的，输出位置则对应**卷积核的中心**所对的那个位置。

$$1 \times 2 + 2 \times 2 + 3 \times 2 = 2 + 4 + 6 = 12$$

得到 12 之后，把它填到对应中心位置的输出格子里。上节课也强调过：输出位置一定是卷积核中心位置所对应的那个输出，所以它对应的就在这里。

第二步，把卷积核向右挪动一个位置（slide），再做一次逐元素相乘：

$$2 \times 2 + 3 \times 2 + 4 \times 2 = 4 + 6 + 8 = 18$$

把 18 填到相应地输出位置。

第三步，再挪一个位置：

$$3 \times 2 + 4 \times 2 + 5 \times 2 = 6 + 8 + 10 = 24$$

第四步，再挪一个位置：

$$4 \times 2 + 5 \times 2 + 6 \times 2 = 8 + 10 + 12 = 30$$

（字幕在第四步处出现"4 乘 2 加 5 乘 2 加 6 乘 2 等于 20 等于 30"的口误，按计算应为 $30$，**原文待核实** [00:10:02]。）

因此四次输出依次为：

$$12,\ 18,\ 24,\ 30$$

到这里就完成了一个最基本的卷积运算。输入 6 个数，输出 4 个数。

## 四、为什么用 GPU 而不是 CPU [00:12:29–00:14:22]

### 4.1 人的计算一定是串行的

老师注意到，刚才那位女同学很厉害，一个人把四个输出都算出来了。但她脑子里算的时候**一定是串行**去算的：先算第一个位置，再算第二个位置，再算第三个位置，再算第四个位置。是人就一定只能这样算。

### 4.2 CPU 与 GPU 的不同特性

从这个观察出发，老师讲了为什么 GPU 在深度学习时代比较强。

刚才这个算法在 CPU 上的流程是一个线性的流程——依次去算。而 GPU 强在什么地方？**GPU 最早设计出来就是渲染图像的，或者说就是为了打游戏产生的**。打游戏要同时渲染很多的细节，需要做很多矩阵运算，有好多好多小的运算可以并行去算，它不需要像 CPU 那样串行处理，而是并行去算。这种设计放到神经网络里，刚好跟卷积的特性很匹配。

> **老师比喻**：CPU 就一个脑袋，这个脑袋很强很厉害；GPU 它的脑袋很简单，它就会算这些基础的，复杂了它处理不了，**但它长了三头六臂**，它的脑袋非常多，它直接就是并行地去算这种事情。

因此 GPU 可以很快地处理矩阵的相乘，这就是为什么在这个时代我们选择 GPU——是 CPU 与 GPU 两种不同的特性造成的。

### 4.3 CPU 上也能跑，只是很慢

老师补充：如果在 CPU 上运算，这个（卷积）可以吗？可以的，你们也可以去跑一下，CPU 上也能跑，就是你会发现它会变得很慢。因为相同的这种卷积核的乘加运算有很多，需要串行处理，它就会变得很慢。

## 五、输出尺寸缩小与填充（padding） [00:14:43–00:19:33]

### 5.1 问题：输入 6 个数字，输出只剩 4 个

老师请大家观察另一个现象：input feature（input vector）有六个数字，但是我们算完之后输出只有四个。因为规定了必须对应位置对齐之后再算，而且输出取的是卷积核中心位置所对应的那个位置。

**老师启发**：我们输入的 input 是 6，输出的是一个 4，输入和输出不一样了。那我每次算都短一截，每次算都短一截，那算一算就没了，是不是？如果我们想要保持输出与输入大小一致，该怎么办？

这就是"怎么去 keep the same size as the input"的问题。

### 5.2 学生的想法与老师的补充

老师先请大家思考。在提示中老师指出第一个位置"一定在这儿"，因为一队到了这里，你这里没有数字，我也挪不过去。

**课堂问答**：老师请一位同学说想法，并鼓励"你不用担心你的描述不准确，你怎么想的你就怎么描述"。同学提出把旁边直接当作有数字来处理（"直接把这个当做……"），老师说"对，就是这样，他们就是这样做的"。

老师解释为什么需要这么处理：因为我们旁边挪不过去，导致了 shape 对不上。计算机很简单，如果是个人的话，可以直接告诉他"你就当旁边有个数字，你把它放在那多余的就行了"；但计算机的脑袋很简单，没有就是没有，你让我乘什么？所以你一定要在那个地方放一个数字。

### 5.3 具体做法：在两侧 pad 两个 0

那么很简单：**我们给旁边 pad 两个 0**。原本 input feature 里没有这个数字，但我们开始计算的时候，给它加上两端，给它 pad 了一个 0。

**推导**：pad 0 之后的验证计算。

补零后输入变为 $[0,1,2,3,4,5,6,0]$。此时第一个输出位置（对应中心为原输入的 $x_1=1$）为：

$$0 \times 1 + 1 \times 0 + 2 \times 1 = 2$$

最后一个位置（对应中心为原输入的 $x_6=6$，缺右侧一格）为：

$$1 \times 5 + 6 \times 0 + 1 \times 0 = 5$$

（这里卷积核中心所对的输入值是 5，右侧落在输入本身与补的 0 上。）

这样一来，input feature 是六个数字，output feature 也是六个数字，输入与输出的 shape 就一样了。这两个 0 只是在计算过程中辅助用的两个数字，**算完之后就把它扔掉**。

**定义**：这个专业名词叫做 **填充**（padding），也就是在输入的边界外侧补上额外的值（这里补 0）。

### 5.4 padding 的历史做法与为什么默认补零

老师强调，padding 0 是一个**已经被验证过**的方式，现在都已经默认 pad 0 了。而在历史发展过程中，我们其实不只是 pad 过零，有很多种 padding 方式：

- **补零（zero padding）**：在边界外补 0，也就是现在默认的做法；
- **复制边缘（replicate padding）**：挨着最近的这个值重复复制，无限延伸出去。比如左边补 1，右边补 6；
- **镜像（reflect padding）**：以最边缘的值作为镜像轴来补。以最边缘的 1 为镜像，则左边补的是 2；以另一端的 6 为镜像，则右边补的是 5（图为 5，字幕说"这个位置判定的是 5"）；如果要 pad 两个位置，可以继续补 2 和 3、依此类推；
- 其他变体做法（**原文待核实**：老师此处提到"两个位置可以 pad 2 和 3"的做法，属于上述镜像的延伸 [00:18:59]）。

经过很多次、很多年的实验，各种尝试都试过了，结论是：**pad 0 是最简单高效的**。

> **老师强调**：计算机里面不要涉及太复杂的东西，the simpler the better。

所以现在你用 PyTorch 之类的框架时，给它设一个 padding，基本上默认就是 pad 0，除非你专门去设置。

### 5.5 一维卷积中被省略的通道维度

讲完一维卷积之后，老师补充说明：这里给大家省略了一个维度。真实操作的时候，这个"1"不只是一个 1，它是一个**有纵深**的向量（vector）——它自己本身这个位置也是一个有纵深的数字，它可能后面跟着 1 到 10 这么多个数。这就跟图像一样：图像上看上去只有一个地方、一个像素，但实际上那个位置是由 3 个 RGB 的 pixel 组成的。

## 六、二维卷积 [00:20:18–00:26:20]

### 6.1 从一维到二维：四步流程完全相同

接下来看**二维卷积**（2D convolution）。刚才这个一维卷积相当于只取了第一列、第一行，现在我们像图像一样把输入正常展开成一个二维矩阵。

二维卷积的整个流程还是很简单，还是这四步：

1. sliding window（滑动窗口，右上、右下两个方向都能移）；
2. element-wise multiplication（逐元素相乘）；
3. summation of all the multiplication results（所有乘积结果求和）；
4. repeat the above steps（重复上述步骤）。

这四步跟一维的卷积是完全一样的。

### 6.2 输入与卷积核的设置

现在 input feature 已经是一个 $4 \times 4$ 的维度，是一个二维的了。相应地，卷积核也成了一个二维的。老师说明，这里先不考虑特殊情况，按所有的主流情况来介绍。

### 6.3 第一个位置的计算

**课堂问答**与演示：二维卷积的第一步。

输入是一个 $4 \times 4$ 的矩阵，卷积核是一个 $3 \times 3$ 的矩阵。先在输入的左上角（top left）找到与卷积核同样大小的一个 $3 \times 3$ 区域，然后做逐元素（element-wise）相乘，再把九个乘积加起来。

第一次计算的展开式为：

$$0 \times 1 + 1 \times 0 + 2 \times 1 + 1 \times (-1) + 0 \times 1 + 0 \times 0 + 1 \times 0 + 1 \times 1 + 1 \times 1$$

老师当场说"这个心算快的可以算一下，我检查一下我这个对不对，可能也是我随手写的一个数字"，最后得到的结果是 **3**。因为这是最左上的第一个位置，所以相应的输出矩阵里左上角也是 3。

**结果与点评**：老师借此说明，卷积里面只有乘加，没有任何复杂运算，就是乘加，用小学算术就可以做。

### 6.4 二维的滑动方向：按阅读习惯先向右、再换行

一维的时候很简单，只有一个方向，只能往一个方向移。而二维的时候，往右也能移，往下也能移。老师选择先按我们中国人正常的阅读习惯来处理：先往右扫。

把窗口**往右移一个格子**，又找到了一个完全对应的 $3 \times 3$ 区域，也是九个数字，再做一次同样的逐元素相乘与求和：

$$1 \times 1 + 2 \times 0 + 2 \times 1 + \cdots$$

按老师的逐步口述，这一次算出来等于 **5**，把 5 填到对应位置。

接下来这一行已经到头了（top 的这一行到头了，因为右边没有了）。对计算机而言，这个就是到头了；对于人而言，你可以说先跨出去一个，但计算机不管这个。到头之后就要往下一个地方挪，还是一样按正常阅读习惯，看第二行。

## 七、输出尺寸公式、步长（stride）与感受野（receptive field） [00:27:51–01:04:39]

### 7.1 步长（stride）概念的引入

老师先回顾：我们一直说 sliding、滑动，而且说的是滑动一格。有没有想过滑动两格呢？我为什么要滑动一格，滑动两格行不行？

老师指出，滑动一格的计算并没有多大差别；如果滑动两格，那么它就不再挪到相邻的位置，而是**直接跳两格**。

**演示**：把滑动步长设为 2 的实验。

- 原本输入是一个 $7 \times 7$ 的矩阵（字幕在 00:28:55 处记为"我们原本是一个 12345，我们之后变成了一个 7 乘 7"，**原文待核实** [00:28:55]）；
- 滑动两格之后，算完之后变成了一个 $3 \times 3$ 的输出。

在纵向方向上也做同样的处理，也就是纵向也滑动两格；横纵都按阅读习惯从左到右、从上到下处理，每个位置都会产生一个输出。

> **老师启发**：遇事一定要问，请问 why。这个才是我们在这个大模型时代成为一个人能存活下去的一个最根本的技能。你看所有的大模型，他能力再强，他的所有的这些东西都是由人去问出来的，就人给他 prompt、给他命令出来的。所以我们自己一定要保持一个（习惯），就是不要去全面接受，每次都要问一下 why。

### 7.2 输出尺寸公式与代入验证

那么 stride 变成 2 之后输出为什么变成 $3 \times 3$，这中间到底有没有什么关系呢？有的，老师给出了这样一个公式（老师说明：这个公式你们如果厉害的话，也可以死记硬背住；如果记不住的话，也可以通过理解自己推出来）：

**定义**：**卷积输出尺寸公式**。设输入的高（宽）为 $n$，卷积核大小为 $k$，填充量为 $p$，步长为 $s$，则输出的高（宽）为

$$
n_{out} = \left\lfloor \frac{n + 2p - k}{s} \right\rfloor + 1
$$

老师逐项解释了公式里每一项的含义：

- **input size**：输入的大小，记作 $n$。因为横纵两个方向都要用，而我们处理的是正方形，所以就横纵共用一个 input size；
- **加 $2 \times$ padding**：为什么要加两个？因为 padding 之后上下（左右）两边都有我该有的位置，也就是我补的位置在两左右都存在，所以要加两倍的 padding；
- **减去卷积核大小 $k$**：因为卷积核有这么宽，它要完整地盖住一段区域；
- **除以 stride**：stride 就是你每次挪动的位置是多少；
- 最后**加一**，就出来了。

**推导**：代入老师给的数字验证。输入 $7 \times 7$，卷积核 $3 \times 3$，padding 为 1（只 padding 了一圈 0），stride 为 2：

$$7 + 2 \times 1 = 9,\qquad 9 - 3 = 6,\qquad \frac{6}{2} = 3,\qquad 3 + 1 = 4$$

这里需要说明的是：老师在板书演示中用的输入是 $7 \times 7$、输出为 $3 \times 3$，按标准卷积输出尺寸公式 $n_{out}=\lfloor (n+2p-k)/s \rfloor + 1$ 反推，对应的是 padding $p=0$（$7\to3$）；而若取 $p=1$，$7\times7$ 会得到 $4\times4$。字幕中老师口述的是 $5\times5$ 与一圈 0，与画面数字之间存在出入（**原文待核实** [00:28:55–00:30:25]）。

### 7.3 为什么必须把这个尺寸算熟

老师说，这个公式在目前的神经网络里算得可能都已经比较少了，但在早期，尤其是像 ResNet 那一类的网络（字幕记为"rest night 那个 list"，按上下文应为 ResNet 这类网络，**原文待核实** [00:32:01]），做分类的人在网络设计时是经常算的，有些数字可能都已经刻在脑海里了。

老师解释了为什么必须熟：因为你的 input feature 是 $H \times W$，你到最后一层 fully connected（全连接）的时候，全连接层是一定要 match 上的。你看 VGG Net，它最后是一个 $7 \times 7$ 的 size，接的是一个 $7 \times 7$ 的全连接层。所以输出到那一层的时候，这个 feature 的高和宽的维度一定得是 $7 \times 7$，不是 $7 \times 7$ 他就一定会报错。

所以为什么要对这个熟？因为你对这个不熟的话，你就会突然发现，每次你设计个什么输进去，他就给你报错——报的就是 size 不匹配这种错。所以这些对于卷积神经网络、或者说对于当时做分类的人而言，一般都会算得很熟。

进入 **Vision Transformer**（ViT）时代之后，因为前面先是切片，把图切成小的 patch，再把 patch 转成 embedding、转成 token，那时它就是一个一维的向量，这个时候 $H$ 和 $W$ 已经无所谓了。但在转成 token 之前还是有所谓的，因为它也是大部分网络规定了你的输入是多少，比如必须是一个 $224 \times 224$，必须是一个 $512 \times 512$。你像很多 vision 的一些模型，比如说 SAM 系列很有名，它就规定它的输入必须是一个 1024 之类的，它是有规定的。

### 7.4 padding 的作用与尺寸不变的条件

接下来老师提醒，公式里这几个东西我们也要大概知道它用来干什么。

首先 padding 用来干什么？padding 现在是一个绝对的默认操作。老师带大家这样想：但凡是算卷积的时候，卷积核不可能是 $1 \times 1$ 的。如果算完之后不加 padding，那么只有一种可能——卷积核是 $1 \times 1$，也就是对应中心位置每个都能当中心位置去算一遍，这种情况下它才不会变小。但凡我这个卷积核大一点的话，我正常算它都会缩小。

而每次算一下、缩小一圈太烦了：我一个 512 的，你算完之后变成 511，然后再算完又变 510，这太难处理了。

所以一般默认的是：**经过一个卷积层之后，我的 input feature 不变**。要么不变，要么是一个以 2 为整数倍的 up sample 或者 down sample。

因此 padding 一般用来**维持 input feature 的高和宽不变**。

**推导**：维持高宽不变时 padding 与卷积核的关系。假设 stride 等于 1，要维持高跟宽不变，那么 output size 跟 input size 就相等。把这个条件代入输出尺寸公式，两边相减得 0：

$$n + 2p - k = n \quad\Longrightarrow\quad 2p - k + 1 = 0$$

移项并整理：

$$k - 1 = 2p \quad\Longrightarrow\quad p = \frac{k - 1}{2}$$

也就是：**卷积核减 1 再除以 2，等于你要 padding 的大小**。老师特别说明这个关系是当场推的。

**例子**：如果卷积核是 $3 \times 3$（$k = 3$），那么 $p = (3-1)/2 = 1$，也就是 padding 一圈，正好跟前面演示的情况相符；如果一个 $3 \times 3$ 卷积核要维持尺寸，就 padding 一圈 0。

**课堂问答**：老师问"我给定一个 $23 \times 23$ 的卷积核，判定（padding）多少？"同学先答"十"，随后修正为"十一"，老师确认"对，十一，这个对"。

> **老师强调**：这些数字要默认，一定要在你心里能形成一个条件反射。因为卷积核的 size 无非过来过去就是 3、5、7，它不可能更大了。当然早年的时候有人设计过特别大的、什么 $15 \times 15$ 或 $15 \times 1$ 这种矩形的卷积核，可能是有人设计过的，而且是进入过 CVPR 的 best paper 的 candidate 的，是有人设计过这种奇怪的卷积核，但是一般情况下都是这种正方形的卷积核，而且最常用的就是 $3 \times 3$ 的。

由此得到常用对应关系（老师当场给出的）：

| 卷积核大小 $k$ | padding $p = \dfrac{k-1}{2}$ |
|---|---|
| $1 \times 1$ | 0 |
| $3 \times 3$ | 1 |
| $5 \times 5$ | 2 |
| $7 \times 7$ | 3 |
| $23 \times 23$ | 11 |

老师总结说：其实无论在什么情况下，现在已经默认了——我 $3 \times 3$ 的时候我要 padding，我一定 padding 1，我就给他 padding 一圈 0；如果 $5 \times 5$，我就 padding 2；$7 \times 7$，padding 3 圈 0。

老师还给出另一种理解 padding 的直观方式：你要让它每个位置都保持不降维，是不是让最边角的这个也能当作中心位置去被卷积核算一遍？那你的 $3 \times 3$ 卷积核对到最边缘之后，下面（外面）剩下多少，它是不是就该 padding 多少。可以自己验算：如果是 $23 \times 23$ 的输入、$3 \times 3$ 的卷积核，往下还有 11 个位置可以用，那我要让边缘也能当成中间位置去算，就肯定要 padding 一个 11。这跟 $(k-1)/2$ 是不是同一个操作。

### 7.5 步长（stride）的作用：控制降维与计算量

**定义**：**步长**（stride）是卷积核移动时每次移动的位置大小。叫 stride 也好，叫步长也好，记住这个概念就是：它是卷积核移动的时候，这个移动位置的大小。

老师指出，刚才讲的 stride 一般用来让这个 feature 降维。具体地：

- **步长较小时**（比如前面图中的 stride = 1），每次只挪一点，我们可以提取的特征更加细微、更详细；
- **步长较大时**，它可以更快地提取特征——我这算完之后直接就到这里，明显会快很多，而且它的计算量明显会减小。

计算量的减少很好理解：因为你每次挪动很小的话，你重复计算的位置太多了。图示中某个情况下输出是一个 $3 \times 3$，其实也就进行了 $3 \times 3 = 9$ 次卷积；而 stride 等于 2 的那个情况下输出一个 $2 \times 2$，其实也就进行了 $2 \times 2 = 4$ 次卷积。

老师接着说明，这里大部分都是一种正方形矩阵的情况。在正方形的情况下，默认 stride 是 1 的时候，往往往右移跟往下移是一样的。但如果你就是"叛逆"，你要让它往右移的时候移一个格子，让它往下移的时候移两个格子，那当然也可以。

### 7.6 课堂练习：横纵方向使用不同步长

**例题**：横纵方向步长不同的卷积输出尺寸。

**题目**：一个 input feature 是 $512 \times 512$（高和宽都是 512），卷积核是一个 $3 \times 3$ 的卷积核，padding 了一圈 0。**我的 stride：往右移的时候 stride 等于 1，往下移的时候 stride 等于 2。** 请问我的输出这个 feature 长什么样子？

**解答**：输出不再是一个正方形，而是一个**矩形**。

- 纵向：因为向下移动的 stride 等于 2，所以 $512$ 会变成一个 $256$；
- 横向：因为向右移动的 stride 等于 1，尺寸没有变，仍是 $512$。

因此输出 feature 的尺寸是 $256 \times 512$。

**结果与点评**：同学回答了这个结论，老师确认"它是一个矩形的了"。老师借此强调，大家要理解 padding 起的作用跟 stride 起的作用。至于具体里面的那些运算，就是我们前面拿数字 123456 演示的那些，它其实就是乘跟加，很简单。

### 7.7 感受野（receptive field）

接下来老师介绍另一个概念，叫做**感受野**（receptive field）。

**定义**：**感受野**就是某一个位置的输出特征，能够"感受到"的输入区域——直观来说，就是输入的哪些位置的数值发生变化会影响到它的值，这个区域就是它的感受野。

老师用形象的讲法解释：假设我们用的是 $3 \times 3$ 的卷积核，而且 padding 了一圈 0，那它的输入输出大小是一样的。这个时候放到这个位置，这个位置的输出值是由这一块区域算出来的，那这个位置的 feature 就是"我只见过你这一片，你其他的我没有见过、我没有看到过"。

**推导**：为什么这是感受野。因为算得出它的时候，是由这个位置做一个 element 的 multiplication，也就是我只跟它发生过计算。那么在这个区域之外的数值改变会影响它吗？不会。而在这个区域之内的数值改变会影响它吗？会的。所以跟它有关联的这个区域就是它的感受野。

老师说明感受野这个概念在早年、一直到 2020 年都是很火的一个概念。为什么？因为卷积核就有一个 $3 \times 3$，我最终一个图有 1024 这么大小，你怎么能保证我最终的每一个 feature 我都能看到全图呢？我都没看到全图，你让我做分类，是不是？所以当时感受野很火。

**课堂问答**：老师反问大家——如果有人对 Transformer 熟的话，虽然这节课还没讲到，后面两周后会讲到，就是为什么 Transformer 时代就不讲感受野了？答案是 Transformer 把全部都关联了（**原文待核实**：字幕此处为"全部就对吧全部关联了""是 former 是一种近似"，语句不完整 [00:45:33–00:45:42]）。老师解释：Transformer 是一种全连接（fully connect）的概念，我们每个都相连，所以不存在感受野——我是每一个我都全部能看到。而只有卷积这里我并不是全部去关联的，所以它会强调感受野。

### 7.8 感受野随层数增大：逐层回推

老师先介绍了**直接感受野**（最直观的一层情形）：这个位置是我直接一次性发生这个计算产生的，所以我直接能看到上一层的这一片。

接着看层数多起来的情形。老师的方法是从输出往回推，并且"一般是挑左上跟右下"来标定，因为中间的可以自己去扫，左上和右下能看出它的大致范围。

**推导**：两层、三层卷积之后感受野的扩大。

1. 第一层：输出中某个位置由上一层（该层为 $3 \times 3$ 的区域，共 9 个元素）算出来，所以它在这一层的感受野就是一个 $3 \times 3$ 的区域。这一层里其他位置数值发生改变，不会影响它。
2. 第二层：再往回推一层，这个红框里最上面的那块是由这里产生的，右下那块是由那里产生的。整个框合起来在这一层是一个 $3 \times 3$ 的区域，放到上一层（前一层）里就已经有 $5 \times 5$ 这么大。

**课堂问答**：老师请大家思考"这样一个 $3 \times 3$ 的感受野在上层的时候，它的感受野是多大？"老师提示最简单的方式就是看某个位置的值发生改变时会不会影响它的值——影响就在感受野范围内，不影响就不在。最后请教室后面一位女生回答，得到 **$5 \times 5$**：因为已经把最左上和右下标出来了，从最上到最下是一个 5，从最左到最右是一个 5，所以是 $5 \times 5$ 的区域。任何一个数字发生改变，它都会影响这里面的改变；而那个中心的数字位置改变，影响得就更多了，这九个可能都会影响。

3. 第三层：再往前推一层，左上都已经到这里、右下都已经到这里了。那么这样的一个 $5 \times 5$ 的区域在更前一层（全图）里，它的感受野就已经是**全图**了。也就是说，从这里这一个位置就能看到这一层的全图，因为这个像素的值改变一定会影响这里，这里被影响了，那里也一定会被影响。

**总结**：我们经过一次、两次、三次的卷积之后，经过三个 layer 之后，它的一个感受野也已经扩大到是一个 $7 \times 7$ 的范围了。

**公式**：感受野大小可以计算，记层数为 $L$、卷积核大小为 $k$，则

$$
\text{感受野} = L \times (k - 1) + 1
$$

代入老师给的例子：卷积核 $k = 3$，一共三次（$L = 3$），所以感受野是 $1 + 3 \times (3 - 1) = 7$，即 $7 \times 7$，跟刚才逐层推出来的结果一致。

> **老师总结**：卷积或者卷积神经网络，它就是依靠这种堆叠、逐步的堆叠，我也要看到全图。我通过逐步的堆叠、通过这种方式增大我的感受野。

相比于传统（全连接）不太好的一点是，这是一种**间接的感受野**——它已经经历了好多个 layer 了。那我这个地方这个值改变一下，对他的影响能有多大？全连接相当于我这个位置跟你的所有都都相连，我一个改变会很直接地影响；而卷积里面它是一种间接影响。

## 八、参数减少与多通道卷积 [01:04:42–01:14:59]

### 8.1 卷积为什么流行：参数量的大幅减少

老师接着看卷积神经网络为什么流行——因为到现在大模型时代，处理前面视觉的这一部分，它还是卷积神经网络。

**推导**：从全连接层到卷积层的参数量对比。

- 全连接层：每个神经元都要跟前面一层所有的神经元相连。图示中上面有 5 个、下面有 7 个，那么至少有 $5 \times 7 = 35$ 根线，也就是 35 个参数，而且每根线都是独特的、不能复用的。
- 卷积层：卷积核是 $3 \times 3$，但我并不是所有的都去相连，我每次就连一部分——每次只连三个。而且参数量还不是"肉眼可见的这么多根线"，而是**只有三根线**，因为它是**复用**的：我的卷积核是移动的、复用的。

那么从 35 降到 3，这个量已经很明显了。而且我们这里只有这么小；如果我们更大，像我们开头讲的那个 $10^{12}$ 的规模，它的减少是不是更大？即使是 $10^{12}$，我也只是一个 $3 \times 3$ 的卷积核去卷。

**减少参数的两个依据**。老师强调，卷积之所以能减少参数，是由两个部分组成的：

1. **局部相连**（local connectivity）：每次只与一部分相连；
2. **权重共享**（weight sharing）：同一个卷积核在整个输入上滑动时重复使用同一组权重。

> **老师强调**：权重共享很重要。如果你只是局部相连，是不是也没用？因为你如果只是局部相连的话，大家看是不是你也就是从这个 35 变成了 1、2、3，然后你有 3、3、3、3、3（共 15 个）变成 15，你并不能从 35 变成 3。你这三根线是我们这里是复用的；如果你只是局部相连但是不共享参数的话，你这三根线跟这三根线是不是要不同的参数？是不同的参数。但是我们这里是相同的参数，因为我是共享。

所以是**局部相连加权重共享**两种方式，我们得到一个比较轻量化的结构：无论你的 input feature 有多大，我就学 $W_1$、$W_2$、$W_3$、$W_4$ 这几个参数（也就是一个 $2 \times 2$ 的核）就够了。因为你权重共享，你再大无非我这个卷你的这个范围大一点，无非我这个滑动范围大一点。

从数据上看，卷积得到的这种 feature 是一种权重的映射，它同时具备两个性质：**局部相连，而且权重是共享的**。

### 8.2 权重共享与减少参数的思想来源

老师进一步解释为什么可以用权重共享，也就是减少参数的依据。

**推导**：图像中的局部不变性。

减少参数的依据就是图像中的**局部不变性**：我不会因为鸟在这儿还是在那儿而特征发生改变——在哪都一样。这种尺度缩放、平移、旋转这些操作都不影响这个语义信息。

> **老师比喻**：比如说我这个激光笔，我这么放着它是个激光笔，我这么放着它也是个激光笔；我怎么放，或者说离你们近一点、离你们远一点，都是个激光笔。所以在这种情况下，我用一个卷积核怎么去操作？我就用这么大一个范围去看，我得出来的这个 feature 它的语义信息应该是一样的。

### 8.3 多通道卷积

接下来讲单通道与多通道。老师说明，刚才为了让大家直观理解卷积，都把通道（channel）这个维度给大家隐去了，但实际上我们是有多通道的。

**例子**：多通道的卷积核。

- 我们有第一组卷积核，对应参数 $W_{11}\ W_{12}\ W_{13}\ W_{14}$，得出对应的输出 $Y_{11}\ Y_{12}\ Y_{13}\ Y_{14}$；
- 我们有另外一组 $W_{21}\ W_{22}\ W_{23}\ W_{24}$，得到对应的 $Y_{21}$ 之类；
- 然后有对应的第三组参数 $W_{31}\ W_{32}\ W_{33}\ W_{34}$，得到第三组输出。

因为我们这里是三个卷积核，所以它也对应有三个这种输出。**卷积核本身是有 channel 维度的**，它的输出是随着我们卷积核的数量在 channel 维度上堆叠起来的。用这种方式我们就得到我们一个多个 channel 的输出。

### 8.4 多通道的输入与输出

老师提醒，input feature 的 channel 就是这个维度，这个 channel 要跟你的卷积核的 channel **一样**，不然的话你 match 不了。我们现在只讲最 normal 的最正常的情况，所以 channel 要一样。**例子**：我们现在有 RGB 三通道的输入，我们用一个 $3 \times 3$ 的卷积核去卷，卷积核也具有三个 channel。这样在同一个位置，第一个 channel 的 $3 \times 3$ 与卷积核的第一个 channel 对应，第二个、第三个 channel 依次对应。

**推导**：为什么输出只有一个通道。对应完了之后，无非是从一个 9 个数字的相乘变成了一个 27 个数字的相乘；相乘之后，这 27 个数字的相乘结果还是要加起来，最终还是等于一个数字。所以在最 top 的最左上的这个 $3 \times 3$ 的区域，我算完之后还是等于一个数字，因此输出出来还是一个（通道）。挪完几次之后，还是得到这样一个输出。

> **老师启发**：我如果想让 output channel 有多个 channel 的话怎么办呢？你可以加核。

每个卷积核是独立算的：比如还是这个 $3 \times 3$ 的卷积核，在这个位置算出来之后等于有一个值，这个值算完之后，它是不是在 output 的这个位置是由这个卷积核一（kernel 1）来算出来的。

**一个卷积核可以提取一种特征**。老师说明，我们一般这样认为：一个卷积核可以提取图像的一种特征。至于它到底学了什么，谁也不知道。你可以最终去可视化出来解释一下，说它学了个猫、学了个狗，但它到底学了个什么，那只是我们人类赋予它的一种解释。

> **老师启发**：因为到这种程度，尤其我们现在大模型时代，我们很多时候我们在强迫着它像我们人类一样思考，但是有没有可能他自己能够摸索出一种他独特的思考方式，才能达到我们输出的一个目的呢？当然是可能的。

**推导**：为什么随机初始化会让不同卷积核学到不同特征。我们讲一讲为什么我们认为一个卷积核可以提取一种特征。这是初始化的一个基本概念：我们上节课讲过，这些 parameter 都是初始化的，然后去让它优化。我们这几个 $W_{11}$、$W_{21}$ 这些在初始化的时候，我们是**随机初始化**，所以它们的**初始位置不一样**。

> **老师比喻**：那就比如说我们做的这个目的是从杨浦区跑到静安区，我把你们放在杨浦区的不同位置，你们都能跑到静安区，那你们是不是都探索出了一条路？那这条路是不是都是都能过去？我们用多种卷积核去提取多种特征。

## 十、多通道卷积与输出通道 [01:14:33–01:21:56]

### 10.1 用多个卷积核产生多通道输出

接着上一段单通道卷积的例子往下走：如果想让输出的特征图有多个通道，就去增加卷积核的个数。老师先用"每个学生各交一份卷子"的说法把这件事讲清楚——卷积核一在某个位置上算出一个值，卷积核二不参与卷积核一的计算，它自己独立地从上到下、从左到右再扫一遍，同样得到一张完整的输出。

在动画里，输入特征图和卷积核都被"平着展开"了：输入特征图有三个通道，卷积核也有三个通道，并且平铺成"kernel one、kernel two"两份（这里叫 filter、过滤器、卷积核都可以）。

每一份卷积核的计算过程是：单个通道内部的卷积和最初讲过的单通道卷积一模一样，只是把通道算完之后，所有数字仍然要加起来，最后得到**一个**数字。

> **老师提示**：不要盲目地写代码，一定要在脑海里面把这种空间的概念建立起来——你都不知道它在干什么，写出来也没有意义。

所以输入是三个通道时，计算就从"9 个数字相乘再相加"变成"27 个数字相乘再相加"（$3\times3\times3=27$），乘完之后这 27 个结果仍然要相加，最终结果**还是一个数字**。因此在最普通的情况下，输出特征图依然是单通道。

> **老师强调**：input feature 的 channel，也就是 Z 这个维度上的通道数，必须跟你的卷积核的通道数一样，不然是匹配不了的。我们现在只讲最 normal、最正常的情况，所以通道要一样。

多出来的通道无非是计算时多几个数字，算完以后仍然是"对应相乘、再相加"，在左上角那个 $3\times3$ 区域算完仍然等于一个数字，所以输出还是一张单通道特征图。

至于输入通道数和输出通道数可不可以不一样，老师明确说：**可以**，但那属于特殊的卷积，有专门的特殊做法，后面会讲到；等上练习课的时候大家可以自己去改着试。不过 `nn.Conv2d` 这个函数一定要熟，本节课讲到的所有参数操作在练习代码里都有对应的参数可以改。

输出有几个通道，取决于有几个卷积核：

$$\text{输出通道数} = \text{卷积核个数}\ (C_{out})$$

每个卷积核各自算自己那一份，算完之后把结果在 channel（Z 轴）方向上叠在一起，就形成了多通道的输出特征图。

> **老师比喻**：这就像考试每人交一张卷子——每个学生都是一个"卷积核"，你自己都要交卷子；你交完往这一放，第二个学生来了再交一张。卷子只能从 Z 轴上落到一块，我不可能把你们的卷子和答案互相融合成一张卷子。

> **老师比喻**：换一种说法，虽然大家都在这个教室里面、我讲的课也都一样，但你们每个人学完之后自己学出来的理解都是不一样的，一定会有差别的地方，所以你输出的这份"试卷"一定会有差异——这就是每个卷积核学到的特征不一样。

### 10.2 图示：$7\times7\times3$ 输入、两个 $3\times3\times3$ 卷积核

课堂上放的这段动画，具体参数是：

| 项目 | 取值 | 说明 |
|------|------|------|
| 输入特征图 | $7\times7\times3$ | $7\times7$ 是宽和高，$3$ 是通道数（1、2、3） |

## 十一、参数量与计算量 [01:21:56–01:29:37]

### 11.1 为什么要报参数量和 FLOPs

**浮点运算次数**（Floating Point Operations, FLOPs）和**参数量**（Number of Parameters）这两个概念非常重要，因为现在写论文基本还是要报一下的。

老师顺带吐槽了审稿这件事：现在很多 review 的人"闲的没事干"，为了凑字数，因为期刊/会议要求审稿意见的字数不能低于 1000 字，低了你这个系统就预警了，系统会给 AC（领域主席）发邮件，说"你的第 100 号 paper 的 reviewer 2 它的这个字数过少，请你鞭笞一下他"——原话用的就是"鞭笞"这个词——然后请你让他增加字数。

> **老师提示**：让他们增加字数，很多时候用的就是一条意见——"请你报一下 FLOPs 和你的 number of parameters"。这是一个非常常见的用来凑字数的意见，因为你不用管这篇 paper 是干什么的，只要是 deep learning 时代的 paper，你一定可以问这个问题。**大家不要把这个坏习惯学过去。**

### 11.2 参数量的计算

参数量顾名思义，就是我这个卷积核里面有多少个值。

先看数得出来的例子：$3\times3\times3$ 的卷积核里面每个通道有 9 个参数，三个通道一共 $9\times3=27$ 个参数；有两个卷积核，$27\times2=54$；再加 2 个 bias，一共 56 个参数。

但如果卷积核个数是 3 个、512 个、1024 个、2048 个，加上层数很多，是数不出来的，所以必须会算。

**推导**（以 $K_W\times K_H$ 的卷积核、输入通道 $C_{in}$ 为例）：

1. 一个卷积核的参数量为

$$K_W\times K_H\times C_{in}$$

其中 $K_W$ 是宽、$K_H$ 是高（老师提到有些"有特殊爱好"的人喜欢把卷积核设成矩形，所以这里用 $K_W$ 和 $K_H$ 分开写；如果是正方形就是 $K^2$），$C_{in}$ 是通道数。

2. 再加上一个偏置项 bias，得到一个卷积核的总参数量：

$$K_W\times K_H\times C_{in}+1$$

3. 再乘以卷积核的个数 $C_{out}$：

$$\text{参数量}= \left(K_W\times K_H\times C_{in}+1\right)\times C_{out}$$

代入上面的例子：$3\times3\times3=27$，$27+1=28$，两个卷积核 $28\times2=56$，跟数出来的完全一致。

并不是所有的层都有参数。比如 ReLU 这类层就没有参数——它不需要学一个什么参数，它就是一个"值的选择"：大于零等于本身，小于零等于 0，这样的层是没有参数的。

### 11.3 计算量（FLOPs）的计算

计算量指的是运算的次数，比如让你算一个 $1\times1$，这就是一次计算量。卷积的计算量算的是**乘法的次数**和**加法的次数**。

**推导**（同样以一次滑动窗口内的运算为例）：

1. 乘法的次数是

$$K_W\times K_H\times C_{in}$$

例如 $3\times3$ 的卷积核在三个通道上，每个通道 9 次乘法，一共 $9\times3=27$ 次乘法。

2. 加法的次数是

$$K_W\times K_H\times C_{in}-1$$

理由是：$N$ 个数相加只需要 $N-1$ 次加法。老师举例说"五个数相加我有四次加法"。

3. 还有一个偏置项加 1，这也是一次加法，那个"尾巴"也得给它加上去。

4. 于是单次滑窗的计算量是

$$\underbrace{K_W K_H C_{in}}_{\text{乘法}}+\underbrace{\left(K_W K_H C_{in}-1\right)}_{\text{加法}}+\underbrace{1}_{\text{偏置}}\;=\;2K_W K_H C_{in}$$

5. 再乘以卷积核的个数 $C_{out}$（有两个卷积核就乘以 2）：

$$\times\ C_{out}$$

6. 再乘以输出特征图的大小 $W\times H$。因为输出特征图上**每一个位置**都进行了这样一次乘法与加法，所以要把这个数量乘以输出特征图的元素个数：

$$\text{FLOPs}=\left(2K_W K_H C_{in}\right)\times C_{out}\times W\times H$$

> **老师提示**：理解 FLOPs 以后，看到别人报 FLOPs 的时候你要知道他在说什么。现在 PyTorch 里面有集成好的代码可以直接运行，它会给你把整个网络里有多少 FLOPs 算出来——放到一个大网络上面我们肯定不能这么手算了，因为网络太复杂，所以直接去调用就行了。

### 11.4 例题：由输入输出反推卷积参数

**例题**：已知输入输出，反推卷积层的各个参数。

**题目**：输入是一个 $128\times128$、通道数为 $3$ 的特征图，用一个 $3\times3$ 的卷积核，输出一个 $128\times96$ 的 output feature。问：

1. 每个卷积核有多少个参数？
2. 有多少个卷积核？
3. padding 是多少？
4. stride 是多少？

**解答**：

1. **每个卷积核的参数个数是 27**。注意题目问的是"每个卷积核"，所以不用看 96，输出通道数对这个问题的答案没有影响。既然是 $3\times3$ 的卷积核而输入的通道是 3，那么每个卷积核就是 $3\times3\times3=27$ 个参数。
2. **有 96 个卷积核**。因为卷积核的个数等于输出层的通道数，输出特征图的通道数是 96。
3. **padding 等于 1**。因为高和宽从 $128$ 到 $128$ 没有变。
4. **stride 等于 1**。同样因为没有降维。

**结果与点评**：四问的答案分别是 $27$、$96$、$1$、$1$。老师说这就是一道非常简单的例题，"既然你们都说自己懂了"，那就要能秒答；关键是要抓住"问的是每个卷积核"这一点，不要把输出通道数混进参数量的计算里。

## 十二、特殊卷积类型 [01:29:37–01:42:28]、[01:52:34–02:05:14]

上面讲的是最 normal、最 common 的卷积。但总有人有"特殊的爱好"，于是出现了一批变种卷积。

这节课讲到这里时老师宣布"我们这节课先到这里，下节课继续"（约 01:42:28）；01:42:28–01:52:33 为课间，字幕中只有零星环境杂音，没有学术内容。01:52:34 复课后老师说："卷积层这块其实我们讲的比较慢，因为这里对于你们挺重要的，希望大家把这里面的一些细节都能够掌握得比较好。"随后老师重新放了一遍膨胀卷积的可视化动画（dilation rate $=2$ 时膨胀成 $5\times5$，rate $=3$ 时膨胀成 $7\times7$，再膨胀就是 $9\times9$，这些数字要很敏感、能很快反应过来），并由此提出"还有什么方式能增加感受野"。

### 12.1 感受野：如何扩大输出单元的感受野

**感受野**（Receptive Field）是这一章反复出现的核心概念：一个正常的 $3\times3$ 卷积，在前一层只能覆盖一个 $3\times3$ 的区域；感受野越大，这一个输出单元能"看到"的输入范围就越大。

老师由此提问：前面讲的这些做法其实都是为了增加感受野，那么**还有什么方式能够增加输出单元的感受野**？

**课堂问答**：

> **老师启发**：怎么能够增加这个输出单元的感受野？或者说你们总结一下，上面有哪些方式能够增加它的感受野？

学生先答出最直观的"膨胀卷积"（也就是改变 dilation rate），老师接着补了"更直观的一个"——直接把卷积核的 size 加大。课堂上归纳出的方式一共四种：

1. **膨胀卷积**（改变 dilation rate）：相同参数量下把采样点拉开；
2. **直接增大卷积核的 size**：更直观，但参数量会跟着涨；
3. **堆叠层数**：前面讲"一个 pixel 能看到全图"时，靠的就是把层数一路堆上去（每过一层，一个输出单元能覆盖的输入范围就往外扩一圈），层数越多感受野越大；
4. **池化操作**（Pooling）：这也是增加感受野的方式，后面会具体讲到池化的操作。

这些手段的共同目的都是为了增加感受野。

### 12.2 深度卷积

**深度卷积**（Depthwise Convolution）玩的把戏是：每个卷积核只有一个 channel，而且它"点名"只跟输入特征图里对应的那**单个**通道发生计算。下一个卷积核也同样只跟它对应的那一个通道计算。

本来正常的做法是卷积核有三个通道，跟输入的全部三个通道都发生计算；深度卷积则是我只有一个卷积核通道，而且我只跟你的第一个 channel 计算，另一个我也很"异类"，点名只跟你的第二个通道计算，其他的我不管。

于是：输入有三个通道，我就要有三个卷积核，每个卷积核只算自己那一路，最终算出三个输出特征图，也就是三个输出通道。

### 12.3 逐点卷积与轻量化思路

**逐点卷积**（Pointwise Convolution）是一个 $1\times1$ 的卷积，只在 channel 上做计算：空间维度上我只管一个点，通道维度上我把所有通道都串起来算。

原本一个正常的卷积是 $3\times3\times3=27$ 个参数，发生计算的范围是一个 $3\times3$ 的区域再乘上所有通道。把逐点卷积和深度卷积拼起来之后，这个 $3\times3\times3$ 的卷积被拆成两部分（老师板书写的是"$3\times3$"与"$1\times1\times3$"；这里 $1\times1\times3$ 表示空间上是 $1\times1$、在 3 个通道上做组合）：

- 深度卷积：$3\times3$（空间上 $3\times3$，通道上每个卷积核只管一路）
- 逐点卷积：$1\times1\times3$（空间上 $1\times1$，在通道维度上做组合）

**推导**（参数量对比）：

$$3\times3+1\times1\times3=9+3=12$$

原来是 $27$ 个参数，拆完只有 $12$ 个，参数量减少了一半还多。

这种做法的动机就是**轻量化**（efficient convolution）：减少参数量、减少计算量。所以一般的做法是——先接一个深度卷积，后面再拼一个逐点卷积，堆叠起来用：用一个 depthwise 先乘一遍，做完之后再接一个 $1\times1$ 的 pointwise，两者结合起来就能实现一种很好的操作。后面还延伸出了比这个更复杂的东西。

### 12.4 分组卷积与 `groups` 参数

深度卷积这个概念提出来之后，后续衍生出的概念在框架里被集成的时候（老师说大约 2018 年左右才集成出这种功能），最终把它定义为 **group（分组）**，也就是**分组卷积**（Group Convolution）。

可以这样理解：group 的数目对应 channel 的分组方式。

- 如果分了三个 group，每个 group 对应一部分通道（`groups` 的数值就等于从 channel 方向上分出的组数）；
- 深度卷积其实只是分组卷积的一个特殊情况：每个 group 里只有一个通道。

老师在黑板上用不同颜色把通道分组来讲这件事。为了讲清楚，先把 $H\times W$ 这个维度放到一边，只看通道方向：把通道画成一组一组的方块。

- 深度卷积是每个卷积核只管一个 channel，那能不能两个 channel 一组呢？也可以。比如把通道分成 1、2、3、4、5 共五组、每组两个通道，每组内部发生计算：卷积核来了之后，"你有几个 channel 我也有几个 channel，我跟你一样"，就跟你最 normal 的卷积一样，组内所有通道都要发生关联。单看一个组的话，它跟前面讲的最普通的卷积一模一样。
- 不同的组之间则互不发生计算：第二个 group 有它自己单独的卷积核，这个卷积核也只在自己内部发生计算，每个 group 都有自己的一个卷积核，从 channel 维度上只在组内计算。
- 还能不能更极端一点？可以。老师假设手上有 10 个通道，接着比较两种分法：一种是两两分组，两个通道为一组；另一种是五个通道一组。按老师讲的口径，五个通道为一组时 **group 等于 2**；两两分组时 group 等于 5（**原文待核实**：老师在同一处的板书写的是把 1 到 5 分成五组，与口述的两个数值之间关系不完全一致 [01:37:20–01:37:53]）。
- 那 group 等于 10 的时候，就是分成十组，每组都是单独的一个卷积核——这就和深度卷积一样了，也就是**完全的 depthwise 卷积**。

所以最后 PyTorch 把 depthwise 集成进 `nn.Conv2d` 的时候，用的就是 group 这个概念去完成它，因为 depthwise 只是 group 的一个特殊情况。在 `nn.Conv2d` 里有一个参数就叫 `groups`：

- 默认情况下 `groups=1`，就是所有通道都在一个组里，也就是正常的、最标准的卷积；
- `groups` 等于 2 或者等于几的时候，它就从 channel 上去分组。

**分组有一个硬性要求**：

> **老师强调**：`groups` 一定要能够整除 channel 的个数。你不能说你来了一个 9 通道，非要给它分成 2 组，它会报错。

### 12.5 膨胀卷积（空洞卷积）

**膨胀卷积**（Dilated Convolution），也叫**空洞卷积**，对应的参数是**膨胀率**（dilation rate）。

先回顾感受野的概念：一个正常的 $3\times3$ 卷积，在前一层只能覆盖一个 $3\times3$ 的区域。老师的提问是——我能不能用一个 $3\times3$ 看到 $5\times5$ 呢？能不能看到 $7\times7$ 呢？而且我**只有这么多参数，没有多余的参数量**。

- dilation rate $=1$ 时，就是原本那么大，是普通的、不膨胀的卷积。
- dilation rate $=2$ 时，卷积核"膨胀"了：中间是空的，一下就展开了，但参数量还是这些（图里红色的区域是参数所在位置，参数量没变），$3\times3$ 膨胀成 $5\times5$。
- rate $=3$ 时炸得更开，$3\times3$ 膨胀成 $7\times7$；再膨胀就是 $9\times9$。

规律是 $3\times3 \rightarrow 5\times5 \rightarrow 7\times7 \rightarrow 9\times9$，这个数字应该要很敏感、能很快反应过来。

实际实现上有两种理解方式：

1. 给中间空出来的位置全部填 0：原来那个 $3\times3$ 的卷积核，看成变成了一个 $7\times7$ 的卷积核，只不过中间补的都是零（这是 dilation rate 为 3 时的说法）；
2. 用 index 的方式：直接告诉采样点"你不要在我旁边，你离我远一点"，把采样点的间隔拉开。

无论哪种理解，参数量都还是 9 个，但 cover 的感受野却是一个 $7\times7$ 的感受野，范围更大了。

> **老师比喻**：你看我这几个手指头就是它的参数量——正常情况下它们应该紧挨着放到这儿，我这样夹紧；那我张得大一点，是不是一样的？这就是利用了图像本身的一个特点。

为什么要这样做？因为图像的信息过于冗余。老师用两个例子说明：

1. 我这样卷积（采样点紧挨着）和我那样卷积（采样点拉开）出来的特征没有多大区别；
2. 大家平时肯定用过电脑上的图像 resize——上传时某些系统（比如学信网照片）要求必须在 10K 以下，你偏偏是 18K，那你肯定得**下采样**（downsample）。下采样干的也是这件事：把中间的一些像素给你扔掉，或者用插值的方式去解决。从一张很大的图变成那么小的一张，你还能认出它来——这就是图像的冗余性。

膨胀卷积恰恰也是利用了这种特性：相同的参数量，我膨胀一下，感受野更大、看到的范围更大，这是一种**采样**的概念——中间那些我不算了，"我猜你跟这两个差不多"，所以它的感受野也就更大。

> **老师提示**：用几层膨胀卷积之后，在相同的层数下可以迅速扩大感受野的范围；通过膨胀系数（dilation rate）来决定到底要膨胀多大。

### 12.6 膨胀卷积的时代背景与命名之争

老师专门介绍了膨胀卷积出现的背景，说它"有很明显的时代痕迹"：它是**由做分割（segmentation）的人提出来的**。

原因是：分割任务做的是**逐像素标注**，它的标注难度明显比分类（classification）要上升不知道多少个维度，所以标注量不够。标注量不够的话，早期怎么做呢？我先用在 ImageNet 上预训练好的一个网络（比如拿过来），再在分割的数据基础上去训练、去微调——放到现在这就叫**后训练**（post-training）。

但这样做有一个问题：

- 分类网络是一路把宽和高降成一个 $1\times1$ 的，它一路在快速地下采样；
- 分割网络跟它相反：我要输出一个跟原图一样大小的结果，所以要**上采样**（upsample）回去，里面的这些操作跟分类网络是相反的。可分割网络还想用分类网络预训练好的那批参数。

那怎么办呢？他们就发明了这种办法：我用了你的参数，但我还要能让我的网络上采样回去、并且保持相同的一个（比较大的）感受野。

最直观的做法是把几个下采样的操作去掉。原来下采样之后我一个像素"就是这么大"，我还是这个 $3\times3$ 的卷积核，那我直接在这一层上面处理不就行了吗？但你把下采样的操作去掉之后，我同一个卷积核作用在这一层上，我原本映射的那个感受野是这么大的，现在直接操作，我的感受野就变得很小了，跟原本网络训练的不一样。为了保持感受野的大小一致，同时我又不想下采样，他们就用"在更大的范围里采样"这种方式：采样到相同的感受野大小，用的还是原本的 parameter（参数没有变），同时保持了 $H$、$W$ 不要降维。

关于这篇工作的出处与命名，老师讲了这么一段（其中人名、年份请以原始文献核实）：

这是 ICCV 2015 的一篇 paper，由一位台湾的研究者（老师记得叫"陈永杰"，当时应该在美国的某个学校，具体学校老师说他忘了）提出来的。他当时提出来的名字是一个法语的词 **atrous convolution**。为什么后来又叫了 dilated convolution 呢？因为一年之后有另一个人提了一个叫 dilated convolution 的工作，几乎是原样照搬了他的 idea——那篇发在 2016 年，两篇的引用都很高，而且都是很 famous 的研究者。做 dilated convolution 的那个人是在 UC Berkeley 做的，当时定名的时候，写 Caffe 的贾扬清也在 UCB。最终这个被定名为 dilated convolution，中间还有一段插曲：后面那个 dilated convolution 的作者"出事了"，很多人为了跟他撇清关系，贾扬清还在网上发布了一段很长的澄清，说这个命名为 dilated convolution 跟这个人没关系。Anyway，最终定义的名字是 dilated convolution。

> **原文待核实**：老师提到提出者为"陈永杰"（约 01:58:20）、论文为"ICCV 2015"（约 01:58:01）、另一篇为"2016"（约 01:58:38），老师本人也说他忘了当时所在的学校，这几项人名、会议与年份需以原始文献核实。

> **老师提示**：大家也要知道它还有另一个词叫 atrous convolution，是一个法语词，来自 DeepLab 这篇论文。感兴趣的话可以搜一篇叫 DeepLab（DEPLAB）的论文，就是提出来这个 work 的那一篇。

### 12.7 转置卷积

**转置卷积**（Transposed Convolution）用于升维。前面讲的那些卷积都是维持 $H$、$W$ 不变、或者往下降的；但要做分割就必须要升维：把池化这些降维的操作去掉一部分（不能全去掉），去掉一部分之后我还要把维度升回去，这就需要升维的操作，也就是转置卷积——它做的是上采样。

例如 stride $=1$、padding $=0$、卷积核大小为 3 的时候，可以理解为它开启了一个很大的区域，然后这样扫回去，把一个 $2\times2$ 的输入产生成一个 $4\times4$ 的输出，正好是两倍的升维。也有 stride $=2$、padding 取 1 和 0 之类的其他组合，这些特殊的卷积在 PyTorch 里面也都能看到。

> **老师提示**：明白它的升维就行了，现在用得比较少。

### 12.8 可变形卷积

**可变形卷积**（Deformable Convolution）是更抽象的一种卷积。

标准的卷积是一个矩形的（大部分是正方形）感受野，你一直在这样做：一个点放到这里，$3\times3$ 是这样，再大也是这样——你扩展感受野一定是按矩形的方式扩展的。老师用"羊前小腿"举例：你的采样点落在羊的小腿上，以它自己为中心按矩形的方式往外扩，扩出来的范围却没有落在羊身上，而是按矩形扩到了旁边的草地上。

可变形卷积想的是：我不要以这种规范好的矩形概念去扩展，我要一种**语义**的扩展——谁跟我关系好，我就去发展谁。

> **老师比喻**：就像你们坐在这个位置上，每次是自己前后左右一步一步去扩展；而它这个是"你跟我有某种关系"——比如说我们是同一个班的、我们是同一个寝室的。

它还是相同的参数量，但做完这一层的卷积之后，采样点相比标准卷积更多地分布在羊的身上。

它是怎么做的呢？正常的卷积就是一个 $3\times3$ 的区域，每次去做就行了；可变形卷积在这里加了一个东西：它告诉这九个点，"你们不要太老实了，你们自己应该想办法挪一下"，去额外学一个**偏移量**（offset），也就是学一下你要往哪里挪动，不要在原本的位置上采样。所以它不是固定位置去做卷积，而是给卷积本身设了一个可以移动、可以跑一定程度的量。你先根据前层的特征，让原本 $3\times3$ 的那九个点各自决定自己往哪里跑，算完之后下一层采样的时候，再按你"想跑到的位置"去做卷积。最终想要达到的效果就是：我这个点落在羊的身上，我就应该全部把这些采样点放到羊的身上，而不是草地上什么都要去采集。

可变形卷积也没有那么常用：可以在某一些层用，但不能完全替代标准卷积。因为它比较复杂——你想额外学一个"我要往哪里走"的偏移量，增加了参数量的学习，训练难度也会陡增。而且提升了精度还不一定划算：

> **老师提示**：假设你用这种办法提升出精度来了——我用 3 个小时训练出来了 90%，你用 30 个小时训练出来了 91%，这就不一定值得了。

> **老师总结**：之所以给大家介绍可变形卷积，是要让大家知道这种思想——你的卷积核这九个点未必要老老实实地待在这里，你可以让它跑到附近的位置上去。

以上差不多就是比较常见的一些卷积上的操作了。

### 12.9 本讲卷积变体汇总

| 卷积类型 | 关键思想 | 对 $H$、$W$ 的影响 | 课堂备注 |
|---|---|---|---|
| 标准卷积（standard convolution） | 固定位置的 element-wise 相乘再相加 | 不变或下降（由 stride、padding 决定） | 最基本的形式，$3\times3$ 为课堂默认例子 |
| 深度卷积（depthwise convolution） | 每个卷积核只有一个通道，只与对应通道计算 | 不变 | 卷积核个数＝输出通道数 |
| 逐点卷积（pointwise convolution） | 用 $1\times1$ 卷积做通道间的组合 | 不变 | 与深度卷积组合实现轻量化 |
| 分组卷积（group convolution） | 把 channel 分组，各组独立卷积 | 不变 | `groups` 必须整除通道数 |
| 膨胀卷积／空洞卷积（dilated convolution） | 核中间插空、膨胀率把采样点撑开 | 维持 $H$、$W$ 不降维，同时保持较大感受野 | 由做分割的人提出，originally 为复用预训练参数 |
| 转置卷积（transposed convolution） | 反向的升维方式，开启一个大区域再扫回去 | 上采样、升维（如 $2\times2 \to 4\times4$） | 现在用得比较少 |
| 可变形卷积（deformable convolution） | 给采样点学一个偏移量，按语义关联挪动采样位置 | 采样点位置可变，参数量不变 | 更抽象、不常用，训练难度陡增 |

## 十三、`nn.Conv2d` 参数逐项讲解 [02:05:14–02:11:22]

这一页是 PyTorch 里 `nn.Conv2d` 的截图，老师讲的这些概念基本上在这里都有，每一个参数都讲到了。有电脑的同学可以同步打开，在 python 里装好 torch 之后，第一步 `import torch`（也可以 `import torch as ...`），然后就是 `torch.nn.Conv2d`。

老师的要求是：对 `nn.Conv2d` 的熟悉程度应该达到"你知道第一个参数、第二个参数、第三个参数分别是什么"这样的程度。

| 参数 | 含义 | 是否必须设置 |
|------|------|--------------|
| `in_channels` | 输入特征图的通道数，input 是多少它就是多少 | **必须给定** |
| `out_channels` | 想要输出的通道数，自己设计 | **必须给定** |
| `kernel_size` | 卷积核的大小 | **必须给定** |
| `stride` | 滑动的步长 | 可默认 |
| `padding` | 填充 | 可默认（默认 0） |
| `dilation` | 膨胀率 | 可默认 |
| `groups` | 分组数 | 可默认（默认 1） |
| `bias` | 是否加偏置，默认 `True` | 可默认 |
| `padding_mode` | 填充方式，默认 `'zeros'` | 可默认 |
| `device` / `dtype` | 用哪块 GPU、用哪种数据类型 | 可默认 |

逐个说明：

- **`in_channels`**：我 input 的 feature 的 channel 是多少——是 3、是 5、是 512，你要告诉我。`in_channels` 是**必须给定的**，input 是多少它就是多少，不设一定是不行的。
- **`out_channels`**：你想要输出的是多少。`out_channels` 是**你自己设计的**——你想让它是一就是一，你想让它是一万就是一万，你想让它是一亿也行，你有这么大的 GPU 设多少都行。
- **`kernel_size`**：你那个卷积核的 kernel 有多大。我们刚才都是以 $3\times3$ 为例，这里只给了一个值；如果你就喜欢矩形的，比如 $2\times3$ 的，你也可以去设。如果默认只给它一个值，它就认为你是个正方形的 $3\times3$ 卷积。
- **`stride`**：你的滑动步长是多少。
- **`padding`**：你要 padding 多少，例如 `padding=0`。
- **`dilation`**：刚才那个膨胀卷积，`dilation=1` 的时候就是一个正常的不膨胀的卷积，`dilation=2` 时它膨胀一倍，$3\times3$ 膨胀成 $5\times5$，中间你可以认为差个零。

> **老师强调**：接下来的这几个参数（`dilation`、`groups`、`bias`、`padding_mode`）我面试的时候最喜欢问。因为大部分人都知道前面的 `in_channels`、`out_channels`、`stride`，但你问他 `groups` 是什么他就不知道了。我们上完这节课一定要知道这个关系。

- **`groups`**：`groups=1` 的时候就是正常的、最标准的卷积；想要达到分组的效果，比如把 10 个通道分成两组，就把 `groups` 设成 2，它自己会算每 5 个 channel 是一个 group；如果设成 `groups=5`，就是两个 channel 一个 group。要求是这个 group 一定要能够整除 channel 的个数，否则会报错。
- **`bias`**：一般设成 `True`，就是最后那个偏置。你给它设成 `True`，它就会在最后加一个数字（加上 bias）；如果你给它设成 `False`，那就只做卷积，不加你那个 bias，后面加的那一项直接就没了。加不加这个影响不大。
- **`padding_mode`**：就是你用哪种方式去填充。默认就是 `zeros`，也就是补零的方式；当然你也可以给它设置成镜像、复制等，你可以设，但**一般不会去改**。
- **`device` 与 `dtype`**：一个是你去选用的 GPU，一个是你去选用的数据类型（比如是 float 还是 int 型），选这些用的。

> **老师总结**：`nn.Conv2d` 所有的参数我们这节课其实都涉及到了——其实一整节课就在讲这一个函数。

课下要自己去 doc 里面看它这个公式，看这些是怎么算的；包括下面没有截图到的部分，比如 `stride`、`out size`、`input size`、`kernel size` 之间的关系公式，它下面都有的，你自己也可以去看。

> **老师总结**：`nn.Conv2d` 一般我们就设 `in_channels`、`out_channels`、`kernel_size` 这几个，这是必须要设的，不设的话一定是不行的；其他的可以让它去默认。这就是卷积。

## 十四、池化层 [02:11:22–02:16:36]

### 14.1 池化的作用：降维与降采样

**定义**：**池化**（pooling）就是一个降维的操作。把一个比如 $4\times4$ 的特征图池化成 $2\times2$，这种操作就叫池化，它一般是为了降采样（down-sampling）。

为什么需要降采样？因为原本图像那么大，直接拿去算很浪费算力。老师算了一笔账：如果把一张图降采样一倍，从 1024 变成 512，其实也看不出来什么差距，那就降采样一下，计算量就少了很多。池化带来的好处有：

- 平移不变性（translation invariance）；
- 提升性能；
- 防止过拟合；
- 降低计算复杂度。

**演示**：老师展示了可视化的结果：有 $24\times24\times64$ 的一个特征图，池化完之后变成 $12\times12\times64$。

> **老师强调**：注意这个 64 是 channel——池化不对 channel 做改变，只是对 $H$、$W$ 做改变。

从 24 的尺寸缩到这样，你觉得差别大吗？其实也不大，但是它可以极大地降低计算量。这正是第一节课开头那张图里看到的网络形态：特征图每次降采样、一路降采样下去。

### 14.2 池化的流程

池化的流程和卷积是一致的，只是中间那一步换了：

1. 滑动窗口（sliding window）；
2. 原来是 element-wise multiplication（逐元素相乘），这里变成了 max pooling 或 average pooling；
3. 重复（repeat）。

因为池化也不需要加偏置，所以取完之后直接得到结果就行了。

### 14.3 数值演示：max pooling 与 average pooling

**演示**：老师用一个 $2\times2$、stride 等于 2 的窗口在一个 $4\times4$ 的输入上做池化。Max pooling 顾名思义就是取最大值：窗口划到第一个位置取最大值，等于 1；到下一个位置、第三个位置、第四个位置，最大值等于 2，于是得到 4 个输出。Average pooling 则是算均值，四个数加起来除以 4。两种池化的结果对照如下（第一个窗口的四个数录音中明确给了 0、1、1、0）：

| 窗口位置 | max pooling 输出 | average pooling 输出 | 说明 |
|---|---|---|---|
| 第 1 个位置 | 1 | $(0+1+1+0)/4=0.5$ | 窗口内四个数是 0、1、1、0 |
| 第 2 个位置 | — | 1.25 | 四个数之和除以 4 |
| 第 3 个位置 | — | 1.25 | 四个数之和除以 4 |
| 第 4 个位置 | 2 | 1.5 | 四个数之和除以 4 |

**命题**：`stride` 一般都等于 2。

> **老师强调**：一般 pooling 不会说是 stride 等于 1，因为 stride 等于 1 没有意义——我就是为了降采样来的，然后你 stride 给我设成等于 1，你还配个 padding 让它保持不变，没有意义。所以 stride 一般等于 2，你也可以让它等于 4，但一般等于 2。

### 14.4 例题：2×2 max pooling 的计算

**例题**：给定一个输入，用一个 $2\times2$ 的 max pooling、stride 等于 2，请同学作答。

**题目**：给定一个输入特征图（一个 $4\times4$ 的矩阵），要求用 $2\times2$ 的 max pooling、stride 等于 2，算出池化后的输出。

（**原文待核实**：题面矩阵的具体数值在录音中没有被逐一念出，老师直接请同学口算并报答案，这里只能依据同学报出的答案与老师的确认还原题意，不补造题面数字。）

**解答**：$2\times2$、stride 等于 2 会把输入切成 4 个互不重叠的 $2\times2$ 窗口（按行优先依次编号为左上、右上、左下、右下），每个窗口取最大值：

- 左上窗口取最大值 → 4；
- 右上窗口取最大值 → 8；
- 左下窗口取最大值 → 9；
- 右下窗口取最大值 → 3。

**结果与点评**：同学的答案是 4、8、9、3，老师确认"对，最大值"。老师点评说这道题因为他给的数据设得相当简单，所以"秒算"就能算出来。

### 14.5 PyTorch 中的池化实现

`torch.nn` 里对应的是 `nn.MaxPool2d` 和 `nn.AvgPool2d`。

> **老师提示**：注意它后面都加了一个 2D 的操作，因为它也有 1D 的、也有一维的，还有 3D 的。

它里面的参数也是 kernel 那一套：`kernel_size` 是有的，但 **input channel 跟 output channel 被省略了**——因为池化不管你输入的特征图通道到底是多少，反正都是统一操作，所以它直接只定义了 `kernel_size`。

除此之外，它也有人定义了 `padding` 跟 `dilation`。为什么要留这些参数呢？

> **老师提示**：你说不定某个 researcher 他有一些非常奇特的想法——我就想要让它 padding 完了之后再进行一个采样；或者我就不想降采样，我就想池化给它平滑一下，这样也可以。

## 十五、归一化层 [02:16:36–02:26:37]

### 15.1 动机：数据分布多样与 mini-batch 的极端情况

除了卷积和池化之外，还有一个重要的是 **批归一化**（Batch Normalization, BN）这一层，或者叫做归一化（normalization）——因为归一化有好几种。老师强调这个也要会：因为这个自从提出来之后，基本上现在的无论是卷积神经网络还是别的什么 Transformer，一定会有 normalization，一定都会用。

为什么要加这个？我们采集的数据，它的分布是非常多样的（diverse）。我们是不可能一次性把所有数据都塞进去的，没有那么大的算力：比如我有 100 万张，我不可能一次都塞进去，所以我是比如说十张（一个 batch）塞进去。

一批一批塞进去的时候，就会存在分布不均匀的问题：比如这一个 batch 进来的全是黑图、图全是黑色的，然后下一个 batch 进来它全是白色的，它就会产生两个极端——一个输入全是 255，另一个输入全是 0。你算完之后，它的 feature 的分布就是两个极端，分布差别特别大，那就会导致网络训练的时候很震荡：一会被拉到这个方向，一会被拉到那个方向。

**定义**：归一化在做的就是——无论你 input 的是一个什么范围的值，我把你归一化（normalize）到一个高斯分布上去：均值（mean）为 0、方差（variance）为 1。

这样的话，我的卷积每次做卷积的时候，我的 input feature 都是一个高斯分布的值；它们之间肯定有差异，但差异不会极端到从 255 到 0 这么大的差异。

> **老师总结**：这就是 normalization 当时提出来的一个想法。

### 15.2 公式与步骤

这个公式大家也要熟。它主要是针对 mini-batch 的，因为背景就是一批一小批一小批地送进来的，所以它一定是针对这种 mini-batch 的：mini-batch 来了之后，它要完成的是把数据映射到一个均值为 0、方差为 1 的高斯分布上。

**推导**：具体做法分三步。首先算均值：

$$
\mu=\dfrac{1}{m}\sum_{i=1}^{m}x_i
$$

均值算完之后再算方差：

$$
\sigma^{2}=\dfrac{1}{m}\sum_{i=1}^{m}(x_i-\mu)^{2}
$$

方差算完之后，减均值、除以标准差，就把它归一化了：

$$
\hat{x}=\dfrac{x-\mu}{\sqrt{\sigma^{2}+\epsilon}}
$$

最后再乘 $\gamma$、加 $\beta$：

$$
y=\gamma\hat{x}+\beta
$$

**定义**：式中 $\epsilon$（epsilon）的作用是防止除零。

> **老师强调**：这个程序员一定要对这个熟——你分母上任何时候都要想一下你的分母会不会是零，一定要把这个加上。

### 15.3 scale 与 shift：可学习的 $\gamma$ 和 $\beta$

**定义**：归一化之后又加了两个操作，scale（缩放）和 shift（平移）。

这是干什么呢？虽然我给你归一化了，但我也不知道你这个网络到底喜不喜欢这种归一化。

> **老师比喻**：我还是比较好商量的一个人。我给你一个一定的这种尺度，你去自己调整一下是不是。

所以我给你的这个归一化后面，乘了一个 $\gamma$、加了一个 $\beta$——那你相当于把这个又给他传过去了；最极端的，把前面减掉的又给它加回去了，如果你不愿意的话，你可以恢复原样；那你觉得这样 OK、只是想适当微调一下，那你自己去适当微调、你自己去学。

> **老师强调**：伽马和贝塔起这样的一个作用，大家一定要记住——归一化之后、normalize 之后，它会有一个乘伽马加贝塔的操作。伽马和贝塔前面那一项都没有可学习的参数，这都是实打实的 feature 算出来的；到这儿之后，伽马和贝塔自己是可学习参数（learned parameter），它是要根据网络梯度回传去学出来、去更新的。

所以 Batch Normalization 这一层里面也是有需要学习的 parameter 的，就是 $\gamma$ 和 $\beta$。

### 15.4 归一化带来的好处

乘 $\gamma$、加 $\beta$ 这套设计的收益是：

- 改善梯度回传；
- 允许使用更高的学习率；
- 减少对初始化的强依赖；
- 有正则化作用，也减少了 dropout 的一种需求。

关于最后一点，老师解释：之前的时候我们训练为什么那么小心？因为你不知道哪个 batch 它会出现一种特别极端的情况，一下子把网络训偏了。

> **老师总结**：那现在有 normalization 之后，你都已经分布差不多了、没有极端情况，那我就安全了。所以它在学习的加速上非常重要，基本上现在网络都会用、一定会用。

### 15.5 几种归一化的区别：在哪些维度上统计

老师用一个 4D tensor 来讲几种不同的 normalization。这里要注意：这是一个 4D 的 tensor，但 4D tensor 画不出来，所以用 3D 给大家表示。表示方式是压缩维度：把 $H$、$W$ 压到一个维度上去，所以 $HW$ 是一个维度，channel 是一个维度，$N$ 是 batch——这样整体是一个 $N\times C\times H\times W$ 的 4D tensor，可视化出来是一个 3D 的块。

**演示**：Batch Normalization 是在 batch 和 $H$、$W$ 这两个维度上去做的。你看它做完之后，所有有颜色的（蓝色）区域都参与了均值和方差的计算；均值算完之后，这些都被算了均值了，那是不是只剩一个数字了？所以它整个算完之后，只剩每个 channel 算一个均值、每个 channel 一个方差——最终的均值、方差的 shape 是 $C$，也就是 $1\times C\times1\times1$。

> **老师强调**：所以大家知道，这个 normalization 虽然叫 Batch Normalization，下次有人问你 Batch Normalization 在哪个 dimension 上做 normalization，你千万不要只说在 batch 上。你要分情况：如果是一个正常的 language 那种的，你就在 batch；但如果是一个图像的 CV，它一定是在 $HW$ 和 batch 上。

也就是说，如果我的 4D tensor 是 $N\times C\times H\times W$ 这样一个 shape，那它 normalize 之后统计量的 shape 是一个 $1\times C\times1\times1$，因为我在 $H$、$W$ 上也要做 normalize。

**演示**：还有 Transformer 常用的 **层归一化**（Layer Normalization, LN）。它在 $C$、$H$、$W$ 这个维度上做归一化。它为什么没有在 batch 上做呢？有两个原因：

1. 图像都很规整：我是 $512\times512$，我都可以是这么多，我给你摞一块儿，大家都规规矩矩、四四方方的。但是句子它有长有短，有特别长的句子、特别短的句子，你给它一个 batch 一个 batch 送进去，它长短不一，是不是不好处理？简单的做法也可以给它 padding 补 0：比如有个句子有两个单词，有个句子有 1 万个单词，那你要给它 padding 9998 个零上去，把它俩拉得一样长，它才是同一个 batch。这种归一化其实是有问题的。
2. Transformer 那篇论文（老师说是 NeurIPS 2017 的那篇，**原文待核实**）是做了实验的，Layer Normalization 的效果更好，所以他们选了 Layer Normalization。

> **老师总结**：大家要知道，CNN 里面基本上用的是 Batch Normalization，Transformer 里面用的是 Layer Normalization。

> **老师强调**：而且这个 normalization 大家要记清、要分清它和 softmax 的区别。因为我发现我历次在问别人的时候，他们经常把这个 softmax 跟这个归一化搞混——我问他 Transformer 里面用的哪种 normalization，他跟我说 softmax，这个就错得很离谱了。

这种归一化是为了实现数据特征的数据规划（分布规范）。

**演示**：当然还有一些其他的，比如 **实例归一化**（Instance Normalization, IN），它是在这里去做，你可以认为它是每张图、每张图地选一下。

> **老师总结**：大家要知道有这几种 normalization，至少要记住 Batch Normalization 和 Layer Normalization 这两种。它们的区别在于它是在不同的维度、不同的 dimension 上做 normalization 的。对于一张图像、对于 vision 而言，Batch Normalization 是在 $HW$ 和 batch 这个维度上去做，Layer Normalization 是在 $HW$ 和 channel 上去做。

## 十八、卷积神经网络发展史 [02:28:36–02:36:56]

### 18.1 先回顾视觉的四个经典任务

在讲卷积神经网络的发展之前，老师先回顾了早些年视觉里最早关注的几个经典任务，因为它们经常被混在一起，需要分清：

- **图像分类**（image classification）：告诉我这张图里有什么就行了，至于它们在哪，"I don't care"。
- **目标检测**（object detection，也叫 object localization）：它就是 what and where——你告诉我它具体在哪里就行了，给我画个框。至于哪个像素是它、哪个像素不是它，我不要那么精准，大概能够框住这个意思就行了。
- **语义分割**（semantic segmentation）：你可以认为是 pixel-wise 的分类，逐像素分类。
- **实例分割**（instance segmentation）：跟语义分割是有区别的。你看同样一个"羊"（原文用"QB"指代这个物体），在 semantic segmentation 里面它俩是不区分的——我不管你俩到底在哪里区分，反正是我就知道这个像素是这个物体就行了，其他的不管了；而在 instance segmentation 里面不一样，它要求知道我是"羊 1"还是"羊 2"，这两个是不同的 instance、不同的 object，要区分出来。

> **老师强调**：这几种——图像分类、目标检测、图像语义分割、图像实例分割，大家也要能分清这几个任务。

### 18.2 早期的玩法：CIFAR-10 与 CPU

图像分类早期很多是用 **CIFAR-10** 这个数据集，大家如果自己想玩，在自己的电脑上拿 CPU 去玩就行，就拿这种 CIFAR-10 去玩：训练很快，自己也很快能看到一个结果，测试也比较快，因为它的图很小很小。

### 18.3 从 LeNet 到 AlexNet 再到深层网络

早期的时候，你像这种卷积神经网络，早期的 **LeNet**（老师口述为"the net"）是用来做手写数字体识别的。

有了 dropout 和 ReLU 之后，就有了 **AlexNet** 在 2012 年夺冠，它是一个比较重要的时刻——CNN 在 2012 年就开始了爆发式的增长。

后来大家开始给它增加各种各样的功能：

- **网络加深**：**VGG**（老师口述为"微基金"）加深到了 19 层；**ResNet** 加深得更多。
- **增加卷积功能的**：Network in Network（简写 NiN）、**GoogLeNet** 以及 Inception 的 V1、V2、V3（后面老师会简单介绍）。
- **ResNet** 最重要的就是加了一个 skip，即 skip connection（跳跃连接）。它是从这里点一下之后再到那里，在这加一个 shortcut。
- 后来有人说，你这加的不够、连的不多，我应该认为前面所有的都得连上，那就出现了 **DenseNet**（老师口述为"更 set"）。

> **老师提示**：Network in Network、GoogLeNet / Inception 这些后面会简单介绍一下。

关于竞赛成绩：AlexNet 在 2012 年夺得冠军；后面 2015 年 ResNet 夺冠，超越了人类的一个识别的准确率（**原文待核实**：老师口述为"15 年 ResNet 夺冠、超越了人类识别准确率"）。

### 18.4 ImageNet 数据集的作用

在这条发展线里，ImageNet 其实起到了非常大的作用，因为它有图像训练集、验证集、测试集。它的训练集真的是相当的大，有 128 万张图——在那个年代是纯人工手工标出来的，非常的不容易。老师对比说，咱现在去标就简单多了：让大模型辅助，第一轮辅助标注，然后第二轮人筛查，就会快很多。

### 18.5 早期网络有多简单

你像经典的 LeNet，它早期的时候多简单——我们今天这节课用到的这些工具，它都没用上。它就是一个最基本的网络，像 Batch Normalization、ReLU 这些它都没用上。

**例子**：老师把 LeNet 的结构念了一遍：就是 6 个 $5\times5$ 的 filter（老师口述为"5 乘 1 乘以 6"，**原文待核实**，这里按 LeNet 惯常结构记为 6 个 $5\times5$ 的卷积核），接 $2\times2$ 的池化，得到 $5\times5\times6$（**原文待核实**），再来 $2\times2$ 的池化，再加一个 5×16，完了就没了，就这么简单。

> **老师提示**：像这样的一个网络，我相信大家一会儿就写出来了，下课可能随便顺手就写出来了，很简单。但是在当年，他们能把这个东西逐个地去试出来、能把这个 A 识别出来，就是一个很大的进步。

到现在过去也就不到 40 年时间，其实发展是真的是非常快的。

### 18.6 人物与图灵奖

这几位（几位深度学习的先驱）大家应该也都很熟悉，他们其实对于卷积神经网络的推动是非常大的，尤其是 Hinton（老师口述为"一个乐观"，**原文待核实**）——当然果子后来被这个新盾给摘了（此处指 AlexNet 的工作，**原文待核实**）。AlexNet 是他们提出来的。LeCun 杨立昆（老师口述为"乐坤"）现在在主推他的世界模型 **JEPA**（老师口述为"街派对"，**原文待核实**），大家感兴趣的话可以去了解一下。这几个人也在 2018 年获得了图灵奖，就是因为他们在这个 deep neural network 里面做的贡献——其实最重要的就是这个卷积神经网络。

### 18.7 AlexNet 的贡献

**演示**：再看 AlexNet。AlexNet 比 LeNet 复杂了一些，但去看它也没有多复杂：也就是 input 之后一个 conv、一个 max pooling、一个 norm，接着又一个 conv、一个 max pooling、一个 norm……我们这节课学的东西它其实已经开始用上了。

- **卷积与归一化的固定搭配**：Convolution 加 normalization 一般是固定出现的，现在是基本上不会分开的。
- **分组卷积的雏形**：**分组卷积**（group convolution）最早的这种概念，你可以认为在 AlexNet 里面已经出现了这种思想——当然他们当时没有正式提出这个东西。因为**显存**（GPU 内存）塞不下的时候，他放了两个 GPU，这两个 GPU 是不是单独的？你可以认为他把 channel 分成了两组：这组去 GPU 1 号，这组去 GPU 2 号，你们先算，算完之后咱们再交流。这就是 group convolution 的一种思想，只是说他当年并没有明确地把它提出来。
- **Dropout**：AlexNet 里面最重要的思想或者概念是提出了 **dropout**（老师口述为"job""交报"）。dropout 里面就是随机地丢弃一些神经元，每次丢弃一些 neuron，每次都是随机的，每次丢弃的哪一个都不一样，都是有差别的。通过这种方式，它提升了一个泛化性。当然我们现在后来有 Batch Normalization 之后，一般也不用 dropout 去做这个事情了。

### 20.2 为什么三通道卷积的结果要相加

> **学生提问**：对一个图像做一个卷积操作，它的通道有三个，卷积核的尺寸跟它对齐。为什么最后卷积完的结果是要相加呢？按理来说我们特征应该是一个单独的特征维度，你这就成了（一个通道），它为什么要相加呢？

老师回答：你可以把它理解为出现了三个特征（三张特征图），还是三个特征——按理来说特征应该是做一个单独的特征的维度。是因为，怎么讲，你这个位置、我要看的这片区域：你单独的一个卷积核上的这一个值不能代表（整体），你是有一系列，我要知道你的全部信息。

> **老师比喻**：你就像我要知道这个学生，你不能总是告诉我他是个男生，你让我去算——我得知道他所有的这些信息，我才能够做计算。

所以它要把所有的做完之后做一个相加，这样的话才知道他所有的信息；但如果我只知道单个的话，就没法去理解它的整体的一个特征。
