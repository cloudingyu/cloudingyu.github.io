## 一、从程序到图灵机：邱奇-图灵论题与 RISC-V 指令集 [00:02:42–00:18:06]

<!-- 时间范围：00:02:42–00:18:06 -->

计算无处不在，而人们常常忽视计算背后的那套理论。上一节课我们定义了计算模型，也就是用数学的方式给“计算机”下了一个定义——或者说是柏拉图式的计算机，就是**图灵机**（Turing machine, TM）。上上节课则定义了图灵机的一些变种，课上点到的有：单带图灵机、多带图灵机、指针（读写头）允不允许停留，以及支持随机读写、带内存的图灵机（也就是 RAM 图灵机，random access machine Turing machine）。

其实图灵机的变种还有很多很多，大家也完全可以自己去定义。老师举了两个例子：可以定义一种带缓存的图灵机；也可以让一条纸带上装两个头、三个头，而且这几个头都可以独立移动。这些变种看起来差别很大，但也是不难论证的——无论你怎么定义，最后它的计算能力都是等价的。

> **老师强调**：无论你怎么定义，最后它的计算能力都是等价的；那不仅仅等价，而且它只相差一个多项式。

这节课我们先讨论**邱奇-图灵论题**（Church–Turing thesis）。

老师特别说明，它不是一个 conjecture，不是一个数学的猜想。理由是：它本身不是关于数学的，因此不是数学上的一个命题；它是和哲学、和物理有关的，所以它叫 thesis（论题）。

> **老师强调**：它不是一个数学的猜想——因为它不是关于数学的，它不是数学上的一个命题；它是和哲学、和物理有关的，所以它叫 thesis。

> **老师提示**：理解这条论题的身份时，要抓住的一点是：叫它 thesis 而不是 theorem 或 conjecture，正是因为它的内容落在数学之外——它牵涉到哲学与物理。

接下来老师带我们看：怎么把我们写的程序和图灵机联系起来。具体来说，就是怎么把一段 C 语言程序、一段 Python 程序转换成图灵机。路线是分两步走的：

1. 先把这段程序转换成汇编语言；
2. 再把汇编对应到图灵机上去。

关于第一步，老师明确划了课程边界：高级语言怎么转换成汇编，这门课不讨论，那是编译原理课讲的内容——编译原理讲的是怎么把一段 Python 程序、怎么把一段 C 程序编译成汇编。这门课现在要看的是第二步：怎么把汇编编译成一个图灵机。

选哪一个指令集来做这件事呢？先用 x86 作对照：x86 是用的比较多的一种，但它的指令有上千条，逐条验证不现实，所以就换一个选。老师选的是 **RISC-V**（字幕 ASR 写作“risk five”）。

选 RISC-V 的理由有三条：它是一个实用的指令集，有一些处理器真的就是用这个的；它相对来说指令集少一点，只有大约 40 条指令。指令少，验证工作就落在“逐条检查”上：我们只要逐条检查，每一条指令都可以被 RAM 图灵机在 $O(1)$ 的时间内实现就可以了。

| 指令集 | 老师给出的取舍理由 |
|--------|--------------------|
| x86 | 用的比较多，但指令上千条，不适合逐条验证 |
| RISC-V | 实用的指令集，有处理器在实际使用；指令集少，只有约 40 条指令 |

那么 RISC-V 是一个什么样的指令集呢？

**定义**：RISC-V 有 32 个寄存器，编号从 `x0` 到 `x31`；每个寄存器的位宽是 32 位。其中 `x0` 是一个常数寄存器，它的值全是 0，并且不可以被修改。此外还有一个 **程序计数器**（program counter, PC），它指向下一条指令。

老师还交代了内存方面的约定：内存地址是 32 位，所以最多就是 4 G（$2^{32}$ 字节）。

| 项目 | 课堂给出的内容 |
|------|----------------|
| 寄存器个数 | 32 个，编号 `x0`–`x31` |
| 寄存器位宽 | 每个 32 位 |
| `x0` | 常数寄存器，值全是 0，不可以被修改 |
| 程序计数器 PC | 指向下一条指令 |
| 内存地址宽度 | 32 位，因此最多 4 G |

指令方面，老师强调了一条重要的分工：只有内存操作才有 load 和 store。load 就是把内存的内容 load 到寄存器上，store 就是把寄存器的内容存到内存里面。除此之外，那些会碰到内存之外的算术指令、逻辑指令，都是在寄存器之间执行的——比如说你可以把 `x3` 加上 `x5`，然后加到 `x6` 上，就是这一类算术和逻辑指令。

还有一条关于指令集结构的说明：基础指令集里面是没有乘法和除法的。因为 RISC-V 有基础指令集，还有衍生指令集，而乘法和除法就是用基础指令集上定义的一个衍生指令集。

老师随后指着板书确认：这个指令集的样子就是这样的，32 个寄存器。

接着老师给了一段具体的 C 语言代码，说明它会被编译成怎样一段汇编指令。

**例题**：

**题目**：这段 C 源代码做的事情是：当 `N` 不等于 0 的时候，`sum` 等于 `sum` 加上指针 `P` 所指向地址上的值（也就是数组元素）；然后 `P++`，`P` 是一个指针，所以 `P++` 等于地址加 4；再对 `N` 做自减。这里 `N` 是数组的长度。用老师的话说，简单地讲，这段程序就是对数组求和。

**解答**：老师把这段代码逐行对照成汇编指令，并逐条说明每条指令在做什么。课堂上明确点到的寄存器分配是：`x5` 存放累加和（sum），`x6` 存放从内存取出的数组元素，`x10` 是指针 `P`，`x11` 存放 `N`。

第一步，第一条汇编指令是 `addi x5, x0, 0`。老师解释，这里的 `i` 表示立即数（immediate），所以这条指令就是 `x5` 等于 `x0` 加 0；而 `x0` 就是 0，所以 `x5` 等于 0。这一行做完，`x5` 就是那个累加和。

第二步是循环条件的判断，用 `beq` 实现：如果 `x11` 等于 0 就跳转出去。因为 `x0` 就是 0，所以这条指令的条件实际上就是“`x11` 是否等于零”，而 `x11` 存的就是 `N`——也就是说，当 `N` 等于 0 的时候就结束循环。

第三步，`lw x6, ...`。老师说明 `lw` 就是 load，就是从内存里读；这里用 `x10` 作为指针，把指针指向的那个内存地址上的内容 load 到寄存器 `x6` 上，而 `x6` 就是那个数组元素。

第四步是 `add x5, x5, x6`：这条指令做求和，`x5` 就是 `sum`，也就是 `sum` 等于 `sum` 加上当前指针指向的那个值。

第五步处理指针：`x10` 是那个指针，这条指令让指针等于指针加 4。老师给了理由——在这个指令集里面一个 `int` 是四个字节，所以指针后移一个元素就是地址加 4。这一行就对应源码里的 `P++`。

第六步是 `addi x11, x11, -1`：`x11` 是 `N`，所以这就是 `N` 等于 `N` 减 1。

第七步是跳回循环开头，指令写作 `jal x0, loop`。老师说这是无条件跳转：如果等于零的话就跳转，而它比较的寄存器是 `x0`，因为 `x0` 永远等于 0，所以这条跳转永远成立，成了无条件跳转，直接跳回循环标号处。

把这段演算整理成一条一条的对照关系，就是下面这张表。

| 步骤 | 汇编指令 | 作用 | 对应源码 |
|------|----------|------|----------|
| 1 | `addi x5, x0, 0` | `x5 = x0 + 0`；`x0` 就是 0，所以 `x5 = 0` | `sum = 0`（初始化累加和） |
| 2 | `beq x11, x0, <循环外>` | `x11` 等于 0 就跳出循环 | `while (N != 0)` 的条件判断 |
| 3 | `lw x6, 0(x10)` | `lw` 是 load，把指针 `x10` 指向的内存内容读到 `x6` | 取数组元素 `*P` |
| 4 | `add x5, x5, x6` | `x5 = x5 + x6` | `sum = sum + *P` |
| 5 | 指针加 4 | `x10` 是指针，一个 `int` 四个字节 | `P++` |
| 6 | `addi x11, x11, -1` | `x11` 是 `N`，即 `N = N - 1` | `N--` |
| 7 | `jal x0, loop` | 比较 `x0`，而 `x0` 永远等于 0，所以是无条件跳转，跳回循环标号 | 回到 `while` 的判断处 |

**结果与点评**：老师总结，这段汇编指令就是把上面那行数组求和翻译过去了。

随后老师把话头收回到本节的验证目标：我们现在要检查的就是，每一条汇编指令都可以被 RAM 图灵机在 $O(1)$ 的时间内实现。

这里出现了一个自然的追问：程序可不可以修改自己呢？

老师的回答是：现在是不允许的。大家写一个 C 程序、写一个 Python 程序，编译完了之后就放在内存里，代码不可以自己修改自己。

那么为什么会有程序计数器这件事？老师解释，因为现在用的都是冯·诺依曼的存储程序架构，也就是这段程序本身是存在内存里的——程序也存在内存里，所以 PC 指向的就是程序执行时下一行的那条指令的内存地址。

对图灵机来说就不需要考虑这个问题了，理由是：图灵机的程序是写死的。老师顺势点出两者最关键的对应关系——图灵机的每一行程序就是一个状态。

> **老师总结**：图灵机的程序是写死的——图灵机的每一行程序就是一个状态。

那我们怎么用一个 RAM 图灵机去模拟 RISC-V 呢？老师说不难，其实挺直接的。依据是字长：字长是 32，是一个常数。

**算法**：模拟方案按下面的方式组织存储：

1. RISC-V 一共只有 32 个寄存器，那我们就用 32 条纸带；
2. 多带图灵机可以用任意多条带子，而这些带子的长度还是无限的；
3. 每条纸带我们实际只用其中的 32 位就可以了；
4. 内存则放在另外那条内存纸带里面。

有了上面的存储组织，我们就把指令分成几类，逐类检查每一条指令都能被 RAM 图灵机在 $O(1)$ 时间内模拟。

第一类是立即数指令：把一个数——也就是一个常数——装到寄存器里面。这个可以想象：因为寄存器的长度就是 32，把常数写进去只要 32 步就可以了，所以这一类是 RAM 图灵机在 $O(1)$ 时间内就可以做的。

第二类是寄存器和立即数之间的操作：比如用一个寄存器加上一个立即数，把结果放到另外一个寄存器里面，也就是用一个常数和一个寄存器相加。这个也是可以做的：我们不是写过那个加法吗；如果是多带图灵机还会更高效一点，那个是线性时间的加法。$O(32)$ 就是 $O(1)$，所以这一类也是 $O(1)$ 时间就可以做。这一类里包含加法，也包含按位或、按位与，以及左移、右移（shift left、shift right），这些都可以。

第三类是寄存器和寄存器之间的操作：比如一个寄存器去异或另外一个寄存器，然后把结果放到第三个寄存器里面，这没有问题。之前我们也做过——做过乘法，做过加法，还有减法，这种异或都是类似的，逐位地去操作就可以。因为每个寄存器的大小是个常数（32 位），所以 $O(1)$ 常数步就可以完成这些所有的算术逻辑操作。

第四类是 load 相关的指令。这一类里面有的是带符号的，有的是没有符号的，还有带 offset（偏移量）的，它们的共同作用是把内存里的四个字节装到寄存器里面。这个没有问题，因为 RAM 图灵机本身也可以 load、也可以读；它每次读一个 bit，而这里我们需要读 32 个 bit，那我们就写 32 次地址、读 32 次，然后把那个结果拼起来。因为 $32\times 32$ 还是一个常数，所以这些内存 load 的操作也可以在大 $O(1)$ 时间内完成。

store 就是它的反过程：把寄存器的值存到内存里面，做法是一样的，我们就用 RAM 图灵机逐步地把这些数据存到内存里。

第五类是跳转指令：比如说相等的时候跳转、不等的时候跳转；还有前面比后面小的时候跳转、前面比后面大的时候跳转——共同点是，条件满足的话就跳转。要模拟这些，首先得判断、比较两个二进制数的大小，而这个是之前也写过的。

第六类是系统指令，一共有三条，功能比如说让系统接管，或者让这个程序就停下来。这两件事在状态转移上都有落点：程序停下来就是跳到终止状态，系统接管就是跳到另外一个状态，也就是系统的状态。老师确认这些都没有问题。

> **老师总结**：跳转就是一个箭头，就是从一个状态跳到另外一个状态，也就是 goto。

> **老师启发**：既然每条指令的跳转都只是“从一个状态跳到另外一个状态”，那么把 RISC-V 程序转成 RAM 图灵机的过程，就可以理解成给这张状态转移图添箭头的过程；反过来说，图灵机每一行程序本来就是一个状态，这正是两条路线能对上号的地方。

最后收束：我们刚刚已经逐类检查过了，一共也只有 40 条指令，都没有问题。

## 二、用 RAM 图灵机模拟 RISC-V：逐类指令的检查与多项式开销 [00:18:07–00:34:35]

<!-- 时间范围：00:18:07–00:34:35 -->
<!-- 建议小节：1) 逐类指令的模拟：算术、访存/拷贝、比较、条件与无条件跳转；2) 模拟的状态与时间开销：为什么整体只多一个多项式；3) 用 RAM 图灵机模拟的程序与真实机器的差异（32 位字长、4G 内存、有限自动机的追问）；4) 教科书为何定义极简指令集，机器模型与"算法"的关系；5) word RAM 模型与算法文章里的复杂度；6) 其他计算模型（λ 演算、寄存器机、字符串改写、细胞自动机、电路）的引入（展开留给 T03） -->

老师先交代态度：大体上这件事前面已经论证过了，如果感兴趣，大家可以去看那 40 条指令的细节，逐条验证一下，确实是没有问题的——每一条指令都可以在 $O(1)$ 时间内被 RAM 图灵机（random access machine Turing machine）模拟。

接着他把这个结论逐类铺开。对每一次操作，无论是读写还是拷贝，还是写入一个常数、加减这些算术运算，还是逻辑运算（课堂上列出的形式是 and、not、or），或者是左移、右移，或者是无符号比较、带符号的比较，都是可以在 $O(1)$ 时间内完成的。这里要注意的是，他并不是笼统地宣称「指令很快」，而是把指令集拆成这些操作类别，逐类地重复同一个判断。

这些操作之所以都能压到常数时间，依据是同一条：因为它的字长是一个常数。此外还有内存操作，也就是读内存和写内存，同样可以在 $O(1)$ 时间内完成——这里要留意一个细节：虽然这个指令集每次访问的是 4 个字节，是 32 位，而我们这个 RAM 图灵机的字长是 1 位，但做 32 次就可以；做 32 次它还是一个常数，仍然算 $O(1)$。也就是说，宽度上的差别只是把一次操作换成固定次数的基本操作，换来的仍然是一个常数因子。

把寄存器、立即数、读内存、写内存这些都过一遍之后，还要补上访存地址这件事：这里内存会有一个 offset，也就是会加上一个偏移量。这个操作等于是做一次加法；地址的这次运算本身也是常数时间，不会因为访存而让单条指令的开销变成长度相关的量。

剩下的几类也照样是常数。跳转就是状态的跳转，显然就是常数——这里面有条件跳转，还有无条件跳转。

还有一类是系统指令。它要么是让程序停下来，也就是进入终止状态；要么是让系统接管，跳转到那个系统的状态。换句话说，这一类指令在模拟里也不产生额外的循环或子计算，它只是把图灵机送进某一个特定的状态。

这样，所有指令都落到了同一张图景上：在这次的统一图景里，每一个函数调用，或者每一次 go to，对应到图灵机里就是一个箭头，也就是一次状态的跳转。

> **老师强调**：跳转就是状态的跳转；每个函数调用、每次 go to，对应于图灵机就是一个箭头，就是一个状态的跳转。

由此老师收口：我们也就论证了，每一条 RISC-V 指令都可以被一个多带图灵机在 $O(1)$ 时间内模拟。再往上推一层：每一个 RISC-V 程序，如果它的运行时间是 $T(n)$，那么相应的图灵机的运行时间就是 $O(T(n))$。这里没有损失——最多可能会损失一个常数。

于是整条模拟链是这样串起来的：一个 C 语言程序，最后转换成单带图灵机，中间要经过这样的步骤——C 语言程序先到 RISC-V 汇编，再把刚刚那份 RISC-V 汇编转换成 RAM 图灵机，然后从 RAM 图灵机转换成多带图灵机，最后多带转成单带。老师顺带提到，这件事现在有 AI，大家去 prompt 一下，这些代码都可以写出来，应该可以很快就生成一段把 RISC-V 汇编转换成 RAM 图灵机的代码。

这里有一个值得点出来的观察：上节课讲的那个 $O(T(n)^2)$ 的模拟证明，本身也是一个算法证明。顺着这个想法往下走——什么是算法？算法就是代码；那代码就是图灵机。所以我们现在做的这些证明，也都可以用代码来写。

> **老师总结**：算法就是代码，代码就是图灵机；所以这些模拟证明本身也都是算法证明。

现在把这条链走完：多带转单带，就是变成 $O(T(n)^4)$。然后通过编码的方式，可以不妨认为它的字母表就是 $\{0,1\}$——当然还有空格。所以一个 C 语言程序，它的运行时间是 $T(n)$，到这里就变成了 $O(T(n)^4)$。

这个量级是多项式。所以其实选哪个模型都可以。

老师随后自问了一句：为什么我们不选择用 RAM 图灵机去定义我们这个图灵机呢？回答是：也可以，但可能稍微复杂一点。不过有的教科书就是这么做的——有的计算理论教科书会定义一个非常极简的汇编指令集，然后就说「这个就是计算」。但相对来说，如果我们直接定义单带图灵机，会更简单一点，一页幻灯片就可以放得下。

无论选哪一种图灵机的定义，用它去定义这个「柏拉图式的计算机」，最后那些主要的复杂性类——像 $\mathrm P$、像 $\mathrm{NP}$、像 $\mathrm{PSPACE}$——都是不变的。所以用什么来定义也是无关紧要的。

不过老师提醒，刚刚讲的这个汇编指令集，如果从理论的角度看，是有一点点问题的。为什么呢？因为它这个内存的地址是 32 位。32 位就说明它能够用的内存最多就是 $2^{32}$，也就是 4G。

这在现实之中问题不大：三四个 G 如果不够用，那 64 位肯定是够用的。但从理论上来说，这个就有点问题——这样它能处理的这个输入，它就是一个常数。老师在这里区分了两个层面：现实层面 4G 够用、不够就上 64 位；但理论层面，地址宽度是常数就意味着可寻址的内存总量是常数，于是能处理的输入规模也成了常数。

顺着这个理论上的麻烦，老师提出了一个看起来更尖锐的追问：比如说这台电脑，它的内存、它的硬盘都是有限的，那它不就是一个有限自动机（finite automaton）吗？它这个状态不就是有限的？那可不可以认为它就是有限自动机呢？

> **老师启发**：这台电脑的内存、硬盘都是有限的，那它不就是一个有限自动机吗？

这个追问的答案是：可以。但问题在于，那它的状态数是多少呢？就是 $2^{32}$，这是一个天文数字。所以用有限自动机可以去「认为」它是，但是用它去建模并不高效。也就是说，老师的立场不是否认这个观察，而是指出：把一台真实计算机看成有限自动机，在概念上成立，在描述上却要付出一个天文数字规模的状态表，因此这种建模方式没有效率。

为了解决这个问题，要把症结说清楚：如果字长是一个常数，它的内存就是一个常数，那处理问题的规模也就是个常数。一般来说，人们会让这个字长 $W$ 等于 $O(\log n)$。

为什么是这样呢？如果我们用一个极小的汇编指令集去定义我们的计算机，关键就在于这个 $W$ 的选择是 $O(\log n)$。原因可以一步步看。

**推导**：

1. 第一步，问：这样能够用的内存是多少？答：是 $2^W$。
2. 第二步，$2^W$ 在 $W=O(\log n)$ 时就是 $2^{O(\log n)}$。
3. 第三步，$2^{O(\log n)}$ 是什么？就是 $n$ 的一个多项式。
4. 第四步，所以既然这个程序能跑，我们就认为它用的内存是多项式。
5. 第五步，反面对照：如果用的是 $2$ 的指数次方那么多内存，那就根本没法跑。
6. 结论：$2^{O(\log n)}$ 就是 $n$ 的一个多项式。

在这个设定下，每一次指令做这个指令运算，它的代价就是 $O(W)$，或者 $O(W)$ 的一个多项式。所以它整个模拟的代价就是 $O(T(n))$ 乘以一个 $\operatorname{poly}(W)$；因为 $O(W^2)$ 就是 $\log n$ 的平方，所以这个开销还是一个多项式。

接下来是另一种模型，叫做 **word RAM**。它比较接近于我们实际的汇编指令集的一种图灵机模型。

所以如果大家在读到一篇论文，它说这个时间复杂度、空间复杂度是什么，就要留意一个问题：它到底用的是什么模型。约定俗成是这样的——如果大家读的是一本算法书，比如说《算法导论》，它分析一个排序算法的时间复杂度，这个复杂度到底是什么意思？

**例子**：这里的 $n$ 是输入的这个整数的个数；每个整数的字长就是 $\log n$，也就是 $W$；然后每一次对于每个字，它的比较、它的四则运算、它的逻辑运算都算单位时间。老师自己点出了这个约定与真实代价之间的偏差：按理说它这个比较不是 $O(1)$，而是 $O(W)$，也就是 $O(\log n)$——但是它这个假设就是这样：对于每个字的这个运算，它的代价是单位时间。

也就是说，word RAM 是把「一个字上的运算」当作单位时间来记账的：它不去追究这个字有 $W=\log n$ 位、真要按照比较去算应该花掉 $O(\log n)$ 的时间，而是直接规定这一步算一个单位时间。这正是它和逐个基本操作计时的模型之间的差别所在。

**例子**：在这个模型里，比如说整数乘法，它的时间复杂度是 $O(n\log n)$。这里的 $n$ 是什么呢？这里的 $n$ 就是输入的长度，也就是输入的 bit length——把你输入转换成一个 0-1 串之后，这个 0-1 串有多长。这也是前面那个排序算法的例子里说「每个整数的字长就是 $\log n$」的同一套口径：这里的 $n$ 不是「输入有多少个整数」，而是输入编码成 0-1 串的长度。

所以我们会这么说：如果你读的是一篇算法的文章，或者是一篇机器学习的这种文章，它假设的这个模型就是 word RAM；如果你读的是复杂性的文章，它的这个模型就是多带图灵机。而多带图灵机这里的时间是这样数的：每一次这个指针的移动，或者说每一次这个状态的跳转，就算 1。

这就是这两个 community 的计算模型的一点差异。这个设定也 make sense，因为在算法里面用一个 word RAM 是非常接近现实的一个汇编指令集。

老师随后小结：我们刚刚就讨论了怎么把一个 C 语言程序转换成单带图灵机。所以这样我们就论证了为什么图灵机它是完备的。

然后除了图灵机之外，还有很多很多计算的模型或者计算的方式，而且有些看起来和计算一点关系都没有，是一些很奇怪的计算模型。

比如像 Church 定义的这个叫 $\lambda$ 演算（lambda calculus）。还有 Minsky 定义的一个叫寄存器机（register machine）——这个就像是一个只有两条指令的汇编。老师点出「只有两条指令的汇编」这个说法，用意在于说明：把指令集削到极简，也照样不损失计算能力。

还有一些像游戏一样的：你可以有一些字符串，字符串之间有一些改写规则，然后它会像一个生成式的字符串生成的系统；这个也是一个完备的计算机。

还有什么细胞自动机（cellular automaton）——这个老师说他马上就会让我们看到。它的定义方式是：比如一维的或者二维的细胞，细胞有两个状态，就是黑色或者白色，或者是死还是活；它由它周围的连接的细胞的状态决定它下一个状态，就是很简单的一些规则；然后它可以演化出很复杂的一些形态；最后它是完备的，最后它是图灵完备的，这个可以当做是一种计算。

还有像电路：电路就是有比如说三种门——与、或、非；然后每个门，与门还有或门，它的扇入是 2，扇出是 1；就用这种三个门，就可以搭出任何你想要的这种逻辑。然后它被证明和图灵机是等价的。

就是有很多奇奇怪怪的、看起来很奇怪的这种模型。

## 三、其他计算模型与"有效可计算"的含义 [00:34:35–00:41:08]

<!-- 时间范围：00:34:35–00:41:08（T03，责任字幕第 500–600 条；衔接上文为 T02 对电路模型的介绍） -->
<!-- 建议小节：1) 各种模型都与图灵机等价的总结与"蚂蚁"的比喻 [00:34:35–00:35:11]；2) 邱奇-图灵论题的表述与"有效可计算"（effectively computable）的含义 [00:35:16–00:36:59]、[00:37:11–00:37:28]；3) 为什么这个论题不能被证明：不是一个数学定义，以及"强论题"与量子计算机 [00:37:35–00:41:08]；4) 计算作为物理学概念 [00:36:08–00:36:43] -->

接上一段对电路的介绍——电路里有与门、或门、非门三种门，与门和或门的扇入是 2，非门的扇入是 1，用这三个门就可以搭出任何你想要的逻辑，因而电路已被证明与图灵机等价；老师随后把话头收拢到一类更普遍的现象上。像这样奇奇怪怪的、看起来很奇怪的计算模型，最后都能证明它和**图灵机**（Turing machine, TM）是等价的，也就是说它是一种完备的计算模型，是**图灵完备**（Turing complete）的。

> **老师比喻**：就好像蚂蚁一样。蚂蚁一起去搬运食物，它们会在周围用气味做一些记号。

老师由这个比喻顺势提出一种设想：这类现象可能也是一种**生物计算**（biological computation）；而且它可能也可以证明是图灵完备的。这里老师用的是"可能"——课堂上并没有给出把蚂蚁搬运食物的过程归约到图灵机的证明，只是把它作为一个"看起来很怪、但可能同样落在同一个计算概念之下"的例子。

针对这一类现象，Church 和 Turing 就提出了那个论题。老师先自问一句"他这个论题是什么，怎么说的呢"，然后说明这应该是他（图灵）的原文，并用英文念出了这一句：

> **老师强调**：every function that is effectively computable is computed by a Turing machine。

也即：每一个有效可计算的函数都是被图灵机计算的。

$$f \text{ 是有效可计算的} \;\Longrightarrow\; f \text{ 是图灵可计算的}$$

老师紧接着把问题的落点放在这个短语上：那怎么理解这个 **effectively computable**（有效可计算）？

> **老师启发**：就怎么理解这个 effectively computable？

要理解这个说法，得先回到提出论题的动机。计算在我们的物理世界里无处不在，是一个非常重要的物理学概念——像蚂蚁、蚊子，它们都在计算，我们也在计算，每个人都是一个行走的计算机；那么到底什么是计算、到底什么是计算机？老师提出这个追问，是因为"到底什么是计算机"是一个很深刻的物理学概念，而往往一个重要的物理学概念，它也是一个重要的数学概念，反之亦然。正是从这个想法出发，Church 和 Turing 才会去想：到底什么是计算，也就是怎么去数学地定义它。

这件事为什么会落到他们身上？因为图灵和 Church 是第一个试图把计算去形式化、去严格地定义"什么是计算"的人：在他们之前，"计算"只是一个日常说法，没有人把它写成一个可以推演的数学对象。老师接着讲，具体的做法是两种不同的形式化方式——Church 定义了 $\lambda$ 演算（lambda calculus），图灵定义了图灵机。

有了这两个定义以后，他们就考虑一个问题：是不是我这个定义，涵盖了所有计算的这种可能性？这才是论题真正要回答的东西。于是老师给出论题的另一种（中文）表述：所有那些可以被计算的，都可以被图灵机计算。

> **老师强调**：这里说的不是 efficiently，是 effectively。

也就是说，"有效可计算"讲的是**能不能算**这件事，而不是**算得快不快**；它不是关于时间开销的要求，而是一个关于"原则上可计算"的说法。时间开销是后面那个更强的版本才加进去的条件。

这个论题我们普遍是相信的。老师给出的理由不是"听起来对"，而是因为刚刚提出来的各种具体模型——像 $\lambda$ 演算、递归函数、寄存器机、元胞自动机（cellular automaton）——对于那些具体的计算模型，都是可以证明它能够被图灵机模拟的；而且反过来反之亦然，图灵机也可以被别的模型模拟，比如图灵机也可以被一个电路来模拟。所以一整套看起来彼此很不一样的模型，在"能算什么"这件事上是重合的，这种重合就是相信论题的实际根据。

那么，可不可以就证明这个论题呢？

老师自己回答：好像不可以。原因就在于到底什么是 effective computable——

> **老师强调**：这不是一个数学定义，这是一个哲学，就是哲学的含义。

换句话说，论题里的关键词项"有效可计算"本身没有数学定义；而一个要拿来证明的数学命题，其中的词项必须先是数学对象。既然"有效可计算"只停留在哲学层面的含义上，论题就不是一个可以用数学证明的命题。老师在这里的实质主张是：**论题不可证明，原因是它不是一个数学命题**，而不是"我们暂时还没证出来"。

在标准的这个论题之外，老师还提到有一个更强的版本，他称为"强 CDT"（strong Church–Turing thesis）；并且提醒这个强版本"很有可能是错的"。这个强 CDT（课堂上后文也说成"强 CTT"）说的是什么呢？

它说的是：所有可以被计算的都可以被图灵机模拟，**并且这个模拟的代价是多项式**。老师把它写成一个关于时间的条件：如果前面这个计算模型它运行的时间是 $T(N)$，那么后面这个计算模型（图灵机）模拟的时间就是 $\mathrm{poly}(T(N))$，也就是 $T(N)$ 的一个多项式。

$$\text{原模型用时 } T(N) \;\Longrightarrow\; \text{图灵机模拟用时 } \mathrm{poly}\bigl(T(N)\bigr)$$

所以强论题比原来的论题多了一句：不仅能被图灵机模拟，而且模拟的代价是一个多项式。老师明确说，这个（强论题）现在普遍认为是错的。

> **老师强调**：麻烦就在于量子计算机，麻烦来自于物理。

道理是这样的：量子计算机可以模拟图灵机，方向上没有问题；但是图灵机如果模拟量子计算机，它那个时间就变成指数了——也就是说，图灵机不能高效地模拟量子计算。经典模型与量子模型之间这种"一边多项式、一边指数"的不对称，正是强论题（要求模拟代价为多项式）出问题的地方。量子计算与 $\mathrm{BPP}$、$\mathrm{BQP}$ 这些复杂度类的展开属于接下去的内容。

最有代表性的例子就是这个大整数分解问题。大整数分解对于我们的经典计算机是非常难的：如果我们就去写一个 for loop，从 $2$ 到 $\sqrt{N}$ 去逐个搜它的因子，那这个时间复杂度是 $2^{O(N)}$——这里 $N$ 是它的 **bit length**（二进制位长），所以如果你写一个 for loop 很暴力地去做，就是 $2^{O(N)}$。老师还补充说，现在最好的算法也没好到哪去：从 $2^{O(N)}$ 降到了 $2^{O(N^{1/3})}$。

$$2^{O(N)} \;\longrightarrow\; 2^{O(N^{1/3})}$$

老师强调这个差别可以先忽略、是次要的：因为它只是把 $2^{O(N)}$ 变成了 $2^{O(N^{1/3})}$，数量级上仍然是指数。然后请大家想象一下，$N$ 如果是一个 1024 位的数，这个（时间）还是相当大。

## 四、概率图灵机与复杂度类 BPP：量子计算与因数分解 [00:41:12–00:56:20]

<!-- 时间范围：00:41:12–00:56:20 -->
<!-- 建议小节：1) 从"1024 位"说起：量子计算与经典计算的关系；2) 概率图灵机（可以抛硬币的图灵机）与错误概率；3) P、BPP 与去随机化；4) 因数分解（factoring）与"把 factoring 变成一个语言"；5) Shor 算法、RSA 与单向函数假设；6) 计算图景的过渡 -->

接着上文对分解问题的代价估计往下走。上文已经算过：如果写一个 `for` 循环很暴力地去做，代价是 $2^{O(N)}$（$N$ 是数长），而目前最好的算法也只是从 $2^{O(N)}$ 降到了 $2^{O(N^{1/3})}$。老师把 $N$ 直接代成一个具体的规模让大家感受一下：$N$ 如果是一个 1024 位的数，那么"这个还是还是挺大的"，也就是说 $2^{O(N^{1/3})}$ 这个量级在 1024 位上依然大得不可接受。不过老师同时提醒，到底有多难还取决于算法里的常数，所以他不把话说死：**目前 1024 位分解应该还是比较难**。

但量子计算机这一侧是另一幅景象。老师指出，对于量子计算机来说有专门的量子算法，它的时间复杂度是多项式的，而且"指数也比较小"（指多项式的次数约为 2，即接近平方级），所以指数也比较小。这里的对照关系是老师要讲的要点：经典侧最好的算法仍然停在 2 的幂上，而量子侧的多项式算法连次数都不大。

于是老师把话题从"某个问题的代价"提升到"模型"这一层。他说，对量子计算机同样**也可以定义它的计算模型，也可以定义各种计算复杂性类**——那是另外一个故事；量子世界这门课就不讨论，但是大家知道就可以。也就是说，前面讲过的整套做法（先定模型，再在模型上定义复杂性类）在量子计算机上是同一套理论、同样的故事再来一遍，只是本课程不做展开。

沿着这套路数，老师接着问：那么对于量子计算机，它的那个 $\mathrm P$ 是什么呢？答案是 $\mathrm{BQP}$。为什么叫 $\mathrm{BQP}$？第一个字母 B 是 bounded error，即有界错误。为什么会有"有界错误"这件事？因为**量子计算机最后要去 measure 一下**，它是有概率性的：测量下来可以出来一个 0，也可以出来一个 1，所以它**有可能出错**。而只要这个出错的概率"比如说小于等于 $\frac13$"就可以了。名字剩下的部分：$\mathrm Q$ 是 quantum，"term 就是 $\mathrm{BQ}$"（老师把 B、Q 两个字母连着念），整个 $\mathrm{BQP}$ 就相当于是量子世界里面的 $\mathrm P$。

讲完量子侧，老师回到经典侧，来拆 $\mathrm{BPP}$ 这个名字。他说：$\mathrm{BPP}$ 是什么呢？第一个字母 B 是 bounded error；第二个 P 是 probabilistic；第三个 P 才是我们熟悉的那一个 polynomial。合起来就是"有界错误概率多项式时间"。

而 $\mathrm{BPP}$ 在模型上有一个很直白的说法：它就是**一个可以抛硬币的图灵机**。老师的说法是，这是我们"还可以定义"的又一种图灵机——在原来那台确定的图灵机之外，再定义一台可以抛硬币的机器。具体怎么实现？就是给它**加一条纸带**，这条纸带上全都是随机数，是 0101 这样的串，而且是**真正的随机数**（不是伪随机）。老师用大家写程序的经历作类比：大家写程序的时候，像 C 语言里面有 `rand` 可以生成一个随机数，也就是这个意思。

有了可以抛硬币的图灵机，就可以提出这一节最重要的猜想。老师说，这里有一个很重要的猜想，就是 $\mathrm{BPP}=\mathrm P$，也就是**你用随机数和不用随机数最后都是一样的**。他把它换成一个更好操作的说法：如果你能用随机数解决（一个问题），那么你就可以不用随机数解决（同一个问题）。

> **老师总结**：有一个很重要的猜想就是 $\mathrm{BPP}$ 等于 $\mathrm P$，就是你用随机数和不用随机数最后都是一样的。

老师马上用排序算法给了这个猜想一个具体的样子。快速排序是有随机数的——它就是随机地找一个元素当关键元素来作比较。而另一侧，像归并排序、像堆排序，就不用随机数。于是老师给出一个判断：可以把堆排序看作对于快速排序的"**去随机化**"（derandomization）。这就是去随机化这个术语在这门课里的具体含义：把一个本来依赖随机选择的算法，换成一个不依赖随机选择、但做同样事情的算法。

顺着这个术语，老师把视野推到整个 TOC（理论计算机科学）里：TOC 里面**有一类假设**都是跟这个相关的，也就是跟 $\mathrm{BPP}=\mathrm P$ 相关——"就是说对于 $\mathrm P$ 这个复杂性来说，用不用随机数都一样"。这是老师给这类猜想的一个定位：它不是孤立的一条命题，而是一整类假设的共同形状。

接下来老师引出本节的另一个假设。他问：所以这个假设是什么呢？这个假设就是，大整数分解（factoring）不在 $\mathrm P$ 里面。讲到这里老师特意停下来说明动机：因为这个假设对密码学很重要。因为很多密码学——现在大家去 HTTPS 上网，或者你输入银行卡的时候——都是在依赖这个假设。他举了具体的例子：就像很多银行系统还在用 RSA，RSA 就是依赖于这个大整数分解难；而"大整数分解难"这件事本身，就是依赖于我们这个复杂性假设。反过来，如果这个假设不成立，如果这个猜想是错的，"那都完蛋了"。

> **老师强调**：如果这个猜想是错的，那（依赖它的这些系统）都完蛋了。

既然要用复杂性类的语言来谈分解，就必须先把"分解"这件事写成判定问题的形式，老师把这一步称为**把 factoring 变成一个语言**。他的理由是：分解本来是要把一个大整数分解下来，这是一个搜索问题；但我们可以这样把它编码成一个语言。因为语言只有"是"或者"否"两种回答，所以编码方式是这样一种判定问题：输入一个整数 $X$，再给一个区间端点 $L$ 和 $R$，判定

> $X$ 在 $[L,R]$ 这个区间之内是否有一个因子。

老师特别说明这一步的意义：只要这个**判定问题**被解决了，那我们就可以**二分搜索**，就可以很快地把这个因子找到。也就是说，"分解"这个搜索问题被归约到了"区间内是否有因子"这个判定问题：反复调用判定算法、用二分的方式缩小区间，就能把因子的具体值确定出来。这就是为什么谈分解的复杂性时，可以只谈这个语言。

于是老师再回到学科层面：所以这个猜想是什么呢？就是现在大家为什么（说）我们这门学科是密码学的基础呢——因为依赖于很多加密系统的安全性、签名系统的安全性，就依赖于这个猜想。他把猜想的正式内容说清楚：这个猜想就是它没有多项式时间的算法，也就是 factoring 不在 $\mathrm P$ 里面。

讲完这个"猜"，老师立刻讲了另一个方向，并强调这是**一个定理**：那就是 Peter Shor 发明（发现）的这个算法。它说明（大整数分解）**在 $\mathrm{BQP}$ 里面**，也就是说存在一个高效的量子算法。老师说"所以当然还有另外一个猜想就是……"，但这句话刚起头就下课休息了。

---

老师接着说密码学系统这件事，并且先界定范围：现在的密码学系统是一个广义的概念，包括像加密、签名、零知识协议、安全多方计算等等。他的结论是：这些密码学系统的安全性，它是依赖于一些难问题，依赖于一些计算理论的计算复杂性的假设。

具体到例子，他再次点了 RSA：比如说像现在很多还在用的就是 RSA，RSA 这个加密算法，它的安全性——它不会被攻破——就是依赖于这个。老师把 RSA 的机制完整讲了一遍：

1. 找两个很大的质数，把它们乘起来；
2. 乘起来之后，这两个质数**是私钥**；
3. 那个**乘积是公钥**；
4. 所以安全性就依赖于对大数进行分解，而分解是难的。

把前面两条合起来看：这个（已经编码成语言的）问题**不在 $\mathrm P$ 里面，但是它在 $\mathrm{BQP}$ 里面**。老师于是讲这两个类之间的推出方向：它们之间是可以从上面推出下面的，但是从下面不一定可以推出上面，所以"上面就是 $\mathrm P\ne\mathrm{BQP}$"（这仍然只是一个猜想）。

> **老师提示**：因为一个方向是显然的——$\mathrm P$ 肯定是属于 $\mathrm{BQP}$ 的；但是 $\mathrm{BQP}$ 就不属于 $\mathrm P$。

把方向再讲一遍：一个方向显然是成立的，$\mathrm P$ 肯定是属于 $\mathrm{BQP}$ 的（经典计算机上多项式时间能做的，量子计算机当然也能做）；而 $\mathrm{BQP}$ 不属于 $\mathrm P$ 则是猜想的内容，不是定理。

最后老师把话题从具体的类转到整幅图景。他说："那大体这个途径（图景）是什么样子的呢？大概是这样的——对于这个经典计算机，$\mathrm P$ 在这里……"从这里开始，他要画出各类之间的包含关系图，先落笔在"经典计算机的 $\mathrm P$"这个位置上。

接前面关于经典计算机与量子计算机的讨论，老师把整个复杂性类的图景画了出来。经典计算机对应的 $\mathrm P$ 画在最里面；$\mathrm{NP}$ 在它外面，老师说"$\mathrm{NP}$ 在这里"；最外面那个大圈是后面才会定义的 $\mathrm{PSPACE}$，也就是那些**多项式空间**（polynomial space）的问题类——老师在这里连着更正了几次说法："就是那些多项式 space 空间"、"就是 space space"、"就是多项式空间"，说的都是同一个东西。

在 $\mathrm{NP}$ 里面有一类很特殊的，叫 $\mathrm{NPC}$，就是 **$\mathrm{NP}$ 完全**（NP-complete）的这一类。量子计算机所在的那一类，也就是 $\mathrm{BQP}$（bounded-error quantum polynomial time，有界误差量子多项式时间），也画在图上：首先它包括了 $\mathrm P$；猜想它不包括 $\mathrm{NPC}$；但是它包括了一些 $\mathrm{NP}$ 里面的问题，也包括了一些 $\mathrm{PSPACE}$ 里面的问题。老师说"大概是这么画"。这里他反复强调，这些都还是猜想——图上关于"包含还是不包含"的判断，尤其是量子计算机与 $\mathrm{NPC}$ 的关系，目前都没有被证明。

图里面还有一个问题叫 factoring，也就是**因数分解**（大整数分解）：它是在 $\mathrm{NP}$ 里面的，但是猜想它不是 $\mathrm{NPC}$。老师补了一句"所以刚刚那个问题叫大整数分解"，并指着图说"它在这里"——它落在 $\mathrm{NP}$ 里，但不在 $\mathrm{NPC}$ 那一类里。

正是在这个背景下，老师接着讲量子计算机对密码学的冲击：量子计算机一旦造出来之后，对现有的这个密码学体系肯定是冲击非常大——他连着说了两遍"冲击非常大"。比如说某些加密货币，它的安全性就是"离散对数难"这个问题。具体地说，在一个群上，由 $x$ 去算 $g$ 的 $x$ 次方（即 $g^x$）这个方向是容易的；但是反过来非常难，也就是说，由 $g^x$ 反推出 $x$ 很难。这个方向上的困难就叫**离散对数难**（discrete logarithm, DL）。老师也把离散对数（DL）指为前面那张复杂性类图里面的一个问题。

不过量子计算机现在的状况是：它也被造出来了，但是量子比特（Q 比特，qubit）位数很少，可能是几位、十几位那种，做不到。比如说想分解（一个大整数），它可能需要比如说 500 位；500 位就需要比较高的位数、比较高的稳定性。

对这件事老师也说自己很好奇：有时候遇到做量子计算的，他就会抓着他们问——这个情况怎么样、什么时候（量子计算机）能被造出来，"你这个你比较懂，你给我讲讲"。但是他们跟我说的东西也相当绕，每次说完之后我也经常听不懂他们在说什么；大体听下来是这个意思：

他们说经常会有一些文章宣扬、宣传什么**量子霸权**（quantum supremacy）：说我找出了这个量子计算机能做什么——经典计算机在一个天文数字的时间内也做不出来的一个问题，最后把这个统计学问题解决了，然后发了一篇什么文章。但是这些问题往往非常刻意，往往就是为了证明"他能做这个"，于是他就想了某种统计问题；并不是我们最关心的那些，比如说大整数分解、离散对数这些。所以这个（造出量子计算机的）时间线，大家其实还没有太多共识：有人悲观一些，认为要 20 年；快一点的人认为 5 年。

但是他们现在都在做的一件事情，就是为我们的后量子时代做准备：他们会提交各种各样的新的加密系统，做这个迁移，也就是 quantum migration——**后量子迁移**（quantum migration）。也就是在稳定的、大的量子比特的量子计算机被造出来之前，我们把现有的这些加密体系（包括数字货币什么的）的协议全部改一遍，慢慢地全部把它迁移到后量子时代。

老师昨天还在朋友圈看到一篇文章，是做密码学的人转发的，他们整体觉得"不要慌"。因为现在很多人就是觉得 AI 对各行各业的冲击都比较大：老师也有同学在制造业，他们觉得冲击实在是太大了，有一段时间就很焦虑，天天就拼命地去 prompt、拼命地去跑那个 AI——因为他们发现 AI 可以解决他们（制造业）的一些问题，所以就会觉得比较焦虑。而做密码学的那边觉得"不要慌啊不要慌"：因为现在大语言模型并没有冲击这些最基本的假设。

为此老师给大家提了一个可以自己试的做法：找两个很大的质数乘一下，乘完之后把这个结果丢给 AI 让它分解——应该是分解不出来的。他随后自己确认："分解不出来的，对。"就这些难问题，AI 还是解决不出来。

> **老师强调**：现在的大语言模型并没有冲击那些最基本的（计算复杂性）假设——找两个很大的质数乘起来，把结果丢给 AI 让它分解，是分解不出来的。

也就是说，强的**邱奇-图灵论题**（Church–Turing thesis, CTT）被认为很可能是错的，因为量子计算机。还有一个就是物理版本的 CTT（physical Church–Turing thesis），它说的是：任何可以被一个物理系统计算的，都可以被图灵机计算。这个说法普遍被认为是对的。

但是（物理版本的 CTT）还是没法证明。原因是现在物理学的这个理论——关于这个——也没有办法统一，就像现在相对论和量子力学也没法统一。所以这个也是没有被证明。不过有一些加上限制的证明：比如有些证明针对的是"有限区域、有限能量的物理系统容纳有限的信息"，对它是有一些证明的；但这些证明是针对一些假设、在特定的假设或者模型下得到的——如果比如说机械装置满足信号传播速度有限、单位空间内信息密度有限等原则，那么它能计算的函数都是图灵可计算的，等等。

之所以还不能算证明，是因为我们对于物理世界的认识还很有限：量子力学还有相对论还没有办法统一。所以目前还没有办法证明，但是它被广泛地相信。

> **老师总结**：物理版本的邱奇-图灵论题目前还没有办法证明，但是被广泛地相信。

讲完这些，老师就带着大家看两三个有代表性的模型："这些都是图灵完备的，我们都可以用它来定义计算。"第一个叫**寄存器机**（register machine）。老师说它有点像汇编，区别在于：它是有限个寄存器，而每个寄存器可以放一个"无限大的"自然数，也就是可以放任意大的自然数。

**定义**：寄存器机（register machine）有有限个寄存器，每个寄存器可以放一个任意大的自然数；它的程序只有两种指令。第一种是加一：对某个寄存器加 $1$，做完之后转到（go to）另外一条指令。第二种是减一：对某个寄存器减 $1$，如果减完之后的值大于零，就转到指定的标号 $L_1$；如果减完之后的值等于 $0$，就转到指定的标号 $L_2$。

就这两条指令，寄存器机就已经是图灵完备的了。

第二个模型看着有点还挺有意思的，叫**细胞自动机**（cellular automaton），它是这样的。

**定义**：细胞自动机是个一维的（一维细胞自动机）：图上横轴是细胞，纵轴是时间，也就是时刻一、时刻二这样排下去。每个细胞有两种状态：黑色或者白色，也就是 $0$ 或者 $1$。每个细胞下一个时刻的状态，由它自己上一个时刻的状态，还有它左右两个邻居上一个时刻的状态共同决定。

这样的规则可以有很多种，老师举了其中的一个：这个规则叫 110 规则。

**例子**：110 规则（Rule 110）。老师按"左、中、右三个细胞上一时刻的状态 → 下一时刻的状态"逐条念了几条规则：如果状态是 $111$，下一个状态就是 $0$；如果中间这个 $1$ 的左边、右边分别是 $1$ 和 $0$（即 $110$），下一个状态就是 $1$；$101$ 下一个状态也是 $1$。念到这里他说"对，就是写出来就是八条规则"——每个细胞下一时刻的状态由三个细胞（它自己、左邻居、右邻居）上一时刻的状态决定，每个位置取 $0$ 或 $1$，一共 $2^3=8$ 种组合，所以规则表写出来就是八条规则；由八条规则决定的这个东西就叫细胞自动机。

| 上一时刻（左、中、右） | 下一时刻 |
|---|---|
| $111$ | $0$ |
| $110$ | $1$ |
| $101$ | $1$ |

有了规则之后，再看它的初始状态：比如说开始的时候只有一个 $1$，其他都是 $0$。老师说最后把这个图画出来就很神奇——初始状态就只有一个（$1$），画出来好像是挺分形的一个结构。如果再复杂一点，比如多放几个 $1$，就会出现一些很神奇的形态：有的看上去比较随机，有的还是自相似的分形结构。

细胞自动机也（被）证明了是图灵完备的。也就是说：我们不是有一个图灵机吗？根据你的图灵机、根据输入 $X$，有一个算法可以把它转换成一个初始状态——就是一些 $0$ 和一些 $1$；然后让这个细胞自动机去执行若干步；若干步之后，看最终的那一条横线，也就是它最终纸带上的状态会出现一个 pattern（图案），由这个图案来决定（图灵机）是接收还是拒绝。这样这个模型就被证明和图灵机是等价的。老师说，这也是一种计算。

反过来，图灵机能模拟细胞自动机，这个是显然的——你可以写一段程序去模拟这个细胞自动机。

细胞自动机还有一些其他的规则，比如 90 规则、30 规则，还有 110、184。这些规则画出来的图：有的很分形，有的很随机。老师看着图说，这个像是在画、想画一个什么，就是像在画某种图案——对，很多图案的。

> **老师启发**：为什么特别简单的这些规则，可以演化出这么复杂的形态？

具体到规则 110，老师要大家了解的是：它被证明就是可以计算的——用这个规则可以去模拟一个图灵机。它把图灵机的程序和输入 $X$ 变成一个初始状态，初始状态就是那一行细胞的状态；然后用刚刚那八条规则去模拟它。它停机，当且仅当某一个特殊的形态出现，它就停机了；然后通过读它的这个形态，就可以决定是接收还是拒绝。这样就被证明这个（规则 110）可以用来模拟图灵机。

第三种模型就是**电路**（也就是布尔电路，Boolean circuit）。这个模型也是很多人会喜欢的，因为它特别简单。比如说，我们先确定一组门，比如 and、or、not；每个门可以计算。它的输入都是 $0$ 和 $1$，都是我们看作布尔的值：零就是假。

## 六、布尔电路与电路复杂度下界 [01:12:53–01:29:09]

<!-- 时间范围：01:12:53–01:29:09 -->
<!-- 建议小节：1) 布尔电路的正式定义；2) 异或函数的电路构造与规模上界；3) 电路复杂性 CF(f) 的定义与 well-defined 性；4) 电路模型与 P≠NP 的一条证明路径；5) 通用门集、完全基与单调门集；6) 历史上的一次振奋：1985 年的超多项式单调电路下界；7) MOD 3 的最少门数与暴力验证法；8) 下界的现状、老师的感慨与第一部分结束 -->

前一段刚刚把布尔值的约定说完：电路的输入都是 $0/1$，都看作布尔的值，$0$ 就是假、$1$ 就是真。老师接着把最基本的几种门过了一遍：AND（与门）算的是两个值的“与”，OR（或门）算的是两个值的“或”，NOT（非门）算的是取反。把这些说清楚之后，老师转入正题：那么，什么是一个电路呢？

**定义**：一个**布尔电路**（Boolean circuit）就是一个**有向无环图**（directed acyclic graph, DAG），图中每一个节点都是一个**门**（gate），门计算一个布尔函数——与、或、非等等；一个电路很自然地就计算一个函数。

老师一边讲一边在黑板上画了一个电路的样子，说明一个电路是由哪些东西拼起来的：输入接在图上，中间是一层层的门，最后得到函数值。对这个模型，老师顺手给了一句评价：它可能比图灵机还简单一些。

接着老师举了具体的函数来看电路怎么搭。

**例子**：异或（exclusive OR, XOR）函数，它是 $\{0,1\}^2\to\{0,1\}$ 的一个映射，也就是算两个输入值的异或。

**推导**：老师问，怎样用门把这个函数拼出来？他取两个输入 $x_1$、$x_2$，按下面的顺序一步步搭：

第一步：先把 $x_1$ 取反，用一个非门得到 $\neg x_1$。

第二步：取反之后把它和 $x_2$ 与一下，得到一个与门的输出 $\neg x_1\wedge x_2$。

第三步：把 $x_2$ 也取反，用另一个非门得到 $\neg x_2$。

第四步：把 $x_1$ 和 $\neg x_2$ 也与一下，得到另一个与门的输出 $x_1\wedge\neg x_2$。

第五步：最后把这两路结果或一下，整个电路的输出就是

$$(\neg x_1\wedge x_2)\vee(x_1\wedge\neg x_2).$$

这个式子正是异或：两个输入一个是 $0$、一个是 $1$ 时，两路与门里恰好有一路为 $1$，输出为 $1$；两个输入相同时两路都为 $0$，输出为 $0$。这样就用与门、或门、非门把异或函数搭了出来——用到的门是两个非门、两个与门和一个或门。

老师随后又把定义重申了一遍：一个电路就是一个有向无环图，图上的每个节点就是门；本节假设我们可以用三种门——与门、或门，还有非门。

接下来的问题是：搭出来只是第一步，能不能搭得更小？

老师指出，计算复杂性（computational complexity）里面有一个分支，叫**电路复杂性**（circuit complexity），它研究的就是一个函数最少可以用多少个门拼出来。老师特别强调，这个方向最关心的是**下界**。他顺手做了一个对比：如果大家做电路设计，关心的是上界——你想把一个逻辑拼出来，拼出来就行；而在复杂性里面，人们更关心下界。

**定义**：对每个函数 $f$，定义 $\mathrm{CF}(f)$ 为用最少多少个门可以把 $f$ 拼出来，即
$$\mathrm{CF}(f)=\min\{\text{门的个数}:\text{该电路计算 }f\}.$$

接着老师用刚才画的电路说明这一点：刚才那个电路只证明了一个方向，它证明的是一个**上界**。异或这个函数，老师当场数了一下门：$1,2,3,4,5$，所以
$$\mathrm{CF}(\text{异或})\le 5.$$
问题的一般提法就是：给一个函数，我们关心最少要多少个门才能把它算出来。

然后老师解释大家为什么关心这个学科——他先自己问了这个问题，然后给出理由。第一，这个电路和图灵机一样，也是**图灵完备**（Turing-complete）的：图灵机能算的电路也能算，电路可以算任何函数。第二，这个 CF、这个门的多少，和图灵机运行的时间差不多是同一个量级，二者之间有这样的一个关系。正因为有这样一层对应，这条线索就成为了一条证明 $\mathrm P\ne\mathrm{NP}$ 的路径。

老师说，这里其实可以写成一个观察：如果存在一个 $\mathrm{NP}$ 里面的函数，它的电路复杂性很高——“很高”是多高呢？就是超过多项式。用大 $O$ 记号可以这样表示：$n^{\omega(1)}$，其中 $\omega(1)$ 就是比任何常数增长得都快。如果存在这样一个函数，那么就得到了 $\mathrm P\ne\mathrm{NP}$。具体操作起来就是：在 $\mathrm{NP}$ 里面找一个 NP 完全（NP-complete）的问题，比如 CLIQUE 这种，然后证明它最少需要超过多项式大小的电路才能把它搭出来，这样也就证明了 $\mathrm P\ne\mathrm{NP}$。

不过老师马上补了一句：如果我们仔细想一想，这个**基**（basis，即所选用的门集）的选取其实是无关紧要的。刚才选取的基有三个门——与门、或门、非门；那么只选两个门可不可以呢？其实也是可以的。比如说就选与门和非门，因为或门可以用这两个门搭出来：对 $x$ 和 $y$，$x\vee y$ 是什么呢？就是

$$x\vee y=\neg(\neg x\wedge\neg y),$$

老师说这两边是相等的，所以两个门就行了。甚至一个门就行了：如果有一个门叫 NAND（与非门），它做的就是“先与一下，然后再取反”，那么一个门就可以了。

所以老师得出结论：这个基的选择根本无关紧要。你选一组基还是选那组基，只要是一组**完全的基**（complete basis），门之间可以互相拼、互相搭出来，那么你最后定义出来的这个电路复杂性就只相差一个常数。也就是说，电路复杂性是一个非常 well defined 的度量。

对每个函数我们都可以定义一个 $\mathrm{CF}$，就是最少用多少个门把它搭出来；而这个定义确实是 well defined 的：无论你选取一个什么样的基，它最后只相差一个常数，原因就是门之间可以相互搭出来。

老师说，所以就是这样的一个路径，看着大家觉得有希望：因为图灵机比较麻烦，而电路就是一个图，说不定哪一天一拍脑袋就能做出来。而历史上还真的发生过这样的一件事情：出现了一个结果，当时大家看了之后都非常振奋，觉得马上就要出来了。

老师接着问：这次取的是一组什么基呢？这组基并不完全，它只有两个门——一个 AND 门，一个 OR 门。这个基是不完全的，但是它是单调的；用这两个门也可以拼，它能搭出所有的单调函数。

**定义**：所谓**单调函数**（monotone function），就是把输入的某个 $0$ 变成 $1$ 之后，最后的结果只会变大不会变小：输出只可能是从 $0$ 变成 $0$、从 $0$ 变成 $1$ 或者从 $1$ 变成 $1$，不会反过来，不会从 $1$ 变成 $0$。

老师这次取的函数是 CLIQUE：就是我们之前定义过的那个图的问题——输入是一个图 $G$，然后问 $G$ 有没有一个 $k$-团（$k$ 个两两相邻的顶点构成的完全子图）。老师说，这个函数是单调的：如果这个图本来就有 $k$-团，你把某个 $0$ 变成 $1$（也就是加一条边），它肯定还是有。所以取这组单调的门，CLIQUE 这个函数正好落在它们能表达的范围内。

1985 年，当时还属于前苏联／俄罗斯的一位数学家证明：对 CLIQUE 这个函数，用这组单调的门，需要超多项式多个门才能把它算出来——这是一个**超多项式的下界**。老师解释了其中的道理：因为用的这组基不完全，这两个门只能搭出单调函数，但它们可以搭出所有的单调函数，所以这个下界是针对单调函数、单调电路的。

这个结果在当时的 TCS（理论计算机科学）圈子里很震撼，这个证明也是非常非常精彩；大家觉得好像 $\mathrm P\ne\mathrm{NP}$ 很快就能证出来了。但是很多年很多年，这个问题都没有什么进展，电路下界都没有什么进展。

那么现在的情况到底有多尴尬呢？老师给同学们看了一下目前的结果，并指出这里就是我们刚刚定义的那个电路复杂性——有多少个门能把 $f$ 搭出来。他说，所以为什么刚刚那个证明特别精彩呢？就是因为下界到底怎么证：上界的话，你把电路搭出来就行了；可是你怎么证明“小于这么多个门做不到”？证明不了。而且那篇文章只有四页——只有四页的一个证明，就非常精彩。

具体能证到什么程度？老师举了一个小函数的例子。

**例子**：有一个函数叫 MOD 3。这个函数有四个输入，输出为 $1$ 当且仅当这四个输入的和是 $3$ 的倍数，也就是它的和等于 $3$ 或者 $0$。如果我们允许用所有的二元函数（所有二输入的门都可以用），那么最少用 $7$ 个门就可以把它搭出来。并且有人验证过了：$6$ 个门就不行，最少要用 $7$ 个门才能把这个函数搭出来。

老师补充说，他们这个验证的方法比较暴力：他把所有 $6$ 个门所能搭出的电路全部枚举一遍，发现都不行。可是这个方法如果想用来证明 $\mathrm P\ne\mathrm{NP}$ 就没有办法用——你总不可能把所有小于多项式个门的电路全部枚举一遍，然后说“发现都不行”。

所以现在就是这么一个情况，一个非常尴尬的情况：这条路径他们想了很多年。老师说自己也是掉到过这个坑里——读 PhD 的时候也在这个问题上想了几年，想的就是怎么样证明一个超多项式的电路下界，从而证明 $\mathrm P\ne\mathrm{NP}$。但目前的情况是，这是最好的界。

老师把现在最好的结果摆了出来：对于刚刚那个 AND/OR/NOT 门集，现在最好的就是 $5n$——能证明有一个这样的函数，它至少需要 $5n$ 个门去算它。如果考虑允许用所有**扇入**（fan-in）为二的门，现在的结果就是 $3.1n$。2022 年，当时清华大学的两个本科生改进了之前的这个思路。所以这个就是我们目前能够证得的最好结果。

所以大家能感受到：我们要的东西和我们现在有的差很多很多。我们要的是一个超多项式的下界，而我们现在有的下界是 $3.1n$、$5n$，甚至不能超线性。你说能不能证明一个 $n\log n$ 的下界？证明不了。

> **老师总结**：我们人类技术在飞速进步——现在大语言模型能够在对话里写代码，可回收火箭能够自己着陆；但是在理论计算机科学、在 TOC 这个角落里，我们这么多年都停滞不前，我们现在哪怕还没有一个超线性的电路下界。

讲到这里，老师说了声“好”，然后对同学们宣布：课程第一部分关于计算模型的讨论就讨论到这里。

## 七、第二部分导论：可计算性与通用图灵机的定义 [01:29:09–01:42:44]

<!-- 时间范围：01:29:09–01:42:45 -->
<!-- 建议小节：1) 第一部分的收束与第二部分的目标：哪些问题可以被算法解决；2) 给足资源也不能解决所有问题，以及对 AI 悲观论调的回应；3) 通用图灵机的直观：手机、电脑都是一台通用图灵机，饮水机"童锁"与交通灯的讨论；4) 程序即数据、存储程序式体系结构；5) 如何把一台图灵机编码成 0/1 字符串（两条要求、ASCII 方案、编译不起来即永远拒绝、加注释与垃圾状态）；6) 通用图灵机的定理陈述 $U(\alpha,x)=M_\alpha(x)$、三种输出与 $t\log t$ 模拟；7) 下一步：构造这台通用图灵机，以及 1966 年的结果 -->

我们课程的这个叫第一部分，关于计算模型的讨论就讨论到这里；然后我们现在进入了这个课程的第二部分，第二部分我们讨论**可计算性**（computability）。

之前我们做了一件什么事情呢？我们定义好了一台**柏拉图式的计算机**（Platonic computer）：我们的这个计算机的定义不能依赖于任何具体的硬件或者物理实现，它是数学的、是一个概念的定义。用柏拉图的话说，就是一个理念的定义。我们有了这台柏拉图式的计算机。

下一个自然的问题就是：哪些问题是可以被计算的？首先，这个问题的答案有一些出乎意料——**并不是所有的问题都可以被算法解决**。即使我们允许给这个算法足够的资源，就是给他足够的、甚至无限的空间，给他足够的时间，他还是并不能解决所有的问题。

所以这些关于可计算性的内容，就是我们课程第二部分要研究的内容：哪些问题可以被算法解决。

这个跟我们这个时代其实也是特别息息相关的，因为现在关于 AI 有太多悲观的一些论调，认为机器很快会全面取代人，大家就在家天天坐着打打游戏，然后政府就给我们发一些钱，就是人什么都干不了了。

对于一些悲观的这个论调，其实**可能不是这样**。我们通过这一部分的学习，也会揭示一些计算本身的局限性：因为无论它这个计算机有多强，是什么样的深度学习，什么样的大模型，它的本质都是一台图灵机。

> **老师强调**：无论是什么样的深度学习、什么样的大模型，它的本质都是一台图灵机。

所以并不是所有的问题它都能被解决。这就是第二部分要揭示的这种局限：局限不在于算力不够、时间不够，而在于计算模型本身所能做到的事情有一个边界。

我们先研究的是一个什么呢？叫**通用图灵机**（universal Turing machine, UTM）。

什么是通用图灵机呢？就是大家的手机、大家的电脑，这个都是一台通用图灵机。因为我们之前不是构造了很多图灵机：我们构造了图灵机去做加法、做乘法，比如说我们可以构造一台图灵机去算欧几里得算法（Euclidean algorithm）的最大公约数——就是如果你把两个数 $x$、$y$ 装到那个图灵机的纸带上，然后你跑那个图灵机，他就把最大公约数算出来。

那我们是不是对每一个算法都要造一台图灵机呢？我们可不可以就造一台图灵机，然后把算法也写在这个纸带上：把算法写在一条带子上，把输入写在另外一条带子上，然后跑这个图灵机，然后你就有一台图灵机，你就可以跑所有的算法。

> **老师比喻**：这就好比大家去打开手机、去 Apple Store 去下载一个 APP，然后你这个 APP 用完了，你可以下载另外一个。

这个就是通用图灵机。

另外一个原因，就是说我们用通用图灵机去证明一些可计算性、不可计算性的结果：就是因为我们有了一台通用图灵机之后，我们就可以去模拟其他的图灵机。这是后面所有关于"能不能算"的结论的操作抓手——凡是需要谈论"某台机器在某个输入上会怎样"的地方，都可以改成让通用图灵机去跑它。

还有一个原因，它就是**存储程序**（stored program）：存储程序这样的一个体系结构，就是一台通用图灵机。就是我们跑一个程序的时候，程序是存在内存上的；所以那个程序就是写在这个图灵机的纸带上的，程序是存储在纸带上。这个就是一台通用图灵机。

就像存储程序大概是这样：就刚刚的那些指令，这些指令就是存放在内存上；然后内存里面既存放这个指令（也就是程序），又存放数据。内存不区分"代码"和"数据"，两者都是同一批内容、放在同一个地方——这正是"程序即数据"这一说法的直接来源。

那对于 UTM 就这样：比如说我们可以把这个程序 $\alpha$ 编码成一串，然后中间可以加一个特殊符号，一个分隔符，$w$ 就是输入；然后我们把程序放在这里，把输入放在这里，然后我们就跑这个通用图灵机，然后他就在执行这个程序。这就是通用图灵机的一个想法。也就是说，纸带上的内容按

$$
[\ \alpha\ ]\quad [\ \text{特殊符号（分隔符）}\ ]\quad [\ w\ ]
$$

这样的顺序摆放：$\alpha$ 是程序（也就是那台被模拟的图灵机）的编码，中间用一个特殊符号作分隔符把程序与输入隔开，$w$ 是待处理的输入；通用图灵机读这段内容，就相当于在执行 $\alpha$ 所描述的那台机器。

哪些是通用图灵机呢？像大家用的笔记本电脑、桌面电脑，像一些智能手表，都是通用图灵机。

之前老师去那边接水，接水不是有热水还是冷水吗？热水冷水。有些饮水机上还有"童锁"，就你现在把童锁打开，然后你才可以接热水。那个是不是一个通用图灵机？可能不是，可能不是，应该不是。还有像这种交通灯，交通灯应该不是通用图灵机。

老师用这两个例子要说明的是：并不是所有会"按规则动作"的机器都算通用图灵机。通用图灵机的要求是能读入一份对算法的描述、并据此执行那个算法；饮水机的童锁开关和交通灯的定时切换都只有固定几档行为，谈不上"把算法写在纸带上再跑"，所以老师把它们判为不是通用图灵机。

所以第一件事情，就是我们怎么样把一台图灵机编码成这个字符串。

怎么样把图灵机编码成字符串呢？方式可以有很多很多，然后我们的要求就是：

1. **每一个字符串都代表了一个图灵机**。如果这个字符串是 $\alpha$，这个图灵机就记为 $M_\alpha$。
2. **每一台图灵机都被无限多的字符串表示**。

我们不关心具体是怎么编码的，我们只需要这个编码方式满足这两个条件就可以。

那具体怎么编码呢？就是图灵机就是一段程序，程序就是用 **ASCII 码**编码的，然后我们把 ASCII 码转换成二进制，二进制的一串就可以了。就像我们经常在用的这个——这个图灵机就是一个文本文件，ASCII 码编码的；然后我们把这个 ASCII 码编码的转换成一个 0/1 串就可以了，这就是一个图灵机的编码。

那怎么样满足第一个条件呢，就是每一个字符串都代表一个图灵机？如果它这个编码是乱的，我们如果在里面插入了一些东西，就是它不是一个合法程序——如果这个程序没法编译怎么办？编译不起来怎么办？那我们就认为：**如果这个程序编译不起来，我们就认为它永远拒绝**。永远拒绝也是图灵机的一种行为，于是任何一个字符串都被指派了一台图灵机（哪怕是一台什么都不干、只会拒绝的机器），第一个条件就满足了。

那怎么样保证每一台图灵机都有无限多种的编码方式呢？因为我们希望无论这个字符串多长，都可以找到一种方式，就是每台图灵机都有无穷多种方式去编码它。这个只要加一些注释就可以了，或者加一些这种垃圾状态，就是加一些永远到达不了的状态；或者在代码里面加一些注释就可以了。

所以我们就固定一种编码方式，然后我们可以把任何一个图灵机都编码成一个字符串，并且满足这两个条件。然后我们就可以选定这个——就是我们用的这个**模拟器**（simulator），以及模拟器的这个编码方式：编码方式固定下来之后，通用图灵机才知道纸带上那段 0/1 串该怎么读成一台机器。

然后我们就是说，下面还要证明的结论就是这样的一个结论：我们就构造了一个通用的图灵机。这里说"there is"是存在的，其实我们已经把它构造出来了：构造了一个**两条带**（两个带）的图灵机，这个图灵机可以模拟任何的图灵机，在上述的编码方式下。

**定理**：存在一台两条带的图灵机 $U$，它按上述编码方式可以模拟任何图灵机，即对任何图灵机 $M_\alpha$ 与任何输入 $x$ 都有

$$
U(\alpha,x)=M_\alpha(x),
$$

其中 $\alpha$ 是一台图灵机的编码，$x$ 是输入，$x$ 和 $\alpha$ 都是 0/1 串；右端 $M_\alpha(x)$ 代表 $\alpha$ 所代表的那台图灵机在输入 $x$ 之下的输出。

这里其实输出有 3 种：就是接受、拒绝或者死循环；死循环也是一种可能性。

这台图灵机它就是在**忠实地模拟**被模拟的那台图灵机：被模拟的机器接受，它也接受；被模拟的机器拒绝，它也拒绝；被模拟的机器死循环，它也死循环。它只承担模拟器的角色，而这个模拟器就是我们说的通用图灵机。

并且这个图灵机还是比较高效的。如果 $M_\alpha$ 执行了 $t$ 步内停下来，那么这个通用图灵机执行了多少步呢？就是 $t\log t$ 步停下来。如果 $M_\alpha$ 停不下来，这个通用图灵机也停不下来；如果 $M_\alpha$ 死循环，这个通用图灵机也死循环。

- $M_\alpha$ 在 $t$ 步内停机 $\Rightarrow$ $U$ 在 $t\log t$ 步内停机，即模拟的时间开销是 $O(t\log t)$；
- $M_\alpha$ 不停机 $\Rightarrow$ $U$ 也不停机；
- $M_\alpha$ 死循环 $\Rightarrow$ $U$ 也死循环。

三句话合起来就是"忠实模拟"在时间上的含义：$U$ 不会比被模拟的机器多算出什么，也不会在被模拟的机器不停机时反而停下来。

所以下面要做的就是这件事情：我们下面这节课就是要证明这样的一个定理，或者说我们就把这样的一台通用图灵机给构造出来。老师说明，这是 **1966 年**的一个结果。

## 八、通用图灵机的构造：O(T²) 的模拟与 T log T 的改进 [01:52:45–02:12:59]

<!-- 时间范围：01:52:45–02:13:00 -->
<!-- 建议小节：1) 构造一台通用图灵机要解决什么问题；2) $O(T^2)$ 的简单证明：多带转单带，再用两条带模拟；3) 模拟一步的代价与"程序长度是常数"；4) 怎么把 $T^2$ 改进到 $T\log T$：扩大字母表把 $k$ 条带压成一条带；5) 关键想法：指针不动、整体移动纸带，以及它的 $O(T)$ 代价；6) 思想来源：vector 的倍增与平衡树的不变量；7) 存储组织：原点与 $2$ 的幂大小的区；8) 维持的不变量与左移算法的引入 -->

课间之后，老师接着上一节末尾的结论往下讲。下面要证明一些可计算性、不可计算性的结果，比如"为什么图灵停机问题不可判定"。要得到这类结论，首先需要构造一台通用图灵机（universal Turing machine, UTM）。

> **老师提示**：大家的手机、笔记本电脑都是一台通用图灵机。

换句话说，通用图灵机就是一台模拟器。它的输入是另外一台图灵机（记作 $\alpha$，也就是一段程序）以及这段程序的输入 $X$；它做的事情就是忠实地模拟 $M_\alpha$ 在输入 $X$ 上的运行。现在我们要把它真正构造出来。

我们构造的这台机器是一台多带图灵机，而且效率还不错：被模拟图灵机跑 $T$ 步，它跑 $T\log T$ 步。这个证明的技术难度主要在多带这一侧。

如果不考虑效率，构造一台模拟器其实是挺容易的。老师建议同学们可以选一门自己最熟悉的语言，比如 Python 或者 C，手搓一个模拟器，或者干脆让 AI 帮忙搓一个：输入是另外一段图灵机程序，你要做的就是模拟它的左移、右移，并改写纸带。这样的代码大概一百到两百行就能写出来。写完之后，再通过上一节课讲的那条链条——编译成汇编、汇编转成 RAM 图灵机、再转成多带图灵机——就得到了一台通用图灵机。沿着这条链条直接得到的是 $T^2$。反过来，如果把多带变成 RAM，这个模拟没有任何损失，或者说只差一个常数，$T$ 就变成 $O(T)$；而如果直接由 RAM 转多带，$T$ 就变成 $T^2$。所以整个证明的技术难度，就在于怎么把 $T^2$ 做到 $T\log T$ 上面。

> **老师总结**：构造这样一台 UTM 本身不是太难；技术难度主要在怎么把 $T^2$ 做到 $T\log T$。

老师把本节的任务说得很清楚：下面 40 分钟就做这一件事情，证明这样一个结论——构造一台通用图灵机，它可以模拟任意的图灵机。有了这台通用图灵机之后，因为程序本身可以作为输入的一部分，我们只需要一台机器就够了，不需要为每一个算法单独去构造一台图灵机。

先给一个简单的证明，就是 $T^2$ 的那个证明。第一步依据上一节课的结论：设 $M_\alpha$ 是一台多带图灵机，我们把它转成单带图灵机，这一步转换使时间从 $T$ 变成 $T^2$。

第二步，我们再用多带图灵机去模拟这台单带图灵机——准确地说，是用两条纸带的图灵机去模拟单带图灵机。这是很容易模拟的，做法是：

1. 第一条纸带专门存放被模拟的那台单带图灵机的描述。我们把被模拟的单带图灵机记作 $\alpha'$（读作 alpha prime），它的描述就放在第一条纸带上；同时这部分还要记录它当前的状态，而状态的长度是 $O(1)$，所以 $O(1)$ 的空间就够了。
2. 第二条纸带忠实地模拟 $\alpha'$ 的那条纸带，并且读写头（指针）的位置也完全跟着走：$\alpha'$ 的读写头停留在哪里，第二条纸带上的读写头就停留在哪里。
3. 每模拟一步，它先去读一下第一条纸带上的描述，找到对应的转移函数；找到转移函数之后，就按照这个转移函数左移或者右移，并改写第二条纸带上的符号。

这一整套动作的代价是常数，因为程序本身是固定长度的：程序的长度是 $O(1)$，$\alpha'$ 是固定的，所以我们在这读一遍描述、修改一遍状态，整个代价都是 $O(1)$，都是一个常数。于是总时间就是 $T^2$ 乘一个常数，而这个常数只跟 $\alpha'$ 有关。这里就用到了之前介绍过的大 $O$ 记号的下标写法：因为常数值和 $\alpha$ 有关，就把 $\alpha$ 放在大 $O$ 的下面（下标位置），即 $O_{\alpha'}(T^2)$。

> **老师强调**：咱们尽量不要把手弄脏。有时候看到一些很复杂的计算就头疼，我们尽量把计算保持在极少，不要做太多计算，保持的时候都干净。

把"模拟一步"这件事拆开看，一共只需要三个动作。第一步，读第二条纸带上指针指向的那个符号。第二步，扫描一遍第一条纸带，找到 $\delta$ 中适用于当前状态 $Q$ 和当前符号 $S$ 的转移规则；这一步用 $O(1)$ 的时间就可以做到。第三步，我们去移动、更新这个符号，移动指针，并且更新状态 $Q$。这三步操作都可以在 $O_{\alpha'}(1)$ 的时间内完成。原因还是那句话：程序的长度是一个常数，也就是图灵机的描述是一个常数。前面多带转单带已经把 $T$ 变成了 $O(T^2)$，这里再乘一个 $O(1)$，所以一共是 $O(T^2)$。

这里还有一个假设，就是 $T \ge N$（$N$ 是输入长度）。之所以可以这样假设，是因为我们一开始做了一次拷贝：把输入 $X$ 拷贝到了第二根纸带上。这次拷贝的代价是 $O(N)$，由 $T \ge N$ 吸收掉。到这里，我们就已经得到了一台通用图灵机，只是它的模拟不是那么高效，是 $O(T^2)$。

这台 $O(T^2)$ 的通用图灵机对于我们后面也够用了：如果只考虑可计算性，我们不是太在乎它的效率。但如果是计算复杂性，就要考虑得更精细，更精细的话就需要这个模拟高效一点比较好。

接下来讲怎么做到 $T\log T$。主要想法是这样的：第一根纸带仍然保存那段程序，也就是之前那台图灵机的描述，外加它当前的状态。

麻烦在第二条纸带。被模拟的本来就是一台多带图灵机，我们现在是用多带模拟多带——那它到底有几条带呢？它可能有 $K$ 条带，可能有十条带，也可能有一百条带。所以难度主要在于：我们要用两条纸带的图灵机去模拟一百条纸带的图灵机。（如果说用三条纸带模拟两条纸带，那只是常数，常数乘上去就行了，不是难点所在。）

办法是：把这一百条带子全部压缩到第二条纸带上，也就是让字母表扩大，把这一百条带子的内容压在一条带子上。具体做法就是把字母表从 $\Gamma$ 扩大成 $\Gamma^k$，这样一条带子就存了 $k$ 条带子的内容。这一步我们是可以承受的，因为 $\Gamma^{100}$ 仍然是一个常数。

但是麻烦在于我们怎么移动。原来各条纸带的读写头是独立移动的：老师举了三个颜色的指针为例——红色（第一条带子）的指针不动，绿色（第二条带子）的指针左移，紫色（第三条带子）的指针右移，三条带的读写头可以在同一步朝各自不同的方向移动。

> **老师强调**：这里有一个比较关键的想法——我们不去移动指针，我们去移动整个纸带。

每次本来读写头要左移或者右移，现在我们让读写头不动，改为把整个纸带往左移一格、往右移一格。于是指针左移就等于把整个纸带往右移，指针右移就等于把整个纸带往左移。

问题又来了：移动整个纸带的代价是 $O(T)$。我们要把整个长度为 $T$ 的内容左移一下，移动整个纸带就是线性时间。

那么怎么把这个线性时间做到均摊 $\log T$ 时间呢？老师说这个想法在计算机里面用得非常多。大家用 C++ 的时候都用过 vector：vector 其实就是一个数组，但它是一个变长数组，每次可以 `push_back`，就是在后面加一个元素进去。如果自己用一个数组加元素，万一空间不够了怎么办？空间不够，你就要去堆（heap）里面再 allocate 开一块。那 vector 是怎么做到的呢？它是每次翻倍。

具体来说：一开始给你的数组大小是 1024，然后你不停地往里面塞，不停地 `push_back`，可以不停地加元素，也可以减元素。1024 用满了之后它翻倍：先把整个旧空间释放掉，再去要一块 2048 的，然后把 1024 个元素拷贝过去，于是你就多出来 1024 个位置，可以继续不停地加。它可以自动地每次用完了就把那个空间 double 一下。

这种想法在平衡树里面用得也比较多：平衡树里面有一些操作，均摊下来都是 $\log$ 的，用的就是这样的一个想法。

放到纸带上，做法就是我们在纸带上加很多的缓冲。屏幕上画出来的那个方块，老师叫它"缓冲"。

> **老师强调**：这个缓冲不是空，空格是空格——它就是一个正常的字符。

而且缓冲没有任何实际意义：我们读到这个缓冲，是把它丢掉的，它就是一种占位符。正因为有很多缓冲，我们每次整体移动这个纸带的时候，就可以把这个代价做到均摊，可以做到 $\log T$。老师补充：如果一根带子上有很多缓冲，那些没有缓冲的地方才是真正的内容，比如机器的描述（MACHINE），而缓冲就不去读它。大体上就是这个想法。

> **老师总结**：我们很仔细地在纸带上加入很多缓冲，然后维持一些不变量，就像平衡树的一些不变量一样；很仔细地做这个事情，然后使它的均摊做到 $\log T$。

技术上是这样的：首先我们把整个纸带进行一个分区，分成原点（origin）和左右两侧——最中间就是指针指向的那个字符，它的左边依次是 $L_0,L_1,L_2,\dots$，右边依次是 $R_0,R_1,R_2,\dots$。每个区 $R_i$ 的大小都是 2 的幂，就是不停地翻倍：中间指向的只有 1 个字符，$R_0$ 是 2 个字符，$R_1$ 是 4 个字符，$R_2$ 是 8 个字符。它为什么这样翻倍？就是跟 vector、跟 C++ 里面那个数据结构 vector 是一个道理。做了这样的分区之后，每个格子都属于某一个区。

那么一共会有多少个区呢？一共最多有 $\log T$ 个区。为什么呢？因为这台图灵机的时间是 $T$，那么空间肯定不超过 $T$；最坏的情况就是它不停地向右移，读写头最多扫过 $T$ 个格子。所以它最多用到的分区就是 $\log T$ 个。屏幕上用方框代表一个缓冲，画出来的那张图，画的就是我们怎么样对图灵机的纸带做分区：中间是原点，两侧是 $L_0,L_1,R_1$ 这些区。

> **老师强调**：最关键的就是我们维持哪些不变量。

老师说要自始至终维持三个不变量，这三个性质必须满足。为什么呢？因为我们希望每一次均摊——也就是每次操作均摊下来的复杂性——都是 $\log T$。老师补充说，类似的这种想法其实并不少见，特别是在平衡树里；大家学数据结构的时候都会用到类似的想法。

第一个不变量：每个区要么是空的，要么是满的，要么是半满的。也就是说，每个区里面缓冲元素的个数要么是空（$0$），要么是 $2^i$，要么是 $2^{i+1}$，分别对应半满和全满（$2^i$ 就是该区容量的一半，$2^{i+1}$ 就是装满整个区）。

第二个不变量：左边和右边并起来——就是对应的分区 $L_i$ 和 $R_i$ 并起来——它正好有 $2^{i+1}$ 个缓冲。于是有这三种情形：如果左边是满的，右边就是空的；左边是空的，右边就是满的；或者左边半满，右边也是半满。也就是说，左边和右边的缓冲加起来一共就是这么多个，正好是一半一半。

再说明一下图上的原点：中间那个圆点就是指针指向的那个元素，它不可以是一个缓冲，它就是指针指向的那个元素。

> **老师提示**：我们下面要做的事情，就是从技术上确认：在维持这些性质的时候，做一次左移、做一次右移，它的均摊时间复杂度就是 $\log T$。

老师说明，下面 15 分钟就是做这样一个证明。而这里最关键的就是左移和右移的算法到底怎么写。因为左移和右移完全对称，所以我们只需要考虑左移。

所谓左移，就是把整个纸带左移一位，也就是把非缓冲字符左移一位。怎么左移呢？我们找到最小的那个下标 $i_0$，使得 $R_{i_0}$ 是非空的；于是 $R_0,R_1,\dots,R_{i_0-1}$ 都是空的，再根据之前的那个性质，$L_0$ 一直到 $L_{i_0-1}$ 都是满的。

屏幕上这张图就是左移。什么叫左移？指针本来是要指向下一个位置的（也就是指针要右移），但是我们不去移动这个指针，而是把整个纸带往左移。

## 九、均摊分析和 O(T log T) 模拟定理：函数的不可数性 [02:13:02–02:29:02]

<!-- 时间范围：02:13:02–02:29:02 -->

指针右移就等于把纸带左移。这句话是整个存储组织方案的实现诀窍：要让读写头“向右走”，并不去移动读写头，而是把整条纸带向左移，于是原本在读写头右边的字符会整体移过原点。按这个做法，字符 $N$ 正好被放到中间，$E$ 排在它后面，$I$ 再往后一位；在这些插入进来的位置之间，可以任意地放入一些缓冲。下面要做的事情，就是实现这样的一个左移。

为此要把左移的完整步骤写清楚。第一件事情是找到指标 $i_0$；然后把 $R_{i_0}$ 最左边的那个字符移动到原点；接着把剩下的字符填充到 $R_0$ 到 $R_{i_0-1}$ 这一串区里；最后，因为左侧是满的，就从左侧满的区里拿一半出来，去填满相应的 $L_{i_0}$。整个过程花的时间是线性的，也就是 $O(2^{i_0})$。

**算法**：一次纸带左移的操作如下。

1. 找到最小的指标 $i_0$，使得 $R_{i_0}$ 非空（在前面已建立的记号里，纸带在原点两侧被分成一对一对的区 $R_0,L_0;R_1,L_1;\dots$，其中 $R_i$ 在原点右侧、$L_i$ 在原点左侧；不变量是每一对 $R_i,L_i$ 恒为半满。本片的推导与例子只用到“每一对 $R_i,L_i$ 的容量为 $2^i$”以及“非空、非满、半满”这几个状态，不额外依赖该容量的具体分配方式）。
2. 把 $R_{i_0}$ 最左边的那个字符移动到原点（也就是读写头当前所在的位置）。
3. 把 $R_{i_0}$ 剩下的字符整体前移，填充进 $R_0,R_1,\dots,R_{i_0-1}$ 这些空区。依据是：$R_{i_0}$ 非空，所以它要么是半满、要么是全满，无论哪种情况都还剩下一半的字符；而 $R_0$ 一直到 $R_{i_0-1}$ 全是空的，所以这些字符正好可以全部填进去。
4. 左侧做完全对称的操作：$L_0$ 一直到 $L_{i_0-1}$ 都是满的，所以从这些满区里拿一半出来，放到 $L_{i_0}$。依据是：既然 $R_{i_0}$ 非空，那么 $L_{i_0}$ 肯定是非满的，它有一半的空间来装这一半字符，装完就装满了。
5. 这一步的目的是保持不变量：$R_0$ 一直到 $R_{i_0-1}$ 现在是半满的，所以对应的 $L$ 侧（$L_0$ 一直到 $L_{i_0-1}$）也必须保持半满。经过上面的搬运，整个性质得到了保持。
6. 以上所有搬运涉及的字符总数，等于这些分区的长度之和；这些长度加起来是 $O(2^{i_0})$，所以整体操作花的时间是线性的，即 $O(2^{i_0})$。

一次左移的代价与 $i_0$ 绑定，这一点后面要用到：找到的指标越大，一次操作搬动的字符就越多，代价就是 $2^{i_0}$ 量级。

在这之前先看一个具体的例子，把上面的步骤走一遍。

**例子**：设这次要做一次纸带左移，取到的指标是 $i_0=1$。$i_0$ 的含义是“最右边那个非满的区域”（字幕此处记为“非满的这个区域就是一就是 $L_1$”，可确定该非满区域就是 $L_1$）。逐步过程如下。

- 把 $R_{i_0}=R_1$ 的第一个字符（例中的字符是 $N$）移动到中间，也就是原点。
- $R_1$ 剩下的一半字符接着填充过去，恰好占满 $R_0$ 的一半；例中把 $E$ 移动到这一半的位置上。
- 这边（左侧 $L_0$ 一侧）是满的，所以再拿出一半，也就是把字符 $C$ 拿出来，去填满 $L_{i_0}=L_1$。
- 整条纸带的数据没有丢失也没有凭空增加：原来分布在 $L_0,R_0$ 与 $R_1$ 上的字符，经过“取出最左字符放到原点、余下部分前移填空、左侧让出一半补到 $L_1$”这三步搬运之后，每一对 $R_i,L_i$ 仍然是半满的。
- 这样的一次移动，它的代价是线性的。

例子里老师逐个搬动字符 $N$、$E$、$I$、$C$。

现在来回答代价问题。单次移动的代价是线性，最坏情况下有可能是 $O(T)$——因为 $i_0$ 最大可以到 $\log T$ 量级，对应的 $2^{i_0}$ 就是 $T$ 量级。那么，怎么可能均摊出 $\log T$ 这个因子呢？这就要做均摊分析。

**推导**：均摊分析的第一步，是给出“指标为 $i$ 的移动”出现频率的上界。

1. 一开始所有的区都是半满的。
2. 每次做完一次左移或者右移，记这次操作的指标为 $i$。如果这次的指标大于等于 $i$，那么它接下来的 $2^i-1$ 次移动，指标都小于 $i$。
3. 为什么？因为做过这样一次移动之后，这些中间的区域都被搬成了半空（也就是半满的相反状态）。具体说，一开始 $R_0$ 一直到 $R_{i-1}$ 都是空的；记这段区域中的字符数量为“非缓冲字符数”$S$，于是此时 $S=0$。
4. 做完一次指标 $\ge i$ 的移动之后，这些区被填充成一半，$S$ 就不再是 $0$，而变成 $2^i-1$。这个数是对一个几何级数求和得到的：第 $j$ 个区（$j=0,1,\dots,i-1$）的容量是 $2^j$，半满就是 $2^{j-1}$ 个字符（$j=0$ 时这一对区只有 $1$ 个字符位，半满记 $0$ 个），所以
$$S=\sum_{j=0}^{i-1}2^{j-1}=2^i-1$$

5. 而每一次指标小于 $i$ 的移动，它只是移动一个字符过来，所以它只会让 $S$ 加减 $1$。
6. 于是要把 $S$ 从 $2^i-1$ 变到 $0$，至少要 $2^i-1$ 次、也就至少需要 $2^i$ 次这样的移动。
7. 也就是说，一次指标 $\ge i$ 的移动之后，必须再积累至少 $2^i$ 次小指标的移动，才可能重新看到一次指标 $\ge i$ 的移动。
8. 作为这个结论的推论：如果下标为 $i$ 的移动出现了一次，那么下面接下来的 $2^i-1$ 次移动指标都小于 $i$；而一开始都是半空的，所以它至少需要 $2^i$ 次移动，然后才可能看到一个指标是大于等于 $i$ 的移动。
9. 总共只有 $T$ 次移动，因此指标为 $i$ 的移动次数至多是 $T/2^i$。用老师的话说：如果一次这个指标很大，那下面就是都很小、都很小。

**推导**：把每次移动的代价加起来，用算两次（double counting）的方法得到 $O(T\log T)$。

1. 记每次左移或右移得到的指标依次为 $i_0,i_1,\dots$（这里的下标只是给每次移动编号，与前面那个区间指标 $i_0$ 的记法重名，注意区分）。每一次移动的代价是 $O(2^{\text{指标}})$，所以总代价就是要把 $2^{i_0}+2^{i_1}+2^{i_2}+\cdots$ 这个和算出来。
2. 直接按项相加无从下手，老师用的方法叫“算两次”，也就是 double counting：把所有指标为零的项放一组，指标为一的放一组，依此类推。
3. 本来是对所有项求和；现在改成先对每一组内部求和，再乘以这一组里面有多少个元素。
4. 每一组的元素个数由前面的推论给出上界：指标为 $0$ 的那一组不超过 $T/2$，指标为 $1$ 的那一组不超过 $T/4$，接着是 $T/8$，依此类推。老师特别说明，这些上界就是根据刚刚那个推论来的。
5. 再看每一组内单次移动的代价：指标为 $0$ 的移动代价是 $O(1)$，接下来依次是 $O(2)$、$O(4)$、$O(8)$，即 $O(2^j)$。
6. 把“组内元素个数”与“组内单次代价”乘起来：每一组都得到 $O(T)$、$O(T)$、$O(T)$、$O(T)$……
7. 一共有多少个这样的组？一共有 $\log T$ 个。
8. 于是总和是 $O(T\log T)$。老师顺手挡掉一个可能的疑问：这不是 $T+1$ 吗？——那个 $+1$（以及常数因子）被大 $O$ 吃掉了。

把第 4–8 步列成表看得更清楚。这里把“每个指标一组”归并成“每段指标一组”：组 $j$ 内含有指标 $2^j,2^j+1,\dots,2^{j+1}-1$，共 $2^j$ 个指标，组内任一次移动的代价都是 $O(2^j)$；而这一段里出现次数最多的那个指标（即 $2^j$）已经满足“次数至多 $T/2^j$”，所以整组的次数上界仍可取 $T/2^j$，会比逐指标相加更宽，但不影响结论。

| 组 $j$ | 组内指标范围 | 组内移动次数上界 | 组内单次代价 | 该组总代价 |
|--------|--------------|------------------|--------------|------------|
| $0$ | $0$ | 至多 $T/2$ | $O(1)$ | $O(T)$ |
| $1$ | $1,2$ | 至多 $T/2$ | $O(2)$ | $O(T)$ |
| $2$ | $3,\dots,6$ | 至多 $T/4$ | $O(4)$ | $O(T)$ |
| $j$ | $2^j-1,\dots,2^{j+1}-2$ | 至多 $T/2^j$ | $O(2^j)$ | $O(T)$ |

（表中特意取宽的上界，例如组 $1$ 的真实上界是“指标 $1$ 不超过 $T/2$、指标 $2$ 不超过 $T/4$，合计不超过 $3T/4$”，这里统一记作 $T/2$；取宽只会让结论更保守。）

一共有 $\log T$ 组，每组都是 $O(T)$，所以 $\sum_{j=0}^{\log T}O(2^j)\cdot O(T/2^j)=O(T\log T)$。

老师又用另外一种方式把这个和重新数了一遍，说明两种数法结果一致。黑板上写的那样一行拿出来，这一行就是 double counting，可以这样算，也可以那样算。换一种数法：按指标的取值 $J$ 来分类——下标指标为 $J$ 的移动一共有多少个？根据推论，不超过 $T/2^J$ 个；而每个这样的移动的代价是 $O(2^J)$。乘起来：

$$O(2^J)\cdot\frac{T}{2^J}=O(T)$$

也就是说，每一个固定的指标值（表中的“一列”）自己就贡献 $O(T)$；而指标一共只有 $\log T$ 个，所以还是

$$\sum_{J=0}^{\log T}O(T)=O(T\log T)$$

到这里，单根带子上的记账结束。老师接着把结论推到多带的情形：对于每根带子都是这样，一共有 $K$ 根带子，所以是 $K\cdot O(T\log T)$；而 $K$ 可以被大 $O$ 继续吃掉——做法是把 $K$ 写在 $O$ 的下标位置，于是写成 $O_K(T\log T)$。这样就证明结束。

把上面一整条链路连起来看：被模拟的多带图灵机每走一步，模拟器要花 $O(2^{\text{该步的指标}})$ 的时间去搬运纸带；由均摊分析，指标为 $i$ 的步骤在 $T$ 步里至多出现 $T/2^i$ 次；按指标分组、组内“次数上界 × 单次代价”相乘，每一组都是 $O(T)$，而组的个数是 $\log T$，所以单根带子上的总开销是 $O(T\log T)$。若被模拟的多带图灵机执行 $T$ 步，则单带通用图灵机的模拟需要 $O(T\log T)$ 步。

现在把通用图灵机这件事总结一下。我们构造了这样的一个通用图灵机（universal Turing machine, UTM），这个通用图灵机就是一个模拟器；这个模拟器的输入是另外一台图灵机**和它的输入**。然后我们的通用图灵机就忠实地模拟了那台图灵机，它模拟的时间是 $T\log T$。如果被模拟的那台图灵机没有停机、陷入了死循环，那么我们的通用图灵机也会死循环。

有了这样的通用图灵机之后，我们就不必为每一个算法都造一台图灵机了。而更重要的是它对于我们做可计算性的用途：有了这样的一个模拟器之后，我们就可以证明一些问题不可以被计算，比如停机问题（halting problem）。

> **老师总结**：这个证明大概就是五分钟，但它是特别重要的一个证明——无论是对于计算机还是对于数学。

老师接着交代了这个结果的难度性质：它的难度主要不在于技术上的难度，不是说我们做了几页的计算，而是哲学上、想法上的难度。虽然这个证明我们可能五分钟或者两分钟就把它做掉了，但它是一个很重要的结果，是一个很有深度的结果。

老师把问题说白：为什么停机问题不可以被判定？为什么你没有办法写一个程序去判断另外一个程序会不会死循环？

**推导**：先“count 一把”，得到“几乎所有的语言都是不可判定的”。

1. 老师先立一个态度：我们都会 count 一把——技术往往都是最简单的，我们先算一把，也就是先算一笔总账。
2. 一个语言就是一个 0/1 串的集合，也就是 $\{0,1\}^*$ 的一个子集。
3. 0/1 串本身是一个无穷集，而且这是一个**可数**的无穷集。
4. 一个可数的无穷集有多少个子集呢？有不可数个子集，也就是 $2^{\aleph_0}$ 个（字幕记为“二列负一”，是老师对 $2^{\aleph_0}$ 的口述）。由于从 $\{0,1\}^*$ 到 $\{0,1\}$ 的每个函数都由“取值为 1 的那些串”这个子集唯一确定，$\{0,1\}^*$ 的子集数就是这样的函数的总数。
5. 而图灵机肯定是可数的——因为每个图灵机都可以编码成一个 0/1 串，而 0/1 串是可数的。
6. 每个可判定的语言都要由某台图灵机来判定，所以可判定的语言只有可数多个；而语言总数是不可数多个。
7. 因此几乎所有的语言都是不可判定的。

同样的结论老师重复了一遍，提醒这是本节的落脚点：几乎所有的语言都是不可以判定的。

但紧接着的问题是：怎么样证明某个**具体**的语言是不可以判定的呢？老师用电路复杂度作了一个类比。就像我们知道几乎所有的函数，它的电路复杂性都是高的、都是很大的——$2^n$ 那种，$2^n/n$ 这种，或者说 $2^{\Omega(n)}$——但是我们找不到一个具体的函数，它的电路复杂性很大。这正是“几乎所有的函数都难”与“找不出一个具体的难函数”之间的落差。

> **老师总结**：就是在很多时候我们遇到的都是这样一个困境——我们知道它大量存在，并且你随机抓一个，它就是满足这个性质，但是构造不出来。

这个困境是本节末尾的引子。老师把即将给出的证明称为“一句话的证明”，并开始给出它的准备步骤。

**推导**：构造一张表，为后面“翻对角线”做准备。

1. 首先把图灵机枚举一下：因为图灵机是可数的（等价地，0/1 串是可枚举的），所以把它们排成一列，记作 $M_0,M_1,M_2,M_3,\dots$，也就是第零个图灵机、第一个图灵机、第二个图灵机、第三个图灵机……
2. 输入也是字符串，同样可枚举，所以把输入串也排成一列，记作 $S_0,S_1,S_2,S_3,\dots$。
3. 然后画一张巨大的表。表中每个元素是什么呢？是“这个图灵机在这个输入字符串下的结果”，也就是 $M_i$ 在输入 $S_j$ 上的运行结果。
4. 结果有三种：要么接受、要么拒绝、要么死循环。老师给这三种结果各一个记号：$A$ 就是 accept（接受），$R$ 就是 reject（拒绝），$L$ 就是 loop forever，也就是死循环。
5. 构造的目标：现在要构造一个语言，让所有的图灵机都没有办法判定它。

这张表按上面的记号可以写成下面的形状（行是图灵机、列是输入串，$M_i$ 在 $S_j$ 上的结果就是第 $i$ 行第 $j$ 列的元素）：

| | $S_0$ | $S_1$ | $S_2$ | $\cdots$ |
|---|---|---|---|---|
| $M_0$ | $A$ 或 $R$ 或 $L$ | $A$ 或 $R$ 或 $L$ | $A$ 或 $R$ 或 $L$ | $\cdots$ |
| $M_1$ | $A$ 或 $R$ 或 $L$ | $A$ 或 $R$ 或 $L$ | $A$ 或 $R$ 或 $L$ | $\cdots$ |
| $M_2$ | $A$ 或 $R$ 或 $L$ | $A$ 或 $R$ 或 $L$ | $A$ 或 $R$ 或 $L$ | $\cdots$ |
| $\vdots$ | $\vdots$ | $\vdots$ | $\vdots$ | $\ddots$ |

本片就写到这里：可数性已经给出“不可判定的语言大量存在”这一存在性结论，并已经枚举出 $M_i$、$S_j$ 并画好了这张表；至于具体怎么利用这张表构造出一个让所有图灵机都判不了的语言，也就是“把对角线翻过来”的那一步，是下一段的内容。

## 十、停机问题的不可判定性：对角化构造 [02:29:02–02:37:49]

<!-- 分片：T10　责任字幕：2041–2203　时间范围：02:29:02–02:37:49 -->
<!-- 建议小节：1) 问题与做法总纲：把对角线整个翻过来；2) 逐条翻转对角线，得到 $L_{\text{flip}}$；3) 课堂问答与复述；4) 巨大的表与"刻意翻转对角线"；5) 图灵的证明与下一步的停机问题；6) 反证法的形式证明；7) 结课与下周见 -->

前一节已经得到两个事实：图灵机是可枚举的，可以排成 $M_0,M_1,M_2,\dots$；输入字符串也是可枚举的，可以排成 $S_0,S_1,S_2,\dots$。由此还得到过"函数不可数"这个结论，也就是说确实存在不可计算的函数。但那一步是存在性论证——它只说明不可计算的东西存在，并没有具体指出是哪一个。所以老师在这里提出问题：那我们怎么办？我们要具体构造出一个语言，让所有的图灵机都没有办法判定它。

做法是：把整张巨大表的**对角线**取出来，然后把这条对角线整个翻过来。老师明确说，这就是我们接下来要用的构造，它和前面证"整数集与实数集之间没有双射"时用的完全是同一套手法——那一次就是把对角线翻过来，从而造出一个不在任何枚举位置上的对象，现在照样翻一遍。

具体地看对角线上的每一个格子。假设看对角线上的 $S_0$ 与 $M_0$：$M_0$ 在 $S_0$ 上的运行结果是 $R$，也就是拒绝。那我们就反过来要求它接受——我们构造一个语言，让这个语言**包含** $S_0$，也就是要求 $M_0$ 接受 $S_0$。这样一来，同一个输入 $S_0$ 上，机器的实际结果是拒绝，语言的要求是接受，两者对不上，$M_0$ 就被排除掉了。

再看 $M_1$ 与 $S_1$：$M_1$ 在 $S_1$ 上的运行结果是死循环，也就是 $L$。那我们也要求它接受，也就是把 $S_1$ 放进这个语言里，于是 $M_1$ 同样被否定。这里老师把正在构造的对象直接称为"对角线化的语言"。

再看 $M_2$ 与 $S_2$：结果是拒绝。拒绝那就要求接受，也就是让这个语言包含 $S_2$；$M_2$ 也不行，也被否定。

再看 $M_3$ 与 $S_3$：这一次 $M_3$ 在 $S_3$ 上的运行结果是接受。方向就要反过来了——我们要求它拒绝，方法是让 $S_3$ **不属于**这个语言，不属于这个集合。于是 $M_3$ 也被排除。

把整条对角线都照这样翻一遍，所有的图灵机就都被排除掉了：没有任何图灵机可以判定这样构造出来的语言。老师把这一步称为"第一步"，并且说，我们是用对角线化的方式构造出了一个语言。

接下来给这个语言一个名字。刚才构造的这个语言，是把对角线上的那些结果都翻一遍得到的，翻一遍之后我们把它记为 $L_{\text{flip}}$。

**定义**：$L_{\text{flip}}$ 是由所有满足"$M_\alpha$ 不接受 $\alpha$"的串 $\alpha$ 组成的语言，即
$$L_{\text{flip}}=\{\alpha:M_\alpha\ \text{不接受}\ \alpha\}.$$
这里的"不接受"包含两种情形：机器在输入 $\alpha$ 上**拒绝**，或者机器在输入 $\alpha$ 上**死循环**。

这个定义用老师的话说是"看着有点绕"，可以拆成两句直白的话来读：如果机器**接受**那个串，那么这个串就不放进 $L_{\text{flip}}$ 里面；如果机器**不接受**那个串，那么这个串就放进 $L_{\text{flip}}$ 里面。

也可以换成写程序的说法来理解：你写了一个程序，这个程序是有输入的；你把这个程序**自己**作为它自己的输入送进去。如果它接受自己，那就不把它放在这个语言里；如果它不接受自己——也就是拒绝它或者对它死循环——那就把它放在这个语言里面。

同样地，前面那套对角线处理也可以直接读成一张"翻译表"，把对角线上原来的三种结果翻译成新的结果：

| 对角线上原来的结果 | 翻译成 | 对 $L_{\text{flip}}$ 的含义 |
|--------------------|--------|------------------------------|
| $R$（拒绝） | $A$（接受） | 该串被收入 $L_{\text{flip}}$ |
| $A$（接受） | $R$（拒绝） | 该串被排除在 $L_{\text{flip}}$ 之外 |
| $L$（死循环） | $A$（接受） | 该串被收入 $L_{\text{flip}}$ |

> **老师总结**：就是把 $R$ 变成 $A$、把 $A$ 变成 $R$，然后把 $L$ 变成 $A$，这就翻译一下。

之所以要做这样的翻译，目的很清楚：要让每一台图灵机都被排除，确保每一台图灵机都不能判定这个语言。而"让每一台图灵机都不能判定它"这件事并不需要在所有输入上做手脚——只需要让它在**某一个具体的输入**上失效就够了，这个具体的输入就取它自己，把它自己作为输入送进去。这也正是对角线上第 $i$ 台机器要配第 $i$ 个串的原因。

**例子**：老师先自己承认这一步"是不是有点抽象""很抽象"，随后举了一个 C 语言程序设计的类比：以前教 C 语言程序设计的时候，会留这样一个作业——写一个程序，去统计一个字符串里面有多少个单词、多少个字符，还有多少个句子。而这个程序本身也是文本，所以你可以拿这个程序**自己**作为它自己的输入装进去，让这个统计程序去统计它自己。课堂用这个作业说明"把程序自己当输入"这种事并不稀奇。

**课堂问答**：老师问："理解这个证明的同学可以举一下手吗？"随后又问："那不理解这个证明的同学可以举下手。"老师说"非常好啊非常好"，并强调这个证明很重要很重要，后面的证明结果都是基于它的，所以又把这个证明再说了一遍。字幕没有记录学生的作答或举手结果。

于是刚才论证的结论是：按上面这种方式定义出来的那个语言，是不可判定的。

下面把这一段的表格与构造完整复述一遍。图灵机是可枚举的，输入的字符串也是可枚举的，所以我们就画了一张巨大的表：行对应图灵机 $M_0,M_1,M_2,\dots$，列对应输入串 $S_0,S_1,S_2,\dots$，表中的每一个元素就是"这台图灵机对这个输入"的运行结果。结果只有三种，要么是 $A$（接受），要么是 $R$（拒绝），要么是 $L$（死循环）。因为一切是可数的，所以我们可以画出这样一张表，整张表被 $A$、$L$、$R$ 填满。对角线上的格子，就是 $M_0$ 对 $S_0$、$M_1$ 对 $S_1$、$M_2$ 对 $S_2$……这些格子，正是我们动手改写的地方。

| | $S_0$ | $S_1$ | $S_2$ | $S_3$ | $\cdots$ |
|---|---|---|---|---|---|
| $M_0$ | **$R$** | $A$ | $L$ | $A$ | $\cdots$ |
| $M_1$ | $A$ | **$L$** | $R$ | $L$ | $\cdots$ |
| $M_2$ | $L$ | $A$ | **$R$** | $A$ | $\cdots$ |
| $M_3$ | $A$ | $R$ | $L$ | **$A$** | $\cdots$ |
| $\vdots$ | $\vdots$ | $\vdots$ | $\vdots$ | $\vdots$ | $\ddots$ |

表中的非对角项只是课堂用来把表填满、显示"表项只有 $A/R/L$ 三种可能"的示意；课堂上逐一点名核对过的只有对角线上的四个格子：$M_0$ 对 $S_0$ 是拒绝、$M_1$ 对 $S_1$ 是死循环、$M_2$ 对 $S_2$ 是拒绝、$M_3$ 对 $S_3$ 是接受。

在这张表上，我们是**人为地构造**了一个语言，这个语言让所有的图灵机都失效，都没有办法判定它。怎么构造呢？还是把对角线翻过来。老师又用两个例子复述了一遍：对于 $M_2$，$M_2$ 是 2 号图灵机，$S_2$ 是 2 号输入，$M_2$ 对于 $S_2$ 本来是要拒绝的，我们让他接受，也就是把 $S_2$ 这个字符串放进这个语言里，所以 $M_2$ 就不可能判定这个语言；对于 $M_3$，$M_3$ 是接收 $S_3$ 的，那我们就把 $S_3$ 不放到这个语言里面，所以 $M_3$ 就失效。

于是我们就定义了这样一个看上去有点奇怪的语言——$M_\alpha$ 不接受 $\alpha$，就把 $\alpha$ 放进去。这个语言不能被任何的图灵机判定，原因就是我们**刻意**地把所有的对角线都翻过来了。

> **老师强调**：所以这个就是图灵的证明，这是非常重要的证明，就是 1936 年那篇文章的证明。

接下来老师交代了这个证明的走向。他先问"然后他怎么证明"，然后说明：下一步就是证明停机问题不可判定；而这个证明就是从上面这个语言出发的。他还说明，这个证明是**形式**的证明，"写下来就是这样"，接着就把形式证明写了下来。

> **老师提示**：老师在本讲只把话说到这里——下一步是证明停机问题不可判定，而它的具体证明本次课没有展开。

**定理**：语言 $L_{\text{flip}}$ 是不可判定的。

**证明**：用反证法。

假设存在一台图灵机 $M_\beta$ 可以判定 $L_{\text{flip}}$，也就是说 $L(M_\beta)=L_{\text{flip}}$；下面拿这个程序它自己作为它的输入，即考察 $M_\beta$ 在输入 $\beta$ 上的运行。由于 $\beta$ 要么属于 $L_{\text{flip}}$，要么不属于 $L_{\text{flip}}$，分两种情况。

情形一：设 $\beta\in L_{\text{flip}}$。

1. 根据 $L_{\text{flip}}$ 的定义，$\beta\in L_{\text{flip}}$ 就意味着 $M_\beta$ **不应该接受** $\beta$（定义要求的是：$M_\beta$ 不接受 $\beta$ 的那些 $\beta$ 才会被收进 $L_{\text{flip}}$；现在 $\beta$ 在里面，所以这句话对 $\beta$ 成立）。
2. 又因为 $M_\beta$ 是判定 $L_{\text{flip}}$ 的机器（$M_\beta$ 判定它），而判定意味着对每个输入都能停机并给出接受或不接受的结论，**所以它永远不会死循环**——这一条把 $L$（死循环）这种结果排除掉了。
3. 既然它不能接受 $\beta$，又不会死循环，那么在"接受 / 拒绝 / 死循环"这三种结果里只剩一种：所以 $M_\beta$ 一定是**拒绝** $\beta$。
4. $M_\beta$ 拒绝 $\beta$，说明 $\beta$ 不在 $M_\beta$ 能够接收的那些串之中，即 $\beta\notin L(M_\beta)$。
5. 但是根据我们的假设 $L(M_\beta)=L_{\text{flip}}$，由 $\beta\notin L(M_\beta)$ 应当有 $\beta\notin L_{\text{flip}}$。这与情形一的假设 $\beta\in L_{\text{flip}}$ **矛盾**。

情形二：设 $\beta\notin L_{\text{flip}}$。

1. 根据 $L_{\text{flip}}$ 的定义，凡是 $M_\beta$ 不接受 $\beta$ 的情形，$\beta$ 都应当被收进 $L_{\text{flip}}$；现在 $\beta\notin L_{\text{flip}}$，说明在输入 $\beta$ 上"不接受"这个前提不成立，也就是 $M_\beta$ 不能是不接受 $\beta$。
2. 同样因为 $M_\beta$ 是判定 $L_{\text{flip}}$ 的机器，它判定它，所以它永远不会死循环，$L$ 这一种结果被排除。
3. 剩下的可能只有接受：于是 $M_\beta$ **接受** $\beta$，即 $\beta\in L(M_\beta)$。
4. 再由假设 $L(M_\beta)=L_{\text{flip}}$，即得 $\beta\in L_{\text{flip}}$，与情形二的假设 $\beta\notin L_{\text{flip}}$ **矛盾**。

两种情形都导出矛盾，所以假设不成立：不存在能判定 $L_{\text{flip}}$ 的图灵机。（字幕在讲完第一种情况的矛盾之后老师直接下课，第二种情况没有被字幕记录下来；上面情形二的四步是按 $L_{\text{flip}}$ 的定义与假设 $L(M_\beta)=L_{\text{flip}}$ 严格对称写全的，不是字幕原话。）

**推论**：语言 $L_{\text{flip}}$ 不能被任何图灵机判定；这也正是前面"把整条对角线刻意翻过来"所保证的结果。

最后老师收尾："对，然后我们先下课。然后我们同学们，我们下周见。"本次课到此结束。字幕中没有提到布置作业，也没有其他事务性通知。
