## 一、本次课安排与上节课回顾 [00:02:14–00:15:16]、[00:15:57–00:21:13]、[01:08:00–01:08:28]

### 1.1 本次课的两条主线

同学们早上好。老师开场先交代了本次课的定位。上节课给出了这门课最重要的一个定义——**图灵机**（Turing machine），我们由此在理论上定义了什么是计算。用柏拉图的话说，这是"理念世界里的计算机"，也就是图灵机这个"形式之物"。

图灵机是什么？它就是一个**有限自动机**（finite automaton, FA），加上读、写和指针移动的功能：指针可以左移、可以右移，还可以写作；而控制它的状态转移仍然由那个有限自动机来完成。

本次课要论证的是：这样一个定义是好的定义、是对的定义，是 **well-defined** 的。论证分两个方面。

一方面，我们继续做图灵机编程，而且逐渐做一些比较复杂的例子，比如二进制乘法。通过这些例子来说服大家、也说服老师自己：图灵机什么都可以做，它是一台完备的计算机。

另一方面，我们从理论上论证这个定义是 **robust**（健壮的）。怎么论证呢？就是定义很多很多图灵机的变种——纸带可以单向也可以双向，可以是一维也可以是二维，可以是单带也可以是多带，还可以带随机存取的功能、加缓存。大家会看到理论计算机的一个奇观：无论你怎么定义，最后都和图灵机等价；不仅等价，时间复杂度也只相差一个多项式。你无论怎么定义一个很奇怪的计算机，只要它是完备的，它就多项式等价于一个图灵机；最后你定义出来的复杂性类，像 $\mathrm{P}$、$\mathrm{NP}$，都是一样的。

这也消除了我们的一些担忧：我们把指针定义成只能左移右移，那能不能一次移两格？能不能停留在原地？其实无论怎么定义，结果都是一样的。

### 1.2 上节课的两个例子：乘二与复制零

老师接着回顾了上节课留下的两个图灵机编程例子。

**例题**：设计一台图灵机，把最低位在前的二进制数 $x$ 乘以 2。

**题目**：输入是一个二进制串，**最低位在前**（least significant bit first），例如输入 `011`（后接空白），要求输出 $2x$。

**解答**：老师先说明了这道题的实质：把整个字符串移位一位，然后在空出来的那一位补 0。例如输入是 `011` 加一个空白，输出就是把字符串移位一位、然后补上 0。做法不唯一。

当时考虑的一种做法是用状态"记住"搬过来的位。老师把这种做法的状态图描述为：

1. 有一个状态叫 `Carry 0`，就是"正在搬运一个 0"：如果读到的还是 0，就把 0 改写成 0，右移；如果读到 1，就把 1 改成 0，右移，然后转入"搬运 1"的状态。
2. 搬运 1 的情形类似：如果搬运的是 1、读到的也是 1，就把这一位换成一个 1，右移；如果搬运的是 1、读到的是 0，就把这一位换成 1，右移。
3. 什么时候结束呢？读到空白就结束：如果搬运的是 0，就把空格变成 0，右移或左移都可以，然后结束；如果搬运的是 1，就把空格变成 1，右移，然后结束。

这样就把一个字符串整体移位了一位。

**结果与点评**：老师提醒这道题的做法不唯一，上面这种"搬运"的做法只是其中一种；他还提到自己觉得这种用状态记着搬运位的做法"总感觉有点费劲"，所以后面设想的是另一种思路（先让机器跑到最右边，再每次把字符串移动一位，最后在最左边补 0）。

**例题**：设计一台图灵机，把 $0^k$ 变成 $0^{2k}$（复制零）。

**题目**：输入是 $k$ 个 0，要求输出 $2k$ 个 0。例如 `000` 变成 `000000`。

**解答**：老师的思路是"每次从左边复制一个 0 到右边"，并用辅助字符做标记：

1. 先把左边第一个 0 改写成 `A`（表示这一位已经被处理过），然后在右边加一个 0，并把它改写成 `B`（表示这是复制出来的结果）。
2. 再把第二个 0 改成 `A`，在右边再加一个 `B`；第三个 0 改成 `A`，再加一个 `B`，以此类推。
3. 最后从右往左（或从左往右）再扫描一遍，把所有的 `A` 和 `B` 都变回 0。

老师把对应的图灵机状态拆成三段来讲：初始状态把第一个 0 变成 `A` 然后右移；紧接着一个"向右"的状态什么都不做、一路右移，读到 0 或读到 `B` 都不管，直到找到最右边的第一个空格，把那个空格改成 `B`，然后左移；再进入一个"回头"的状态，一路向左，读到 0 或 `B` 都不管，直到读到第一个 `A`——第一个 `A` 的右边就是还没处理的 0，于是读到这个 `A` 时向右移，回到最初那个状态，重新再来一遍。等所有的 0 都被处理完，读到的字符就不再是 0 而是 `B` 了；这时把指针移到最右边，从右往左扫描一遍，把 `A`、`B` 都变回 0，最后读到左边那个空格时结束。

**结果与点评**：老师说大家这两个例子都做得挺不错、很聪明，并再一次说明这个答案不唯一。老师也重申了做图灵机编程的一般方法：先理清思路，写一下**伪代码**，再去设计状态机；和最喜欢的程序设计语言相比，图灵机肯定是非常笨拙、不太好用的。

**补充说明**：上述乘二与复制零两道题在本次课的两份补充材料中都没有对应页面——它们来自上一讲（图灵机编程那一讲）布置的课堂练习，本次课老师只重新讲了思路与状态图。此处不引用任何幻灯片页码。

### 1.3 图灵机定义的回顾

因为图灵机的定义非常重要，老师又带着大家回顾了一遍。图灵机是一个**七元组**：

$$M=(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}),$$

其中 $Q$ 是一个有限的状态集，$\Sigma$ 是有限的输入字符集，$\Gamma$ 是有限的工作字符集（纸带字母表），并且输入字符集是工作字符集的一个子集。老师解释：输入的字符串的字符来自 $\Sigma$；而机器在工作的时候可以引入一些其他字符，所以工作字符集比输入字符集更大。

最关键的是那个转移函数 $\delta$：它由当前状态和当前指针读到的字符**唯一地**决定下一个新的状态、新的字符（也就是用新字符去改写之前的字符，当然这两个字符可以相等，也就是可以不改写），以及指针左移还是右移。

> **老师强调**：从这个转移函数也能看出，计算是局部的——每次指针指向一个字符，然后根据状态做一些局部的改动。

$q_0$ 是初始状态，$q_{\mathrm{accept}}$ 是接收状态，还有一个拒绝状态。老师说不失一般性，我们可以认为只有一个接收状态、只有一个拒绝状态。原因和图灵机与有限自动机的差别有关：

> **老师强调**：和有限自动机不同，图灵机一旦进入接收状态或拒绝状态就停机了；而有限自动机不会停机，它会一直读到最后一个字符，再由最后一个状态决定是接收还是拒绝。

这也是这个定义与有限自动机定义的不同之处。老师总结：计算理论研究的就是图灵机的性质。有了计算模型、有了数学上"计算"的定义之后，我们就可以定义很多事情——比如可计算性，哪些语言是可判定的；也可以定义计算复杂性：机器的运行时间就是它做了多少次状态转移才停下来，我们还可以定义时间；空间就是指针扫过的格子数量。

老师说，这个定义要满足两个方面的要求。

> **老师强调**：一方面，我们要求这个定义可以囊括各种计算——无论大家在 CPU 上编程、在 GPU 上编程，还是深度学习、大语言模型，我们希望我们定义的这个计算机（图灵机）都可以做；另一方面，我们希望它尽可能简单，越简单越好，直到不能更简单了。所以图灵机的定义就是一张幻灯片的篇幅。

### 1.4 算法书上的复杂度其实用的是 RAM 图灵机

老师在讲完几个算法之后回到一个问题：大家学算法导论的那些算法，它那个时间复杂度是怎么回事呢？在算法书里、包括我们刚刚看的这几个算法，用的其实是我们马上会讲到的**带随机存取的图灵机**（RAM 图灵机）——它的内存可以在 $O(1)$ 的时间内访问任何一个指定的内存位置。也就是说，算法书上默认的计算模型不是单带图灵机，而是带 **RAM**（Random Access Memory，随机存取存储器）的图灵机。

## 二、回文判定与复杂度讨论 [00:15:17–00:15:56]、[00:21:14–00:32:53]

### 2.1 回文语言与解题思路

老师接着讲稍微复杂一点的例子——**回文数**。

**定义**：**回文串**（palindrome）是这样一个 01 串 $w$：正着读和倒着读都一样，即 $w=w^{R}$。包含所有回文串的语言记为 $\{w: w=w^{R}\}$。

**例子**：$0110$ 是回文（接收）；$0011$ 不是回文（拒绝）；$010$ 是回文（接收）。

这个语言不是**正则语言**（regular language）——我们之前用**泵引理**（pumping lemma）证明过它不是正则的，不存在有限自动机去识别它；但它是可计算的、可判定的。那么图灵机怎么判定它呢？

老师先讲了思路：可以让指针**来来回回**地比较。有限自动机不能来来回回，它只能扫一遍；扫一遍的话你就只能记住有限的信息，这就很麻烦。而图灵机可以来回移动，还可以做一些标记（mark）。所以做法是：

1. 读最左边的字符，擦掉它，并记住它是 0 还是一 1——**用状态记住**。
2. 移动到最右边，读最右边的字符。如果右边已经没有字符了（读到空白），就接收；如果不匹配，直接拒绝；如果匹配，就把最右边这个字符也擦掉。
3. 回到当前最左边那个非空白的字符，重复上面的过程。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 2–3 张幻灯片（PDF 第 2–3 页），幻灯片把这一思路概括为三条：读最左边符号、记住并擦除；移到最右端读符号，若不存在则接收，若不匹配则拒绝，否则擦除；回到当前最左边的非空白符号并重复。幻灯片上给出的三个示例输入正是 $0110$（接收）、$0011$（拒绝）、$010$（接收），与老师口述一致。

### 2.2 回文图灵机的状态设计

老师接着对着幻灯片上的状态图讲了这台机器长什么样。

一开始读到的如果是 0，就把这个 0 擦掉（改成空白），进入状态 $R_0$；在 $R_0$ 里就不停地向右，直到最右边读到空白为止，然后向左——此时下一个读到的就是最右边那个字符，对应的状态是 $S_0$ 向左。

接下来有两种可能：读到 0 或者读到 1。老师特别说明了图中没有画出的那种情形：

> **老师提示**：读到 1 的这条边老师没有画，这是约定俗成的——如果你没画，就相当于进入了一个陷阱状态（也叫死状态），也就是直接拒绝掉了；画出来的话，那个陷阱状态就是一个拒绝状态，进去就停机。

如果读到 0，说明左右匹配：把最右边这个 0 变成空白，然后到了 $Q_1$ 这个状态再往左走。此时如果读到的又是一个空白，说明这个字符串已经处理完了，所以接收。如果读到的是 0，说明最右边是 0，我们就通过一个循环回到最左边再比较：最左边如果是 0 就匹配，如果是 1 就进入陷阱状态、拒绝。

上面是读到 0 的情况，读到 1 的情况完全对称。整个逻辑就是左右来回比较。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 4 张幻灯片（PDF 第 4 页），幻灯片给出的正是这台回文判定图灵机的完整状态图（含 $q_0$、$R_0$、$S_0$、$L_0$、$R_1$、$S_1$、$L_1$、$q_{\mathrm{acc}}$ 以及未画出的陷阱转移），并附有模拟器代码的链接（`turing-machines/palindrome.txt`）。老师课堂上正是按这张图逐条讲解的。

## 三、判定 $L=\{0^{2^n}\}$ 与复杂度讨论 [00:32:53–00:40:51]

### 3.1 问题与算法思路

老师接着看下一个语言。

**定义**：$L=\{0^{2^n}: n\ge 0\}$——输入是一串 0，当且仅当 0 的个数是 2 的幂时接收。

**例子**：1 个 0 接收（因为 $2^0=1$）；2 个 0 接收（$2^1=2$）；4 个 0 接收（$2^2=4$）；8 个 0 接收（$2^3=8$）。而 3 个 0、6 个 0、5 个 0 都拒绝。

老师讲的算法是"每一次把 0 的个数减半"：

1. 从左到右扫一遍，保留奇数位置上的 0，把偶数位置上的 0 划掉。怎么划掉呢？把 0 改成一个特殊字符（老师课堂上用的是井号 `#`）来表示"已删除"。
2. 如果做完一遍之后发现还剩不止一个 0、而剩下的个数是奇数个，那就拒绝——因为奇数的个数不可能是 2 的幂（除了 1）。
3. 如果做完一遍之后发现只剩一个 0 了，那就接收（$2^0=1$）。
4. 否则回到纸带的最左边，重复再做一遍。

老师总结：你每次把它除以二；如果最后得到的是一，那它就是 2 的幂。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 6 张幻灯片（PDF 第 6 页），幻灯片把这一思路写成五步：从左到右扫一遍、划掉每隔一个的 0；如果恰好剩一个 0 就接收；如果剩下的多于一个且个数为奇数就拒绝；把磁头移回纸带最左端；重复第一步。同一份材料的第 5 张幻灯片（PDF 第 5 页）给出的判定表为：0 个 0（即空串 $\epsilon$）拒绝、$0$ 接收（$2^0=1$）、$00$ 接收（$2^1=2$）、$0000$ 接收（$2^2=4$）、$00000000$ 接收（$2^3=8$）、$000$ 拒绝、$00000$ 拒绝。这与老师课堂上口述的判定完全一致。

### 3.2 状态设计

老师照着状态图讲解：

$Q_1$ 是初始状态。在这个状态读到 0 就向右——这是第一个 0，保留它；再读到下一个字符时：如果是井号（就是被划掉的那个特殊字符），就忽略它、不管；这样读到第二个 0，就把它划掉、变成井号；然后是井号不管；第三个 0 保留，第四个 0 划掉，第五个保留，第六个划掉，第七个保留……如果读到第 7 个 0 之后结束了，那就拒绝，因为它是奇数个，奇数就拒绝。

## 四、二进制比较：判断 $x>y$ [00:40:51–01:07:58]

### 4.1 问题设定

老师说，前面这两个例子可能还不足以说服大家"图灵机什么都能做"，那我们再看稍微复杂一点的：比较两个二进制数。

**定义**：语言 $\{x,y: x>y\}$——输入是两个二进制数 $x$ 和 $y$，**高位在前**（most significant bit first），中间用逗号隔开；逗号也是字母表里的一个字符，所以输入字符集包括 `0`、`1` 和逗号。如果 $x>y$ 就接收，如果 $x\le y$ 就拒绝。

**例子**：输入 `101,11` 接收（$5>3$）；输入 `11,101` 拒绝（$3<5$）；输入 `101,101` 拒绝（$5=5$）；输入 `1,0` 接收（$1>0$）。这里假设前面没有多余的前导 0。

老师补充了动机：CPU 里是有这样的指令的，比如一个叫"比较"的指令——如果你接触过一点汇编，你可以比较两个寄存器的值；如果是大于的话，它会有一个特殊的寄存器（比如叫比较寄存器），把它设成一。所以我们希望图灵机也能做二进制的比较。

### 4.2 思路：先比长度，再逐位比

> **老师提示**：我们人怎么做，机器就怎么做。如果我们人类（碳基）都不知道怎么做，那硅基也不知道怎么做。

人类是怎么比较两个二进制数的呢？

1. **先比较长度**：如果第一个更长就接收，如果第一个更短就拒绝。
2. **长度相等时再逐位比较**：从最高位开始逐位比较，第一个不同的位置就决定了答案——如果左边这一位比右边小，就直接拒绝；比它大就接收；相等就继续比较下一位。

怎么比较长度呢？老师提醒"我们之前用过这个技术"：把两个串做标记，逐位标记过去，然后看 $x$ 和 $y$ 哪一个先被标记完，就可以比较它们的长度。逐位比较的做法也做过，就像回文串那样：读最左边的，用状态记住它是 0 还是一。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 8–9 张幻灯片（PDF 第 8–9 页），幻灯片把这道题的输入约定写为"$x$ 和 $y$ 都是二进制数、最高位在前、除非这个数本身是 0 否则没有前导零，写在纸带上时先是 $x$、然后逗号、然后 $y$"，字母表为 $\Sigma=\{0,1,,\}$；思路则分为两个阶段：第一阶段反复标记掉 $x$ 与 $y$ 各自最右边尚未标记的那一位（注意是标记而不是擦除），直到其中一个没有剩余的位为止，若长度相同则进入第二阶段；第二阶段从左往右成对比较两个数的数字，第一个不同的位置决定答案。幻灯片给出的四个示例（$101$ 与 $11$ 接收、$11$ 与 $101$ 拒绝、$101$ 与 $101$ 拒绝、$1$ 与 $0$ 接收）与老师口述一致。

回到算法。老师对着状态图说明了这台机器的结构：上面这一段做的是**比较两个字符串的长度**，下面这一段做的是**逐位比较**。

老师提醒大家，做这台机器的时候，反复对 0 和 1 进行标记：把 0 变成 `P`、把 1 变成 `Q`，先比较 $x$ 和 $y$ 的长度，如果 $x$ 比 $y$ 长就接收、比 $y$ 短就拒绝，如果长度相等就进入下面这一段；下面这一段就像状态名字说的一样，找到它们的最低位，然后再去比较。

老师在讲状态图之前还提醒了一句方法：这个"比较长度"的技术我们之前用过，就是做标记、逐位标记过去，然后看哪一个先被标记完；而逐位比较的做法也做过，就像回文串那样，读最左边的、用状态记住它是 0 还是一。

> **老师提示**：相信大家一定也是能实现出来。

具体地，在 `find y` 这个状态里，机器什么都不做、不停地向右，直到最右边读到空格；然后略过 `P`、`Q`（它们是被标记后的字符，0 被标记成 `P`、1 被标记成 `Q`），把最右边的那个 0 标记成 `P`、最右边的一标记成 `Q`——也就是先对 $y$ 的最右边那个字符做一个标记。做完之后进入一个叫 `to comma` 的状态，这个状态名字就像注释一样，说明我们要去找那个逗号：不停地向左直到找到逗号；如果是 `P`、`Q` 就继续忽略、继续向左。找到逗号之后，我们再找逗号左边的那个 0 或者 1，对 $x$ 的这一位也做标记——也就是**先标记 $y$、再标记 $x$**。如果找不到 0 或者 1（也就是 $x$ 已经标记完了），那就进入陷阱状态。

## 五、二进制加法 [01:08:47–01:17:04]

### 5.1 问题设定与动机

**定义**：输入是 $x+y$，其中 $x$、$y$ 是二进制数、高位在前，写在纸带上时先是 $x$、然后一个加号、然后 $y$；字母表为 $\Sigma=\{0,1,+\}$；输出是 $x+y$。

**例子**：$101+1=110$（$5+1=6$）；$111+1=1000$（$7+1=8$）；$1+1=10$（$1+1=2$）。

老师先讲了小学的做法：把它写成一个竖式进行对齐，对齐之后记录有没有进位。但这里只有一根纸带，没有办法去"对齐"；没有关系，我们可以继续来来回回地读。

> **老师总结**：一个算法就是什么？一个算法就是一个图灵机。算法就是图灵机。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 11 张幻灯片（PDF 第 11 页），幻灯片把输入约定写为 $x+y$（二进制、最高位在前，写在纸带上先是 $x$、然后加号、然后 $y$），字母表为 $\{0,1,+\}$，并列出三组示例 $101(5)+1(1)=110(6)$、$111(7)+1(1)=1000(8)$、$1(1)+1(1)=10(2)$，与老师口述一致。

### 5.2 算法

图灵机上的做法是：

1. 纸带布局为 $z=x+y$，其中 $z$ 初始为空；把结果写在最左边（纸带向两个方向都是无限延伸的，所以左边也有空间）。
2. **从最低位开始加**，因为这样定位会方便一点。每一轮：
   - 读 $x$ 的最低一位未用过的位和 $y$ 的最低一位未用过的位（缺失的位算作 0），并把这两位都标记为"已用过"；
   - 计算 $s=x_i+y_i+c$，其中 $c$ 是进位（carry）；
   - 把 $s \bmod 2$ 写到 $z$ 已经写出的部分的左边；并把新的进位 $c=\lfloor s/2\rfloor$ 记在状态里。
3. 当 $x$ 和 $y$ 都用完了、并且进位为 0 的时候，图灵机停机；最后做一下"打扫战场"，把不需要的字符全部擦掉，只留下结果。

老师解释：每一位的和 $s$ 有 0、1、2 三种可能，所以状态图上有三条路径，原因就在这里。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 12 张幻灯片（PDF 第 12 页），幻灯片把上面的过程概括为：纸带布局 $z=x+y$，$z$ 初始为空；每轮读 $x$、$y$ 最低的尚未使用的位（缺失的位算 0）并把两者标记为已用，计算 $s=x_i+y_i+c$，把 $s\bmod 2$ 立刻写在 $z$ 已写部分的左边，并把新的进位 $c=\lfloor s/2\rfloor$ 记在状态中；当 $x$、$y$ 都用完时停机（若 $c=1$ 还要再写一个 1），然后擦掉除 $z$ 之外的一切。这与老师课堂上口述的规则逐条一致。

### 5.3 例题：$101+1$ 的完整过程

**例题**：用图灵机计算 $101+1$（即 $5+1$）。

**题目**：输入纸带上写着 $101+1$，要求输出 $110$。

**解答**：按上面的算法逐轮走：

1. **准备**：在最左边放一个等号作为标记，结果为 `=` 右边的 $z$；初始化进位 $c=0$。纸带为 `=101+1`。
2. **第 1 位**：读 $x$ 的最低一位 1、$y$ 的最低一位 1，$1+1+0=2$，所以写 $2\bmod 2=0$，进位 $c=1$。纸带变为 `0=10#+#`（已用过的位用特殊符号标记掉）。
3. **第 2 位**：$x$ 的第二位是 0，$y$ 没有第二位（算 0），$0+0+1=1$，写 1，进位 $c=0$。纸带变为 `10=1##+#`。
4. **第 3 位**：$x$ 的第三位是 1，$y$ 已经没有位了，$1+0+0=1$，写 1，进位 $c=0$。纸带变为 `110=###+#`。
5. **收尾**：$x$、$y$ 都用完了、进位为 0，所以停机；然后打扫战场，把标记和 $x$、$y$ 都擦掉，最后留下结果 `110`。如果要求的话，还可以把指针停在最左边。

**结果与点评**：结果是 $110$，即 $5+1=6$，正确。老师在课堂上还请大家举手确认是否理解了这个算法，并说"画出来看着有点可怕，但就是做这样的事情"。老师同时说明了状态图上的几个部件：最左上角是初始状态；`mark` 什么都不做，就是在最左边加一个等号；`find x` 那一段之所以要一直转圈走到最右边，是因为二进制数是高位在前，只有走到最右边才能找到它的最低位。

## 六、二进制乘法 [01:17:04–01:28:41]

### 6.1 问题设定

老师说，这是最后一个例子，看完之后希望能说服大家"这个图灵机啥都可以干"。

**定义**：输入是 $x*y$，其中 $x$、$y$ 是二进制数、高位在前，写在纸带上时先是 $x$、然后一个星号（乘号）、然后 $y$；字母表为 $\Sigma=\{0,1,*\}$；输出是 $x\cdot y$，同样是高位在前。

**例子**：$101\times 11=1111$（$5\times3=15$）；$11\times 11=1001$（$3\times3=9$）；$110\times 10=1100$（$6\times2=12$）。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 15 张幻灯片（PDF 第 15 页），幻灯片给出的输入约定、字母表 $\{0,1,*\}$ 与三组示例（$101(5)\times11(3)=1111(15)$、$11(3)\times11(3)=1001(9)$、$110(6)\times10(2)=1100(12)$）与老师口述一致。

### 6.2 算法：移位相加

老师讲的思路是"古埃及人的做法"（也就是移位相加）：

$$x\cdot y=\sum_{j:\,y_j=1} x\cdot 2^{j}.$$

也就是说，如果 $y$ 的这一位是 0，就什么都不加；如果这一位是 1，就把整个 $x$ 复制一遍、在后面添 0（这在二进制里就是乘 2 的幂）。所以乘法就是加法——要做 $y$ 的长度那么多次加法。老师提醒："$x$ 怎么样得到 $x$ 乘以 $2^j$ 呢？我们设计过这个图灵机"——就是上节课那个把字符串移位并在空位上补 0 的机器。

具体到这台机器：

1. 把结果写在最左边，记作 $z$（初始为空）。
2. 逐步处理 $y$：从 $y$ 的最低位开始，找到最低的尚未使用过的那一位 $y_j$，把它标记为"已用过"。
3. 如果 $y_j=1$，就把 $x$ 加到 $z$ 上，并且加在合适的位置上——对齐到 $z$ 最低的尚未"完成"的那一位。
4. 把 $z$ 的最低未完成位标记为"已完成"。
5. 重复这个过程，直到 $y$ 用完；最后去掉 $z$ 上的标记，并擦掉除 $z$ 之外的一切。

老师解释了这个做法的关键：处理完 $y_j$ 之后，$z$ 的最低 $j+1$ 位就再也不会变了，所以把它们标记为"已完成"；这些"已完成"的标记就起到了**移位 $2^j$** 的作用。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 16–17 张幻灯片（PDF 第 16–17 页），幻灯片把算法写成：$x\cdot y=\sum_{j:y_j=1}x\cdot2^j$；纸带布局 $z=x*y$，$z$ 初始为空；关键技巧是"处理完 $y_j$ 之后 $z$ 的最低 $j+1$ 位永远不会再改变"，把它们标记为 finished，而这些 finished 标记就扮演了移位 $2^j$ 的角色。每一轮的操作为：读 $y$ 最低的尚未使用的位 $y_j$ 并标记为已用；若 $y_j=1$ 则把 $x$ 就地加到 $z$ 上、对齐到 $z$ 最低的未完成位；把 $z$ 的最低未完成位标记为已完成；当 $y$ 用完时停止，去掉 $z$ 上的标记并擦掉除 $z$ 之外的一切。同一份材料的第 18 张幻灯片（PDF 第 18 页）给出了完整状态图，其中的标记约定为：$x$ 用 `p,q` 表示已用的 0、1，$y$ 用 `r,s` 表示已用的 0、1，$z$ 用 `u,v` 表示本轮改动的 0、1，$z$ 用 `a,b` 表示已完成的 0、1；模拟器代码链接为 `turing-machines/binary_multiplication.txt`。

### 6.3 例题：$11\times 110$ 的全程演示

**例题**：用图灵机计算 $11\times 110$（即 $3\times 6$）。

**题目**：输入纸带上写着 $11*110$（$x=11$、$y=110$），要求输出 $10010$（$18$）。

**解答**：老师按这台机器的运行顺序完整走了一遍，幻灯片上的算例与课堂演示一致。纸带上的记号约定是：$x$ 的已用位用 `p`（0）、`q`（1）标记，$y$ 的已用位用 `r`（0）、`s`（1）标记，$z$ 中本轮被改动的位用 `u`（0）、`v`（1）标记，$z$ 中"已完成"的位用 `a`（0）、`b`（1）标记。

1. **准备**：在 $x$ 的左边写一个等号 `=`；结果 $z$（此刻为空）将在 `=` 的左边向左生长。纸带为 `=11*110`，此时 $z$ 为空。
2. **第 1 轮，$y_0=0$**：读 $y$ 的最低未用位 $y_0=0$，把它标记为已用（`r`）。这一位是 0，所以什么都不加。随后把 $z$ 的最低未完成位标记为已完成：它现在是空白，所以写一个 0 上去，纸带变为 `0=11*110`——因为这一位以后永远不会再改变了。
3. **第 2 轮，$y_1=1$**：读 $y$ 的最低未用位 $y_1=1$，标记为已用（`s`）。这一位是 1，所以把 $x$ 加到 $z$ 上，从 $z$ 的最低未完成位开始：
   - $z$ 位 $+$ $x$ 位 $+$ 进位 $=0+1+0=1$（空白算 0），写 1，进位 $=0$；纸带变为 `10=11*110`。
   - 再加下一位：$0+1+0=1$，写 1，进位 $=0$；纸带变为 `110=11*110`。
   - $x$ 用完了、进位 $=0$，加法结束。此时把 $z$ 的最低未完成位标记为已完成。
   - 清除本轮在 $z$ 上的标记，这一轮结束。
4. **第 3 轮，$y_2=1$**：读 $y$ 的最低未用位 $y_2=1$，标记为已用；这一位是 1，所以再从 $z$ 的最低未完成位开始把 $x$ 加进 $z$。但要先把 $x$ 恢复出来——回到 `=` 的位置，重新读 $x$ 的各位（我们需要再用一次 $x$）：
   - $z$ 位 $+$ $x$ 位 $+$ 进位 $=1+1+0=2$，写 0，进位 $=1$；纸带变为 `010=11*110`。
   - 下一位：$0+1+1=2$（空白算 0），写 0，进位 $=1$；纸带变为 `0010=11*110`。
   - $x$ 用完了但仍然有进位 1：$z$ 位 $+$ 进位 $=0+1=1$（空白算 0），写 1，进位 $=0$；纸带变为 `10010=11*110`。
   - $x$ 用完了、进位 $=0$，加法结束；把 $z$ 的最低未完成位标记为已完成；清除本轮在 $z$ 上的标记，这一轮结束。
5. **收尾**：指针走到 `*` 的位置，说明 $y$ 已经用完了，机器停止；擦掉 `=` 以及它右边的一切，再去掉 $z$ 上的所有标记。

**结果与点评**：最后纸带上只剩下 $z=10010$，也就是 $18$，即 $3\times6=18$，正确。老师指出这台机器的代码有"两百多行、三百行"——也就是用三百行左右的模拟器代码实现了一个乘法。老师也提到，这个算例在幻灯片上被逐步画成了 19 页（从 Setup 到 Finish），课堂上是对着这些页面逐步讲解的。

**补充说明**：根据本节补充材料《lec9_slides_turing_machine_programming.pdf》第 19–37 张幻灯片（PDF 第 19–37 页），幻灯片把 $11\times110$ 的算例拆成 19 张图逐步展示：Setup（写 `=`、$z$ 将在其左侧生长）、Round 1（$y_0=0$：标记为已用、不加任何东西、把 $z$ 的最低未完成位写成 0）、Round 2（$y_1=1$：$0+1+0=1$ 写 1，$0+1+0=1$ 写 1，得到 `110`，标记完成并清除本轮标记）、Round 3（$y_2=1$：先回到 `=` 恢复 $x$，$1+1+0=2$ 写 0 进位 1，$0+1+1=2$ 写 0 进位 1，$0+1=1$ 写 1 得到 `10010`，标记完成并清除本轮标记）、Finish（到达 `*`、$y$ 用完；擦掉 `=` 及其右侧的一切；去掉 $z$ 上的标记，结果 $z=10010$，即 $3\times6=18$）。这与老师课堂上的逐步讲解完全对应，正文中的每一位数字均按幻灯片的算式核对。**原文待核实**：老师在 `01:20:45–01:20:53` 口述"把一一加到这个一上就变成 00，还有一个进位 0100 的，然后最后结果就是 10010"，口述的中间步骤比较含混，正文按幻灯片第 30–32 页的逐步算式（$1+1+0=2$ 写 0 进位 1、$0+1+1=2$ 写 0 进位 1、$0+1=1$ 写 1）还原。

## 七、稳健性目标：为什么图灵机模型是定义良好的 [01:28:41–01:34:06]

### 7.1 从"什么都可以做"到"怎么定义都一样"

做了这么多编程之后，老师转入理论部分：我们现在要做一些证明，证明无论怎么定义这样一个计算机、怎么定义这样一个模型，最后定义出来的都是一样的——它们的计算能力都是一样的，这种图灵机能算的、那种也能算，而且它们运行时间都差不多。

那什么是"差不多"呢？就是**差一个多项式**。老师自己先提出了疑问：如果运行时间从 $T(n)$ 变成了 $T(n)^2$、$T(n)^4$，那这不是差很多吗，怎么能叫差不多呢？

老师解释：首先在理论上，常数项肯定是忽略掉的，然后多项式也忽略掉了。

> **老师强调**：只要一个算法有多项式时间的算法，哪怕是 $N^{100}$，我们也认为它是高效的。

那为什么这样认为呢？老师说法，这有它的道理，这是理论的优美之处，是一个**奇观**。

> **老师总结**：老师有时候静下来想一想，觉得真是不可思议——不管你怎么定义，最后都一样，都相差一个多项式。这样的话你无论选什么样的模型，你定义 $\mathrm{P}$ 都是一样的：单带的、多带的、带不带随机存取内存的、带不带缓存的，甚至是并行的，最后都是一样的。

### 7.2 Robust 定义的三条标准

老师强调，我们现在不是在定义计算模型，我们是在论证这样一个模型的定义是 **robust** 的。他给出了三条标准。

1. 它要能囊括现实中各种计算：无论是 CPU、GPU，还是深度学习、大语言模型，甚至是未来全新的 AI 范式，都能被它包括。
2. 它允许我们忽略一些效率上的细节：比如常数因子，甚至是多项式级别的差异，我们都可以忽略。但如果你研究的是**细粒度计算复杂性**——研究哪些问题有 $O(N)$ 时间的算法、哪些问题可以在 $O(N^2)$ 内解决但不能在 $O(N)$ 内解决——那就不能忽略了，必须要更小心地去定义计算模型。
3. 更重要的是我们追求**简单**：*complexity out of simplicity*——这个模型越简单越好，因为这样我们方便把它当作数学对象来处理，然后就可以去研究可执行性、以及计算复杂性（时间复杂性、空间复杂性）这些问题。

### 7.3 本次课的证明计划

老师说，下面的 50 分钟就做这样一件事：定义一些图灵机的变种，然后论证、证明这些变种和我们定义的单带图灵机是**等价**的——它们之间可以相互模拟，而且模拟的时间只差一个多项式。也就是说，如果一种图灵机的运行时间是 $T(n)$，那么另一种图灵机的运行时间就是 $\operatorname{poly}(T(n))$。老师解释 $\operatorname{poly}$ 就是我们之前学过的大 $O$ 记号，也就是 $T(n)$ 的"大 $O(1)$ 次方"，也就是 $T(n)^{O(1)}$。

这样一来，我们定义复杂性类 $\mathrm{P}$ 的时候就与模型无关：无论选取哪一种模型，只要这个问题在多项式时间内可判定，它在另一种模型下也是多项式时间可判定的。

## 八、变种一：允许磁头停留（Lemma 1） [01:34:06–01:37:02]

老师开始讲第一个变种：我们定义一种图灵机，比之前那个图灵机强一点，增加一个功能——**S（stay）**，也就是指针可以停下来。原来的指针只能左移右移，在这个变种里我们允许它左移、右移，或者**停在原地**。

这里有个时间账要先说清楚：因为每一步停留都会变成两步，所以原来 $T(n)$ 步的运行时间变成 $2T(n)$ 步——而 $2T(n)$ 仍然是大 $O(T(n))$。

**引理**：允许磁头停留的图灵机不增加计算能力。设 $M$ 是一台转移函数为 $\delta:Q\times\Gamma\to Q\times\Gamma\times\{L,R,S\}$ 的图灵机，其中 $S$ 表示磁头保持不动；设 $L\subseteq\Sigma^{*}$ 是一个语言。如果 $M$ 在时间 $T(n)$ 内判定 $L$，那么 $L$ 可以被一台标准的图灵机在时间 $O(T(n))$ 内判定。

**证明**：两个方向中，一个方向是显然的——允许停留的图灵机显然比原来的定义要强，它显然可以模拟之前的图灵机。我们要证的是另一个方向：如果语言 $L$ 可以被允许停留的图灵机在时间 $T(n)$ 之内判定，那么它就可以被我们原始的那台图灵机在时间 $2T(n)$（也就是大 $O(T(n))$）内判定，只相差一个常数。

**推导**：把每一个"停留一步"用标准图灵机的两步来实现。

1. 第一步，对每一个状态 $q\in Q$，增加一个新的辅助状态 $q_{\mathrm{back}}$。原来所有的 $L$、$R$ 转移都保留不变。
2. 第二步，把每一条停留转移 $\delta(q,a)=(q',b,S)$ 替换成第一步的转移 $\delta'(q,a)=(q'_{\mathrm{back}},b,R)$——也就是先读 $a$、改写为 $b$、**向右**移一格，并进入辅助状态 $q'_{\mathrm{back}}$。
3. 第三步，在辅助状态上对它读到的任何字符 $c\in\Gamma$ 都回到原状态：$\delta'(q'_{\mathrm{back}},c)=(q',c,L)$——无论读到什么，都原样写回、向**左**移一格，然后进入 $q'$。
4. 于是原来"停在原地"的效果达成了：先向右再向左回来，指针就回到了原来那一格，而状态也变成了原先该进入的 $q'$。每一步停留都被换成两步，所以 $T(n)$ 变成了 $2T(n)$。

**结果与点评**：老师问大家能不能理解这个证明，请理解的同学举手，然后说"非常好"。老师总结：

> **老师总结**：允许指针停留并不能增加额外的功能，它对时间的影响也只是影响一个常数。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 3–4 张幻灯片（PDF 第 3–4 页），幻灯片把这条结论写成 Lemma 1 (stay option)：设 $M$ 的转移函数为 $\delta:Q\times\Gamma\to Q\times\Gamma\times\{L,R,S\}$，$S$ 表示磁头保持不动；若 $M$ 在时间 $T(n)$ 内判定 $L\subseteq\Sigma^*$，则 $L$ 可由一台标准图灵机在时间 $O(T(n))$ 内判定。证明为：对每个 $q\in Q$ 增加一个新状态 $q_{\mathrm{back}}$，保留每一条 $L/R$ 转移，并把每一条停留转移 $\delta(q,a)=(q',b,S)$ 替换为 $\delta'(q,a)=(q'_{\mathrm{back}},b,R)$ 与 $\delta'(q'_{\mathrm{back}},c)=(q',c,L)$（对所有 $c\in\Gamma$）；每个停留步变成两步，所以时间最多为 $2T(n)$。这与老师课堂上的讲法完全一致。

## 九、变种二：字母表变换（Lemma 2） [01:37:07–01:42:19]、[01:52:29–01:52:52]

### 9.1 问题：扩大字母表会不会更强

老师提出第二个问题：如果我们增加字母表，用很多很多的字符，可不可以？我们之前用的不是只有 0、1 和空格吗？如果我们允许用很多字符，会不会让这个图灵机变得更强？

答案是不会。

**引理**：设 $L\subseteq\{0,1\}^{*}$，且 $T(n)\ge n^{2}$。如果 $L$ 被一台纸带字母表为 $\Gamma$ 的图灵机在时间 $T(n)$ 内判定，那么 $L$ 可以被一台纸带字母表为 $\{0,1,\sqcup\}$ 的图灵机在时间 $O(\log|\Gamma|\cdot T(n))$ 内判定。

老师顺带说明了 $T(n)\ge n^{2}$ 这个条件的来源：这个限制对**单带**图灵机有一个技术上的原因；对多带图灵机我们没有这个限制。

### 9.2 编码的思路

老师讲的思路是编码，就像 ASCII 码一样：大家知道 ASCII 码是用一个字节、也就是八个位来编码的，一个八位的二进制数可以编码 $2^8=256$ 个字符。如果你有 256 个字符，你就用八位；如果你有 1024 个字符，你就用十位。然后你每一步本来是读一个字符就可以转移，现在就变成读八位、需要八步来处理；但最后影响的只是这个常数。

所以形式化写下来就是：把这个字母表 $\Gamma$ 用 0、1 进行编码，用多少位呢？用 $\lceil\log_2|\Gamma|\rceil$ 位就可以进行编码；空格的话就特殊处理一下，编码成 $k$ 个空格。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 5–7 张幻灯片（PDF 第 5–7 页），幻灯片给出的 Lemma 2 (change of alphabet) 为：设 $L\subseteq\{0,1\}^*$ 且 $T(n)\ge n^2$；若 $L$ 被一台纸带字母表为 $\Gamma$ 的图灵机在时间 $T(n)$ 内判定，则 $L$ 可由一台纸带字母表为 $\{0,1,\sqcup\}$ 的图灵机在时间 $O(\log|\Gamma|\cdot T(n))$ 内判定。证明分两步：先固定一个单射 $\mathrm{enc}:\Gamma\setminus\{\sqcup\}\to\{0,1\}^{k}$（其中 $k=\lceil\log_2|\Gamma|\rceil$），并令 $\mathrm{enc}(\sqcup)=\sqcup^{k}$，于是 $M$ 的每个格子对应 $M'$ 的 $k$ 个格子；预处理阶段，输入 $x_1x_2\cdots x_n$ 原本一格一位，$M'$ 先把它改写成 $\mathrm{enc}(x_1)\mathrm{enc}(x_2)\cdots\mathrm{enc}(x_n)$，每次把其余输入向右推，这一步耗时 $O(n)\cdot O(kn)=O(kn^2)$。然后 $M'$ 把 $M$ 的状态保存在自己的状态里，磁头停在当前块的**最左格**，模拟 $M$ 的一步：读（扫描这一块的 $k$ 格并记在状态里，得到符号 $a$，$O(k)$）、决定（在状态内部算出 $\delta(q,a)=(q',b,D)$，$0$ 步）、写（扫回去写入 $\mathrm{enc}(b)$，$O(k)$）、移动（沿方向 $D$ 移动 $k$ 格到下一块并进入 $q'$，$O(k)$）。总时间为 $O(kn^2)+O(k)\cdot T(n)=O(\log|\Gamma|\cdot T(n))$，因为 $T(n)\ge n^2$。这与老师课堂上讲的"用 $\lceil\log_2|\Gamma|\rceil$ 位编码、空格特殊处理"一致。

### 9.3 预处理为什么带来 $n^2$，以及每一步的代价

老师进一步说明了 $N$ 平方那个限制是怎么来的：就是第一步的**预处理**。我们的输入是 $x_1x_2\cdots x_n$，我们要用编码的方式把它展开——比如 0 被编码成 $k$ 个格子里写 $0$、1 被编码成 $k$ 个格子里写 $1$，所以它要做一次展开。单带图灵机做这个展开比较麻烦一点，需要做 $N^2$ 步；如果（机器本来）是多带的话，$O(N)$ 就可以了。

然后每一步：之前是读一个字符就可以转移，现在就是读 $k$ 个字符，用状态记录一下读到了什么，再根据转移函数进行转移，然后把新的这 $k$ 个字符写回去——比如说往左走 $k$ 步，然后把结果写下来；每次左移或者右移的时候也是移动 $k$ 步。所以加起来是 $O(k)$ 这一项乘以 $T(n)$，再和前面展开输入的 $O(kn^2)$ 相加；假设 $T(n)\ge n^2$，总的就是 $O(kn^2)+O(k)T(n)$。

> **老师总结**：这也是大 $O$ 记号的好处。老师也是比较喜欢这个大 $O$ 记号——如果没有这个记号，处理起来就不会这么干净。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 7 张幻灯片（PDF 第 7 页），幻灯片把总时间写成 $O(kn^2)+O(k)\cdot T(n)=O(\log|\Gamma|\cdot T(n))$（因为 $T(n)\ge n^2$），与老师的口述一致。

### 9.4 课间与结论

老师在 `01:42:19` 说"我们先休息一下，到 45 分"；`01:52:22` 复课后，老师接着上一条结论说：扩大字母表不能使图灵机变得更强，或者说只相差一个常数、一个纯粹常数。所以**不失一般性**，我们不妨认为图灵机能用的字符只有 0、1 和空格。

**补充说明**：老师在这里说的是"不是一般性"，即通常所说的"不失一般性"（without loss of generality）。

## 十、变种三：单向纸带图灵机（Definition 3 与 Lemma 4） [01:52:57–02:00:20]

### 10.1 单向纸带图灵机的定义

老师介绍下一种变种：**单向纸带图灵机**（one-way Turing machine）。我们之前那个图灵机有一根纸带向两个方向无限延伸；这种图灵机的纸带只往一个方向无限延伸。那左边这一端（有限的那一端）怎么处理呢？

> **老师提示**：我们在最左边放一个三角形（$\triangleright$），放一个特殊的字符，然后强制要求这个图灵机如果读到这个三角形，就必须右移。

这台图灵机的工作字母表里包括 0、1、空格，还有这个三角形；三角形标记的就是纸带的最左端。

**定义**：一台**单向纸带图灵机**是一个七元组 $(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}})$，其中：

1. $Q$ 是一个有限的状态集；
2. $\Sigma$ 是输入字母表，且 $\sqcup,\triangleright\notin\Sigma$；
3. $\Gamma$ 是纸带字母表，且 $\Sigma\cup\{\sqcup,\triangleright\}\subseteq\Gamma$；
4. $\delta:Q\times\Gamma\to Q\times\Gamma\times\{L,R\}$ 是转移函数，并且对每一个状态 $q$ 都有 $\delta(q,\triangleright)=(q',\triangleright,R)$，其中 $q'\in Q$；
5. $q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}\in Q$ 分别是初始状态、接收状态和拒绝状态，且 $q_{\mathrm{accept}}\ne q_{\mathrm{reject}}$。

纸带的格子用自然数编号：格子 0 放的是三角形 $\triangleright$，格子 $1,\dots,|x|$ 放输入 $x$，其余格子放 $\sqcup$，磁头从格子 1 开始。老师强调：三角形不能被改写；其他定义都是一样的。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 8–9 张幻灯片（PDF 第 8–9 页），幻灯片把单向纸带画为 $\triangleright\,0\,1\,1\,0\,1\,\sqcup\,\sqcup\,\sqcup\cdots$，注明"$\triangleright$ 上必须向右移动、磁头永远不能移到 $\triangleright$ 的左边"，并给出 Definition 3（one-way Turing machine）的上述五条，与老师口述一致；其中格子编号与初始磁头位置（格子 1）也由该页给出。

### 10.2 初步观察：单向纸带更弱，但它也能模拟双向纸带

老师先说：显而易见这个（单向纸带图灵机）更弱一点，因为我们可以用一个双向的图灵机去模拟一个单向的——只要在中间放一个三角形就可以了。但老师想证的结论是：它也没有更弱，它也可以去模拟双向纸带图灵机。

**引理**：设 $L\subseteq\{0,1\}^{*}$。如果 $L$ 可以被一台（双向纸带的）图灵机在时间 $T(n)$ 内判定，那么 $L$ 也可以被一台单向纸带图灵机在时间 $O(T(n))$ 内判定。

### 10.3 证明思路：把纸带折叠成两条轨道

老师给了一张图，说明证明就是把纸带折叠一下（fold）：

- 原来双向延伸的纸带，格子编号是 $\dots,-3,-2,-1,0,1,2,3,\dots$；
- 折叠之后，单向纸带的格子 1 里放的是这一对：上面一条轨道（upper track）放原来格子 0 的内容，下面一条轨道（lower track）放原来格子 $-1$ 的内容；格子 2 放原来格子 1 与格子 $-2$；格子 3 放原来格子 2 与格子 $-3$；依此类推。
- 一般地，单向纸带的格子 $j\ge1$ 放的是一个**对**：上面是原两向纸带的格子 $j-1$，下面是原两向纸带的格子 $-j$。格子 0 放三角形。

怎么把两个格子放到一个格子里呢？扩大字母表就可以了：字母表里放一个 pair，也就是放一个 $\Gamma\times\Gamma$ 的元素。老师具体说明：这一对的前一个放的是 $j-1$ 的内容，后面那个放的是 $-j$ 的内容。

然后用状态记录一下当前磁头是在正数那一侧还是在负数那一侧：

- 如果是在上面这条轨道（对应 $M$ 的正数一侧），那么 $M$ 右移我们就右移，$M$ 左移我们就左移。
- 如果是在下面这条轨道（对应 $M$ 的负数一侧），方向就要反过来。
- 如果我们读到这个三角形，就要改变一下符号（也就是**换轨**），并向右移动。

### 10.4 形式化构造

老师说，然后他就继续对着 AI"嘟嘟嘟"，让 AI 把这个证明形式化地写下来。形式化的内容是：

- 原来的每一个状态变成两个状态：一个"上"状态 $(q,\mathrm{up})$、一个"下"状态 $(q,\mathrm{down})$，用来表示磁头当前读的是这条纸带的上面还是下面。
- 字母表并上 $\Gamma\times\Gamma$ 这个集合。读一个格子的时候：如果一个格子放的是 $s\in\Sigma\cup\{\sqcup\}$（输入并没有被预先改写），就当作这一对是 $(s,\sqcup)$；如果放的本来就是一对 $s\in\Gamma\times\Gamma$，就按原样读。老师把"格子 $s$ 所表示的那一对"记作 $\pi(s)$。
- 一开始输入放在上面那条轨道上，下面装的都是空白。这段预处理什么都没做，就是把纸带折叠了一下——把空格、把那些（原来在）负数一侧的内容放到下面。
- 然后主要就是怎么改那个转移函数。设 $\pi(s)=(a,b)$：

  - **上面轨道**：如果 $\delta(q,a)=(q',a',D)$，那么 $\delta'((q,\mathrm{up}),s)=((q',\mathrm{up}),(a',b),D)$——方向不变，把 $\delta$ 用在上面那个字符上。
  - **下面轨道**：如果 $\delta(q,b)=(q',b',D)$，那么 $\delta'((q,\mathrm{down}),s)=((q',\mathrm{down}),(a,b'),\bar D)$——把方向**反向**（记 $\bar L=R$、$\bar R=L$），并把 $\delta$ 用在下面那个字符上。
  - **边界**：$\delta'((q,t),\triangleright)=((q,\bar t),\triangleright,R)$——读到三角形时换一条轨道（$\mathrm{up}$ 与 $\mathrm{down}$ 互换）并向右移动。

- $M'$ 在 $M$ 接受（或拒绝）时立即接受（或拒绝）。
- 时间：$M$ 的每一步在 $M'$ 里花一步，再加上最多一步用来从 $\triangleright$ 上弹回来，所以总共不超过 $2T(n)$，即 $O(T(n))$。

老师补充：这个构造本身**又是一个算法**——我们给一台图灵机，主要是用 $\delta$ 描述它，然后我们构造另一个 $\delta'$、构造出另外一台单向图灵机，它的功能和之前那台双向图灵机一样，运行时间不超过之前的两倍。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 10–14 张幻灯片（PDF 第 10–14 页），幻灯片给出的正是 Lemma 4（two-way vs. one-way tape）与上述构造：折叠图（two-way tape 的 $-4\cdots4$ 与 one-way tape 的格子 0/1/2/3/4 对应、cell $j\ge1$ 放 cell $j-1$（upper track）与 cell $-j$（lower track））、双轨移动规则（upper track 与 $M$ 同向、lower track 反向、在 $\triangleright$ 上向右移动并换轨）、构造 $1/2$（$\Gamma'=\Sigma\cup\{\sqcup,\triangleright\}\cup(\Gamma\times\Gamma)$，状态集 $Q\times\{\mathrm{up},\mathrm{down}\}$，初始为 $(q_0,\mathrm{up})$ 且在格子 1 上，$\pi(s)$ 的定义）与构造 $2/2$（上面轨道、下面轨道与边界的三条 $\delta'$ 公式、$M'$ 随 $M$ 接受/拒绝、时间 $\le 2T(n)$）。老师课堂上讲的"折叠一下、用 $\Gamma\times\Gamma$ 的 pair、用状态记录在上面还是下面、读到三角形就反向"与这些页面逐条对应。

## 十一、变种四：多带图灵机（Definition 5 与 Lemma 6） [02:00:20–02:10:39]

### 11.1 多带图灵机与"默认模型"

老师说，我们主要的这个模型——在计算理论里面，如果没说这个图灵机是什么图灵机，那它一般就是**多带图灵机**（multitape Turing machine）。所以如果大家读论文，作者没说是哪一种，一般就是多带。

**定义**：设 $k\ge1$ 是一个常数，一台 **$k$ 带图灵机**是一个七元组 $(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}})$，定义与标准图灵机相同，唯一的区别是它有 $k$ 根纸带、每根纸带各有一个磁头，并且转移函数是

$$\delta:Q\times\Gamma^{k}\to Q\times\Gamma^{k}\times\{L,R,S\}^{k}.$$

它的含义是：$\delta(q,a_1,\dots,a_k)=(q',b_1,\dots,b_k,D_1,\dots,D_k)$ 表示在状态 $q$ 下，如果第 $i$ 个磁头读到 $a_i$（对每个 $i$ 都成立），那么机器进入 $q'$，每个磁头 $i$ 写入 $b_i$ 并按方向 $D_i$ 移动。

老师解释：它有 $k$ 根纸带可以同时操作，每根纸带上都有一个指针，指针的移动是**独立的**——比如第一个指针可以左移、第二个可以右移、第 $k$ 个可以不动（stay）。

那 $k$ 到底是几呢？都可以——$k$ 是一个常数，可以是 1 带、100 带、100 万带，但它是固定的一个常数。一般说来第一根纸带是**输入带**，剩下的是工作带；输入带有的时候会要求它是只读的，但这个不太要紧，因为如果要求只读，我们把它复制一下放到工作带上去读、去改写就可以了。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 15–17 张幻灯片（PDF 第 15–17 页），幻灯片给出 Definition 5（$k$-tape Turing machine）的上述定义与含义，并用两页图说明运行情形：起始时输入 $x$ 在第 1 根纸带上、纸带 2 和 3 全是空白，三个磁头都在格子 0，状态为 $q_0$；计算过程中若 $\delta(q,1,1,\sqcup)=(q',1,0,1,R,S,L)$，则一步之内状态变为 $q'$、三个磁头分别写入 $1,0,1$ 并按 $R,S,L$ 移动。这与老师课堂上讲的"$k$ 根纸带、指针独立移动、第一根是输入带"一致。

### 11.2 引理：多带可以转单带

**引理**：设 $k\ge1$ 是常数，$T(n)\ge n$。如果一个语言 $L$ 可以被一台 $k$ 带图灵机在时间 $T(n)$ 内判定，那么 $L$ 可以被一台单带图灵机在时间 $O_k(T(n)^{2})$ 内判定。

老师给出的目标形式是：$T(n)$ 变成 $T(n)$ 的平方，并且和 $k$ 也有关系，所以写成大 $O(k\cdot T(n)^2)$。

### 11.3 证明：把多带叠成多轨，用帽子标记磁头

老师给的证明思路是"就这一张图"：我们把这三根纸带**压缩成一条纸带**——一个格子里放三个字符。怎么放三个字符呢？就是放一个 $\Gamma$ 的三元组（$\Gamma\times\Gamma\times\Gamma$）。

那怎么记录每个磁头的位置呢？因为现在只有一个磁头。我们就在相应格子里的那个字符上**加一个帽子**（hat）来表示：如果某个字符上有帽子，说明原来那根纸带的磁头就在这一格；没有帽子就不在。老师把 $\hat a$ 这样的记号解释为"标记被模拟的磁头在哪里"。

关于时间为什么从 $T(n)$ 变成 $T(n)^2$：模拟 $M$ 的每一步要花 $O(T(n))$。具体怎么模拟一步呢？

1. 先**从左到右扫一遍**，把这三个戴帽子的符号读出来；
2. 读出来之后就知道该用哪一条转移函数了，然后再扫一遍把符号改写掉；
3. 再扫一遍把帽子移动一下。

所以模拟一步就要来回读三四遍，每遍是 $O(T(n))$，合起来每一步是 $O(T(n))$，而 $M$ 一共有 $T(n)$ 步，所以整体的时间复杂度就是 $O(T(n)^2)$。

老师补充了两个细节：帽子一开始都放在 0 号格子上；移动帽子的时候，如果要从右往左、而帽子又是要右移的，那就需要"退回去一下"再继续，所以每一步模拟的代价是 $T(n)+k$ 这一项（在定理的假设 $T(n)\ge n$ 之下，当 $n$ 足够大时 $n\ge k$，这个 $k$ 就可以拿掉）。老师也承认我们省略了一些细节——到底怎样从左往右扫一遍、怎样找到这 $k$ 个戴帽子的符号、状态之间怎么转移；这些可以用很多个状态（比如用 $\Gamma^{k}$ 个状态去记录读到的 $k$ 元组）来实现。

**结果与点评**：老师说这个证明写出来会有点冗长，如果真的把它形式化，"我们就留做这次的作业"；课堂上只说它的想法。老师问不太理解这个证明的同学举手，然后说"非常好"。

> **老师总结**：这又是一个算法的证明——你给一台 $k$ 带图灵机，我们有一个算法把这台 $k$ 带图灵机转换成一个单带图灵机，而这个单带图灵机的运行时间就是大 $O(T(n)^{2})$。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 18–22 张幻灯片（PDF 第 18–22 页），幻灯片给出的 Lemma 6（multitape to single-tape）为：设 $k\ge1$ 是常数、$T(n)\ge n$；若语言 $L$ 由一台 $k$ 带图灵机在时间 $T(n)$ 内判定，则它可由一台单带图灵机在时间 $O_k(T(n)^2)$ 内判定。证明思路是"把纸带叠成轨道"（stack the tapes as tracks）：单带的每个格子放一个 $k$ 元组，用帽子 $\hat a$ 标记每个被模拟磁头的位置；模拟一步是两次扫描（sweep 1 向右读出戴帽的符号、sweep 2 向左写入新符号并把每个帽子最多移动一格），中间在状态里计算 $\delta$；时间复杂度上，因为 $T(n)$ 步之内 $M$ 的每个磁头都停留在格子 $-T(n),\dots,T(n)$ 之内，所以 $M'$ 纸带被用到的部分最多有 $2T(n)+1$ 格，$M$ 的每一步花两次扫描再加 $O(k)$ 步，即 $O(T(n)+k)$ 步，总时间为 $T(n)\cdot O(T(n)+k)=O_k(T(n)^2)$。这与老师课堂上讲的"三元组、帽子、扫三四遍、就是 $T(n)$ 的平方"完全对应。

## 十二、DTIME 与 P 的定义 [02:10:41–02:15:53]

老师说，下面是一个非常重要的定义，它属于我们这门课的最后一部分——研究计算复杂性，研究这些复杂性类。我们现在开始定义。

**定义**：设 $T:\mathbb{N}\to\mathbb{N}$ 是一个函数。一个语言 $L\subseteq\{0,1\}^{*}$ 属于 $\mathrm{DTIME}(T(n))$，当且仅当存在一台**多带图灵机** $M$，它在时间 $O(T(n))$ 内判定 $L$。

老师说，也就是说 $\mathrm{DTIME}(n)$ 就是在线性时间内可以判定的那些语言，$\mathrm{DTIME}(n^2)$ 就是在 $O(n^2)$ 时间内可以判定的语言。这样我们就定义了一些**复杂性类**（complexity class）；所谓复杂性类，就是语言的集合。

**定义**：$\mathrm{P}$ 是所有多项式时间的并：

$$\mathrm{P}=\bigcup_{c\ge1}\mathrm{DTIME}(n^{c})=\mathrm{DTIME}(n)\cup\mathrm{DTIME}(n^{2})\cup\mathrm{DTIME}(n^{3})\cup\cdots$$

也就是说，$\mathrm{P}$ 就是那些在多项式时间内可以被判定的语言。

老师接着解释了"语言地图"：我们定义了图灵机之后，就可以定义一个小圈——所有语言的圈里，有一个"可判定的语言"的圈；然后我们刚刚定义了 $\mathrm{DTIME}$，比如可以定义 $\mathrm{DTIME}(n)$（$O(n)$ 时间内可以判定的语言），再定义一个 $O(n^2)$ 时间内可以判定的，再定义一个 $O(n^3)$ 时间内可以判定的；然后把这些全部并起来，我们就得到了 $\mathrm{P}$。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 23–24 张幻灯片（PDF 第 23–24 页），幻灯片把这两条定义写成 Definition 7（DTIME）：设 $T:\mathbb{N}\to\mathbb{N}$，语言 $L\subseteq\{0,1\}^*$ 属于 $\mathrm{DTIME}(T(n))$，若存在一台多带图灵机 $M$ 在时间 $O(T(n))$ 内判定 $L$；以及 Definition 8：$\mathrm{P}=\bigcup_{c\ge1}\mathrm{DTIME}(n^c)$，并附 Remark："$\mathrm{P}$ 与图灵机模型的选取无关，因为这些模型之间都可以在多项式时间内相互模拟"。这与老师课堂上的表述一致，也正是本章前面几个引理的意义所在。

### 12.1 为什么 P 的定义与模型无关

老师解释了这里面的优美之处，也就是"理论之美"：优美之处就在于它和这个模型是**无关**的，因为这些模型之间都可以在多项式时间内相互模拟——模拟的代价是多项式。而且多项式对复合是**封闭**的：多项式的多项式还是多项式；多项式加多项式是多项式；多项式乘多项式还是多项式。所以 $\mathrm{P}$ 的定义和模型的选取无关。

老师还提到了一个学生常会担心的问题：这个会不会指数实在太大？比如 $N^{100}$，$N$ 等于 2 的时候就没法算了；但它还是被认为在 $\mathrm{P}$ 里面。

> **老师总结**：这又是一件神奇的事情——在现实中我们遇到的那些自然的问题，要么就不在 $\mathrm{P}$ 里面，要么在 $\mathrm{P}$ 里面时那个指数都相当小，都小于 2 那种，甚至接近线性。比如近些年来，以前那些比较难一点的问题，像线性规划、最大流，都做到了近线性。

老师补充：你说我可不可以通过人为地定义一些问题，让它的指数非常大？是可以的，但那些问题看着就不那么自然了。

## 十三、两个猜想：$\mathrm{P}\ne\mathrm{NP}$ 与最大团问题 [02:15:54–02:22:28]

### 13.1 现在就可以陈述 $\mathrm{P}\ne\mathrm{NP}$

老师说，其实我们现在已经可以陈述 $\mathrm{P}\ne\mathrm{NP}$ 猜想了——我们可以先不定义 $\mathrm{NP}$ 就陈述它。为什么呢？因为我们任取一个 **NP 完全**问题，比如**最大团问题**（CLIQUE，也叫团问题）。

**定义**：$\mathrm{CLIQUE}=\{\langle G,k\rangle: G\text{ 有大小为 } k \text{ 的团}\}$——给你一个 $N$ 个顶点的无向图 $G$，问这个图里面有没有一个 $k$ 个顶点的**团**（clique，也就是 $k$ 个顶点两两之间都有边的子图）。

**例子**：老师给了一个生成随机实例的方式——假设你生成一张随机图：找比如 1000 个顶点，每两个顶点之间你抛硬币决定要不要连一条边（连边的概率是 $1/2$），这样就得到了一张随机图；然后你在这张图里**悄悄地种一个 $k$ 团**：比如悄悄选 5 个顶点，把这 5 个顶点之间全部连边。这样任务就是把这个 $k=5$ 的子图（$K_5$）找出来。

老师说这个问题很难——它是 **NP 难**、**NP 完全**的：现在只能用一些比较暴力的方法去找；如果你找出来了，验证是很容易的（只要验证这几个顶点两两之间是不是都有边），而 NP 就是那些容易验证的问题。但如果这个团藏在一张大图里面，就很难找出来。

**猜想**：

- $\mathrm{P}\ne\mathrm{NP}$；等价地，$\mathrm{CLIQUE}\notin\mathrm{P}$。
- $\mathrm{CLIQUE}\notin\mathrm{DTIME}(n)$——也就是说，最大团问题连线性时间算法都不存在。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 25 张幻灯片（PDF 第 25 页），幻灯片以"Two Conjectures"为题给出：$\mathrm{CLIQUE}=\{\langle G,k\rangle:G\text{ 有大小为 }k\text{ 的团}\}$；Conjecture 9：$\mathrm{P}\ne\mathrm{NP}$，等价地 $\mathrm{CLIQUE}\notin\mathrm{P}$；Conjecture 10：$\mathrm{CLIQUE}\notin\mathrm{DTIME}(n)$。老师课堂上的口述（"我们任取一个 NP 完全问题，这个叫最大团问题"）与这一页对应；其中"两个猜想"这一编号也来自该页。

### 13.2 为什么会卡住：我们连线性下界都证不出来

老师接着讲了 $\mathrm{P}\ne\mathrm{NP}$ 的等价表述与实际困难：

> **老师总结**：如果你证明了最大团问题没有多项式时间算法，你就证明了 $\mathrm{P}\ne\mathrm{NP}$；如果你为它找到了一个多项式时间算法，那你就解决了所有的 NP 问题——你就证明了 $\mathrm{P}=\mathrm{NP}$。

老师也顺便提醒：不建议大家去找这个证明。因为每年都会有一些热爱科学的"民科"会写出一些文章，说比如为最大团问题找到了一个 $N^5$ 时间的算法，然后把邮件到处群发、群发给一些学者，请大家审阅；但一般都是不对的。老师也感叹，看这样的东西非常花时间——你得研究它错在哪里。

那我们现在卡在哪里了呢？老师说，一个令人非常尴尬的事情是：不仅我们离这个猜想非常远，而且这种"远"是一种**不知道怎么证**的远——能用的工具实在太少了。

具体地说：你要证明最大团问题没有线性时间的算法，就是我们考虑多带图灵机，你要证明**不存在**一台多带图灵机在 $O(N)$ 时间内判定最大团问题这种 NP 难问题。完全不知道怎么证。

> **老师启发**：所以大家如果想感受一下这个学科的前沿，想看看是什么样的问题把那些最聪明的学者卡住了，就是这样的问题——证明一个超线性的下界：你找一个问题，它不能在线性时间内被解决；这更别说多项式了。你想证明一个超多项式的下界，比如证明 $N^2$ 的下界、$N^3$ 的下界，那就更难。

主要卡在哪里呢？就是到底用什么样的方法去证它。如果我们想证明这个问题**有**这样的算法，我们就设计这样一台图灵机；那你怎么样证明它**没有**？老师还提了一个开放式的想法：会不会有一天大模型把这个问题给砸出来？但最后还是要回到这个问题，从哲学上（philosophy）看，到底是用一个什么样的想法把它证否的。

## 十四、RAM 图灵机（Definition 11 与 Lemma 12） [02:22:28–02:35:28]

### 14.1 RAM 图灵机：定义与动机

老师说，最后一个是**最强**的模型，这个模型也已经很接近我们现在用的计算机了，它叫 **RAM 图灵机**（RAM Turing machine），RAM 就是 **random access memory**（随机存取存储器）——可以随机读写内存的图灵机。

**定义**：一台 RAM 图灵机是一台 $(k+1)$ 带的图灵机

$$M=(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}},Q_{\mathrm{access}}),$$

它具有下面这些额外的特征：

1. 纸带 $1,\dots,k$ 是工作带（第 1 根纸带放输入）；第 $k+1$ 根纸带是**地址带**（address tape）；
2. 有一个**内存**（memory）$A:\mathbb{N}\to\Gamma$，初始时对所有 $i$ 都有 $A[i]=\sqcup$；
3. 有一个**访问状态集** $Q_{\mathrm{access}}\subseteq Q\setminus\{q_{\mathrm{accept}},q_{\mathrm{reject}}\}$。

$\Gamma$ 里包含两个特殊符号：`Rd`（读）和 `Wr`（写）。当 $M$ 进入 $Q_{\mathrm{access}}$ 中的一个状态时：

- **读**：如果地址带上写着 $\mathrm{bin}(i)\,\mathtt{Rd}$，那么地址带被擦掉，并把 $A[i]$ 写到它的第一个格子里。
- **写**：如果地址带上写着 $\mathrm{bin}(i)\,\mathtt{Wr}\,\sigma$，那么把 $A[i]$ 置为 $\sigma$，并擦掉地址带。
- **其他情况**：什么都不发生。

每一次访问都算**一步**。

转移函数与一台普通的 $(k+1)$ 带图灵机一样：

$$\delta:Q\times\Gamma^{k+1}\to Q\times\Gamma^{k+1}\times\{L,S,R\}^{k+1}.$$

内存 $A$ 不出现 $\delta$ 里；它只通过访问状态来使用。

老师解释说：它和多带图灵机的区别就是它增强了一点——多了一个内存带；这个内存是一个从自然数集合到 $\Gamma$ 的映射，这个机器可以在常数时间内、在一步之内去读写这个内存。它是怎么做到的呢？因为它加了一条内存（以及一条地址带）。老师说这个定义的细节其实不是那么要紧，因为你这样定义、那样定义都是等价的；我们就看这样的一个版本。

老师说明了这个版本的工作方式：地址带存放的就是地址的二进制数、高位在前，然后还有两个特殊字符，一个叫 `read`、一个叫 `write`。如果这边写的是 `read`，就代表要读了：读的话就把内存 $A[i]$ 的值读下来、放到地址带上，然后这个地址就被擦掉了，只剩下 $A[i]$ 这个符号。如果是 `write`，就是把某个符号 $\sigma$ 写到 $A[i]$。而所有这些都在**一步之内**完成。它是用特殊状态来控制的——有一些特殊状态叫内存读写状态，一旦进入这个状态，它就进行这种内存的读写。地址带则像其他工作带一样，用 $\delta$ 转移函数控制。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 26–28 张幻灯片（PDF 第 26–28 页），幻灯片给出的 Definition 11 与上述三条特征一致（第 $k+1$ 根为地址带、内存 $A:\mathbb{N}\to\Gamma$ 初始全为 $\sqcup$、访问状态集 $Q_{\mathrm{access}}\subseteq Q\setminus\{q_{\mathrm{accept}},q_{\mathrm{reject}}\}$）；第 27 张幻灯片给出"读/写/其他"三种情形的动作并注明"每次访问算一步"；第 28 张幻灯片给出转移函数 $\delta:Q\times\Gamma^{k+1}\to Q\times\Gamma^{k+1}\times\{L,S,R\}^{k+1}$ 并注明"内存 $A$ 不出现在 $\delta$ 中，只通过访问状态使用"。这些都与老师课堂上的口述逐条对应。

### 14.2 内存读写的演示

**演示**：老师说"看看这个图就明白了"。

- **读**：地址带上写的是 `101Rd`，其中 `101` 就是 5；然后我们就去读内存里的 $A[5]$；$A[5]$ 这个 1 就被写到地址带上，地址本身被擦掉了。这就是读操作，而且这些都在一步之内完成。
- 但是地址带上的地址是怎么写下去的呢？这个一步之内做不到——这需要四步：先写 1、再写 0、再写 1、再写 `Rd`，先花四步把这个地址准备好，然后一步之内把这个值读下来。
- **写**：写操作是对称的。比如地址是 `10`（也就是 2），然后要把 1 写过去；也是先花四步做这样的一步准备，然后一步之内把这个 1 写过去，然后地址再清空。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 29–30 张幻灯片（PDF 第 29–30 页），幻灯片给出两个算例：**读**——地址带上写着 $\mathrm{bin}(5)\,\mathtt{Rd}$，一次访问步之后 $A[5]=1$ 被复制到地址带的第一个格子，其余部分被擦掉；**写**——地址带上写着 $\mathrm{bin}(2)\,\mathtt{Wr}\,1$，一次访问步之后 $A[2]$ 从 0 变成 1，地址带被擦除。这与老师课堂上讲的 `101Rd`、`10` 写 1 两个演示完全对应（`101` 即 5、`10` 即 2）。

### 14.3 和汇编语言的关系

老师说，这个（内存访问机制）已经有点像我们的汇编语言了：汇编语言里有一个操作叫 `load`，还有 `store`；`load` 就是把内存读出来、`store` 就是往内存里写，也就是读内存、写内存这样的操作。汇编里面也有一些**地址寄存器**，专门用来存放地址；只不过汇编里那个地址一般是 64 位的。

### 14.4 引理：RAM 图灵机可以被多带图灵机模拟

**引理**：如果语言 $L\subseteq\Sigma^{*}$ 可以被一台 RAM 图灵机在时间 $T(n)$ 内判定，那么 $L$ 可以被一台多带图灵机在时间 $O(T(n)^{2})$ 内判定。

**证明**：老师说这个证明"就一句话"——我们用一个工作带来模拟这个内存。

1. 给 $M$ 原来的 $k$ 根工作带和地址带都配上普通纸带；再增加一根**内存带**（memory tape），用来存放一个 pair 的列表 $(\mathrm{bin}(i),A[i])$，每个到目前为止被访问过的地址 $i$ 对应一项。从来没有被访问过的地址不存进去，它们的值就是 $\sqcup$。
2. $M$ 的每一个**非访问步**在 $M'$ 里用一步模拟。
3. 每当 $M$ 进入访问状态，$M'$ 就把内存带**从左到右扫描**一遍：对每一个条目，把它的地址与地址带上的地址逐符号比较，遇到第一个不一致就停下来（跳过这一项、继续读下一个条目）。
4. 如果读到的是 $\mathrm{bin}(i)\,\mathtt{Rd}$：设 $i$ 对应存的值为 $a$（如果列表中没有这一项，则 $a=\sqcup$），擦掉地址带并把 $a$ 写到它的第一个格子。
5. 如果读到的是 $\mathrm{bin}(i)\,\mathtt{Wr}\,\sigma$：把 $i$ 对应条目的值改写为 $\sigma$；如果本来没有这一项，就在末尾追加一个新条目 $\#\mathrm{bin}(i)\!:\!\sigma$。然后擦掉地址带。
6. 最后把内存带的磁头移回最左端。读或写本身都只涉及一个符号，所以这部分在 $O(1)$ 时间内可以完成。

关于时间：每一次访问的代价是 $O(T(n))$，因为要扫描一遍内存带；所以总时间是 $T(n)\cdot O(T(n))=O(T(n)^{2})$。

为什么内存带的长度是 $O(T(n))$ 呢？老师给了理由：设 $M$ 访问过的地址依次为 $i_1,i_2,\dots,i_m$，$i_j$ 的二进制长度为 $\ell_j=|\mathrm{bin}(i_j)|$。因为每次写一个地址，它在地址带上都要移动 $\ell_j$ 这么多步；而一次访问之后地址带上最多只有一个非空白符号（那时地址带刚被擦掉）；在访问 $j$ 之前，地址带上必须写着 $\mathrm{bin}(i_j)$ 后面跟 `Rd` 或 `Wr`，也就是说 $M$ 至少要写 $\ell_j$ 个符号；而每一步在地址带上最多写一个符号。所以

$$\ell_1+\ell_2+\cdots+\ell_m\le T(n),$$

也就是说地址的总长度不会超过 $T(n)$，地址带的长度不会超过大 $O(T(n))$。于是每一步模拟的时间不会超过大 $O(T(n))$：如果没访问内存就是 $O(1)$，如果访问了内存就是大 $O(T(n))$；总的时间就不超过 $T(n)\times O(T(n))=O(T(n)^{2})$。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 31–36 张幻灯片（PDF 第 31–36 页），幻灯片给出的 Lemma 12 为：若语言 $L\subseteq\Sigma^*$ 可由一台 RAM 图灵机在时间 $T(n)$ 内判定，则它可由一台多带图灵机在时间 $O(T(n)^2)$ 内判定。证明思路为：$M'$ 保留 $M$ 的 $k$ 根工作带与地址带，另加一根内存带存放已访问地址的 $(\mathrm{bin}(i),A[i])$ 列表；每个非访问步一步模拟，每次访问用扫描内存带来模拟（逐符号比较地址、遇第一个不一致即跳过；读时若无条目则值为 $\sqcup$；写时覆盖或追加新条目 $\#\mathrm{bin}(i)\!:\!\sigma$；最后把内存带磁头移回最左端）；第 33 张幻灯片给出的内存带例子为 `#101:1#10:1#111:0#⊔…`（即 $A[5]=1$、$A[2]=1$、$A[7]=0$，地址 5、2、7 按此顺序被访问）；地址总长度 $\ell_1+\cdots+\ell_m\le T(n)$、内存带长度 $O(T(n))$、每次访问 $O(T(n))$、总时间 $T(n)\cdot O(T(n))=O(T(n)^2)$。这与老师课堂上逐条讲的内容一致。

### 14.5 从 RAM 到多带再到单带：时间账

证明完 Lemma 12 之后，老师把前面几个引理串起来算了一遍总的时间账：

- RAM 图灵机的运行时间是 $T(n)$；
- 把它转换成**多带**图灵机，变成大 $O(T(n)^{2})$；
- 再把多带转换成**单带**，就变成了大 $O(T(n)^{4})$——也就是 $T(n)$ 变成了 $T(n)$ 的四次方。
- 当然转换到单带之后，我们不妨假设它就是在 $\{0,1\}$ 上（因为前面证过字母表也无关紧要，又只相差一个常数），所以还是大 $O(T(n)^{4})$。

老师再次强调，这些都是"算法的证明"：我们给出一台（更强的）图灵机，就有一个算法把它转换成一台（更弱的）图灵机。

**补充说明**：根据本节补充材料《lec10_slides_variants_of_turing_machines.pdf》第 37 张幻灯片（PDF 第 37 页），幻灯片给出的总结表为：

| 变种 | 模拟所需时间 | 想法 |
|---|---|---|
| 允许停留（$S$） | $O(T(n))$ | 停留 = 先向右、再向左 |
| 字母表 $\Gamma$ | $O(\log\lvert\Gamma\rvert\cdot T(n))$（假设 $T(n)\ge n^2$） | 每个符号用 $\lceil\log_2\lvert\Gamma\rvert\rceil$ 位编码 |
| 双向纸带 | $O(T(n))$ | 把纸带折叠成两条轨道 |
| $k$ 根纸带 | $O_k(T(n)^2)$ | $k$ 条轨道、帽子标记磁头 |
| RAM 图灵机 | $O(T(n)^2)$（在多带图灵机上；在单带图灵机上是 $O(T(n)^4)$） | $(\text{地址},\text{值})$ 对的列表 |

幻灯片的结论是：每一个变种都把 $T(n)$ 变成最多 $\operatorname{poly}(T(n))$，所以可判定语言的类是相同的，$\mathrm{P}$ 无论用哪种模型都是一样的。老师课堂上按同样的顺序讲了这些结论，并在最后特别指出 RAM→多带是 $T(n)^2$、多带→单带再变成 $T(n)^4$。
