# UML 静态类图详解

UML（Unified Modeling Language，统一建模语言）是一种标准化的可视化建模语言，广泛应用于软件工程中。其中，静态类图是 UML 中最常用的图表之一，用于描述系统中的类及其之间的静态关系。本文将详细介绍 UML 静态类图的各个组成部分及其表示方法。

## 一、类的表示

### 1. 基本结构

一个类在 UML 中通常被表示为一个矩形，分为三个部分：
- **顶部**：类名（必须）
- **中部**：属性列表（可选）
- **底部**：方法列表（可选）

```
┌───────────────┐
│   ClassName   │  <- 类名
├───────────────┤
│ - attribute1  │
│ # attribute2  │  <- 属性
│ + attribute3  │
├───────────────┤
│ - method1()   │
│ # method2()   │  <- 方法
│ + method3()   │
└───────────────┘
```

### 2. 访问修饰符

属性和方法前的符号表示访问修饰符：
- `+` 表示 public（公有）
- `-` 表示 private（私有）
- `#` 表示 protected（受保护）
- `~` 表示 package/default（包/默认）

### 3. 属性表示

属性的完整表示形式：
```
[可见性] 名称 [: 类型] [= 默认值] [{属性字符串}]
```

例如：
```
+ name: String = "default" {readOnly}
- age: int
# scores: int[]
```

### 4. 方法表示

方法的完整表示形式：
```
[可见性] 名称([参数列表]) [: 返回类型] [{属性字符串}]
```

参数列表格式：
```
[方向] 参数名称: 类型 [= 默认值]
```
其中方向可以是：`in`、`out`、`inout`

例如：
```
+ calculateGrade(): double
- setName(in newName: String): void
# processData(inout data: DataType): boolean
```

### 5. 抽象类与接口

- **抽象类**：类名使用斜体字，或者在类名上方加上 `<<abstract>>` 构造型
- **接口**：使用 `<<interface>>` 构造型，或者使用特殊符号（圆圈加实线）

```
┌─────────────────┐    ┌──────────────────┐
│  <<abstract>>   │    │   <<interface>>  │
│   AbstractClass │    │    Interface     │
└─────────────────┘    └──────────────────┘
```

## 二、类之间的关系

### 1. 关联（Association）

表示类之间的一般性连接关系。

- **基本关联**：使用实线连接两个类
- **双向关联**：线两端都没有箭头
- **单向关联**：线的一端有箭头，指向被访问的类
- **多重性标记**：显示关联端点上的对象数量

多重性表示：
- `1` 表示精确一个
- `*` 或 `0..*` 表示零个或多个
- `0..1` 表示零个或一个
- `1..*` 表示一个或多个
- `m..n` 表示 m 到 n 个

```
ClassA ─────────> ClassB
        0..*   1
```

### 2. 聚合（Aggregation）

表示"整体-部分"关系，部分可以独立于整体存在。使用空心菱形箭头从整体指向部分。

```
┌───────┐      ┌───────┐
│ Whole │◇─────│ Part  │
└───────┘      └───────┘
```

### 3. 组合（Composition）

表示更强的"整体-部分"关系，部分不能独立于整体存在。使用实心菱形箭头从整体指向部分。

```
┌───────┐      ┌───────┐
│ Whole │◆─────│ Part  │
└───────┘      └───────┘
```

### 4. 泛化/继承（Generalization）

表示类之间的继承关系。使用空心三角形箭头从子类指向父类。

```
┌────────┐
│ Parent │
└────────┘
    ▲
    │
┌────────┐
│ Child  │
└────────┘
```

### 5. 实现（Realization）

表示类实现接口的关系。使用空心三角形和虚线从实现类指向接口。

```
┌────────────┐
│<<interface>>│
│ Interface  │
└────────────┘
      ▲
      ┊
      ┊
┌────────────┐
│    Class   │
└────────────┘
```

### 6. 依赖（Dependency）

表示一个类使用另一个类的关系，通常是暂时性的。使用虚线箭头表示。

```
┌───────┐      ┌───────┐
│ ClassA│- - ->│ ClassB│
└───────┘      └───────┘
```

## 三、高级特性

### 1. 模板/泛型类

使用虚线框表示模板参数。

```
┌───────────────┐
│   Class<T>    │
│ - - - - - - - │
│      <T>      │
└───────────────┘
```

### 2. 枚举类型

使用 `<<enumeration>>` 构造型。

```
┌──────────────────┐
│  <<enumeration>> │
│       Days       │
├──────────────────┤
│ MONDAY           │
│ TUESDAY          │
│ WEDNESDAY        │
│ THURSDAY         │
│ FRIDAY           │
└──────────────────┘
```

### 3. 静态成员

静态属性和方法使用下划线表示。

```
┌───────────────┐
│    ClassName  │
├───────────────┤
│ + attribute   │
│ + _staticAttr │  <- 静态属性
├───────────────┤
│ + method()    │
│ + _staticM()  │  <- 静态方法
└───────────────┘
```

### 4. 抽象方法

抽象方法使用斜体字表示。

```
┌───────────────────┐
│  AbstractClass    │
├───────────────────┤
│ + attribute       │
├───────────────────┤
│ + *abstractMethod()*  │  <- 抽象方法
│ + concreteMethod()│
└───────────────────┘
```

## 四、类图实例分析

下面是一个综合示例，涵盖了多种关系：

```
┌───────────────┐      ┌────────────────┐
│    Person     │      │<<enumeration>> │
├───────────────┤      │   GenderType   │
│ - name: String│      ├────────────────┤
│ - age: int    │      │ MALE           │
│ # gender: GenderType │◇--│ FEMALE         │
├───────────────┤      │ OTHER          │
│ + getName()   │      └────────────────┘
│ + setName()   │
│ + getAge()    │
└───────────────┘
        ▲
        │
┌───────────────────┐       ┌───────────────┐
│      Student      │       │    Course     │
├───────────────────┤       ├───────────────┤
│ - studentId: String│◆─────○─│ - courseId   │
│ - grades: Map      │0..*  1│ - courseName │
├───────────────────┤       ├───────────────┤
│ + enrollCourse()  │- - - >│ + register()  │
│ + calculateGPA()  │       │ + complete()  │
└───────────────────┘       └───────────────┘
```

在这个例子中：
- `Person` 是 `Student` 的父类（泛化关系）
- `Student` 和 `Course` 之间有组合关系，一个学生可以选多门课程，一门课程属于一个学生
- `Person` 和 `GenderType` 之间有聚合关系
- `Student` 对 `Course` 的 `register` 方法有依赖关系

## 五、类图最佳实践

1. **保持简洁**：仅显示对理解系统必要的类和关系
2. **合理分组**：将相关类放在一起，提高可读性
3. **明确标记多重性**：在关联端点标明多重性，清晰表达关系
4. **使用注释**：对复杂关系添加文字说明
5. **区分关系类型**：正确使用泛化、实现、组合、聚合、关联和依赖
6. **一致性**：整个图中使用一致的表示法

## 六、常见误区

1. **混淆聚合与组合**：聚合(◇)是"弱"的整体-部分关系，组合(◆)是"强"的关系
2. **过度复杂化**：类图应当清晰表达设计意图，不要包含过多细节
3. **忽略多重性**：多重性标记对理解关系至关重要
4. **混淆依赖与关联**：关联是结构性关系，依赖则是使用关系
5. **滥用继承**：继承应该遵循"是一个"原则，而不仅仅是共享代码

## 总结

UML 静态类图是面向对象设计中描述系统结构的强大工具。通过正确使用类表示、关系符号和高级特性，可以清晰地表达系统中各个类的职责和它们之间的交互方式。掌握这些表示方法不仅有助于设计阶段的沟通，也能帮助开发人员更好地理解和实现系统架构。
