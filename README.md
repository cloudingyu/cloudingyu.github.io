这是一份**纯内容导出包**，用于从零重建 CloudingYu 的个人博客。

包内只保留**信息本身**：个人信息、站点结构、文章正文、图片素材。
**不包含任何样式、布局、模板、脚本或设计资产**——新站点请自行设计视觉与交互。

> 本包已自包含。读完本文件 + `SITE_DATA.md` + `POSTS_INDEX.md`，无需访问原仓库即可完成重建。

## 重建任务说明

### 必须原样保留（内容层）

1. **全部 15 篇文章的正文**，一字不改，包括标题、副标题、日期、标签、作者署名。
2. **全部 50 个图片文件**，不要重新压缩、裁剪或替换。
3. **`SITE_DATA.md` 中的个人信息**：站点标题、副标语、邮箱、头像、侧边栏简介、社交链接、友链。
4. **各页面的背景图与描述文案**（首页、About、Archive、404 各有专属背景与一句引言）。
5. **站点结构**：首页（分页 6 篇）、About、Archive（按年份分组 + 标签筛选）、404、站内搜索。
6. **Markdown 富文本能力**：代码高亮（多语言）、LaTeX 数学公式（10 篇文章依赖）、表格、图片。
7. **文章引用的外部资源**直链（About 页的 shields.io 徽章、Giphy 动图；洛谷/力扣题目外链）。

### 必须重新设计（展示层）

以下部分**刻意未包含**在本包中，新站点应完全自行发挥：

- 所有 CSS / SCSS / LESS / 主题配色 / 字体
- 布局模板与组件结构（原为 Bootstrap 3 时代的三栏卡片式布局）
- JavaScript 交互与动画
- 图标方案与图标库（原为 Font Awesome）
- PWA / Service Worker 行为（原站点最终已禁用）
- Disqus 评论（原为注释状态，未启用）
- 统计埋点（原为注释状态，无有效 ID）

**风格不做任何继承**。唯一需要延续的是内容的气质：技术向、学术感、中文为主的个人技术博客。

⚠️ 如果新设计需要「封面图」概念，注意只有 `2025-01-26-vim-VScode` 一文有专属头图，其余 14 篇**没有配图**，需要靠版式与文字排布撑起列表页，不要为它们编造图片。

## 技术栈建议

原站点是 Jekyll + SCSS。既然是重写，推荐考虑：

| 方案 | 适合场景 |
| --- | --- |
| **Astro** | 内容站首选，Markdown 原生支持、默认零 JS、内置分页与内容集合 |
| **Hugo** | 构建最快，单二进制，无需 Node 环境 |
| **Next.js (App Router + MDX)** | 需要复杂交互或后续接 CMS 时 |
| **VitePress / Docusaurus** | 偏文档站风格，中文技术博客适配良好 |

无论选哪个，两个硬性要求：

- **数学公式渲染**必须开启（KaTeX 或 MathJax），否则 10 篇文章会显示成乱码般的 `$...$`。
- **代码高亮**需支持原文用到的语言（C++、Python、Java、JavaScript、Ruby、Bash、HTML、YAML、JSON 等）。

## 关键实施细节

### 1. 图片路径需改写

文章正文统一使用**根绝对路径**引图：

```markdown
![相向而行](/img/posts/2022-02-08-luogu-P1007/1.png)
```

而本包中的图片位于 `images/posts/...`。两种处理方式：

- **批量改写正文**（推荐）：
  ```bash
  sed -i 's|](/img/|](/images/|g' posts/*.markdown
  ```
- **或在构建配置中设置 `baseurl` / 静态资源根**，让 `/img/` 映射到 `images/`。

⚠️ 注意 `2025-01-26-vim-VScode.markdown` 的 `header-img` 字段写的是 `img/posts/...`（**缺前导斜杠**），批量替换时要单独确认它没被漏掉。

### 2. Front matter 需要转换

原文件为 Jekyll 格式，字段含义见 `POSTS_INDEX.md` 末节。转换要点：

- `layout: post` → 换成新框架的布局约定或直接删除
- `header-style: picture` → 纯展示层标记，删除
- `header-img` → 转成新站点的封面图字段（仅 1 篇有值）
- `mathjax` → 可全局开启，无需逐篇判断
- `date` + 文件名中的日期 → 保持两者一致，用于排序与永久链接
- 第 15 篇的作者署名是小写 `cloudingyu`，与其余 14 篇的 `CloudingYu` 不同，这是原样数据，**不要"修正"**

### 3. 永久链接格式

原站点用 `permalink: pretty`，文章 URL 形如：

```
/2025/04/07/UML/
/2022/02/08/luogu-P1007/
```

如果要保持旧链接可用（外部有引用、SEO 有积累），新站点应沿用这个 `/YYYY/MM/DD/<slug>/` 结构。

### 4. 标签体系

共 17 个标签，其中 7 个文章数 ≥ 2。原站点「特色标签」阈值为 1（即数量 > 1 会被突出）。标签的多语言混合（中文标签 + `VSCode`/`Vim`/`IDE` 英文标签）是原样数据，注意排序与展示时的中英混排效果。

### 5. 中文排版

站点为中文为主。注意：

- 标题与正文中的中英混排、全角标点（`（）`、`：`、`「」`）
- 引号在 YAML 中需要转义处理（原文用双引号包裹含中文标点的字段）
- 时区为 `Asia/Shanghai`

### 6. 已清理的冗余文件（无需找回）

- `icon_wechat.png` — 与头像 `profile_pic.jpg` **字节完全相同**（MD5 一致），已去重
- `DeviceWithVisitorPro.svg` — 访问者模式一文的废弃旧版图，正文从未引用，且与保留版 `DeviceWithVisitor.svg` 内容高度重复

## 快速上手

```bash
# 1. 解压后进入目录
cd blog-content-export

# 2. 改写图片路径
sed -i 's|](/img/|](/images/|g' posts/*.markdown

# 3. 用你选定的框架初始化站点，把 posts/ 与 images/ 纳入内容目录
#    然后参考 SITE_DATA.md 填充个人信息与页面结构
```

任何不确定「这算内容还是算设计」的取舍，判断标准是：**它是不是关于这个人的信息，或这个人写下的东西？** 是则保留，否则自行设计。
